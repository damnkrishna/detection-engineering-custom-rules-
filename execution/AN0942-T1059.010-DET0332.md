### 1. Technique Breakdown: T1059.010

* What it is: Command and Scripting Interpreter: AutoHotKey & AutoIT. Adversaries use compiled scripts or scripting interpreters like AutoHotKey and AutoIT to automate host operations, run obfuscated payloads, or evade standard shell-based script monitoring.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688, and Sysmon File Creation events (Event ID 11).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Interpreter execution and script file creation on local storage are monitored.
  - NIDS (Suricata + Zeek): NO. Host-local application scripting.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 11 (file_event)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: AutoHotKey or AutoIT Interpreter Execution
Detects the execution of AutoHotKey or AutoIT interpreters or their compiled scripts, pairing tool identity with command-line script parameters.

```yaml
title: AutoHotKey or AutoIT Interpreter Execution (AN0942-A)
id: cbdf2e03-a178-4db9-8b9a-7c9802cf6914
status: experimental
description: Detects command-line execution of AutoHotKey or AutoIT script engines.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\autohotkey.exe'
            - '\autoit3.exe'
    selection_orig:
        OriginalFileName:
            - 'AutoHotkey.exe'
            - 'AutoIt3.exe'
    selection_cli:
        CommandLine|contains:
            - '.ahk'
            - '.au3'
            - ' /ErrorStdOut '
            - ' /AutoIt3ExecuteScript '
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_images or selection_orig) and selection_cli and not filter_installer
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Administrative automation tools or custom keystroke-mapping helpers.
level: medium
tags:
    - attack.execution
    - attack.t1059.010
    - analytic.an0942
    - detection.det0332
```

#### Rule 2 of 2: AutoHotKey or AutoIT Script File Drop
Detects the creation of `.ahk` or `.au3` scripts in temporary or user directories.

```yaml
title: AutoHotKey or AutoIT Script File Drop (AN0942-B)
id: f48debb3-cb3d-4c3e-b8d9-cc90e2cfc214
status: experimental
description: Detects the drop of AutoHotKey or AutoIT scripts into temp or AppData folders.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: file_event
    product: windows
detection:
    selection_paths:
        TargetFilename|contains:
            - '\AppData\Local\Temp\'
            - '\AppData\Roaming\'
    selection_exts:
        TargetFilename|endswith:
            - '.ahk'
            - '.au3'
    filter_installer:
        Image|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_paths and selection_exts and not filter_installer
fields:
    - TargetFilename
    - Image
    - User
falsepositives:
    - Software installers or desktop utility upgrades dropping local files.
level: medium
tags:
    - attack.execution
    - attack.t1059.010
    - analytic.an0942
    - detection.det0332
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Keystroke Automation
  * The Issue: IT staff using AutoHotKey to automate repetitive GUI work will trigger Rule 1.
  * The Fix: Baseline standard developer or administrator machines and apply targeted source IP or path exclusions.
* Problem 2: Evasion via Compiled Binaries
  * The Issue: AutoHotKey scripts compiled into standard executable binaries (.exe) will bypass file drop checks (Rule 2) and interpreter name checks (Rule 1).
  * The Fix: Enable monitoring of unrecognized executables dropping into temp directories or starting without digital signatures.
