### 1. Technique Breakdown: T1059.005

* What it is: Visual Basic. Adversaries abuse the Windows Script Host (WSH) engine (via interpreters like `wscript.exe` and `cscript.exe`) to execute malicious Visual Basic scripts (`.vbs`, `.vbe`, or `.vba`). This is a common execution method used in phishing attacks, where a malicious macro in an Office document (Word, Excel) spawns a VBScript file, or a user runs a downloaded `.vbs` script disguised as a document.
* Log Source Requirements: Endpoint logs capturing process creation and command line parameters (specifically targeting built-in script hosts spawned by Office applications or running from temporary directories).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs the execution of `wscript.exe` or `cscript.exe` and records command-line flags showing the executed script paths. It also logs parent-child process relationships (e.g., Office applications spawning script hosts).
* NIDS (Suricata + Zeek): NO. VBScript execution is a local endpoint activity. Network security tools cannot inspect host-internal script execution (though they might alert on the initial download of the `.vbs` file or outbound C2 traffic).

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect when Windows Script Host interpreters (`wscript.exe`, `cscript.exe`) are executed under suspicious contexts: either spawned by Microsoft Office applications (indicating macro exploitation) or executing scripts from user-writable temporary directories.

```yaml
title: Suspicious Visual Basic Script Execution (AN0209)
id: c57f8e9a-1b2c-4d92-8c8d-6f7d8e9a0b0c
status: experimental
description: Detects suspicious execution of wscript.exe or cscript.exe spawned by Microsoft Office applications or executing VBScripts from user-writable directories.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_images:
        - Image|endswith:
            - '\wscript.exe'
            - '\cscript.exe'
        - OriginalFileName:
            - 'wscript.exe'
            - 'cscript.exe'
    selection_office_parents:
        ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\powerpnt.exe'
            - '\outlook.exe'
    selection_temp_paths:
        CommandLine|contains:
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\Windows\Temp\'
            - '\AppData\Roaming\'
    condition: selection_images and (selection_office_parents or selection_temp_paths)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Administrative logon scripts or internal deployment tools executing VBScripts.
    - Specialized local applications executing macro tasks during update processes.
level: high
tags:
    - attack.execution
    - attack.t1059.005
    - analytic.an0209
    - detection.det0076
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
