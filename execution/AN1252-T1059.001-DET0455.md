### 1. Technique Breakdown: T1059.001

* What it is: Command and Scripting Interpreter: PowerShell. Adversaries abuse PowerShell to download payloads, execute commands, run scripts in memory, and perform post-exploitation activities.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. PowerShell command-line parameters and parent process relationships are monitored.
  - NIDS (Suricata + Zeek): YES. PowerShell-initiated egress downloads can be identified at network egress checkpoints.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Obfuscated or Encoded PowerShell CommandLine
Detects PowerShell execution containing encoding flags, execution bypass switches, or download/execution indicators, separating image and original filename checks.

```yaml
title: Obfuscated or Encoded PowerShell CommandLine (AN1252-A)
id: f023d881-819a-44f2-9ca0-80ef522f0020
status: experimental
description: Detects command-line execution of PowerShell with suspicious switches, encoding, or download strings.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_orig:
        OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
            - 'pwsh.exe'
    selection_cli:
        CommandLine|contains:
            - ' -enc'
            - ' -encoded'
            - ' -e '
            - ' bypass'
            - ' hidden'
            - 'iex'
            - 'downloadstring'
            - 'downloadfile'
            - 'invoke-expression'
            - '[char[]]'
            - '[convert]::'
    condition: (selection_images or selection_orig) and selection_cli
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Administrative maintenance or backup scripts implementing encoded or hidden windows configurations.
level: high
tags:
    - attack.execution
    - attack.t1059.001
    - analytic.an1252
    - detection.det0455
```

#### Rule 2 of 2: Unusual PowerShell Parent Process
Detects PowerShell processes spawned by web server processes, office suites, or database servers.

```yaml
title: Unusual PowerShell Parent Process (AN1252-B)
id: cbdf2001-a189-4db8-bb9a-7c9802cf0021
status: experimental
description: Detects PowerShell spawned by non-standard parent applications.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_orig:
        OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
            - 'pwsh.exe'
    selection_parents:
        ParentImage|endswith:
            - '\w3wp.exe'
            - '\nginx.exe'
            - '\tomcat.exe'
            - '\winword.exe'
            - '\excel.exe'
            - '\powerpnt.exe'
            - '\sqlserver.exe'
            - '\postgres.exe'
            - '\mysqld.exe'
    condition: (selection_images or selection_orig) and selection_parents
fields:
    - Image
    - ParentImage
    - CommandLine
    - User
falsepositives:
    - Authorized database plugins or web applications executing system tasks.
level: critical
tags:
    - attack.execution
    - attack.t1059.001
    - analytic.an1252
    - detection.det0455
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Script Integration
  * The Issue: Custom database integration modules spawning PowerShell to synchronize data will trigger Rule 2.
  * The Fix: Baseline administrative service accounts and add their specific user context or script paths to whitelist filters.
* Problem 2: Evasion via System.Management.Automation
  * The Issue: If the attacker loads System.Management.Automation DLL directly in a custom C# binary to run PowerShell code without spawning powershell.exe, Rule 1/2 will not trigger.
  * The Fix: Enable monitoring of DLL loads of System.Management.Automation.dll by unusual parent binaries.
