### 1. Technique Breakdown: T1059

* What it is: Command and Scripting Interpreter. Adversaries abuse default Windows script hosts like Windows Script Host (WSH - `wscript.exe` / `cscript.exe`) to execute malicious scripts (.vbs, .js) as part of their delivery or execution chain.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. WSH execution CLI parameters and parent processes are monitored.
  - NIDS (Suricata + Zeek): YES. Script-initiated network traffic can be tracked.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Suspicious Script Execution CommandLine
Detects execution of `wscript.exe` or `cscript.exe` running scripting engines with specific switches or targeting temp/script files, separating image and original filename checks.

```yaml
title: Suspicious Script Execution CommandLine (AN1428-A)
id: f023d881-819a-44f2-9ca0-80ef522f0028
status: experimental
description: Detects command-line execution of wscript.exe or cscript.exe with parameters executing vbscript or jscript.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\wscript.exe'
            - '\cscript.exe'
    selection_orig:
        OriginalFileName:
            - 'wscript.exe'
            - 'cscript.exe'
    selection_cli:
        CommandLine|contains:
            - ' //e:vbscript'
            - ' //e:jscript'
            - ' .vbs'
            - ' .js'
            - ' .sct'
            - ' //b'
            - ' //nologo'
    condition: (selection_images or selection_orig) and selection_cli
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - IT administration scripts deploying legacy packages.
level: medium
tags:
    - attack.execution
    - attack.t1059
    - analytic.an1428
    - detection.det0516
```

#### Rule 2 of 2: Unusual Script Host Parent Process
Detects Windows Script Host processes spawned by browser engines, office productivity programs, or web server services.

```yaml
title: Unusual Script Host Parent Process (AN1428-B)
id: cbdf2001-a189-4db8-bb9a-7c9802cf0029
status: experimental
description: Detects cscript.exe or wscript.exe processes spawned by unusual parent processes.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\wscript.exe'
            - '\cscript.exe'
    selection_orig:
        OriginalFileName:
            - 'wscript.exe'
            - 'cscript.exe'
    selection_parents:
        ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\chrome.exe'
            - '\msedge.exe'
            - '\w3wp.exe'
    condition: (selection_images or selection_orig) and selection_parents
fields:
    - Image
    - ParentImage
    - CommandLine
    - User
falsepositives:
    - Web services configured to spawn custom backend diagnostics (uncommon).
level: critical
tags:
    - attack.execution
    - attack.t1059
    - analytic.an1428
    - detection.det0516
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Software Installer Scripts
  * The Issue: Software packages deploying components using embedded `.vbs` or `.js` scripts will trigger Rule 1.
  * The Fix: Exclude known, trusted installer parent directories or signature-verified binaries.
* Problem 2: Evasion via Registry Hijacking
  * The Issue: If the adversary hijacks the registry associations for `.vbs` or `.js` to point to a custom parser rather than `wscript.exe`, this rule will not trigger.
  * The Fix: Monitor registry keys associated with shell file opening defaults (`HKCR\VBSFile\Shell\Open\Command`).
