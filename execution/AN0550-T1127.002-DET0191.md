### 1. Technique Breakdown: T1127.002

* What it is: Trusted Developer Utilities Proxy Execution: ClickOnce. Adversaries abuse the Windows ClickOnce deployment technology (`dfshim.dll` and `dfsvc.exe`) to execute malicious applications. ClickOnce allows users to install and run Windows applications by clicking a link in a web page or document. Attackers can abuse this by using `rundll32.exe` to call `dfshim.dll` with a URL pointing to a malicious ClickOnce application, bypassing application control rules because both `rundll32.exe` and `dfsvc.exe` (the ClickOnce engine) are legitimate, trusted Microsoft utilities.
* Log Source Requirements: Endpoint logs capturing process creation and command line parameters (specifically targeting `rundll32.exe` loading `dfshim.dll` or `dfsvc.exe` spawning unexpected child processes).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs the command line arguments when `rundll32.exe` is called with `dfshim.dll` and when `dfsvc.exe` spawns follow-on processes.
* NIDS (Suricata + Zeek): NO. ClickOnce execution is an endpoint-local application loading process. Network monitoring cannot differentiate a malicious ClickOnce application download from a legitimate one (though network logs may capture the SMB or HTTP requests fetching the `.application` file).

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the abuse of ClickOnce utility proxies, specifically focusing on `rundll32.exe` calling `dfshim.dll` to launch remote apps, or the ClickOnce service engine (`dfsvc.exe`) spawning command shell interpreters or other suspicious child processes.

```yaml
title: ClickOnce Proxy Execution Abuse (AN0550)
id: c46e7f8a-1c2b-4d92-8c8d-6f7d8e9a0b0d
status: experimental
description: Detects ClickOnce utility abuse, including rundll32.exe loading dfshim.dll to execute applications or dfsvc.exe spawning unexpected child shells.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_rundll:
        - Image|endswith: '\rundll32.exe'
        - OriginalFileName: 'RUNDLL32.EXE'
    selection_dfshim_args:
        CommandLine|contains|all:
            - 'dfshim.dll'
        CommandLine|contains:
            - 'ShOpenVerbApplication'
            - 'ShOpenVerbShortcut'
    selection_dfsvc:
        ParentImage|endswith: '\dfsvc.exe'
    selection_suspicious_children:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\regsvr32.exe'
            - '\rundll32.exe'
            - '\mshta.exe'
            - '\csc.exe'
            - '\msbuild.exe'
    condition: (selection_rundll and selection_dfshim_args) or (selection_dfsvc and selection_suspicious_children)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate corporate ClickOnce application deployments launching administrative scripts or self-updating utilities.
level: high
tags:
    - attack.execution
    - attack.defense-evasion
    - attack.t1127.002
    - analytic.an0550
    - detection.det0191
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
