### 1. Technique Breakdown: T1127.002

* What it is: Trusted Developer Utilities Proxy Execution: ClickOnce. Adversaries abuse the Windows ClickOnce deployment technology (dfshim.dll and dfsvc.exe) or MSBuild compiler utilities to execute malicious applications. Attackers can abuse this by using rundll32.exe to call dfshim.dll with a URL pointing to a malicious ClickOnce application, or by deploying malicious XML project files, bypassing application control rules because these utilities are trusted Microsoft executables.
* Log Source Requirements: Endpoint logs capturing process execution, command line parameters, and file write events.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs when rundll32.exe loads dfshim.dll and when dfsvc.exe spawns subprocesses, and Sysmon Event ID 11 (File Event) logs when project or deployment files are written.
* NIDS (Suricata + Zeek): NO. Execution is local.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 11 (file_event)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring of ClickOnce proxy execution and file event logging of ClickOnce/MSBuild project file writes.

Rule 1 of 2: ClickOnce Proxy Execution Abuse (Process Creation)
```yaml
title: ClickOnce Proxy Execution Abuse (AN0550)
id: c46e7f8a-1c2b-4d92-8c8d-6f7d8e9a0b0d
status: experimental
description: Detects ClickOnce utility abuse, including rundll32.exe loading dfshim.dll to execute applications or dfsvc.exe spawning unexpected child shells.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_rundll:
        - Image|endswith: '\rundll32.exe'
        - OriginalFileName: 'RUNDLL32.EXE'
    selection_dfshim_args:
        CommandLine|contains|all:
            - 'dfshim.dll'
        CommandLine|contains:
            - 'ShOpenVerbApplication'
            - 'ShOpenVerbShortcut'
    selection_dfsvc:
        ParentImage|endswith: '\dfsvc.exe'
    selection_suspicious_children:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\regsvr32.exe'
            - '\rundll32.exe'
            - '\mshta.exe'
            - '\csc.exe'
            - '\msbuild.exe'
    condition: (selection_rundll and selection_dfshim_args) or (selection_dfsvc and selection_suspicious_children)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate corporate ClickOnce application deployments launching administrative scripts.
level: high
tags:
    - attack.execution
    - attack.defense-evasion
    - attack.t1127.002
    - analytic.an0550
    - detection.det0191
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
