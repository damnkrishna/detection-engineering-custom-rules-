### 1. Technique Breakdown: T1059.003

* What it is: Command and Scripting Interpreter: Windows Command Shell. Adversaries use `cmd.exe` or batch files (`.bat`, `.cmd`) to interact with the system, execute programs, or launch subsequent scripts. Because `cmd.exe` is ubiquitous and heavily utilized by the OS, attackers frequently use it to blend in.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures every invocation of `cmd.exe`, including full command-line parameters (like `/c` or `/k`) and the parent process.
    * NIDS (Suricata + Zeek): NO. Command shell usage is strictly a local host activity.

---

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect suspicious invocation chains involving `cmd.exe`, particularly when launched by unusual parent processes like Microsoft Office or when using suspicious command-line parameters indicative of evasion.

```yaml
title: Suspicious Windows Command Shell Execution (AN0578)
id: 59a35e4d-080c-43f1-b1e6-b040cf6e3e5c
status: experimental
description: Detects interactive or scripted abuse of cmd.exe, focusing on anomalous parent processes, suspicious command-line flags, or chained execution.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_cmd:
        Image|endswith: '\cmd.exe'
    selection_parent:
        ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\powerpnt.exe'
            - '\mshta.exe'
            - '\wmiprvse.exe'
            - '\spoolsv.exe'
            - '\lsass.exe'
    selection_flags:
        CommandLine|contains:
            - ' /c '
            - ' /k '
            - '^' # Obfuscation using caret
            - '&' # Command chaining
    condition: selection_cmd and (selection_parent or selection_flags)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Logon scripts executing via wmiprvse.exe.
    - Legacy applications heavily chaining commands with ampersands.
level: high
tags:
    - attack.execution
    - attack.t1059.003
    - analytic.an0578
    - detection.det0202
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
