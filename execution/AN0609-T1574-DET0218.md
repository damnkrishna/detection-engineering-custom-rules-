### 1. Technique Breakdown: T1574

* What it is: Hijack Execution Flow. Adversaries modify the environment Windows uses to locate and execute programs (such as DLL load paths, service binary configurations, or application pathways) to hijack execution flow. By changing the binPath of a service, pointing a service's ServiceDll registry key to a malicious module, or modifying Image File Execution Options (IFEO) registry keys, they force system processes or applications to run their payload.
* Log Source Requirements: Endpoint logs capturing process creation and registry modifications.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs configuration utilities like sc.exe and reg.exe, and Event ID 13 (Registry Set) logs direct service path or IFEO debugger registry writes.
* NIDS (Suricata + Zeek): NO. Local host configurations.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 13 (registry_set)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring of command-line service modification tools, and registry set monitoring of Image File Execution Options debugger modifications.

Rule 1 of 2: Service Execution Flow Hijacking via CLI (Process Creation)
```yaml
title: Service Execution Flow Hijacking via CLI (AN0609)
id: c4e7d1b2-2e1f-4b92-8c7a-5f6d7e8a9b0d
status: experimental
description: Detects command-line service modifications or registry additions that alter the execution flow of system services (such as modifying service binPath or adding custom ServiceDlls).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_sc:
        - Image|endswith: '\sc.exe'
        - OriginalFileName: 'sc.exe'
    selection_sc_args:
        CommandLine|contains|all:
            - 'config'
            - 'binpath'
    selection_reg:
        - Image|endswith:
            - '\reg.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'reg.exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_reg_args:
        CommandLine|contains|all:
            - 'System\CurrentControlSet\Services'
            - 'add'
        CommandLine|contains:
            - 'ImagePath'
            - 'ServiceDll'
    condition: (selection_sc and selection_sc_args) or (selection_reg and selection_reg_args)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate software installers configuring service binary paths during application deployment.
level: high
tags:
    - attack.execution
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1574
    - analytic.an0609
    - detection.det0218
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
