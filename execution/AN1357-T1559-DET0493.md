### 1. Technique Breakdown: T1559

* What it is: Inter-Process Communication. Adversaries abuse IPC mechanisms (like named pipes, COM objects, or DDE) to execute remote code, perform lateral movement, or bypass boundary defense configurations.
* Log Source Requirements: Sysmon Named Pipe Creation events (Event ID 17) and Sysmon Process Creation events (Event ID 1).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Named pipe creations and COM command execution registrations are tracked.
  - NIDS (Suricata + Zeek): NO. Host-local inter-process communication.
* Log Sources Covered:
  - Sysmon Event ID 17 (pipe_created)
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Anomalous Named Pipe Creation
Detects creation of named pipes associated with known post-exploitation tool suites or containing suspicious indicators in their naming strings.

```yaml
title: Anomalous Named Pipe Creation (AN1357-A)
id: f023d881-819a-44f2-9ca0-80ef522f0024
status: experimental
description: Detects Sysmon Event ID 17 named pipe creation events pointing to post-exploitation frameworks or anomalous prefixes.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: pipe_created
    product: windows
detection:
    selection_pipes:
        PipeName|contains:
            - '\postex_'
            - '\status_'
            - '\msagent_'
            - '\msse-'
            - '\spooler_'
            - '\lsass_'
    filter_system:
        # Exclude standard built-in spooler or LSASS calls
        Image|endswith:
            - '\system32\spoolsv.exe'
            - '\system32\lsass.exe'
            - '\system32\services.exe'
    condition: selection_pipes and not filter_system
fields:
    - PipeName
    - Image
    - User
falsepositives:
    - Diagnostic packages mimicking standard pipe structures (rare).
level: critical
tags:
    - attack.execution
    - attack.t1559
    - analytic.an1357
    - detection.det0493
```

#### Rule 2 of 2: Suspicious COM Execution Registration
Detects execution of administrative utilities registering or invoking COM components from remote URLs or scripting objects, separating image and original filename checks.

```yaml
title: Suspicious COM Execution Registration (AN1357-B)
id: cbdf2001-a189-4db8-bb9a-7c9802cf0025
status: experimental
description: Detects command-line execution of regsvr32.exe or mshta.exe executing COM scripts.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\regsvr32.exe'
            - '\mshta.exe'
    selection_orig:
        OriginalFileName:
            - 'regsvr32.exe'
            - 'mshta.exe'
    selection_cli:
        CommandLine|contains:
            - 'scrobj.dll'
            - 'http'
            - '/i:'
    condition: (selection_images or selection_orig) and selection_cli
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Internal business applications registering trusted COM objects during deployment.
level: high
tags:
    - attack.execution
    - attack.t1559
    - analytic.an1357
    - detection.det0493
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Software Agent Named Pipes
  * The Issue: Security agents or monitoring packages can create custom named pipes that happen to use similar status/agent keywords.
  * The Fix: Baseline the approved binaries and add their exact paths to the whitelists in Rule 1.
* Problem 2: Evasion via Local Files
  * The Issue: If the attacker loads a local script file (`.sct`) instead of fetching it from a remote URL (`http`), Rule 2 will not trigger the `http` indicator.
  * The Fix: Enforce the detection of `scrobj.dll` or `/i:` switches independently of network parameters.
