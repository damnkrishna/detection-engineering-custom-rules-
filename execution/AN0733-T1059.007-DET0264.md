### 1. Technique Breakdown: T1059.007

* What it is: Command and Scripting Interpreter: JavaScript. Adversaries use JavaScript (often executed via Windows Script Host binaries like `wscript.exe` and `cscript.exe`, or HTML Applications via `mshta.exe`) to execute malicious code. This is commonly seen in spearphishing campaigns where a user opens an Office document with a macro that drops a `.js` or `.jse` file and executes it.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon tracks executions of `wscript.exe`, `cscript.exe`, and `mshta.exe`, along with their script arguments.
    * NIDS (Suricata + Zeek): NO. Local execution of JavaScript is host-level activity.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of Windows Script Host executing JavaScript files, particularly when spawned from suspicious parents or running from user directories.

```yaml
title: Suspicious JavaScript Execution via WSH (AN0733)
id: f42a7862-2f08-4121-81d3-3fc8c21a115d
status: experimental
description: Detects JavaScript execution through wscript.exe, cscript.exe, or mshta.exe, particularly when spawned from Office macros or abnormal user paths.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_wsh:
        Image|endswith:
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
    selection_js:
        CommandLine|contains:
            - '.js'
            - '.jse'
    selection_suspicious:
        - ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\outlook.exe'
        - CommandLine|contains:
            - '\AppData\Local\Temp\'
            - '\Downloads\'
            - '\ProgramData\'
    condition: selection_wsh and selection_js and selection_suspicious
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legacy enterprise applications relying on local JavaScript automation.
level: high
tags:
    - attack.execution
    - attack.t1059.007
    - analytic.an0733
    - detection.det0264
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
