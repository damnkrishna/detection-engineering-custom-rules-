### 1. Technique Breakdown: T1204.002

* What it is: User Execution: Malicious File. Adversaries rely on a user opening a malicious file (e.g., an Office document, PDF, script, or executable) delivered via email, USB, or download. When opened, the file exploits a vulnerability, runs macros, or directly executes malicious code. This typically manifests as a user-facing application (Word, archiver) dropping payloads into user-controlled paths and spawning script engines.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1) and File Creation logs (Sysmon Event ID 11).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon tracks the execution chain (e.g., WinRAR spawning a `.bat` file) and files dropped into `Downloads` or `Temp`.
    * NIDS (Suricata + Zeek): PARTIAL. NIDS can detect the malicious file being downloaded (e.g., analyzing an unencrypted email attachment or HTTP download), but not the local execution.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect user-facing applications (like archivers or document readers) spawning shells or script interpreters, indicating the execution of a malicious file.

```yaml
title: User Execution - Malicious File Opened (AN0819)
id: cc9fa89e-4a6f-4d37-8b09-b6732cf0505a
status: experimental
description: Detects a handler application (archiver, Office, PDF reader) spawning a new or unusual child process, indicating execution of a malicious file.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_parent:
        ParentImage|endswith:
            - '\winrar.exe'
            - '\7zFM.exe'
            - '\winzip64.exe'
            - '\explorer.exe'
            - '\winword.exe'
            - '\excel.exe'
            - '\AcroRd32.exe'
    selection_child:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\regsvr32.exe'
            - '\rundll32.exe'
            - '\msiexec.exe'
    condition: selection_parent and selection_child
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Users legitimately extracting installer scripts from archives and running them.
    - Approved enterprise macros running administrative commands.
level: high
tags:
    - attack.execution
    - attack.t1204.002
    - analytic.an0819
    - detection.det0294
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
