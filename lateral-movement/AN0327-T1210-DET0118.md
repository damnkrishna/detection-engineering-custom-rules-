### 1. Technique Breakdown: T1210

* What it is: Exploitation of Remote Services. Adversaries exploit security vulnerabilities (such as buffer overflows or remote code execution bugs) in network services (like Print Spooler spoolsv.exe, Local Security Authority Subsystem lsass.exe, RPC service host svchost.exe, or SMB helper service) to run commands or shellcode. Successful exploitation typically results in these high-privilege system services spawning command interpreters (cmd.exe, powershell.exe) or staging binaries, which is an extremely anomalous execution pattern.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) capturing parent-child process chains and account context.
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures parent process paths (e.g., spoolsv.exe, lsass.exe) launching child programs. Wazuh aggregates these and triggers immediate high-severity warnings.
  * NIDS (Suricata + Zeek): YES. Network logs track exploit attempts (like RPC or SMB exploitation payloads) on boundary interfaces, but host logs are needed to verify if shell execution followed.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect Windows remote system services (such as Local Security Authority lsass.exe or Print Spooler spoolsv.exe) spawning command shell interpreters or script hosts.

```yaml
title: Lateral Movement - Windows Service Spawning Suspicious Shell (AN0327)
id: bc47b72b-b56a-487a-aaa0-8e1e1bf703bf
status: experimental
description: Detects core Windows services (lsass.exe, spoolsv.exe) spawning command interpreters or script hosts, indicating potential exploitation (e.g., PrintNightmare, remote code execution).
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_parent:
        ParentImage|endswith:
            - '\spoolsv.exe' # Print Spooler
            - '\lsass.exe' # LSASS
    selection_child:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
        - OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'mshta.exe'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_parent and selection_child and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate administrative troubleshooting or vendor driver installation scripts that directly communicate with system services.
level: critical
tags:
    - attack.lateral-movement
    - attack.t1210
    - analytic.an0327
    - detection.det0118
```

        process.file.path|endswith:
            - '\cmd.exe'

    - Critical vendor driver configuration tools spawning shell processes (extremely rare).
level: critical

    - attack.lateral-movement

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Third-Party Print Driver Helpers
  * The Issue: Certain HP, Xerox, or Lexmark print driver packages legitimately trigger command shell runs under the spooler service (spoolsv.exe) to unpack configuration files or write port assignments, causing false alerts.
  * The Fix: Add a rule whitelist filter excluding standard command line patterns or paths belonging to verified print drivers, checking code signatures.

* Problem 2: Execution via Service DLL Injection (In-Memory)
  * The Issue: If the exploit injects shellcode directly into the running thread of the target service (e.g. lsass.exe) and establishes a reverse shell socket connection within the service thread itself without launching a new process, parent-child checks will see no child process.
  * The Fix: Monitor LSASS process access events (Sysmon Event ID 10) or alert on network socket creation (Event ID 3) initiated directly by lsass.exe or spoolsv.exe targeting external IPs.

* Problem 3: Standard Windows error reporting
  * The Issue: If the service crashes during an exploit attempt, Windows Error Reporting (WerFault.exe) is spawned by the crashing service process, which can match generic parent-child anomaly alerts.
  * The Fix: Exclude WerFault.exe from the child process list in the rule to avoid generating alerts during standard application crashes.
