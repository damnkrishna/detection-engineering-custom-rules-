### 1. Technique Breakdown: T1021.001

* What it is: Remote Services: Remote Desktop Protocol. Adversaries use Remote Desktop Protocol (RDP) to log in interactively to a remote system. Once they establish the RDP GUI session, they start executing administrative utilities or credential theft programs. Host-based detection checks for RDP sessions (Logon Type 10) running command shells, script hosts, or known discovery tools (like ipconfig.exe, net.exe) shortly after logon.
* Log Source Requirements: Windows Security Event Log Event ID 4624 (Logon) and Sysmon process creation logs (Event ID 1) linked by logon session ID.
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Windows Security logs capture Logon Type 10 (RDP) successful authentications. Sysmon logs process creation events containing the session's logon ID. Wazuh links these events.
  * NIDS (Suricata + Zeek): YES. Network filters detect outbound RDP sessions (port 3389) and track connection statistics, but cannot see what commands run inside the session.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - PowerShell Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Command execution in RDP sessions can be detected using process creation and PowerShell script block logs.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring and PowerShell script block logging.

Rule 1 of 2: Command Execution in RDP Session (Process Creation)
```yaml
title: Lateral Movement - Command Execution in RDP Session (AN0931)
id: ca7c6ff1-a1eb-430b-a76e-0274173b72ef
status: experimental
description: Detects command-line interpreters or administrative utilities executing within a Remote Desktop (RDP - Logon Type 10) session, suggesting post-access lateral movement activities.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
detection:
    selection_session:
        LogonId|not: '0x3e7'
    selection_executables:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\whoami.exe'
            - '\net.exe'
            - '\net1.exe'
            - '\nltest.exe'
        - OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'whoami.exe'
            - 'net.exe'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_session and selection_executables and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate IT administrators logging in remotely via RDP to troubleshoot systems or run maintenance commands.
level: medium
tags:
    - attack.lateral-movement
    - attack.t1021.001
    - analytic.an0931
    - detection.det0327
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Standard IT Administration Overhead (Noise)
  * The Issue: Network engineers use RDP daily to run script execution tasks or manage local servers, generating a high baseline of alerts.
  * The Fix: Scope the rule to ignore alerts on systems in authorized administration VLANs, or limit logging to non-admin user accounts executing RDP commands.

* Problem 2: Execution via RDP Initial Applications (No Explorer)
  * The Issue: Windows allows RDP connections to launch a single target application (e.g. MS Access or custom database tool) instead of the full desktop shell. If that application has a vulnerability, code executes inside its path.
  * The Fix: Monitor process starts where the parent is userinit.exe but the child is not explorer.exe.

* Problem 3: RDP Hijacking (Session hijacking)
  * The Issue: If the attacker hijacks an existing RDP session (e.g., using tscon.exe to take over a disconnected admin session), no new logon event (Event ID 4624) is generated, bypassing initial logon filters.
  * The Fix: Monitor for execution of tscon.exe or terminal service session modifications in the System log (Event ID 40 in TerminalServices-LocalSessionManager).
