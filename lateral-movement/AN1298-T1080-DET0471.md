### 1. Technique Breakdown: T1080

* What it is: Shared Content. Adversaries may deliver payloads to a system by tainting content that is shared across systems, e.g., in shared network directories or repositories. An administrative network share (such as C$, ADMIN$, or IPC$) is often used by lateral movement tools and adversaries to copy binaries, scripts, or shortcut files. Once dropped on the shared repository or administrative volume, these files can be executed by target hosts through remote scheduled tasks, remote service control, or manual user interaction.
* Log Source Requirements: Endpoint file creation events (e.g. Sysmon Event ID 11 / Windows Security Event ID 4663) monitoring writes to shared folders or administrative volumes.
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 11 logs the creation of files, their target paths, writing processes, and extensions.
  * NIDS (Suricata + Zeek): NO. While NIDS can track SMB file transfers, detecting file creation events on host volumes (like specific administrative shares mapped locally) requires host-based filesystem auditing.
* Log Sources Covered:
  - Sysmon Event ID 11 (file_event)
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Dropping and executing tainted shared content can be detected using file event and process creation logs.

### 2. Custom Sigma Rule

The detection logic is split into file creation monitoring and process creation execution monitoring on shared storage.

Rule 1 of 2: Tainted Content Dropped on Shared Storage (File Event)
```yaml
title: Tainted Content Dropped on Shared Storage (AN1298)
id: fec142f1-c3f4-41db-81ad-e335625fd6d6
status: experimental
description: Detects file creation events dropping executable, scripting, or shortcut extensions (e.g., .exe, .vbs, .lnk) onto administrative network shared directory paths.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: file_event
    product: windows
detection:
    selection_shares:
        TargetFilename|contains:
            - '\C$\'
            - '\Admin$\'
            - '\IPC$\'
            - '\\'
    selection_extensions:
        TargetFilename|endswith:
            - '.exe'
            - '.vbs'
            - '.lnk'
            - '.bat'
            - '.ps1'
            - '.scr'
            - '.cmd'
    condition: selection_shares and selection_extensions
fields:
    - Image
    - TargetFilename
    - User
falsepositives:
    - Administrative software distribution or patch management tools that deploy updates via admin shares.
level: medium
tags:
    - attack.lateral-movement
    - attack.t1080
    - analytic.an1298
    - detection.det0471
```

Rule 2 of 2: Executable Run from Shared Storage (Process Creation)
```yaml
title: Executable Run from Shared Storage (AN1298-B)
id: 1be652bc-20d8-467a-9c1f-995fc0b094c8
status: experimental
description: Detects the execution of binaries directly from administrative or UNC shared directory paths, indicating potential lateral execution of dropped tools.
author: Krishna Gupta
date: 2026-06-16
logsource:
    category: process_creation
    product: windows
detection:
    selection_path:
        - Image|contains:
            - '\C$\'
            - '\Admin$\'
            - '\\'
        - CommandLine|contains:
            - '\C$\'
            - '\Admin$\'
            - '\\'
    filter_legitimate:
        Image|startswith: 'C:\'
    condition: selection_path and not filter_legitimate
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Legitimate administrative software deployment or installation packages running directly from network shares.
level: medium
tags:
    - attack.lateral-movement
    - attack.t1080
    - analytic.an1298
    - detection.det0471
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Update and Deployment Systems
  * The Issue: Deployment agents (e.g. SCCM, Tanium, PDQ Deploy) routinely push installation packages and scripts to administrative shares (like ADMIN$ or C$\Windows\Temp) before launching them. This causes significant noise.
  * The Fix: Correlate and filter out file creation events initiated by known, signed installer binaries or authorized service accounts (e.g., domain administrator accounts dedicated to software deployment).

* Problem 2: Non-Standard Network Share Paths
  * The Issue: Attackers might create custom network shares (e.g. \\*\PublicShare\) which do not contain administrative flags like C$ or ADMIN$. Simple string checks looking for administrative shares will miss these drops.
  * The Fix: Expand directory auditing to log file write activity across all active SMB shares or monitor registry modifications of shared directories under HKLM\SYSTEM\CurrentControlSet\Services\LanmanServer\Shares.

* Problem 3: Execution Delay/Evasion
  * The Issue: Simply dropping a file does not guarantee execution. An attacker might place a DLL payload (like uxtheme.dll or similar) in a shared directory to exploit DLL search order hijacking when a legitimate application is run later.
  * The Fix: Enable file creation logging and combine it with Process Creation events (Sysmon ID 1 / Security Event ID 4688) monitoring execution of newly dropped files.
