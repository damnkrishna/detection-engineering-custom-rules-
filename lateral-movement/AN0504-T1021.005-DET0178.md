### 1. Technique Breakdown: T1021.005

* What it is: Remote Services: VNC. Adversaries install Virtual Network Computing (VNC) software on target systems to establish interactive GUI remote control sessions. This allows them to interact with the target machine directly, bypass standard administrative shell logs, and easily move laterally across the network. Detection focuses on identifying VNC server processes launching from non-standard folders or running as unauthorized services.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) and network connection logs (Event ID 3) capturing VNC client/server activity.
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 tracks VNC process execution, and Event ID 3 logs network connections targeting standard VNC ports.
  * Windows Security Logs: NO. Standard Windows Security Logs (service: security) do not capture active RFB protocol sessions or custom VNC software executions unless mapped specifically.
* Conclusion: VNC binary executions and connections can be detected via Sysmon process creation and network connection logs.

### 2. Custom Sigma Rule

The detection logic is split into two rules to target process creation and network connections separately.

Rule 1 of 2: VNC Server Binary Execution
```yaml
title: Suspicious VNC Server Binary Execution (AN0504-A)
id: b7e3f1a2-4c9d-4e8b-a6f5-1d2c3b4a5e6f
status: experimental
description: Detects execution of known VNC server binaries which may indicate an adversary installing remote control capability for lateral movement or persistent access (T1021.005).
author: Krishna Gupta
date: 2026-06-12
logsource:
    category: process_creation
    product: windows
detection:
    selection_vnc_binaries:
        - Image|endswith:
            - '\winvnc.exe'
            - '\tvnserver.exe'
            - '\vncviewer.exe'
            - '\uvnc_service.exe'
            - '\vncserver.exe'
            - '\vncconfig.exe'
            - '\xvnc.exe'
        - OriginalFileName:
            - 'winvnc.exe'
            - 'tvnserver.exe'
            - 'vncviewer.exe'
            - 'uvnc_service.exe'
            - 'vncserver.exe'
    filter_legitimate_path:
        Image|contains:
            - '\Program Files\RealVNC\'
            - '\Program Files\TightVNC\'
            - '\Program Files\UltraVNC\'
    filter_legitimate_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_vnc_binaries and not (filter_legitimate_path or filter_legitimate_installer)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - User
    - CurrentDirectory
falsepositives:
    - Legitimate IT helpdesk or remote support teams using VNC
    - Sanctioned VNC deployments outside Program Files (requires path tuning)
    - Software deployment pipelines installing VNC tooling
level: high
tags:
    - attack.lateral-movement
    - attack.t1021.005
    - analytic.an0504
    - detection.det0178
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Non-standard Port Mappings
  * The Issue: Attackers can configure VNC services to listen on common business ports (like port 80, 443, or 8080) to bypass firewall filters and static port detection rules.
  * The Fix: Focus detection on the VNC server process name (winvnc.exe) and command line parameters, rather than relying solely on destination port numbers.
* Problem 2: Execution via Portable VNC Binaries
  * The Issue: Attackers can copy portable, single-file VNC binaries to local writeable directories (like Temp or Downloads) and rename them to avoid file name checks (e.g. renaming winvnc.exe to taskhost.exe).
  * The Fix: Enable PE file metadata monitoring (checking OriginalFileName header signatures) and monitor network sockets initiated by renamed processes executing from temp directories.
* Problem 3: Standard corporate helpdesk usage
  * The Issue: Desktop support teams may use VNC to manage end-user workstations, triggering a large volume of alerts.
  * The Fix: Restrict VNC client access to authorized administrator subnets and GPO whitelist policies, and alert on connections originating from standard user segments.
