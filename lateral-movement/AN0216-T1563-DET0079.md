### 1. Technique Breakdown: T1563

* What it is: Remote Service Session Hijacking. Adversaries may hijack an existing session of a remote service (such as RDP or ssh) to move laterally and bypass multi-factor authentication or credentials requirements. On Windows, RDP session shadowing (mstsc.exe /shadow) or session redirection (tscon.exe) allows administrators or attackers to hijack or observe user sessions. Before hijacking, adversaries typically run query utilities (like query.exe user or qwinsta.exe) to list active terminal sessions and discover session IDs.
* Log Source Requirements: Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs process paths (mstsc.exe, tscon.exe, query.exe, qwinsta.exe) and command line parameters.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Conclusion: Remote service session hijacking and query tool executions can be detected via Sysmon process creation and Windows Security logs.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect RDP session hijacking via tscon.exe executed under SYSTEM context or via sc.exe creating a service targeting tscon in the binary path, as well as session enumeration queries.

```yaml
title: RDP Session Hijacking via tscon.exe (AN0216)
id: d4e2f1a3-6b8c-4d9e-a7f2-3c1b2a4d5e6f
status: experimental
description: Detects RDP session hijacking via tscon.exe executed under SYSTEM context or via sc.exe creating a service with tscon in the binary path. Adversaries with SYSTEM privileges use this native Windows utility to take control of disconnected RDP sessions without requiring credentials (T1563.002).
author: Krishna Gupta
date: 2026-06-12
logsource:
    category: process_creation
    product: windows
detection:
    selection_tscon_img:
        - Image|endswith: '\tscon.exe'
        - OriginalFileName: 'tscon.exe'
    selection_tscon_system:
        User|contains:
            - 'SYSTEM'
            - 'NT AUTHORITY\SYSTEM'
    selection_sc_img:
        - Image|endswith: '\sc.exe'
        - OriginalFileName: 'sc.exe'
    selection_sc_args:
        CommandLine|contains|all:
            - 'create'
            - 'tscon'
            - '/dest:'
    selection_query_user:
        - Image|endswith:
            - '\query.exe'
            - '\qwinsta.exe'
        - OriginalFileName:
            - 'query.exe'
            - 'qwinsta.exe'
    selection_query_args:
        CommandLine|contains:
            - ' user'
            - ' session'
    filter_console_reconnect:
        CommandLine|contains: '/dest:console'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: ((selection_tscon_img and selection_tscon_system) or (selection_sc_img and selection_sc_args) or (selection_query_user and selection_query_args)) and not filter_console_reconnect and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - IT administrators reconnecting to their own disconnected sessions
    - Terminal server maintenance reconnecting sessions via scripts
    - Helpdesk tooling that uses tscon.exe for user session management
level: high
tags:
    - attack.lateral-movement
    - attack.t1563.002
    - analytic.an0216
    - detection.det0079
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Shadowing Without CLI (Windows Remote Assistance / GUI)
  * The Issue: Administrators or attackers can initiate RDP shadowing or Remote Assistance through GUI shortcuts or MMC console snap-ins. This doesn't involve running mstsc.exe with explicit /shadow parameters on the command line.
  * The Fix: Monitor RPC connections targeting the Terminal Services interface, or enable registry auditing on HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services\Shadow which configures RDP shadowing policies.

* Problem 2: Legitimate IT Remote Desktop Support Noise
  * The Issue: Helpdesk technicians routinely run query session (qwinsta) or use RDP shadowing to assist users. This can generate false alarms.
  * The Fix: Filter out processes run by known IT Support or System Administrator groups, or restrict alerts to non-standard parent processes (e.g. cmd.exe or powershell.exe spawned by web servers or database processes).

* Problem 3: Custom / Alternate Remote Session Queries
  * The Issue: Attackers can list active sessions using WMI (Get-WmiObject Win32_LogonSession) or NetAPI calls (NetSessionEnum), bypassing the execution of standard utilities like query.exe.
  * The Fix: Supplement this rule by monitoring WMI querying events and auditing API calls to NetSessionEnum within endpoint security or network traffic logs.
