### 1. Technique Breakdown: T1550.003

* What it is: Use Alternate Authentication Material: Pass the Ticket. Adversaries hijack Kerberos Ticket Granting Tickets (TGT) or Service Tickets (TGS) to authenticate to remote resources without knowing the user's password. They inject stolen tickets into their local LSASS session (e.g., using Rubeus or Mimikatz). Detection focuses on identifying Kerberos Ticket requests (Event ID 4768/4769) containing anomalous or weak encryption types (like RC4-HMAC, 0x17 / 23), or process creations referencing ticket injection command parameters.
* Log Source Requirements: Windows Security Event Log Event ID 4768 (TGT requested) and Event ID 4769 (Service Ticket requested), or Sysmon process creation logs (Event ID 1).
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Windows Security log audits Kerberos service requests. Sysmon Event ID 1 logs ticket injection tool parameters (e.g., rubeus.exe ptt). Wazuh parses these logs to trigger alerts.
  * NIDS (Suricata + Zeek): YES. Network sensors monitor Kerberos ticket request traffic and flag anomalous encryption algorithms.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Windows Security Log Event ID 4768 (security)
  - Windows Security Log Event ID 4769 (security)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Pass the ticket activity can be detected using process creation and security authentication logs.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring and Kerberos authentication request monitoring.

Rule 1 of 2: Pass the Ticket Kerberos Command Line (Process Creation)
```yaml
title: Pass the Ticket Kerberos Command Line (AN1000)
id: 4928e1de-dfad-467d-97fb-ecddb53471b2
status: experimental
description: Detects process executions containing command arguments associated with Kerberos ticket injection (Rubeus, Mimikatz).
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
detection:
    selection_tools:
        CommandLine|contains:
            - 'ptt ' # Pass the ticket
            - 'asktgt '
            - 'createnetonly'
            - 'kerberos::ptt'
    condition: selection_tools
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Red team testing or authorized security auditing.
level: high
tags:
    - attack.lateral-movement
    - attack.t1550.003
    - analytic.an1000
    - detection.det0352
```

Rule 2 of 2: Pass the Ticket Kerberos Authentication Activity (Authentication)
```yaml
title: Pass the Ticket Kerberos Authentication Activity (AN1000-B)
id: 98ce318b-ce8b-4db4-9082-a7cfdfe758ce
status: experimental
description: Detects Kerberos Ticket Granting Ticket (TGT) or Service Ticket (TGS) requests using legacy RC4 encryption (0x17/23), suggesting alternate authentication material usage.
author: Krishna Gupta
date: 2026-06-16
logsource:
    product: windows
    service: security
detection:
    selection_kerberos:
        EventID:
            - 4768 # TGT Request
            - 4769 # TGS Request
        TicketEncryptionType:
            - '0x17' # RC4-HMAC
            - '23'
    condition: selection_kerberos
fields:
    - EventID
    - TicketEncryptionType
    - TargetUserName
    - TargetDomainName
    - IpAddress
falsepositives:
    - Legacy operating systems or legacy application servers in the domain that do not support AES Kerberos encryption and fallback to RC4.
level: high
tags:
    - attack.lateral-movement
    - attack.t1550.003
    - analytic.an1000
    - detection.det0352
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Legacy Domain controllers falling back to RC4
  * The Issue: If the Active Directory domain contains old Windows Server 2008/2012 servers or legacy trusts, standard authentications may fallback to RC4-HMAC, creating false positive alerts.
  * The Fix: Disable RC4 support domain-wide in Group Policy settings (enforcing AES128/AES256) and alert on any fallback attempt.

* Problem 2: Use of AES tickets for Pass the Ticket
  * The Issue: Modern ticket injection tools (like Rubeus) support stealing and injecting AES256 tickets (0x12), which bypasses the legacy RC4-HMAC (0x17) encryption type filter.
  * The Fix: Complement this rule by monitoring endpoint memory access events (Sysmon Event ID 10) targeting lsass.exe to block ticket harvesting.

* Problem 3: Standard administrative Rubeus usage
  * The Issue: Internal red teams or security auditors running authorized penetration tests will generate ticket injection alerts.
  * The Fix: Set up explicit time-bound exceptions matching audit hostnames or designated security testing user accounts.
