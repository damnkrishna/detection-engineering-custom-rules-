### 1. Technique Breakdown: T1531

* What it is: Account Access Removal. Adversaries delete or disable local or domain user accounts (particularly administrator accounts) to lock out legitimate system administrators, prevent incident response recovery, or disrupt business operations. They execute account deactivations or deletions using command-line administrative tools (`net.exe user <username> /delete` or `/active:no`) or PowerShell cmdlets (`Remove-LocalUser`, `Disable-LocalUser`).
* Log Source Requirements: Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs CLI command parameters for user configuration utilities. Windows Security Event ID 4726 (A user account was deleted) and Event ID 4725 (A user account was disabled) can also verify account changes.
* NIDS (Suricata + Zeek): NO. User account modifications are directory service or local database operations and do not generate network logs.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of `net.exe` or PowerShell cmdlets used to delete or disable user accounts.

```yaml
title: User Account Access Removal via CLI (AN0334)
id: e7428d4c-c06b-4e08-b6d4-17fe9e06bd25
status: experimental
description: Detects command-line execution of net.exe or PowerShell cmdlets used to delete, disable, or deactivate user accounts, which can be abused to lock out administrators.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_net:
        - Image|endswith:
            - '\net.exe'
            - '\net1.exe'
        - OriginalFileName:
            - 'net.exe'
            - 'net1.exe'
    selection_net_user:
        CommandLine|contains:
            - 'user'
    selection_net_action:
        CommandLine|contains:
            - '/delete'
            - 'active:no'
            - '/active:no'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_args:
        CommandLine|contains:
            - 'Remove-LocalUser'
            - 'Disable-LocalUser'
            - 'Remove-ADUser'
            - 'Disable-ADAccount'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: ((selection_net and selection_net_user and selection_net_action) or (selection_powershell and selection_powershell_args)) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate administrative account management tasks or automated user lifecycle provisioning scripts disabling inactive accounts.
level: high
tags:
    - attack.impact
    - attack.t1531
    - analytic.an0334
    - detection.det0334
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Direct Active Directory LDAP/API Deletions
  * The Issue: Attackers can write scripts using LDAP API protocols or ADSI COM interfaces in .NET to delete/disable domain accounts directly, without spawning CLI processes like net.exe or loading standard AD PowerShell modules.
  * The Fix: Enable active directory auditing and monitor Windows Security Event ID 4726 (A user account was deleted) and Event ID 4725 (A user account was disabled) on Domain Controllers.

* Problem 2: Local SAM API Bypasses
  * The Issue: Attackers can directly call Windows SAM APIs (like SamDeleteUser) using compiled binaries (e.g. Mimikatz or custom C++ tools) to delete local accounts without running net.exe.
  * The Fix: Monitor Windows Security Event ID 4726 on endpoints, and audit changes to the Security Accounts Manager (SAM) database under HKLM\SAM\SAM.

* Problem 3: Automated HR/Identity Provisioning Noise
  * The Issue: Identity Management (IDM) or HR integration scripts automatically disable or remove accounts when employees leave, generating regular logs.
  * The Fix: Whitelist known identity sync service accounts and specific administrative server IPs.
