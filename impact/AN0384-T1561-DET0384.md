### 1. Technique Breakdown: T1561

* What it is: Disk Wipe. Adversaries destroy primary storage volumes, logical partitions, or Master Boot Records (MBR) on targeted systems, making the hosts completely unbootable and destroying all stored data. Under Windows, they abuse built-in utilities (like diskpart.exe, format.com, or fsutil.exe) to execute destructive routines (such as partition deletions, disk cleans, or volume dismounts). They may also use PowerShell storage cmdlets to modify or wipe disk layouts.
* Log Source Requirements: Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688) and PowerShell script block logs (Sysmon Event ID 4104).
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 captures the invocation of disk utility tools along with destructive CLI arguments. Sysmon Event ID 4104 (Script Block) is effective at catching PowerShell-based partition removal or disk clearing commands.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Disk wiping activity can be detected using process creation and PowerShell script block logs.

### 2. Custom Sigma Rule

The detection logic is split into utility execution monitoring and script block content monitoring.

Rule 1 of 2: Disk Wiping and Partition Destruction Utilities via CLI (Process Creation)
```yaml
title: Disk Wiping and Partition Destruction Utilities via CLI (AN0384-A)
id: 09df714a-0a0c-42f4-b9a0-439b48288311
status: experimental
description: Detects command-line execution of disk formatting, partition management, or raw volume dismounting tools (such as diskpart, format, fsutil) used in disk wiping.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_diskpart:
        - Image|endswith:
            - '\diskpart.exe'
            - '\format.com'
            - '\fsutil.exe'
        - OriginalFileName:
            - 'diskpart.exe'
            - 'format.com'
            - 'fsutil.exe'
    selection_args:
        CommandLine|contains:
            - 'clean'
            - 'delete partition'
            - 'format'
            - 'dismount'
            - 'volume dismount'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_diskpart and selection_args and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - IT administrators formatting external drives or scripting storage setups on new server clusters.
level: high
tags:
    - attack.impact
    - attack.t1561
    - analytic.an0384
    - detection.det0384
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Raw Driver/Kernel Level MBR Wiping
  * The Issue: Direct block write operations to physical drives bypass standard high-level command utilities entirely.
  * The Fix: Monitor raw disk access events (Sysmon Event ID 9) targeting physical volumes.

* Problem 2: Script Block Logging Disabled
  * The Issue: In-memory PowerShell cmdlets will not be captured if script block logging is disabled.
  * The Fix: Audit system endpoint logging policies to ensure Event ID 4104 is configured.

* Problem 3: Automated OS Deployment Tools
  * The Issue: Automated system imaging environments execute disk clean cmdlets legitimately, causing false alarms.
  * The Fix: Whitelist system deployment subnets and service accounts.
