### 1. Technique Breakdown: T1565.003

* What it is: Data Manipulation: Runtime Data Manipulation. Adversaries modify data in memory or during runtime execution to alter transaction values, bypass checks, or steal retail cards (e.g., POS RAM scraping). They achieve this by injecting threads or acquiring process handles with write access targeting active business/database processes.
* Log Source Requirements: Sysmon Process Access events (Event ID 10) and Sysmon CreateRemoteThread events (Event ID 8).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. API calls requesting write handles and remote threads are natively monitored.
  - NIDS (Suricata + Zeek): NO. Host-local memory space operations.
* Log Sources Covered:
  - Sysmon Event ID 10 (process_access)
  - Sysmon Event ID 8 (create_remote_thread)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Code Injection into Transaction Applications
Detects Sysmon Event ID 10 process access events indicating suspicious processes requesting write handles (e.g. `0x1F0FFF`, `0x1410`) targeting POS, database, or retail transaction processes by using specific binary name ends-with rules.

```yaml
title: Code Injection into Transaction Applications (AN1097-A)
id: 4555f9ce-672f-4a8e-ab78-082c3e5c3ec2
status: experimental
description: Detects processes requesting high-privilege write access handles targeting transaction or database processes.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_access
    product: windows
detection:
    selection_target:
        TargetImage|endswith:
            - '\pos.exe'
            - '\retail.exe'
            - '\sap.exe'
            - '\sqlserver.exe'
            - '\postgres.exe'
    selection_access:
        # Requesting write or full VM control access handles
        GrantedAccess:
            - '0x1F0FFF'
            - '0x1010'
            - '0x1410'
    filter_sys:
        SourceImage|endswith:
            - '\system32\svchost.exe'
            - '\system32\lsass.exe'
            - '\system32\csrss.exe'
            - '\system32\winlogon.exe'
            - '\MsMpEng.exe'
    condition: selection_target and selection_access and not filter_sys
fields:
    - SourceImage
    - TargetImage
    - GrantedAccess
    - User
falsepositives:
    - Administrative diagnostics or application monitoring engines capturing query profiles.
level: high
tags:
    - attack.impact
    - attack.t1565.003
    - analytic.an1097
    - detection.det0391
```

#### Rule 2 of 2: Remote Thread Creation in Transaction Application Processes
Detects Sysmon Event ID 8 logs showing a process spawning a remote thread inside the memory space of a POS, transaction, or database application.

```yaml
title: Remote Thread Creation in Transaction Application Processes (AN1097-B)
id: 1d799b7b-8c5f-45bc-9a82-9c054e7d86ee
status: experimental
description: Detects Sysmon Event ID 8 capturing remote thread creations inside POS or database processes.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: create_remote_thread
    product: windows
detection:
    selection_target:
        TargetImage|endswith:
            - '\pos.exe'
            - '\retail.exe'
            - '\sap.exe'
            - '\sqlserver.exe'
            - '\postgres.exe'
    filter_sys:
        SourceImage|endswith:
            - '\system32\svchost.exe'
            - '\system32\csrss.exe'
            - '\system32\lsass.exe'
            - '\system32\winlogon.exe'
            - '\MsMpEng.exe'
    condition: selection_target and not filter_sys
fields:
    - SourceImage
    - TargetImage
    - User
falsepositives:
    - System level updates or development debuggers attached during runtime patching.
level: critical
tags:
    - attack.impact
    - attack.t1565.003
    - analytic.an1097
    - detection.det0391
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Debuggers
  * The Issue: Database administrators running performance profiles or memory attachments will trigger Rule 1.
  * The Fix: Baseline administrative source images (such as specific diagnostic binaries) and add them to the `filter_sys` or custom whitelists.
* Problem 2: Evasion via Process Hollowing
  * The Issue: If the attacker performs process hollowing on the target process during creation, they do not trigger EID 8.
  * The Fix: Enable monitoring of process creations referencing untrusted paths or mismatching binary hashes.
