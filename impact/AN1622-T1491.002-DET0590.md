### 1. Technique Breakdown: T1491.002

* What it is: Defacement: External Defacement. Adversaries modify content or resources on external services (such as CDN endpoints, public DNS registries, or corporate landing pages hosted externally) to display messages, redirect traffic, or damage the organization's reputation.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688, and Sysmon File Creation/Modification events (Event ID 11).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Outbound deployment script arguments and local DNS server zone file writes are monitored.
  - NIDS (Suricata + Zeek): NO. Host-local deployment or zone modification execution.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 11 (file_event)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: CDN or External Hosting Update Command Line
Detects command-line parameters indicating non-standard script or CLI updates targeting external CDNs or cloud storage buckets (e.g. AWS S3, Cloudflare, Azure CDN) containing static page updates, filtering out known corporate CI/CD agents and user accounts independently.

```yaml
title: CDN or External Hosting Update Command Line (AN1622-A)
id: e021d5e2-ba1d-4798-a5c6-f142a0443ca9
status: experimental
description: Detects command-line arguments indicating CLI or scripting modifications targeting public CDN or cloud static assets.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\aws.exe'
            - '\az.exe'
            - '\python.exe'
            - '\node.exe'
    selection_cli:
        CommandLine|contains:
            - 's3 sync'
            - 's3 cp'
            - 'cdn profile'
            - 'cloudflare'
            - 'invalidate'
            - 'defaced'
    filter_cicd_images:
        Image|endswith:
            - '\gitlab-runner.exe'
            - '\agent.exe'
            - '\jenkins.exe'
            - '\tcagent.exe'
    filter_cicd_users:
        User|contains:
            - 'service'
            - 'build'
            - 'deploy'
    filter_installers:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_images and selection_cli and not (filter_cicd_images or filter_cicd_users or filter_installers)
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Legitimate CI/CD pipelines deploying standard corporate assets to public facing CDNs.
level: medium
tags:
    - attack.impact
    - attack.t1491.002
    - analytic.an1622
    - detection.det0590
```

#### Rule 2 of 2: Local DNS Server Zone File Modification
Detects file write/modification events targeting Windows DNS server zone configuration files (`*.dns` in `system32\dns\`) by processes other than the official Microsoft DNS server process (`dns.exe`).

```yaml
title: Local DNS Server Zone File Modification (AN1622-B)
id: a10f0210-3952-4bae-a5f8-4bae09a94fa3
status: experimental
description: Detects unauthorized edits to active DNS server zone files by non-DNS system processes.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: file_event
    product: windows
detection:
    selection_paths:
        TargetFilename|contains:
            - '\system32\dns\'
    selection_exts:
        TargetFilename|endswith:
            - '.dns'
    filter_dns:
        Image|endswith:
            - '\system32\dns.exe'
    condition: selection_paths and selection_exts and not filter_dns
fields:
    - TargetFilename
    - Image
    - User
falsepositives:
    - DNS administrators updating zone profiles via standard admin scripts (rare outside of controlled migration windows).
level: high
tags:
    - attack.impact
    - attack.t1491.002
    - analytic.an1622
    - detection.det0590
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Automated CI/CD Pipeline Scoping
  * The Issue: CI/CD build agents run `aws s3 sync` continuously, creating heavy logs under Rule 1.
  * The Fix: Baseline the specific build server machine names or service account contexts and add them to custom exclusions in the SIEM layer.
* Problem 2: Administrative DNS Changes
  * The Issue: Domain admins updating DNS configurations will trigger Rule 2.
  * The Fix: Set up audit checks to compare zone changes against registered corporate service tickets.
