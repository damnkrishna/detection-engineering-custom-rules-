### 1. Technique Breakdown: T1498

* What it is: Network Denial of Service. Adversaries execute scripts or customized network stress engines on compromised endpoints to perform network flooding (e.g. UDP, TCP SYN, Slowloris HTTP floods) against external or internal target systems.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Flood utility executions and specific script command-line arguments are captured.
  - NIDS (Suricata + Zeek): YES. Flooding packets are highly visible at the network boundary.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Denial of Service Script Engine Execution
Detects the execution of script interpreters with command-line arguments specific to denial-of-service tool suites or flooding routines.

```yaml
title: Denial of Service Script Engine Execution (AN1434-A)
id: 3941789c-c32a-4af4-aa0f-ee01cf4b7d7c
status: experimental
description: Detects command-line execution of Python, PowerShell, or Perl interpreters targeting network flooding or DoS attacks.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\python.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\perl.exe'
            - '\go.exe'
    selection_cli:
        CommandLine|contains:
            - 'slowloris'
            - 'goldeneye'
            - 'hulk.py'
            - 'rudy.py'
            - 'syn-flood'
            - 'udp-flood'
            - 'ping-of-death'
    condition: selection_images and selection_cli
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Internal network security team running approved stress tests or load capability checks.
level: high
tags:
    - attack.impact
    - attack.t1498
    - analytic.an1434
    - detection.det0518
```

#### Rule 2 of 2: Denial of Service Custom Executables
Detects the execution of compiled custom binary tools commonly used to perform application or connection-exhaustion attacks, separating image and original filename checks to catch renamed binaries.

```yaml
title: Denial of Service Custom Executables (AN1434-B)
id: 438ece20-59b6-4b17-8c1e-33413b25c791
status: experimental
description: Detects execution of known compiled denial-of-service binaries.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\slowloris.exe'
            - '\goldeneye.exe'
            - '\rudy.exe'
            - '\hulk.exe'
    selection_orig:
        OriginalFileName:
            - 'slowloris.exe'
            - 'goldeneye.exe'
            - 'rudy.exe'
            - 'hulk.exe'
    condition: selection_images or selection_orig
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Security teams testing web server tolerance under controlled scenarios.
level: high
tags:
    - attack.impact
    - attack.t1498
    - analytic.an1434
    - detection.det0518
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Load Testing
  * The Issue: System administrators running load runners (like ApacheBench `ab.exe` or JMeter) to benchmark system performance will trigger false alarms.
  * The Fix: Baseline the approved performance tools and whitelist their executables.
* Problem 2: Evasion via Process Renaming
  * The Issue: If custom scripts are compiled into custom executables and renamed, they will bypass Rule 2.
  * The Fix: Rely on network-level behavior checks (AN0969-B and AN1140-A/B) to detect traffic bursts at the egress boundary.
