### 1. Technique Breakdown: T1496.001

* What it is: Resource Hijacking: Compute Hijacking. Adversaries leverage compromised systems' computing power to mine cryptocurrency or run custom compute workloads. They achieve persistence by registering miners as system services or scheduling periodic mining tasks using built-in Windows utilities.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688, and Sysmon Registry Set events (Event ID 13).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Service creation in the registry and command-line task configurations are monitored.
  - NIDS (Suricata + Zeek): YES. Stratum protocol egress networks can be flagged by NIDS.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 13 (registry_set)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Persistent Miner Service Registration
Detects registry modifications creating or altering service values to launch cryptocurrency miners.

```yaml
title: Persistent Miner Service Registration (AN1489-A)
id: b929a881-9336-490b-8857-6967d4043854
status: experimental
description: Detects registry entries creating system services pointing to known cryptomining processes.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: registry_set
    product: windows
detection:
    selection_registry:
        TargetObject|contains:
            - 'SYSTEM\CurrentControlSet\Services\'
    selection_details:
        Details|contains:
            - '\xmrig'
            - '\minerd'
            - '\cgminer'
            - '--stratum'
            - '--pool'
    filter_installer:
        Image|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_registry and selection_details and not filter_installer
fields:
    - TargetObject
    - Details
    - Image
    - User
falsepositives:
    - Standard enterprise software deploying components that share parameters with mining tools (extremely rare).
level: critical
tags:
    - attack.impact
    - attack.t1496.001
    - analytic.an1489
    - detection.det0540
```

#### Rule 2 of 2: Scheduled Task Creation for Mining Tasks
Detects command-line parameters utilizing `schtasks.exe` or PowerShell cmdlets to schedule tasks running cryptomining scripts or binaries.

```yaml
title: Scheduled Task Creation for Mining Tasks (AN1489-B)
id: d44e1c75-5b5b-49fd-9ca0-80ef522f5e6e
status: experimental
description: Detects CLI scheduling of tasks containing miner parameters or stratum pool configurations.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\schtasks.exe'
    selection_args:
        CommandLine|contains:
            - ' /create '
            - ' -create '
    selection_miner_args:
        CommandLine|contains:
            - 'stratum'
            - 'xmrig'
            - 'minerd'
            - 'pool'
    condition: selection_images and selection_args and selection_miner_args
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Authorized admin tasks scheduling compute testing routines (rare in production).
level: high
tags:
    - attack.impact
    - attack.t1496.001
    - analytic.an1489
    - detection.det0540
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Mining Scripts inside Administrative Tasks
  * The Issue: Custom administration tasks that synchronize or update web apps can occasionally share the `pool` keyword.
  * The Fix: Rely on highly specific Stratum checks (Rule 1 details or network checks) to tune out administrative task false alarms.
* Problem 2: Evasion via Process Injection
  * The Issue: If the scheduled task launches a legitimate process (like `svchost.exe`) and injects the miner code into it, the command line won't show mining arguments.
  * The Fix: Deploy process injection rules (Event ID 8 / EID 10) to detect runtime anomalies.
