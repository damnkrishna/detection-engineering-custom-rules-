### 1. Technique Breakdown: T1529

* What it is: System Shutdown/Reboot. Adversaries shut down or reboot target systems to interrupt operations, cover their tracks, or initiate process updates (like loading altered boot records or driver payloads). They achieve this using built-in utilities (like `shutdown.exe`) or administration scripting engines.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688, and Windows System Event Log (Event ID 1074 indicating shutdown/restart initiator).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Invocations of shutdown commands are monitored. Windows System logs capture shutdown signals.
  - NIDS (Suricata + Zeek): NO. Host-local system state execution.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Local System Shutdown/Reboot Invocations
Detects the command-line execution of native tools or scripting cmdlets to initiate a local system shutdown, reboot, or hibernation, splitting system filters to avoid logic gaps.

```yaml
title: Local System Shutdown/Reboot Invocations (AN1538-A)
id: 00ccaca1-f523-4ad1-b89d-1d6e56b834ab
status: experimental
description: Detects command-line execution of shutdown.exe or scripting utilities to shut down or restart the local system.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\shutdown.exe'
    selection_args:
        CommandLine|contains:
            - ' /s'
            - ' /r'
            - ' -s'
            - ' -r'
            - ' /p'
            - ' /h'
    selection_powershell:
        CommandLine|contains:
            - 'Stop-Computer'
            - 'Restart-Computer'
    filter_system_images:
        ParentImage|endswith:
            - '\tiworker.exe'
            - '\svchost.exe'
            - '\trustedinstaller.exe'
    filter_system_user:
        User: 'NT AUTHORITY\SYSTEM'
    condition: ((selection_images and selection_args) or selection_powershell) and not (filter_system_images or filter_system_user)
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Legitimate system restarts triggered by administrators or patching engines (e.g. Windows Update).
level: high
tags:
    - attack.impact
    - attack.t1529
    - analytic.an1538
    - detection.det0559
```

#### Rule 2 of 2: Remote System Shutdown Invocations
Detects command-line execution targeting remote systems for shutdown or reboot commands using `shutdown.exe` or `wmic.exe`. Designed for SIEM-side volume correlation.

```yaml
title: Remote System Shutdown Invocations (AN1538-B)
id: d2ccebb4-719a-4de0-9981-29ab8e0e108f
status: experimental
description: Detects command-line commands targeting remote systems for shutdown. Designed to be aggregated at the SIEM layer.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\shutdown.exe'
    selection_remote_args:
        CommandLine|contains:
            - ' /m'
            - ' -m'
            - ' /g'
            - ' -g'
    selection_wmic:
        Image|endswith:
            - '\wmic.exe'
            - '\wbem\WmiPrvSE.exe'
        CommandLine|contains:
            - 'Win32_OperatingSystem'
            - 'Reboot'
            - 'Shutdown'
    condition: (selection_images and selection_remote_args) or selection_wmic
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - IT administrators remotely rebooting servers during maintenance windows.
level: high
tags:
    - attack.impact
    - attack.t1529
    - analytic.an1538
    - detection.det0559
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Standard Patching Reboots
  * The Issue: Automated patch management tools (like SCCM) reboot systems frequently, causing rule triggers.
  * The Fix: Baseline the deployment parent processes (like `ccmexec.exe` or Windows Update service hosts) and add them to custom exclusions.
* Problem 2: SIEM-Side Volume Thresholds
  * The Issue: Ransomware or attackers performing fleet-wide reboots can create high alert volume.
  * The Fix: In the SIEM, configure alerts to correlate multiple shutdown events across different machines within a brief time window (`count(Computer) by Computer > 3 in 5m`).
