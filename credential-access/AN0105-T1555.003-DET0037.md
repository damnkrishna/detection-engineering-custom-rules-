### 1. Technique Breakdown: T1555.003

* What it is: Credentials from Password Stores: Credentials from Web Browsers. Adversaries search for and extract the local files where web browsers (like Chrome, Edge, and Firefox) store saved usernames, passwords, and session cookies. These are typically SQLite databases (like Login Data or Cookies) or JSON files.
* Log Source Requirements: Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688) tracking execution.
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) is highly effective at catching Living off the Land (LotL) techniques where attackers use native commands (copy, xcopy, tar) to stage these database files for exfiltration.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Conclusion: Browser credential store access attempts using command line utilities can be detected using process creation and command line logs.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect command-line operations attempting to copy, compress, or access web browser credential and cookie databases, suggesting credential theft.

```yaml
title: Suspicious Browser Credential Store Access (AN0105)
id: 7c8e9d1a-4f5b-6a2c-3d8e-1f2a3b4c5d6e
status: experimental
description: Detects command-line operations attempting to copy, compress, or access web browser credential and cookie databases, indicating potential credential theft.
author: Krishna Gupta
date: 2026-06-12
logsource:
    category: process_creation
    product: windows
detection:
    selection_tools_image:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\xcopy.exe'
            - '\robocopy.exe'
            - '\tar.exe'
            - '\7z.exe'
    selection_tools_original:
        OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
            - 'xcopy.exe'
            - 'robocopy.exe'
            - 'tar.exe'
            - '7z.exe'
    selection_chrome_login:
        CommandLine|contains|all:
            - '\Google\Chrome\User Data\'
            - '\Login Data'
    selection_chrome_cookies:
        CommandLine|contains|all:
            - '\Google\Chrome\User Data\'
            - '\Network\Cookies'
    selection_edge_login:
        CommandLine|contains|all:
            - '\Microsoft\Edge\User Data\'
            - '\Login Data'
    selection_firefox:
        CommandLine|contains:
            - '\Mozilla\Firefox\Profiles\'
    selection_files:
        CommandLine|contains:
            - 'logins.json'
            - 'key4.db'
            - 'key3.db'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_tools_image or selection_tools_original) and (selection_chrome_login or selection_chrome_cookies or selection_edge_login or selection_firefox or selection_files) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate browser profile migrations or backup scripts by administrators.
    - Endpoint management tools performing user state migrations.
level: high
tags:
    - attack.credential-access
    - attack.t1555.003
    - analytic.an0105
    - detection.det0037
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Info Stealers & API Abuse (The Biggest Blind Spot)
  * The Issue: Dedicated stealer malware (like RedLine, Vidar, or Lumma) does not spawn cmd.exe or xcopy.exe to grab these files. The malware process opens the SQLite database directly using Windows API calls. Sysmon Event ID 1 will completely miss this because the command line won't show the file path.
  * The Fix: You would need to enable Windows Security Auditing for Object Access (Event ID 4663) specifically on those browser Login Data files, and then filter out the legitimate browser executable (e.g., alert if any process other than chrome.exe reads the Chrome Login Data file).

* Problem 2: File Locking
  * The Issue: If the browser is open, the Login Data file is locked. Basic copy commands will fail. Advanced scripts will bypass this by making a shadow copy of the drive first, or by killing the browser process entirely.
  * The Fix: Cross-correlate this rule with unexpected taskkill /IM chrome.exe commands, or the Volume Shadow Copy creation rule we discussed for the SAM dumping technique.

* Problem 3: Path Variations
  * The Issue: Browsers support multiple profiles. If a user sets up a secondary profile, the path changes from \Default\Login Data to \Profile 1\Login Data.
  * The Fix: If your SIEM supports regex, modify the path selection to account for wildcard directories (e.g., \\User Data\\[^\\]+\\Login Data), though this can increase computational overhead on the SIEM.
