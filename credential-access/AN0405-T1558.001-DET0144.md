### 1. Technique Breakdown: T1558.001

* What it is: Steal or Forge Kerberos Tickets: Golden Ticket. If an adversary compromises your Domain Controller and extracts the KRBTGT account password hash, they can use it to cryptographically forge their own Kerberos Ticket-Granting Tickets (TGTs). This "Golden Ticket" grants them unfettered, persistent administrative access to virtually any resource in the Active Directory domain, even if the user account they are impersonating has its password changed.
* Log Source Requirements: Detecting the creation of the ticket requires endpoint process/command-line monitoring (Sysmon Event ID 1) and PowerShell script block logging (Sysmon Event ID 4104).
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 (Process Creation) can detect the command-line execution of popular forging tools like Mimikatz or Rubeus on compromised endpoints. Sysmon Event ID 4104 (Script Block) is effective at catching script-based forging.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Golden Ticket forging tool execution on local endpoints can be detected using process creation and PowerShell script block logs.

### 2. Custom Sigma Rule

The detection logic is split into command-line execution monitoring and script block content monitoring.

Rule 1 of 2: Golden Ticket Forging Tool Execution via CLI (Process Creation)
```yaml
title: Golden Ticket Forging Tool Execution via CLI (AN0405-A)
id: d4c3b2a1-1a2b-3c4d-5e6f-7a8b9c0d1e2f
status: experimental
description: Detects command-line parameters and process executions associated with the forging or injection of Kerberos Golden Tickets using tools like Mimikatz or Rubeus.
author: Krishna Gupta
date: 2026-06-12
logsource:
    category: process_creation
    product: windows
detection:
    selection_mimikatz:
        CommandLine|contains: 'kerberos::golden'
    selection_rubeus:
        CommandLine|contains|all:
            - 'golden'
            - '/krbtgt:'
    selection_rubeus_ptt:
        CommandLine|contains|all:
            - 'golden'
            - '/ptt'
    selection_tools_image:
        Image|endswith:
            - '\mimikatz.exe'
            - '\rubeus.exe'
    selection_tools_original:
        OriginalFileName:
            - 'mimikatz.exe'
            - 'Rubeus.exe'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_mimikatz or selection_rubeus or selection_rubeus_ptt or selection_tools_image or selection_tools_original) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Authorized red team engagements or adversary emulation exercises.
level: critical
tags:
    - attack.credential-access
    - attack.t1558.001
    - analytic.an0405
    - detection.det0144
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: In-Memory execution
  * The Issue: Tools like Rubeus executed in memory using Cobalt Strike bypass CLI process creation rules.
  * The Fix: Rely on script block monitoring (Rule 2) or network Kerberos log monitoring for RC4 encryption downgrades.

* Problem 2: Ticket Lifetime Customization
  * The Issue: Adversaries can forge tickets that match standard AD lifetimes, evading anomaly detection on ticket age.
  * The Fix: Correlate TGS requests (Event ID 4769) against corresponding TGT requests (Event ID 4768) on Domain Controllers.

* Problem 3: Password Filter Bypass
  * The Issue: If the KRBTGT password hash has not been reset twice, old forged tickets may still work.
  * The Fix: Enforce standard double KRBTGT password reset procedures post-incident.
