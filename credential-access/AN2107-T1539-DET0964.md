### 1. Technique Breakdown: T1539

* What it is: Steal Web Session Cookie. Adversaries may steal web application or service session cookies and use them to gain access to web applications or internet services as an authenticated user without needing credentials.
* Log Source Requirements: Sysmon Process Creation (Event ID 1) / Sysmon File Access (Event ID 11).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Process access to browser cookie databases is detectable.
  - NIDS (Suricata + Zeek): NO. Local file access.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - Sysmon Event ID 11 (FileCreate) could detect cookie file copies but is high-volume.

### 2. Custom Sigma Rule

#### Rule 1 of 1: Browser Cookie Database Access by Non-Browser Process
Detects non-browser processes accessing Chrome, Edge, or Firefox cookie SQLite databases — a common credential/session theft pattern.

```yaml
title: Browser Cookie Database Access by Non-Browser Process (AN2107)
id: 0d5e8c23-6b4f-4a79-c1e9-5f2b7d84a361
status: experimental
description: Detects processes other than browsers reading SQLite cookie databases from Chrome, Edge, or Firefox profile directories. Used by attackers to steal authenticated session tokens without re-authenticating.
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_sqlite_tools:
        Image|endswith:
            - '\sqlite3.exe'
            - '\python.exe'
            - '\python3.exe'
    selection_cookie_paths:
        CommandLine|contains:
            - 'AppData\Local\Google\Chrome\User Data'
            - 'AppData\Local\Microsoft\Edge\User Data'
            - 'AppData\Roaming\Mozilla\Firefox\Profiles'
            - '\Cookies'
            - '\Network\Cookies'
    selection_ps_cookie:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_ps_cookie_ofn:
        OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.exe'
    selection_ps_cookie_cli:
        CommandLine|contains:
            - 'Chrome\User Data'
            - 'Edge\User Data'
            - 'Firefox\Profiles'
            - 'Cookies'
    condition: (selection_sqlite_tools and selection_cookie_paths) or ((selection_ps_cookie or selection_ps_cookie_ofn) and selection_ps_cookie_cli)
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Cookie management or synchronization tools operating on browser data for backup purposes.
level: high
tags:
    - attack.credential_access
    - attack.t1539
    - analytic.an2107
    - detection.det0964
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: In-Memory Cookie Theft
  * The Issue: Advanced tools read cookie databases directly from process memory (Mimikatz-style) without touching the file on disk.
  * The Fix: Requires memory forensics or EDR-level process memory scanning.
* Problem 2: Custom Stealer Binaries
  * The Issue: Commodity stealers (Vidar, Raccoon, RedLine) are custom binaries that directly read cookie files without invoking sqlite3.exe or Python.
  * The Fix: Detect the stealer binary via hash/YARA, or monitor for suspicious file reads of Cookies paths using Sysmon Event ID 11 with path filters.
* Problem 3: Browser Lock Files
  * The Issue: Chrome locks its Cookies database while running. Stealers often copy the file first — detectable via Sysmon Event ID 11 (FileCreate) of Cookies in a temp directory.
  * The Fix: Add a companion FileCreate rule for Cookies file creation in %TEMP% or user temp directories.
