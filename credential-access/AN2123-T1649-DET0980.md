### 1. Technique Breakdown: T1649

* What it is: Steal or Forge Authentication Certificates. Adversaries may steal private keys or certificates, or forge certificates, to authenticate as users or computers, or to establish secure tunnels. This is monitored by detecting commands attempting to export certificates (using parameters like `exportPFX`) or execution of credential recovery tools targeting certificate structures (such as `Certify.exe`).
* Log Source Requirements:
  * Sysmon Process Creation (Event ID 1) capturing command line keywords related to certificate and private key export/theft.
* Coverage Check:
  * HIDS (Sysmon): YES. Certificate management utilities run via command line leave process telemetry.
  * NIDS (Zeek/Suricata): NO. local exporting of certificates is not visible on the network interface.
* Log Sources Covered:
  * Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  * None.

### 2. Custom Sigma Rule

The following rule monitors the process creation log for execution of certificate retrieval tools or command parameters attempting to export private keys.

```yaml
title: Authentication Certificate or Private Key Export Tool Execution (AN2123)
id: f1a2b3c4-e5f6-7a8b-9c0d-1e2f3a4b5c84
status: experimental
description: "Detects the execution of known AD CS enumeration tools (e.g. Certify) or command-line parameters attempting to export authentication certificates and private keys (such as certutil.exe -exportPFX or similar commands) to steal credentials."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_certify:
        Image|endswith: '\certify.exe'
    selection_certify_ofn:
        OriginalFileName: 'Certify.exe'
    selection_export_images:
        Image|endswith:
            - '\certutil.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_export_ofn:
        OriginalFileName:
            - 'certutil.exe'
            - 'PowerShell.EXE'
            - 'pwsh.exe'
    selection_export_cli:
        CommandLine|contains:
            - '-exportPFX'
            - '-exportpfx'
            - 'Export-PfxCertificate'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_certify or selection_certify_ofn or ((selection_export_images or selection_export_ofn) and selection_export_cli)) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - Administrators legitimately backing up server certificates or exporting public keys for deployment.
level: high
tags:
    - attack.credential-access
    - attack.t1649
    - analytic.an2123
    - detection.det0980
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Exporting via MMC interface
  * The Issue: If the administrator/attacker exports the certificate using the MMC graphical certificate manager tool, no process arguments like `-exportPFX` are captured in command line logs.
  * The Fix: Enable auditing for Certificate Services operations (Event ID 4886 / 4887) on Domain Controllers / CA servers and monitor local certificate store query events (Event ID 5058/5059).
* Problem 2: Native C# script exports
  * The Issue: If the attacker uses a custom .NET execution framework (like Cobalt Strike executing assembly) to fetch certificates via the CryptoAPI directly, no subprocess is spawned.
  * The Fix: Monitor access handle requests to local certificate files and registry store paths under `HKLM\SOFTWARE\Microsoft\SystemCertificates\`.
* Problem 3: Multi-purpose tools
  * The Issue: Tools like `mimikatz` command `crypto::certificates` can extract certificates, but this is handled by distinct Mimikatz CLI rules.
  * The Fix: Deploy comprehensive Mimikatz detection rules alongside certificate-specific commands.
```
