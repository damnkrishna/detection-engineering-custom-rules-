### 1. Technique Breakdown: T1111

* What it is: Multi-Factor Authentication Interception. Adversaries may intercept multi-factor authentication credentials, codes, or tokens to bypass security controls. A common method to capture both credentials and MFA codes is by registering custom LSA (Local Security Authority) plugins or Security Support Providers (SSPs). These providers reside in the LSA address space and intercept plaintext credentials during logon.
* Log Source Requirements:
  * Sysmon Registry Value Set (Event ID 13) capturing modifications to the LSA Security Packages or SSP registry values.
* Coverage Check:
  * HIDS (Sysmon): YES. Modifying LSA package settings in the registry generates Event ID 13.
  * NIDS (Zeek/Suricata): NO. LSA configuration is entirely local to the Windows host.
* Log Sources Covered:
  * Sysmon Event ID 13 (registry_event)
* Log Sources Missing / Unused:
  * None.

### 2. Custom Sigma Rule

The following rule monitors the registry for updates to LSA security packages, authentication providers, or security providers, which are abused by attackers to install custom credential-intercepting SSP DLLs.

```yaml
title: Custom Security Support Provider or LSA Package Registration (AN2115)
id: f1a2b3c4-e5f6-7a8b-9c0d-1e2f3a4b5d98
status: experimental
description: "Detects modifications to registry values under HKLM\\SYSTEM\\CurrentControlSet\\Control\\Lsa (Security Packages, Authentication Packages) or SecurityProviders, which can be abused by adversaries to register custom Security Support Providers (SSPs) to intercept plaintext passwords and MFA credentials."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: registry_set
    product: windows
detection:
    selection_registry_paths:
        TargetObject|contains:
            - '\System\CurrentControlSet\Control\Lsa\Security Packages'
            - '\System\CurrentControlSet\Control\Lsa\Authentication Packages'
            - '\System\CurrentControlSet\Control\SecurityProviders\SecurityProviders'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_registry_paths and not filter_installer
fields:
    - TargetObject
    - Details
    - Image
    - User
falsepositives:
    - Standard enterprise software (like backup tools or custom endpoint security agents) registering their own security support packages during system installation.
level: high
tags:
    - attack.credential-access
    - attack.t1111
    - analytic.an2115
    - detection.det0972
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Sysmon bypass via direct driver access
  * The Issue: If the rootkit directly alters kernel memory pointers to reference the custom authentication package without touching the registry, Sysmon Event ID 13 will not fire.
  * The Fix: Rely on Sysmon Event ID 7 (Image Load) to detect anomalous DLLs loaded by `lsass.exe` (specifically DLLs loaded outside of `C:\Windows\System32\`).
* Problem 2: Legitimate software registration false positives
  * The Issue: Certain corporate VPNs or third-party authentication utilities (like Duo or Okta LSA integrations) register custom providers, causing alerts.
  * The Fix: Whitelist the specific names or details of the trusted provider DLLs registered by these tools.
* Problem 3: File dropping blind spot
  * The Issue: The registry key only references the DLL name. If the DLL is dropped in a non-standard location or overwrites an existing DLL, it bypasses the registry check.
  * The Fix: Combine this with a rule monitoring file drops (`EID 11`) in the `C:\Windows\System32\` folder for unsigned or newly dropped DLLs.

  * The Log: Registry Activity modifying `\System\CurrentControlSet\Control\Lsa\Security Packages`.

  * Expected Outcome: Tests if the engine's JSON parser crashes on type mismatches or coerces the type gracefully. MUST trigger an alert.

* True Positive 4: Exact Duplicate Event (Rule 1)
  * The Log: Exact duplicate of TP-01 with the exact same timestamp.
  * Expected Outcome: Tests if the engine's deduplication window correctly suppresses identical events.

#### Benign / True Negatives
* Benign 1: Installer Modifying LSA (Rule 1 Filter)
  * The Log: Registry Activity matching TP-01 but ParentImage is `msiexec.exe`.
  * Expected Outcome: Matches `filter_installer`. MUST NOT trigger an alert.
