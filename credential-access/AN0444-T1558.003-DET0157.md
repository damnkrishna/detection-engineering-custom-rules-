### 1. Technique Breakdown: T1558.003

* What it is: Steal or Forge Kerberos Tickets: Kerberoasting. Adversaries abuse the Kerberos protocol to request Service Ticket (TGS) for accounts with Service Principal Names (SPNs) configured—usually highly privileged service accounts. Active Directory grants these tickets encrypted with the service account's password hash. The attacker extracts this ticket from memory and cracks it offline to get the cleartext password.
* Log Source Requirements: Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688) tracking execution, and PowerShell script block logs (Sysmon Event ID 4104).
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 (Process Creation) is excellent for catching the enumeration phase (e.g., using native setspn.exe) or the execution of known tools like Rubeus. Sysmon Event ID 4104 (Script Block) is effective at catching PowerShell-based Kerberoasting implementations.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Kerberoasting tool execution and native SPN query commands can be detected using process creation and PowerShell script block logs.

### 2. Custom Sigma Rule

The detection logic is split into command-line execution monitoring and script block content monitoring.

Rule 1 of 2: Suspicious SPN Enumeration and Kerberoasting Activity via CLI (Process Creation)
```yaml
title: Suspicious SPN Enumeration and Kerberoasting Activity via CLI (AN0444-A)
id: e5b6c7d8-2f3a-4b1c-9d0e-1a2b3c4d5e6f
status: experimental
description: Detects command-line parameters associated with Service Principal Name (SPN) enumeration via setspn.exe or direct Kerberoasting attacks using Rubeus.
author: Krishna Gupta
date: 2026-06-12
logsource:
    category: process_creation
    product: windows
detection:
    selection_setspn:
        - Image|endswith: '\setspn.exe'
        - OriginalFileName: 'setspn.exe'
    selection_setspn_args:
        CommandLine|contains:
            - '-q'
            - '-Q'
            - '/q'
            - '/Q'
    selection_setspn_query:
        CommandLine|contains:
            - '*/*'
    selection_rubeus:
        CommandLine|contains:
            - 'kerberoast'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (((selection_setspn_image or selection_setspn_original) and selection_setspn_args and selection_setspn_query) or selection_rubeus) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Active Directory administrators running legitimate SPN checks or audits.
    - Automated identity management platforms checking service account configurations.
level: high
tags:
    - attack.credential-access
    - attack.t1558.003
    - analytic.an0444
    - detection.det0157
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Domain Controller Telemetry Gap
  * The Issue: If an attacker roasts AD accounts from a non-domain Windows or Linux machine, local Sysmon logs will show no command execution.
  * The Fix: Ingest Domain Controller Event ID 4769 logs to detect service ticket requests with weak RC4 encryption.

* Problem 2: Target-Specific (Low and Slow) Kerberoasting
  * The Issue: Single target Kerberoasting will not trigger volumetric detection thresholds.
  * The Fix: Deploy fake "Honey SPN" accounts and alert on any ticket requests targeting them.

* Problem 3: PowerShell Script Block Logging Disabled
  * The Issue: Script block executions won't be recorded if logging is disabled.
  * The Fix: Enforce Script Block Logging GPO policies and audit host endpoints.

#### True Positives
* True Positive 1: SPN Enumeration via setspn (Rule 1)
  * The Log: Process Activity with Image `setspn.exe` and CommandLine `setspn.exe -q */*`.
  * Expected Outcome: Matches `selection_setspn` and related blocks. MUST trigger an alert.

* True Positive 2: PowerShell Kerberoasting (Rule 2)
  * The Log: Process Activity with CommandLine containing `Invoke-Kerberoast`.
  * Expected Outcome: Matches `selection_keywords`. MUST trigger an alert.

* True Positive 3: Malformed JSON Robustness Test (Rule 1)
  * The Log: Process Activity simulating TP-01 but intentionally omitting the `unmapped` object entirely.
  * Expected Outcome: Engine parser should degrade gracefully and still trigger the alert. MUST trigger an alert.

* True Positive 4: Schema Type Validation Failure (Rule 1)
  * The Log: Exact match of TP-01, but `activity_id` is passed as a string `"1"` instead of an integer `1`.
  * Expected Outcome: Tests if the engine's JSON parser crashes on type mismatches or coerces the type gracefully. MUST trigger an alert.

* True Positive 5: Exact Duplicate Event (Rule 1)
  * The Log: Exact duplicate of TP-01 with the exact same timestamp.
  * Expected Outcome: Tests if the engine's deduplication window correctly suppresses identical events.

#### Benign / True Negatives
* Benign 1: Installer Executing setspn (Rule 1 Filter)
  * The Log: Process Activity matching TP-01 but ParentImage is `msiexec.exe`.
  * Expected Outcome: Matches `filter_installer`. MUST NOT trigger an alert.
