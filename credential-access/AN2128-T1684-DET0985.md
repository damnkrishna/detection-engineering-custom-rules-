### 1. Technique Breakdown: T1684

* What it is: Social Engineering. In a post-compromise scenario, adversaries may run script-based credential collectors that pop up fake authentication boxes on the target system (e.g. using PowerShell `Get-Credential`, Windows Shell objects, or custom HTML applications in MSHTA) to trick the user into typing their passwords.
* Log Source Requirements:
  * Sysmon Process Creation (Event ID 1) to audit command-line keywords that initialize credential prompts or UI boxes.
* Coverage Check:
  * HIDS (Sysmon): YES. Processes launched with UI credential prompting arguments are logged.
  * NIDS (Zeek/Suricata): NO. Keystroke prompting occurs locally at the graphical layer.
* Log Sources Covered:
  * Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  * None.

### 2. Custom Sigma Rule

The following rule monitors the process creation log for shell hosts or scripts running credential retrieval prompts or GUI popup forms to extract credentials from target users.

```yaml
title: Social Engineering Script-Based Credential Dialog Prompt (AN2128)
id: f1a2b3c4-e5f6-7a8b-9c0d-1e2f3a4b5c89
status: experimental
description: "Detects process command line arguments indicating the spawning of credential dialog boxes or login forms (such as PowerShell Get-Credential or MSHTA HTML forms) used in post-exploitation to trick users into typing administrative passwords."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\mshta.exe'
            - '\wscript.exe'
            - '\cscript.exe'
    selection_ofn:
        OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.exe'
            - 'mshta.exe'
            - 'wscript.exe'
            - 'cscript.exe'
    selection_cli:
        CommandLine|contains:
            - 'Get-Credential'
            - 'PromptForCredential'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    filter_admin_context:
        ParentImage|endswith:
            - '\powershell_ise.exe'
            - '\vscode\Code.exe'
            - '\mmc.exe'
    condition: (selection_images or selection_ofn) and selection_cli and not (filter_installer or filter_admin_context)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - Legitimate administrative scripts that prompt the user to input credentials for running remote server tasks.
level: high
tags:
    - attack.credential-access
    - attack.t1684
    - analytic.an2128
    - detection.det0985
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Native COM objects
  * The Issue: If the attacker uses native DLL injection or a custom binary that calls the Windows Credential Manager API `CredUIPromptForCredentialsW` directly, the string `Get-Credential` will not appear in any command lines.
  * The Fix: Monitor API logs for processes loading `credui.dll` and initiating credential prompt calls from non-standard folders.
* Problem 2: Legitimate administrative prompts
  * The Issue: Internal helpdesk or IT scripts legitimately use `Get-Credential` to authenticate for database queries or AD connections, causing alerts.
  * The Fix: Scope alerts to non-standard user profiles or exclude scripts executed from signed central repositories.
* Problem 3: Obfuscated script streams
  * The Issue: In MSHTA execution, the HTML file can construct the credential popup dynamically, preventing detection of strings in the process creation logs.
  * The Fix: Combine this with a rule monitoring Sysmon Event ID 11 (File Creation) for temporary HTML files written by MSHTA or browser processes.
```
