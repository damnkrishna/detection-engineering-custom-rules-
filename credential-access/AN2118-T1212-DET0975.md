### 1. Technique Breakdown: T1212

* What it is: Exploitation for Credential Access. Adversaries may exploit software vulnerabilities in credential-holding processes or services to extract plaintext passwords or hashes. A classic example is exploiting the Windows Print Spooler service (e.g., PrintNightmare CVE-2021-34527) to run code inside `spoolsv.exe` and access credential structures. Spawning child command shells or interpreters from the Print Spooler parent process is a direct indicator of successful exploitation.
* Log Source Requirements:
  * Sysmon Process Creation (Event ID 1) capturing child process executions from the spooler parent.
* Coverage Check:
  * HIDS (Sysmon): YES. Processes spawned by the spooler service generate Event ID 1 logs.
  * NIDS (Zeek/Suricata): NO. local process spawning telemetry is not visible on the network interface.
* Log Sources Covered:
  * Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  * None.

### 2. Custom Sigma Rule

The following rule monitors the process creation log to detect command shells, interpreters, or administrative binaries spawned as child processes of the Windows Print Spooler service (`spoolsv.exe`), indicating active credential service exploitation.

```yaml
title: Print Spooler Service Spawning Suspicious Child Process (AN2118)
id: f1a2b3c4-e5f6-7a8b-9c0d-1e2f3a4b5d99
status: experimental
description: "Detects command shells, interpreters, or system administrative utilities spawned as child processes of spoolsv.exe (Windows Print Spooler), which is a common indicator of successful exploitation of Print Spooler vulnerabilities (such as PrintNightmare CVE-2021-34527) to perform local execution or credential harvesting."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_parent:
        ParentImage|endswith:
            - '\spoolsv.exe'
    selection_parent_ofn:
        ParentOriginalFileName: 'spoolsv.exe'
    selection_child_images:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\rundll32.exe'
            - '\regsvr32.exe'
            - '\whoami.exe'
            - '\nltest.exe'
    selection_child_ofn:
        OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'pwsh.exe'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'rundll32.exe'
            - 'regsvr32.exe'
            - 'whoami.exe'
            - 'nltest.exe'
    condition: (selection_parent or selection_parent_ofn) and (selection_child_images or selection_child_ofn)
fields:
    - ParentImage
    - Image
    - CommandLine
    - User
falsepositives:
    - Legitimate printer installation scripts that invoke command line utilities to configure ports or load driver details during printer configuration.
level: critical
tags:
    - attack.credential-access
    - attack.t1212
    - analytic.an2118
    - detection.det0975
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Print driver dll writes
  * The Issue: If the attacker exploits the print spooler to load a custom DLL without spawning a child command process (e.g. they inject code that directly accesses memory), this child process rule will not trigger.
  * The Fix: Enable Sysmon Event ID 11 (File Event) rules to monitor driver directories for new `.dll` files being written under `C:\Windows\System32\spool\drivers\`.
* Problem 2: Legitimate printing vendor scripts
  * The Issue: Certain enterprise PDF printing applications spawn helper scripts from the spooler context, causing false positives.
  * The Fix: Whitelist the specific helper utility executables by code signer signature or verify the command line arguments match legitimate setup patterns.
* Problem 3: Execution under renamed spoolsv.exe
  * The Issue: The rule targets child processes of `spoolsv.exe` using ParentImage and ParentOriginalFileName, which is robust against renaming spoolsv itself; however, if the spooler service is run via generic `svchost.exe` hosting, the parent is svchost.
  * The Fix: Monitor svchost spawning command shells under unusual service group environments.
```
