### 1. Technique Breakdown: T1555.004

* What it is: Credentials from Password Stores: Windows Credential Manager. Adversaries attempt to extract passwords and credential materials stored securely in the Windows Credential Manager (the "Vault"). This vault often contains saved RDP credentials, network share passwords, and web credentials. Attackers typically use native "Living off the Land" (LotL) binaries like cmdkey.exe or vaultcmd.exe to enumerate and dump these.
* Log Source Requirements: Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688) tracking execution, and PowerShell script block logs (Sysmon Event ID 4104).
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 (Process Creation) is perfectly suited to catch the execution of cmdkey.exe or vaultcmd.exe when paired with enumeration flags. Sysmon Event ID 4104 (Script Block) is effective at catching script-based queries.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Windows Credential Manager access using command line utilities and PowerShell script blocks can be detected using process creation and script block logs.

### 2. Custom Sigma Rule

The detection logic is split into command-line execution monitoring and script block content monitoring.

Rule 1 of 2: Suspicious Windows Credential Manager Access via CLI (Process Creation)
```yaml
title: Suspicious Windows Credential Manager Access via CLI (AN0378-A)
id: f3b91a7e-2c8d-4a1f-9e6b-5d4c8a2f1e0d
status: experimental
description: Detects command-line operations attempting to enumerate or extract stored credentials from the Windows Credential Manager (Vault) using native utilities, indicating potential credential theft.
author: Krishna Gupta
date: 2026-06-12
logsource:
    category: process_creation
    product: windows
detection:
    selection_tools:
        - Image|endswith: 
            - '\cmdkey.exe'
            - '\vaultcmd.exe'
        - OriginalFileName: 
            - 'cmdkey.exe'
            - 'vaultcmd.exe'
    selection_args:
        CommandLine|contains:
            - '/list'
            - '/l'
            - '-l'
            - '-list'
            - '/listcreds'
            - '/listproperties'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_tools and selection_args and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - IT administrators troubleshooting network drive mappings or RDP access.
    - Automated deployment scripts configuring persistent network share access.
level: high
tags:
    - attack.credential-access
    - attack.t1555.004
    - analytic.an0378
    - detection.det0134
```

Rule 2 of 2: Suspicious Windows Credential Manager Access via PowerShell Script Block (Script Block)
```yaml
title: Suspicious Windows Credential Manager Access via PowerShell Script Block (AN0378-B)
id: 821989b1-41a7-4935-b988-7de8298f395a
status: experimental
description: Detects PowerShell script block logs containing keywords related to Windows Credential Manager or Vault querying.
author: Krishna Gupta
date: 2026-06-16
logsource:
    category: ps_script
    product: windows
detection:
    selection_keywords:
        ScriptBlockText|contains:
            - 'cmdkey'
            - 'vaultcmd'
            - 'Get-VaultCredential'
            - 'CredEnumerate'
            - 'CredentialManager'
            - 'Get-CachedCredential'
    condition: selection_keywords
fields:
    - ScriptBlockText
falsepositives:
    - Legitimate administrative scripting for backup or credentials validation.
level: high
tags:
    - attack.credential-access
    - attack.t1555.004
    - analytic.an0378
    - detection.det0134
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: API Abuse (Bypassing cmdkey/vaultcmd)
  * The Issue: Custom binaries or scripts calling CredEnumerateW directly will bypass process creation cmdkey.exe rules.
  * The Fix: Monitor access to C:\Users\<user>\AppData\Local\Microsoft\Vault using File auditing or catch scripts using Rule 2.

* Problem 2: DPAPI Master Key Offline Extraction
  * The Issue: If attackers copy master keys and vault folders offline, no host queries will execute.
  * The Fix: Monitor files archiving or copies targeting local appdata vault folders.

* Problem 3: GPO/Logon Script False Positives
  * The Issue: Auto-mounting drives may execute cmdkey /list or cmdkey /add, causing alerts.
  * The Fix: Exclude known signed logon scripts or deployment agents from the parent process filters.
