### 1. Technique Breakdown: T1553.004

* What it is: Install Root Certificate. Adversaries install untrusted root certificates into the victim's Trusted Root Certification Authorities store to subvert trust controls. Once installed, the operating system and web browsers will trust any TLS/SSL certificate signed by the adversary's certificate authority (CA). This allows adversaries to perform middle-person (MitM) inspection of encrypted traffic, bypass code signing restrictions (allowing malware to run as "trusted" signed software), or establish persistence.
* Log Source Requirements: Endpoint logs capturing process execution and command line parameters (specifically administrative certificate utility tools like `certutil.exe`, `certmgr.exe`, or PowerShell command-lines).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs the execution of utilities like `certutil.exe`, `certmgr.exe`, or PowerShell cmdlets with parameters containing flags like `-addstore` or `/add` directed at the `root` store.
* NIDS (Suricata + Zeek): NO. Certificate store modification is a host-local configuration change. It does not produce a distinct network signature (though network tools may observe the resulting decrypt-and-inspect MitM activity later).
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 13 (registry_set)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring and registry modification monitoring of system certificate stores.

Rule 1 of 2: Installation of Root Certificate via CLI (Process Creation)
```yaml
title: Installation of Root Certificate via CLI (AN0153)
id: b3c8d1e2-4f3b-4a2e-9d8c-5b6c7d8e9f0a
status: experimental
description: Detects command-line execution of certutil.exe, certmgr.exe, or PowerShell cmdlets adding a certificate to the local Trusted Root Certification Authorities store.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_certutil:
        - Image|endswith: '\certutil.exe'
        - OriginalFileName: 'CertUtil.exe'
    selection_certutil_args:
        CommandLine|contains|all:
            - '-addstore'
            - 'root'
    selection_certmgr:
        - Image|endswith: '\certmgr.exe'
        - OriginalFileName: 'certmgr.exe'
    selection_certmgr_args:
        CommandLine|contains|all:
            - '/add'
            - 'root'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_cmdlets:
        CommandLine|contains|all:
            - 'Import-Certificate'
            - 'Root'
    condition: (selection_certutil and selection_certutil_args) or (selection_certmgr and selection_certmgr_args) or (selection_powershell and selection_powershell_cmdlets)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Internal IT administrator scripts deployed to distribute enterprise PKI root certificates.
    - Security agent or VPN installations that require installing custom root certificates.
level: high
tags:
    - attack.defense-evasion
    - attack.t1553.004
    - analytic.an0153
    - detection.det0056
```

    - User

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
