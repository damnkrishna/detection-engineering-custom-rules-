### **1. Technique Breakdown: T1484.001**

* **What it is:** **Group Policy Modification**. Adversaries modify Group Policy Objects (GPOs) to deploy malware, establish persistence, disable security settings, or escalate privileges across an Active Directory domain. By modifying GPO files within the domain's SYSVOL share (e.g., `GptTmpl.inf` to change privilege assignments, or `ScheduledTasks.xml` to execute immediate tasks), they can execute code on thousands of domain-joined systems.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters from domain administrative utilities and scripting engines (like PowerShell, `secedit.exe`, or `lgpo.exe`).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs the execution of CLI tools like `secedit.exe`, `lgpo.exe`, or PowerShell containing GPO cmdlets.
* **NIDS (Suricata + Zeek): NO.** While GPO templates are loaded over SMB (port 445), network logs cannot reliably inspect the semantic contents of encrypted SMB traffic or determine if a template write is malicious.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line modifications of Group Policy templates or local security policies using built-in Windows administrative utilities (`secedit.exe`, `lgpo.exe`) or Group Policy PowerShell cmdlets.

```yaml
title: Command-Line Group Policy Modification (AN0854)
id: f48e7b92-3a1f-4c92-bd93-6f7d8e9a0b2d
status: experimental
description: Detects command-line execution of utilities (like secedit.exe, lgpo.exe) or PowerShell cmdlets used to modify Group Policy Objects (GPOs), domain policies, or local security policies.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_utilities:
        - Image|endswith:
            - '\secedit.exe'
            - '\lgpo.exe'
        - OriginalFileName:
            - 'secedit.exe'
            - 'lgpo.exe'
    selection_secedit_args:
        CommandLine|contains:
            - '/configure'
            - '/import'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_cmdlets:
        CommandLine|contains:
            - 'New-GPO'
            - 'Set-GPO'
            - 'Set-GPRegistryValue'
            - 'New-GPLink'
            - 'Import-GPO'
            - 'New-GPOImmediateTask'
    condition: (selection_utilities and (selection_secedit_args or Image|endswith: '\lgpo.exe' or OriginalFileName: 'lgpo.exe')) or (selection_powershell and selection_powershell_cmdlets)
falsepositives:
    - Legitimate administrator configuration of local security policies or domain-level GPOs during standard system provisioning.
level: high
tags:
    - attack.defense_evasion
    - attack.privilege_escalation
    - attack.t1484.001
    - analytics.an0854
    - detection.det0305
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: GUI-Based GPO Modification (Bypassing CLI)**
* *The Issue:* Administrators and attackers can modify GPOs using the Group Policy Management Console (GPMC) GUI or direct LDAP/ADSI API calls that do not spawn CLI processes or use PowerShell. This process-creation rule will miss such changes completely.
* *The Fix:* Enable directory service auditing on Domain Controllers and monitor Windows Security Event ID 5136 (Directory Service Object Modified) for changes to `groupPolicyContainer` objects, specifically targeting attributes like `gPCFileSysPath` and `gPCMachineExtensionNames`.


* **Problem 2: Direct SYSVOL File Manipulation**
* *The Issue:* If an adversary has write access to the domain share, they can directly modify or overwrite GPO configuration files (like `ScheduledTasks.xml` or `GptTmpl.inf`) within the SYSVOL path (`\\<domain>\SYSVOL\...\Policies\`) using SMB client scripts or raw network writes without executing commands on the DC itself.
* *The Fix:* Implement File Integrity Monitoring (FIM) or file access auditing (Event ID 4663/4656) on Domain Controllers for the SYSVOL folder (`%SystemRoot%\SYSVOL\domain\Policies\`), alerting on modifications to files like `ScheduledTasks.xml` or `GptTmpl.inf`.


* **Problem 3: Code Obfuscation in PowerShell**
* *The Issue:* Threat actors can obfuscate PowerShell cmdlets (e.g. using string concatenation like `'New-' + 'GPO'` or base64 encoding `[Convert]::ToBase64String`) to bypass simple command line string searches.
* *The Fix:* Enable PowerShell Script Block Logging (Event ID 4104) and System-wide Transcription to log and analyze the deobfuscated code blocks.
