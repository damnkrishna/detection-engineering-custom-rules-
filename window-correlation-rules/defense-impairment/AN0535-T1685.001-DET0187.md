### **1. Technique Breakdown: T1685.001**

* **What it is:** **Disable or Modify Windows Event Log**. Adversaries impair Windows event logging to hide their actions, prevent forensic analysis, and bypass security alerts. They do this by clearing log channels using native tools like `wevtutil.exe`, disabling specific event channels in the registry, modifying system audit policies via `auditpol.exe` to stop recording high-risk activities, or forcibly stopping/disabling the EventLog service.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (specifically target administrative tools used to stop services, adjust audit policies, or configure log channels).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs the execution of utilities like `wevtutil.exe`, `auditpol.exe`, `sc.exe`, or PowerShell commands targeting event services.
* **NIDS (Suricata + Zeek): NO.** Impairing local system logging is an endpoint-internal operation. It generates no network signatures.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line attempts to clear event logs, disable specific logging channels, tamper with system audit policies, or disable the Windows EventLog service.

```yaml
title: Disabling or Tampering with Windows Event Logging (AN0535)
id: f38a1b2c-4a3b-4c2d-8e9f-5b6d7e8a9f0b
status: experimental
description: Detects command-line operations that attempt to disable, clear, or modify Windows Event Log services, logging channels, or system audit policies.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_wevtutil:
        - Image|endswith: '\wevtutil.exe'
        - OriginalFileName: 'wevtutil.exe'
    selection_wevtutil_args:
        CommandLine|contains:
            - ' cl '      # Clear log
            - ' clear-log '
            - '/e:false'  # Disable log
            - '/enabled:false'
    selection_auditpol:
        - Image|endswith: '\auditpol.exe'
        - OriginalFileName: 'Auditpol.exe'
    selection_auditpol_args:
        CommandLine|contains:
            - '/clear'
            - '/remove'
            - '/success:disable'
            - '/failure:disable'
    selection_service_control:
        - Image|endswith:
            - '\sc.exe'
            - '\net.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'sc.exe'
            - 'net.exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_service_args:
        CommandLine|contains|all:
            - 'eventlog'
        CommandLine|contains:
            - 'stop'
            - 'disable'
    condition: (selection_wevtutil and selection_wevtutil_args) or (selection_auditpol and selection_auditpol_args) or (selection_service_control and selection_service_args)
falsepositives:
    - Legitimate administrative maintenance, diagnostic troubleshooting, or script-based log rotation configured by enterprise engineers.
level: high
tags:
    - attack.defense_evasion
    - attack.t1685.001
    - analytics.an0535
    - detection.det0187
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Service Registry Tampering (Bypassing Services Control CLI)**
* *The Issue:* Instead of running `sc.exe stop` or PowerShell commands, an adversary with administrator/SYSTEM access can directly modify the registry key `HKLM\SYSTEM\CurrentControlSet\Services\EventLog` or specific channel status keys under `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\WINEVT\Channels\` (setting `Enabled` to 0) and then restart the machine. The service control process monitoring will not catch this direct registry modification.
* *The Fix:* Enable registry auditing and monitor Sysmon Event ID 13 (Registry Value Set) or Windows Event ID 4657 for values set to 0 under the `WINEVT\Channels` or `Services\EventLog` subkeys.


* **Problem 2: Direct API/Process Termination or Injection**
* *The Issue:* Attackers can inject code into the service host process hosting the EventLog service (`svchost.exe`) and patch the API functions that write event logs (like `ReportEventW` or `EtwEventWrite`) in memory, or terminate the Event Log thread directly (e.g., using the Phant0m evasion technique).
* *The Fix:* Monitor process memory tampering (Sysmon Event ID 10 - ProcessAccess) with granted access masks containing `PROCESS_VM_WRITE` or `PROCESS_VM_OPERATION` targeting the svchost process hosting the EventLog service. Monitor for unexpected thread creation or DLL loads in that svchost container.


* **Problem 3: Event Log Clearance Gaps**
* *The Issue:* While clearing logs using `wevtutil` triggers process detection, if an attacker succeeds, the logs clearing will wipe the historical records of the attack itself.
* *The Fix:* Ensure that Windows Security Event ID 1102 (The audit log was cleared) and System Event ID 104 (The log file was cleared) are immediately forwarded to a central SIEM/log collector in real-time. The act of clearing logs will trigger a high-severity alert in the central system before the endpoint's local history is wiped.
