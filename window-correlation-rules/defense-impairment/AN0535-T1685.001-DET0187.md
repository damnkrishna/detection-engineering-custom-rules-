### 1. Technique Breakdown: T1685.001

* What it is: Disable or Modify Windows Event Log. Adversaries impair Windows event logging to hide their actions, prevent forensic analysis, and bypass security alerts. They do this by clearing log channels using native tools like `wevtutil.exe`, disabling specific event channels in the registry, modifying system audit policies via `auditpol.exe` to stop recording high-risk activities, or forcibly stopping/disabling the EventLog service.
* Log Source Requirements: Endpoint logs capturing process creation and command line parameters (specifically target administrative tools used to stop services, adjust audit policies, or configure log channels).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs the execution of utilities like `wevtutil.exe`, `auditpol.exe`, `sc.exe`, or PowerShell commands targeting event services.
* NIDS (Suricata + Zeek): NO. Impairing local system logging is an endpoint-internal operation. It generates no network signatures.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect command-line attempts to clear event logs, disable specific logging channels, tamper with system audit policies, or disable the Windows EventLog service.

```yaml
title: Disabling or Tampering with Windows Event Logging (AN0535)
id: f38a1b2c-4a3b-4c2d-8e9f-5b6d7e8a9f0b
status: experimental
description: Detects command-line operations that attempt to disable, clear, or modify Windows Event Log services, logging channels, or system audit policies.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_wevtutil:
        - Image|endswith: '\wevtutil.exe'
        - OriginalFileName: 'wevtutil.exe'
    selection_wevtutil_args:
        CommandLine|contains:
            - ' cl '      # Clear log
            - ' clear-log '
            - '/e:false'  # Disable log
            - '/enabled:false'
    selection_auditpol:
        - Image|endswith: '\auditpol.exe'
        - OriginalFileName: 'Auditpol.exe'
    selection_auditpol_args:
        CommandLine|contains:
            - '/clear'
            - '/remove'
            - '/success:disable'
            - '/failure:disable'
    selection_service_control:
        - Image|endswith:
            - '\sc.exe'
            - '\net.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'sc.exe'
            - 'net.exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_service_args:
        CommandLine|contains|all:
            - 'eventlog'
        CommandLine|contains:
            - 'stop'
            - 'disable'
    condition: (selection_wevtutil and selection_wevtutil_args) or (selection_auditpol and selection_auditpol_args) or (selection_service_control and selection_service_args)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate administrative maintenance, diagnostic troubleshooting, or script-based log rotation configured by enterprise engineers.
level: high
tags:
    - attack.defense-evasion
    - attack.t1685.001
    - analytic.an0535
    - detection.det0187
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
