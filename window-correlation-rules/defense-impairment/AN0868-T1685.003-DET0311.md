### **1. Technique Breakdown: T1685.003**

* **What it is:** **Disable or Modify Tools: Modify or Spoof Tool UI**. Adversaries may modify or spoof the user interface of security tools to hide their activities. This involves showing a false "healthy" or "active" status for tools like Windows Defender, even when the underlying security services (e.g., WinDefend, MsMpEng.exe) are stopped or disabled.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and System logs for service states.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 can monitor the execution of UI components, and Windows System logs can monitor the actual service states (Event ID 7036 for service stops).
    * **NIDS (Suricata + Zeek): NO.** UI spoofing and service state manipulation are strictly host-level activities.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** and service state logs to detect scenarios where security UI components are running, but the underlying engines are suspiciously stopped or disabled.

```yaml
title: Disable or Modify Tools - Spoof Tool UI (AN0868)
id: 5a8b2734-abc9-482d-88b6-96a84c2f42d2
status: experimental
description: Detects inconsistencies between reported sensor health and actual process/service state, suggesting UI spoofing.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_ui:
        Image|endswith:
            - '\SecurityHealthSystray.exe'
            - '\MSASCui.exe'
    selection_cmd:
        CommandLine|contains:
            - 'spoof'
            - 'hidden'
            - 'disable'
    condition: selection_ui and selection_cmd
fields:
    - CommandLine
    - Image
falsepositives:
    - Administrative troubleshooting of security tool UI components.
level: medium
tags:
    - attack.defense_evasion
    - attack.t1685.003
    - analytics.an0868
    - detection.det0311
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Complex Stateful Correlation**
    * *The Issue:* Sigma is stateless. It is very hard to detect the *absence* of a service (WinDefend stopped) while another process is running using a single log line.
    * *The Fix:* Utilize a SIEM correlation rule that triggers when `SecurityHealthSystray.exe` is running but `Event ID 7036` reports the `WinDefend` service as stopped within the same timeframe.

* **Problem 2: API Hooking**
    * *The Issue:* Advanced malware might hook APIs to spoof the status directly in memory rather than manipulating command lines.
    * *The Fix:* Employ EDR memory scanning for unbacked executable regions or API hooks in the security UI processes.

* **Problem 3: False Alarms during Updates**
    * *The Issue:* During major Windows Defender updates, services might briefly stop while the UI remains active.
    * *The Fix:* Implement a time window (e.g., 5 minutes) before alerting on the inconsistency.
