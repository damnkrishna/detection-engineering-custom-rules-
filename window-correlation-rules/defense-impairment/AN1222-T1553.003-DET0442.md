### **1. Technique Breakdown: T1553.003**

* **What it is:** **Subvert Trust Controls: SIP and Trust Provider Hijacking**. Adversaries may hijack Subject Interface Packages (SIPs) and Trust Providers in Windows to bypass code signing protections. By modifying registry keys associated with `Cryptography\Providers\Trust`, attackers can force Windows to use a malicious DLL to validate digital signatures. This causes the OS to falsely trust unsigned or maliciously signed files.
* **Log Source Requirements:** Registry modification logs (Sysmon Event ID 13/14) and Image Load logs (Sysmon Event ID 7).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event IDs 12/13/14 monitor registry keys. Sysmon Event ID 7 can capture the loading of non-Microsoft DLLs into processes like `signtool.exe` or `explorer.exe`.
    * **NIDS (Suricata + Zeek): NO.** Registry tampering and trust provider validation occur strictly at the OS level.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 13 (Registry Event)** to detect modifications to the Cryptography Trust Providers registry keys, which indicates potential SIP hijacking.

```yaml
title: SIP and Trust Provider Hijacking (AN1222)
id: fca3b91a-8c6f-44de-9e2c-29b35b6b1fc9
status: experimental
description: Detects abnormal registry modifications to Subject Interface Packages (SIPs) and Trust Providers.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: registry_set
    product: windows
    # Relies on Sysmon Event ID 13 collected via Wazuh
detection:
    selection_keys:
        TargetObject|contains:
            - 'SOFTWARE\Microsoft\Cryptography\Providers\Trust'
            - 'SOFTWARE\Microsoft\Cryptography\OID\EncodingType 0\CryptSIPDll'
    condition: selection_keys
fields:
    - TargetObject
falsepositives:
    - Installation of legitimate third-party security software or custom trust providers.
    - Major Windows OS upgrades patching cryptographic components.
level: high
tags:
    - attack.defense_evasion
    - attack.t1553.003
    - analytics.an1222
    - detection.det0442
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Alert Fatigue from Legitimate Software**
    * *The Issue:* Enterprise endpoint protection platforms or specific developer tools legitimately register custom SIPs.
    * *The Fix:* Baseline the environment and whitelist known good processes (`actor.process.file.path`) that modify these keys.

* **Problem 2: Monitoring Image Loads**
    * *The Issue:* Registry keys might be modified stealthily if auditing is disabled.
    * *The Fix:* Enable Sysmon Event ID 7 (Image Load) and alert when an unsigned DLL is loaded by `svchost.exe`, `explorer.exe`, or `signtool.exe` during signature validation operations.

* **Problem 3: In-Memory Validation Hooking**
    * *The Issue:* Attackers might hook `WinVerifyTrust` directly in memory without modifying the registry.
    * *The Fix:* Employ EDR solutions capable of scanning for user-land API hooks on cryptographic functions in running processes.
