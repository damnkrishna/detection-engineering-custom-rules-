### **1. Technique Breakdown: T1686**

* **What it is:** **Disable or Modify System Firewall**. Adversaries disable or modify system firewalls to permit network traffic that would otherwise be blocked. They do this to enable command-and-control (C2) communication, permit inbound lateral movement (RDP, WinRM, SMB), or allow file exfiltration. On Windows, this is commonly done by executing commands via `netsh.exe`, PowerShell cmdlets like `Set-NetFirewallProfile`, or stopping the Windows Defender Firewall service (`mpssvc`).
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (specifically targeting tools that modify firewall profiles or stop the firewall service).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs the execution of utilities like `netsh.exe`, `sc.exe`, or PowerShell commands modifying firewall states.
* **NIDS (Suricata + Zeek): NO.** Firewall configuration modification is a local host action. It does not produce a distinct network signature (though network tools may capture the resulting unauthorized traffic that is allowed through the firewall).

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line attempts to disable Windows Defender Firewall profiles, remove firewall rules, or stop the Windows Firewall service (`mpssvc`).

```yaml
title: Disabling or Tampering with Windows Firewall (AN0406)
id: d58b1c2a-3e2f-4a3b-9c8d-5f6d7e8a9b0c
status: experimental
description: Detects command-line operations that attempt to disable, modify, or stop the Windows Defender Firewall service or profiles using netsh.exe, PowerShell, or service control utilities.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_netsh:
        - Image|endswith: '\netsh.exe'
        - OriginalFileName: 'netsh.exe'
    selection_netsh_args:
        CommandLine|contains|all:
            - 'advfirewall'
            - 'set'
            - 'state'
            - 'off'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_cmdlets:
        CommandLine|contains:
            - 'Set-NetFirewallProfile'
            - 'Disable-NetFirewallRule'
            - 'Remove-NetFirewallRule'
    selection_powershell_args:
        CommandLine|contains:
            - 'False'
            - 'off'
    selection_service_control:
        - Image|endswith:
            - '\sc.exe'
            - '\net.exe'
        - OriginalFileName:
            - 'sc.exe'
            - 'net.exe'
    selection_service_args:
        CommandLine|contains|all:
            - 'mpssvc'
        CommandLine|contains:
            - 'stop'
            - 'disable'
    condition: (selection_netsh and selection_netsh_args) or (selection_powershell and selection_powershell_cmdlets and selection_powershell_args) or (selection_service_control and selection_service_args)
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Legitimate administrative troubleshooting or network configuration scripts that temporarily disable profiles or remove rules.
level: high
tags:
    - attack.defense_evasion
    - attack.t1686
    - analytics.an0406
    - detection.det0145
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Registry Disabling (Bypassing CLI command line checks)**
* *The Issue:* An adversary with administrative privileges can directly disable the firewall by modifying the registry key `HKLM\SYSTEM\CurrentControlSet\Services\SharedAccess\Parameters\FirewallPolicy\[DomainProfile|PublicProfile|StandardProfile]\EnableFirewall` setting it to `0`, and then applying the change or restarting. This bypasses the command line detections since `netsh` or PowerShell are not executed.
* *The Fix:* Monitor registry changes (Sysmon Event ID 13 or Windows Security Event ID 4657) targeting `SharedAccess\Parameters\FirewallPolicy` and alerting when the value `EnableFirewall` is set to `0`.


* **Problem 2: Stopping the Service via API calls or Driver unloading**
* *The Issue:* Attackers can stop the Windows Defender Firewall service (`mpssvc`) via direct Service Control Manager (SCM) API calls in compiled code or by unloading the firewall driver (`mpsdrv`) using kernel-level exploits, leaving the CLI process monitoring blind.
* *The Fix:* Enable system service audit policies and monitor Windows System Event ID 7036 (The Windows Defender Firewall service entered the stopped state) or Sysmon Event ID 10 (ProcessAccess) targeting the service host process hosting `mpssvc`.


* **Problem 3: Firewall Configuration Obfuscation or Custom Rules**
* *The Issue:* Instead of turning the firewall off globally, adversaries may add specific rules allowing their C2 traffic (e.g. `netsh advfirewall firewall add rule name="Malicious" dir=in action=allow program="C:\temp\malware.exe"`) which doesn't match the simple "state off" rule selection, or obfuscate the cmdlets in PowerShell.
* *The Fix:* Audit rule additions. Monitor for `netsh` executions containing the keyword `add rule` or PowerShell script blocks (Event ID 4104) adding rules. Additionally, monitor Windows Security Event ID 2004 (A rule has been added to the Windows Firewall exception list).
