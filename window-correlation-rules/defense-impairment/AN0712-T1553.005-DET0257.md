### **1. Technique Breakdown: T1553.005**

* **What it is:** **Subvert Trust Controls: Mark-of-the-Web Bypass**. Adversaries bypass Mark-of-the-Web (MOTW) protections by placing malicious payloads inside container or disk image files (such as `.iso`, `.vhd`, `.img`, `.zip`, `.cab`). When these container files are downloaded from the Internet, the operating system assigns them a `Zone.Identifier` stream (MOTW). However, when the user mounts the disk image or extracts the archive, the nested files inside are extracted without the `Zone.Identifier` stream, bypassing security features like SmartScreen or Microsoft Office Protected View. Detection monitors the mounting of disk images or execution of unsigned/untrusted binaries launched from mounted container drives.
* **Log Source Requirements:** Windows Security Event Log Event ID 4688 or Sysmon process creation logs (Event ID 1) combined with Event ID 11 (File Creation) or System Log Event ID 12 (ISO/VHD mounting events).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process details, capturing when applications (such as `explorer.exe`) launch disk mounting utilities or run binaries directly from newly mounted drive paths.
    * **NIDS (Suricata + Zeek): NO.** Disk mounting and local MOTW checks are internal host operating system functions.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of unsigned or script-based binaries launched from drive letters associated with newly mounted virtual disk images (like `.iso` or `.vhd`).

```yaml
title: Subvert Trust Controls - Mark-of-the-Web Bypass via Container Mount (AN0712)
id: dd4bf63e-93e5-41f3-82af-56cfbf584e98
status: experimental
description: Detects processes executing from drive paths that are typically created when mounting container or disk image files (like .iso, .vhd), suggesting an attempt to bypass Mark-of-the-Web (MOTW).
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_drive:
        # Mounted container files often allocate drive letters starting from D: to Z: 
        # and execute script engines or executable payloads.
        CommandLine|contains:
            - 'D:\'
            - 'E:\'
            - 'F:\'
            - 'G:\'
            - 'H:\'
    selection_payloads:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\rundll32.exe'
            - '\regsvr32.exe'
            - '\mshta.exe'
        - OriginalFileName:
            - 'cmd.exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'rundll32.exe'
            - 'regsvr32.exe'
            - 'mshta.exe'
    condition: selection_drive and selection_payloads
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - User installing legitimate software from a mounted physical/virtual CD/DVD.
    - IT administrators deploying software from network-attached ISO images.
level: medium
tags:
    - attack.defense_evasion
    - attack.t1553.005
    - analytics.an0712
    - detection.det0257
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Mount Actions Without Immediate Execution**
    * *The Issue:* If the container file is mounted but the malicious file is subsequently copied to a local staging directory (like `C:\Users\Public\`) before execution, the execution path will not contain the mounted drive letters.
    * *The Fix:* Enable file creation logging (Sysmon Event ID 11) and monitor files written by processes like `explorer.exe` or extraction engines that do not inherit the MOTW zone identifier stream.

* **Problem 2: Alternate Drive Letters**
    * *The Issue:* Disk mounts can be mapped to less common drive letters (such as `M:\` or `V:\`), bypassing drive letter filters in the rule.
    * *The Fix:* Query Windows System Logs for Event ID 12 (device driver start for virtual disk drives) or Event ID 4624 (logon sessions containing new device arrivals) to dynamically associate disk mount events.

* **Problem 3: Routine CD/DVD mounting (Noise)**
    * *The Issue:* Users regularly mount CD/DVD images for legitimate application/game execution or patches.
    * *The Fix:* Baseline known good virtual disk installers and whitelist their signatures or digital certificates.
