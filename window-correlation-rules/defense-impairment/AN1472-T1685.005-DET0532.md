### 1. Technique Breakdown: T1685.005

* What it is: Disable or Modify Tools: Clear Windows Event Logs. Adversaries may clear Windows Event Logs to hide their activity from system administrators and security analysts. This is typically done using native tools like `wevtutil.exe`, PowerShell cmdlets (`Clear-EventLog`), or by deleting the underlying `.evtx` files.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and Windows Security Event Log (Event ID 1102 / 104).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Windows Security log intrinsically captures Event ID 1102 (Audit log was cleared) and System log captures Event ID 104. Sysmon Event ID 1 captures command-line attempts.
    * NIDS (Suricata + Zeek): NO. Event log manipulation is an endpoint activity.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect command-line execution of native tools attempting to clear the Windows Event Logs.

```yaml
title: Clear Windows Event Logs - CLI Utilities (AN1472)
id: f30ea238-1a5c-411a-ab57-36eeb5452f36
status: experimental
description: Detects command-line activity using wevtutil.exe or PowerShell to clear Windows event logs.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_wevtutil:
        Image|endswith: '\wevtutil.exe'
        CommandLine|contains|all:
            - 'cl'
            - 'Security'
    selection_powershell:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        CommandLine|contains:
            - 'Clear-EventLog'
            - 'Remove-EventLog'
    condition: selection_wevtutil or selection_powershell
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Administrative scripts performing automated log rotation (rare in modern environments due to built-in log wrapping).
level: high
tags:
    - attack.defense-evasion
    - attack.t1685.005
    - analytic.an1472
    - detection.det0532
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
