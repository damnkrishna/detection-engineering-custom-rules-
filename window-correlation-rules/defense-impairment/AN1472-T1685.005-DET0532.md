### **1. Technique Breakdown: T1685.005**

* **What it is:** **Disable or Modify Tools: Clear Windows Event Logs**. Adversaries may clear Windows Event Logs to hide their activity from system administrators and security analysts. This is typically done using native tools like `wevtutil.exe`, PowerShell cmdlets (`Clear-EventLog`), or by deleting the underlying `.evtx` files.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and Windows Security Event Log (Event ID 1102 / 104).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Windows Security log intrinsically captures Event ID 1102 (Audit log was cleared) and System log captures Event ID 104. Sysmon Event ID 1 captures command-line attempts.
    * **NIDS (Suricata + Zeek): NO.** Event log manipulation is an endpoint activity.

---

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line execution of native tools attempting to clear the Windows Event Logs.

```yaml
title: Clear Windows Event Logs - CLI Utilities (AN1472)
id: f30ea238-1a5c-411a-ab57-36eeb5452f36
status: experimental
description: Detects command-line activity using wevtutil.exe or PowerShell to clear Windows event logs.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_wevtutil:
        Image|endswith: '\wevtutil.exe'
        CommandLine|contains|all:
            - 'cl'
            - 'Security'
    selection_powershell:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        CommandLine|contains:
            - 'Clear-EventLog'
            - 'Remove-EventLog'
    condition: selection_wevtutil or selection_powershell
fields:
    - CommandLine
    - Image
falsepositives:
    - Administrative scripts performing automated log rotation (rare in modern environments due to built-in log wrapping).
level: high
tags:
    - attack.defense_evasion
    - attack.t1685.005
    - analytics.an1472
    - detection.det0532
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct File Deletion**
    * *The Issue:* Attackers might stop the EventLog service and directly delete the `.evtx` files from `%SystemRoot%\System32\Winevt\Logs\`.
    * *The Fix:* Monitor Sysmon Event ID 11 (File Creation/Deletion) targeting the `Winevt\Logs` directory, especially for core logs like Security, System, and Application.

* **Problem 2: Native Event ID 1102 Reliability**
    * *The Issue:* Command-line detection can be bypassed, but Windows intrinsically logs Event ID 1102 when the Security log is cleared.
    * *The Fix:* Always prioritize alarming on Event ID 1102 (Security) and 104 (System) in the SIEM, using this CLI Sigma rule as a secondary behavioral indicator.

* **Problem 3: Selective Event Deletion**
    * *The Issue:* Advanced malware (e.g., using DSE bypass) can patch the EventLog service in memory to drop specific events or remove single records from the `.evtx` file, leaving the bulk of the log intact.
    * *The Fix:* Implement Event Log sequence number monitoring. If the `RecordNumber` jumps unexpectedly or there's a gap, it indicates targeted deletion.
