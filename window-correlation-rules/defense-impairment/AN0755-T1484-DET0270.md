### **1. Technique Breakdown: T1484**

* **What it is:** **Domain or Tenant Policy Modification**. Adversaries modify domain or tenant policies to establish persistence, elevate privileges, or facilitate lateral movement. In Active Directory, this includes modifying GPOs, altering domain trust relationships (to allow access from external malicious domains), or changing directory service object permissions (to grant replication/delegation rights). Adversaries use CLI tools like `netdom.exe`, `nltest.exe`, or PowerShell AD modules to make these modifications.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (specifically targeting administrative Active Directory and trust management utilities).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs the execution of utilities like `netdom.exe`, `nltest.exe`, or PowerShell Active Directory cmdlets.
* **NIDS (Suricata + Zeek): NO.** Trust and policy modifications are local configurations or RPC-based changes. Network logs can capture the replication or RPC calls (like `DRSUAPI`), but do not parse them as policy modification events.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line execution of domain trust modification tools (`netdom.exe`, `nltest.exe`) or PowerShell cmdlets managing domain trust relationships.

```yaml
title: Command-Line Domain Trust or Policy Modification (AN0755)
id: c58b2e1c-4f3b-4a2e-9d8c-6b7c8d9e0f0a
status: experimental
description: Detects command-line execution of netdom.exe, nltest.exe, or PowerShell Active Directory cmdlets used to modify domain trust relationships, register rogue domain controllers, or alter domain policy.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_netdom:
        - Image|endswith: '\netdom.exe'
        - OriginalFileName: 'netdom.exe'
    selection_netdom_args:
        CommandLine|contains:
            - 'trust'
            - 'member'
    selection_nltest:
        - Image|endswith: '\nltest.exe'
        - OriginalFileName: 'nltest.exe'
    selection_nltest_args:
        CommandLine|contains:
            - '/trust_commit'
            - '/dsreg'
            - '/domain_trusts'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_cmdlets:
        CommandLine|contains:
            - 'Add-ADDomainTrust'
            - 'Remove-ADDomainTrust'
            - 'Set-ADDomainTrust'
    condition: (selection_netdom and selection_netdom_args) or (selection_nltest and selection_nltest_args) or (selection_powershell and selection_powershell_cmdlets)
falsepositives:
    - Authorized active directory migration activities or configuration of cross-forest trusts by enterprise domain administrators.
level: high
tags:
    - attack.defense_evasion
    - attack.privilege_escalation
    - attack.t1484
    - analytics.an0755
    - detection.det0270
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: GUI/API-Based Active Directory Trust/Policy Manipulation**
* *The Issue:* Attackers can use GUI administrative snap-ins like "Active Directory Domains and Trusts" (`domain.msc`) or execute raw LDAP queries and programmatic API calls (using `.NET` classes like `System.DirectoryServices`) to modify trusts or delegations, completely bypassing CLI-based process monitoring.
* *The Fix:* Enable directory service change auditing and monitor Windows Security Event ID 5136 (A directory service object was modified), Event ID 4713 (A domain trust was created), Event ID 4714 (A domain trust was deleted), and Event ID 4715 (A domain trust was modified).


* **Problem 2: DCSync and DCShadow Evasions**
* *The Issue:* Techniques like DCSync or DCShadow abuse native AD replication protocols without running `netdom` or `nltest`. DCShadow registers a rogue Domain Controller by modifying Configuration partition objects in memory/replication.
* *The Fix:* Monitor replication requests from non-domain controllers (using Event ID 4662 auditing extended rights for replication GUIDs) and analyze RPC endpoints for unauthorized `DRSUAPI` calls.


* **Problem 3: Standard Domain Migration and Federation Setup Noise**
* *The Issue:* During domain migration or when integrating third-party SaaS services requiring Federation/Active Directory trusts, administrators will execute these commands, producing false alerts.
* *The Fix:* Maintain a change management schedule, filter out known domain controller service accounts, and whitelist specific administrative staging host IP addresses.
