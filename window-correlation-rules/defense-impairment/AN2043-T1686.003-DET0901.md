### **1. Technique Breakdown: T1686.003**

* **What it is:** **Disable or Modify System Firewall: Windows Host Firewall**. Adversaries modify Windows Defender Firewall settings using tools like `netsh` or `Set-NetFirewallRule` to allow malicious inbound connections (e.g., for C2 or lateral movement) or to prevent outbound telemetry.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1) and Windows Security Event Log (Event ID 4946 - A change has been made to Windows Firewall exception list).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Windows Security log intrinsically captures Event ID 4946 for rule additions/modifications. Sysmon Event ID 1 logs the execution of CLI tools used to manage the firewall.
    * **NIDS (Suricata + Zeek): NO.** Firewall rule manipulation is an endpoint configuration change.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line execution of native tools attempting to modify Windows Firewall rules.

```yaml
title: Disable or Modify Windows Host Firewall (AN2043)
id: f42a7862-2f08-4121-81d3-3fc8c21a115c
status: experimental
description: Detects command-line execution of netsh or PowerShell attempting to modify Windows Firewall rules or profiles.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_netsh:
        Image|endswith: '\netsh.exe'
        CommandLine|contains|all:
            - 'advfirewall'
            - 'firewall'
        CommandLine|contains:
            - 'add rule'
            - 'set rule'
            - 'delete rule'
            - 'set currentprofile'
            - 'state=off'
    selection_powershell:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        CommandLine|contains:
            - 'New-NetFirewallRule'
            - 'Set-NetFirewallRule'
            - 'Remove-NetFirewallRule'
            - 'Set-NetFirewallProfile'
    condition: selection_netsh or selection_powershell
fields:
    - CommandLine
    - Image
falsepositives:
    - IT administrators configuring network access for new applications.
    - Software installers automatically adding necessary firewall exceptions during deployment.
level: high
tags:
    - attack.defense_evasion
    - attack.t1686.003
    - analytics.an2043
    - detection.det0901
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Registry Manipulation**
    * *The Issue:* Advanced attackers can bypass command-line tools by modifying the firewall rules directly in the registry (`HKLM\System\CurrentControlSet\Services\SharedAccess\Parameters\FirewallPolicy\`).
    * *The Fix:* Enable Sysmon Event ID 12/13 (Registry Event) monitoring for changes under the `FirewallPolicy` key.

* **Problem 2: Group Policy Noise**
    * *The Issue:* In enterprise environments, Group Policy updates frequently push firewall rules, which may trigger native Event ID 4946 if not filtered properly.
    * *The Fix:* Baseline legitimate Group Policy updates (typically executed by `svchost.exe` under specific conditions) and whitelist those rule names or origins.

* **Problem 3: Obfuscated PowerShell Commands**
    * *The Issue:* Cmdlets like `New-NetFirewallRule` might be obfuscated or invoked via aliases in PowerShell scripts.
    * *The Fix:* Supplement command-line monitoring with PowerShell Script Block Logging (Event ID 4104) to catch de-obfuscated script executions.
