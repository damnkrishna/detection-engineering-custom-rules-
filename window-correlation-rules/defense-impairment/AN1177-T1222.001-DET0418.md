### **1. Technique Breakdown: T1222.001**

* **What it is:** **File and Directory Permissions Modification: Windows Permissions**. Adversaries modify Discretionary Access Control Lists (DACLs) and permissions using native Windows utilities (like `icacls.exe`, `takeown.exe`, `attrib.exe`) to access restricted files, hide malicious artifacts, or weaken system defenses.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and Object Access logs (Windows Security Event ID 4670 - Permissions changed).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs the execution of utilities like `icacls.exe` and their command-line arguments.
    * **NIDS (Suricata + Zeek): NO.** File permissions manipulation is a local host filesystem activity.

---

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of native Windows permission modification utilities with suspicious parameters indicating intent to grant access or take ownership.

```yaml
title: File and Directory Permissions Modification (AN1177)
id: cb120e3f-6772-4d1a-8288-51f7bb9183cc
status: experimental
description: Detects the execution of permission-modifying utilities with suspicious parameters indicating privilege escalation intent.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_tools:
        Image|endswith:
            - '\icacls.exe'
            - '\takeown.exe'
            - '\cacls.exe'
    selection_args:
        CommandLine|contains:
            - '/grant'
            - '/takeown'
            - 'Set-Acl'
            - 'Everyone:F'
    condition: selection_tools and selection_args
fields:
    - CommandLine
    - Image
falsepositives:
    - System administrators managing file shares or restoring backups.
    - Software installers configuring application directories.
level: medium
tags:
    - attack.defense_evasion
    - attack.t1222.001
    - analytics.an1177
    - detection.det0418
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct API Calls Bypass CLI Logs**
    * *The Issue:* Attackers can modify DACLs programmatically using Win32 APIs like `SetNamedSecurityInfo` directly in C/C++ or C#, generating no command-line logs for `icacls.exe`.
    * *The Fix:* Enable Windows Security Event ID 4670 (Permissions on an object were changed) and alert on unexpected processes modifying critical system files or directories.

* **Problem 2: Administrative Noise**
    * *The Issue:* In enterprise environments, logon scripts, management tools (SCCM), and admins use `icacls.exe` frequently.
    * *The Fix:* Whitelist known management processes, specific IT administrator accounts, and common target directories (like user profile creations).

* **Problem 3: PowerShell Aliases and Indirect Execution**
    * *The Issue:* `Set-Acl` might not appear in cleartext if the PowerShell script is encoded or obfuscated.
    * *The Fix:* Utilize PowerShell Script Block Logging (Event ID 4104) to analyze decoded script contents for `Set-Acl` or .NET access control methods.
