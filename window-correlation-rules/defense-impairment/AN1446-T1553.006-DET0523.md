### **1. Technique Breakdown: T1553.006**

* **What it is:** **Subvert Trust Controls: Code Signing Policy Modification**. Adversaries modify system policies to allow the execution of unsigned or improperly signed code. On Windows, this often involves modifying Boot Configuration Data (BCD) using `bcdedit.exe` to disable Driver Signature Enforcement (DSE) or enable Test Signing. This allows the loading of malicious kernel-level drivers.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 easily captures the execution of `bcdedit.exe` and its command-line parameters.
    * **NIDS (Suricata + Zeek): NO.** BCD modification is entirely a host-level OS activity.

---

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of `bcdedit.exe` attempting to disable Driver Signature Enforcement or enable test signing mode.

```yaml
title: Code Signing Policy Modification - Bcdedit DSE Disable (AN1446)
id: 489e2402-b2da-4a55-894d-45db9129df8f
status: experimental
description: Detects command-line execution of bcdedit.exe attempting to disable Driver Signature Enforcement or enable test signing.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_img:
        Image|endswith: '\bcdedit.exe'
    selection_cmd:
        CommandLine|contains:
            - 'loadoptions DDISABLE_INTEGRITY_CHECKS'
            - 'testsigning on'
            - 'nointegritychecks on'
    condition: selection_img and selection_cmd
fields:
    - CommandLine
    - Image
falsepositives:
    - Kernel developers testing custom unsigned drivers on non-production development machines.
level: high
tags:
    - attack.defense_evasion
    - attack.t1553.006
    - analytics.an1446
    - detection.det0523
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Reboot Requirement**
    * *The Issue:* Modifying BCD requires a system reboot to take effect. If the attacker modifies BCD but never reboots, the vulnerability isn't immediately exploitable.
    * *The Fix:* Correlate BCD modification events with subsequent unexpected system reboots (Event ID 1074) within a short time window.

* **Problem 2: API/WMI Modifications**
    * *The Issue:* Attackers might use WMI (`root\WMI` classes) or native APIs to modify boot variables without directly running `bcdedit.exe`.
    * *The Fix:* Monitor Sysmon Event ID 13 for direct registry writes to the BCD hive (`HKLM\BCD00000000`).

* **Problem 3: Bring Your Own Vulnerable Driver (BYOVD)**
    * *The Issue:* Instead of disabling DSE, attackers simply bring an already signed but vulnerable driver (like `capcom.sys`) to execute unsigned kernel code.
    * *The Fix:* DSE disabling checks must be augmented with driver load monitoring (Sysmon Event ID 6) alerting on known vulnerable driver hashes.
