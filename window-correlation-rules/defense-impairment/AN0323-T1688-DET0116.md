### **1. Technique Breakdown: T1688**

* **What it is:** **Safe Mode Boot**. Adversaries force a system to boot into Windows Safe Mode to disable security features (like antivirus, EDRs, and network monitoring agents) that do not load in this minimal environment. Attackers achieve this by using the command-line utility `bcdedit.exe` to configure the system to boot into Safe Mode (`minimal` or `network`) on the next restart. Alternatively, they modify the registry keys under `SafeBoot` to allow their own malware or malicious drivers to execute even in Safe Mode.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (specifically targeting boot configuration and registry utilities).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs the execution of utilities like `bcdedit.exe` or `reg.exe` targeting boot configuration parameters.
* **NIDS (Suricata + Zeek): NO.** Configuring boot options is a local operating system administrative task. It generates no network telemetry.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line execution of `bcdedit.exe` configured to force Safe Mode boot on next restart, or `reg.exe` modifying SafeBoot registry configurations.

```yaml
title: Force Safe Mode Boot or Tamper SafeBoot Configuration (AN0323)
id: f48e2b1c-3e2f-4a3b-9c8d-5f6d7e8a9b0d
status: experimental
description: Detects command-line execution of bcdedit.exe used to force the system into Safe Mode boot, or reg.exe modifying SafeBoot configuration keys to inject persistent drivers/services.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_bcdedit:
        - Image|endswith: '\bcdedit.exe'
        - OriginalFileName: 'bcdedit.exe'
    selection_bcdedit_args:
        CommandLine|contains|all:
            - 'safeboot'
    selection_reg:
        - Image|endswith: '\reg.exe'
        - OriginalFileName: 'reg.exe'
    selection_reg_args:
        CommandLine|contains:
            - 'add'
        CommandLine|contains:
            - '\Control\SafeBoot\Minimal'
            - '\Control\SafeBoot\Network'
    condition: (selection_bcdedit and selection_bcdedit_args) or (selection_reg and selection_reg_args)
falsepositives:
    - Legitimate administrator troubleshooting or IT deployment tasks configuring system boot options.
level: high
tags:
    - attack.defense_evasion
    - attack.t1688
    - analytics.an0323
    - detection.det0116
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Registry Modification (Bypassing CLI Tools)**
* *The Issue:* Instead of running `reg.exe` or `bcdedit.exe` to modify the registry, an attacker can modify SafeBoot configurations directly using custom malware binaries that call Win32 Registry APIs or load registry hives offline, which will not trigger this command-line process creation rule.
* *The Fix:* Enable registry auditing and monitor Sysmon Event ID 12/13/14 (Registry Event) or Windows Security Event ID 4657 targeting registry keys matching `\Control\SafeBoot\Minimal\` or `\Control\SafeBoot\Network\`.


* **Problem 2: Alternate Utilities or Native Windows GUI Tools**
* *The Issue:* Attackers or administrators can use MSConfig (system configuration GUI utility) to configure Boot options, which spawns GUI threads and modifies configuration files/registry without exposing obvious CLI arguments for `bcdedit.exe`.
* *The Fix:* Monitor process execution of `msconfig.exe` (Event ID 1 / `process.file.path` matches `msconfig.exe`) in combination with registry modifications to BCD registry settings.


* **Problem 3: Standard Administrative Troubleshooting**
* *The Issue:* Engineers frequently use `bcdedit` and boot systems into Safe Mode when repairing broken drivers or performing system recovery, leading to false positives.
* *The Fix:* Create a profile baseline of systems that routinely run BCD modifications (like VM staging environments) and filter out administrative user accounts or known domain maintenance scripts.
