### **1. Technique Breakdown: T1112**

* **What it is:** **Modify Registry**. This involves adversaries modifying the Windows registry to achieve persistence, privilege escalation, or defense evasion. Specifically, targeting critical system settings like `Winlogon\Notify`, `Winlogon\Userinit`, and startup keys (`Run`, `RunOnce`) allows malicious binaries to load automatically on logon or boot. Disabling security settings like `SafeDllSearchMode` (forcing it to search the current working directory first) enables DLL hijacking attacks.
* **Log Source Requirements:** Telemetry focusing on process creation and command-line execution (specifically Windows CLI registry modification tools).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) captures execution of `reg.exe`, `powershell.exe`, or `wmic.exe` with command-line arguments targeting these keys. Wazuh scans these events to flag malicious registry commands.
* **NIDS (Suricata + Zeek): NO.** Registry modifications are local host-level configuration changes. They do not generate direct network traffic, making NIDS blind to the modification itself (though network telemetry might catch follow-on C2 traffic or the initial download of payloads).

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line modifications of critical registry keys using built-in Windows CLI tools (`reg.exe`, `powershell.exe`, `pwsh.exe`, `cmd.exe`, or `wmic.exe`).

```yaml
title: Registry Modification via CLI (AN0781)
id: d76b5a3e-4b92-421c-bd93-6f7d8e9a0b1c
status: experimental
description: Detects command-line registry modifications using reg.exe, powershell.exe, cmd.exe, or wmic.exe targeting critical keys for persistence, privilege escalation, or defense evasion (e.g., Winlogon Notify, Userinit, Run/RunOnce, SafeDllSearchMode).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_images:
        - Image|endswith:
            - '\reg.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wmic.exe'
        - OriginalFileName:
            - 'reg.exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
            - 'cmd.exe'
            - 'wmic.exe'
    selection_keys:
        CommandLine|contains:
            - 'CurrentVersion\Winlogon\Notify'
            - 'CurrentVersion\Winlogon'
            - 'CurrentVersion\Run'
            - 'CurrentVersion\RunOnce'
            - 'Session Manager\SafeDllSearchMode'
            - 'SafeDllSearchMode'
    selection_actions:
        CommandLine|contains:
            - 'add'
            - 'import'
            - 'delete'
            - 'Set-ItemProperty'
            - 'New-ItemProperty'
            - 'Remove-ItemProperty'
    condition: selection_images and selection_keys and selection_actions
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Administrative scripts or software installations updating registry keys.
    - System updates or security agent configurations.
level: high
tags:
    - attack.defense_evasion
    - attack.persistence
    - attack.t1112
    - analytics.an0781
    - detection.det0280
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct API Registry Modification (Bypassing CLI)**
* *The Issue:* Attackers can execute compiled code (C/C++, Go, C#) or scripting frameworks that call direct Win32 APIs (e.g., `RegCreateKeyEx`, `RegSetValueEx`) without spawning `reg.exe` or using PowerShell commands. A command-line rule will miss these entirely.
* *The Fix:* You must monitor registry event telemetry (Sysmon Event ID 12/13/14 or Windows Event ID 4657) directly. Once those schemas are fully standardized, you should deploy a registry-level Sigma rule matching path patterns.


* **Problem 2: Registry Obfuscation and Relative Paths**
* *The Issue:* Attackers can use shorthand or relative keys (e.g., `HKLM:Run` instead of the full path, or environment variables) or obfuscate PowerShell command strings (e.g., string concatenation or base64 encoding) to evade simple command-line string matching.
* *The Fix:* Implement Script Block Logging (Event ID 4104) to deobfuscate PowerShell commands. Enable PowerShell transcript logging and use regex-based signatures on the decoded commands.


* **Problem 3: Standard Administrative/Software Noise**
* *The Issue:* Legitimate software installations and patch management scripts often modify autostart registry keys (Run/RunOnce) or Winlogon settings during updates, causing high volume of false alerts.
* *The Fix:* Create a baseline of authorized administrative tools, process parent-child relationships, or signer certificates. Exclude known update/installer parent processes (e.g., SCCM, Windows Update, GPO installers) from the alerting logic.
