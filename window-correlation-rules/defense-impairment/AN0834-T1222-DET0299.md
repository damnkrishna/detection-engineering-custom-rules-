### **1. Technique Breakdown: T1222**

* **What it is:** **File and Directory Permissions Modification**. Adversaries modify file and directory permissions (DACLs) and attributes to bypass access controls, escalate privileges, or evade detection. They use built-in Windows utilities like `icacls`, `cacls`, `takeown`, and `attrib` to grant themselves full control over system directories, deny access to defenders/security tools, remove audit trails, or hide malicious binaries under system and hidden attributes.
* **Log Source Requirements:** Endpoint logs capturing process creation and command-line execution (specifically Windows CLI utilities modifying DACLs or attributes).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) captures when utilities like `icacls.exe`, `cacls.exe`, `takeown.exe`, or `attrib.exe` are spawned, including their command-line arguments.
* **NIDS (Suricata + Zeek): NO.** DACL and attribute modifications are local system/operating system tasks. They generate no network traffic.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of Windows utilities (`icacls`, `cacls`, `takeown`, `attrib`) with command-line arguments indicating suspicious ownership changes, granting full control, denying access, or setting hidden attributes.

```yaml
title: Suspicious File and Directory Permissions Modification (AN0834)
id: c46f7e8a-2c1b-4d92-8c7a-5f6d7e8a9b0d
status: experimental
description: Detects command-line permissions modifications using built-in Windows utilities (icacls, cacls, takeown, attrib) targeting directory ownership, granting excessive rights, denying access, or hiding files.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_takeown:
        - Image|endswith: '\takeown.exe'
        - OriginalFileName: 'takeown.exe'
    selection_takeown_cmd:
        CommandLine|contains|all:
            - ' /f '
            - ' /r'
    selection_icacls:
        - Image|endswith:
            - '\icacls.exe'
            - '\cacls.exe'
        - OriginalFileName:
            - 'iCACLS.EXE'
            - 'cacls.exe'
    selection_icacls_cmd:
        CommandLine|contains:
            - 'Everyone:F'
            - 'Everyone:FA'
            - ' /deny '
            - ' /reset'
    selection_attrib:
        - Image|endswith: '\attrib.exe'
        - OriginalFileName: 'attrib.exe'
    selection_attrib_cmd:
        CommandLine|contains|all:
            - ' +h'
            - ' +s'
    condition: (selection_takeown and selection_takeown_cmd) or (selection_icacls and selection_icacls_cmd) or (selection_attrib and selection_attrib_cmd)
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Administrative scripts, software installation, or updates modifying permissions or attributes on legacy applications.
    - System setup utilities configuring system files.
level: high
tags:
    - attack.defense_evasion
    - attack.privilege_escalation
    - attack.t1222.001
    - analytics.an0834
    - detection.det0299
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Native PowerShell or API Modification (Bypassing CLI utilities)**
* *The Issue:* Attackers can use PowerShell's built-in cmdlets like `Set-Acl` or custom .NET API calls (e.g., `System.Security.AccessControl`) to change permissions programmatically without ever launching `icacls.exe` or `takeown.exe`. This process-name based detection will not see it.
* *The Fix:* Monitor Windows Security Event ID 4670 (Permissions on an object were changed) which registers DACL modifications regardless of whether CLI tools or APIs were used. Enable PowerShell Script Block Logging (Event ID 4104) to audit the use of `Set-Acl`.


* **Problem 2: Obfuscation and Alternate Binary Names**
* *The Issue:* Attackers can copy `icacls.exe` or `takeown.exe` to a user-writable directory, rename them (e.g., `update.exe`), and run them. This defeats the `Image|endswith` filter.
* *The Fix:* Rely on the `OriginalFileName` PE metadata field in Sysmon, which remains `iCACLS.EXE` or `takeown.exe` even if the file is renamed.


* **Problem 3: False Positives from Installer/Update Scripts**
* *The Issue:* Software installers, administrative deployment scripts, or GPO updates regularly modify permissions of program directories or user folders. This can trigger high-volume alerts.
* *The Fix:* Maintain an exclusion baseline of authorized administrative tools, installers (e.g., `msiexec.exe`), and system accounts (e.g., `NT AUTHORITY\SYSTEM`).
