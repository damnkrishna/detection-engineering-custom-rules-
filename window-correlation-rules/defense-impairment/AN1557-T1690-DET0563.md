### **1. Technique Breakdown: T1690**

* **What it is:** **Prevent Command History Logging**. Adversaries may disable the recording of command history in shells (like PowerShell or bash) to hide their execution artifacts. In Windows, this is commonly done by modifying the PSReadLine options in PowerShell, setting the `HistorySaveStyle` to `SaveNothing`, or pointing the `HistorySavePath` to `NUL` or a volatile location.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and PowerShell Script Block Logging (Event ID 4104).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures command-line arguments. Event ID 4104 captures the script blocks executed inside the PowerShell session, even if history saving is disabled.
    * **NIDS (Suricata + Zeek): NO.** Command history manipulation is a local shell configuration activity.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** and **PowerShell Event ID 4104** to detect commands attempting to disable PSReadLine history logging.

```yaml
title: Prevent Command History Logging - Set-PSReadLineOption (AN1557)
id: cd2aa272-d4b9-43a4-845a-eb378b273bcf
status: experimental
description: Detects PowerShell commands altering PSReadLine options to disable history saving, a common evasion technique.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: ps_script
    product: windows
    # Relies on PowerShell Script Block Logging (Event ID 4104) or Command Line (Event ID 1)
detection:
    selection_cmd:
        - CommandLine|contains|all:
            - 'Set-PSReadLineOption'
            - 'SaveNothing'
        - ScriptBlockText|contains|all:
            - 'Set-PSReadLineOption'
            - 'SaveNothing'
    condition: selection_cmd
fields:
    - CommandLine
    - ScriptBlockText
falsepositives:
    - Privacy-conscious administrators or developers intentionally disabling history on jump boxes.
level: high
tags:
    - attack.defense_evasion
    - attack.t1690
    - analytics.an1557
    - detection.det0563
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct File Deletion**
    * *The Issue:* Attackers might not change the configuration; they might simply delete the `ConsoleHost_history.txt` file after executing their commands.
    * *The Fix:* Monitor Sysmon Event ID 11 (File Deletion) targeting the `%APPDATA%\Microsoft\Windows\PowerShell\PSReadLine\` directory.

* **Problem 2: Obfuscation of Script Blocks**
    * *The Issue:* The `Set-PSReadLineOption` cmdlet might be obfuscated in script files, bypassing simple keyword matches.
    * *The Fix:* Rely heavily on PowerShell Event ID 4104, which often logs the de-obfuscated script block right before execution, making keyword matching more reliable.

* **Problem 3: Bypassing PSReadLine entirely**
    * *The Issue:* Attackers can execute commands via `powershell.exe -Command` directly from cmd.exe, which bypasses the interactive PSReadLine history entirely.
    * *The Fix:* Maintain robust Sysmon Event ID 1 logging for all `powershell.exe` invocations, as this provides a parallel log of commands executed outside the interactive prompt.
