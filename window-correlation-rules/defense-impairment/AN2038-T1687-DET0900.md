### **1. Technique Breakdown: T1687**

* **What it is:** **Exploitation for Defense Impairment**. Adversaries exploit software vulnerabilities specifically within security products (like EDR agents, Antivirus, or firewall services) to impair their functionality. This can result in the security service crashing, hanging, or failing to report telemetry.
* **Log Source Requirements:** Windows Application Logs (Event ID 1000 - Application Error), System Logs (Event ID 7031 - Service Terminated Unexpectedly), and Process Creation logs (Sysmon Event ID 1).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Windows Application and System logs natively capture service crashes and unexpected terminations. Sysmon can monitor process creation sequences immediately following a crash.
    * **NIDS (Suricata + Zeek): PARTIAL.** NIDS might detect the network-based exploitation attempt if the security product has an exposed network service (e.g., a vulnerable web management interface), but the actual impairment is host-centric.

### **2. Custom Sigma Rule**

This rule utilizes **Windows Application Event ID 1000 (Application Crash)** and **System Event ID 7031/7034 (Service Crash)** to detect unexpected failures of critical security processes.

```yaml
title: Exploitation for Defense Impairment - Security Service Crash (AN2038)
id: f48b1112-9844-4632-901b-c1284a14f4e7
status: experimental
description: Detects unexpected crashes or terminations of critical security services, which may indicate exploitation for defense impairment.
author: Krishna Gupta
date: 2026-06-09
logsource:
    product: windows
    category: application
    # Relies on Windows Application and System Event Logs
detection:
    selection_crash:
        EventID:
            - 1000
            - 7031
            - 7034
    selection_target:
        - Message|contains:
            - 'WinDefend'
            - 'MsMpEng.exe'
            - 'Sysmon.exe'
            - 'Sentinel'
            - 'csagent.sys'
    condition: selection_crash and selection_target
fields:
    - EventID
    - Message
falsepositives:
    - Legitimate software bugs or unstable updates to the security product causing spontaneous crashes.
level: high
tags:
    - attack.defense_evasion
    - attack.t1687
    - analytics.an2038
    - detection.det0900
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Silent Exploitation**
    * *The Issue:* If the exploit successfully modifies memory (e.g., blinding the sensor) without crashing the process, no crash logs (Event 1000/7031) are generated.
    * *The Fix:* Correlate network exploitation signatures with subsequent anomalous process behavior (like the AV process suddenly launching `cmd.exe` or injecting into other processes) using Sysmon Event IDs 1 and 8.

* **Problem 2: Driver Unloads**
    * *The Issue:* Instead of crashing the user-land agent, attackers might exploit kernel vulnerabilities to silently unload the security vendor's filter driver.
    * *The Fix:* Monitor Sysmon Event ID 6 (Driver Load) and system events for unexpected driver unloads related to security products.

* **Problem 3: Distinguishing Exploits from Bugs**
    * *The Issue:* Security agents crash occasionally due to software defects, causing false positives.
    * *The Fix:* Tune the rule by correlating the crash event temporally with other suspicious activities, such as a prior network connection from an untrusted subnet or a suspicious file drop.
