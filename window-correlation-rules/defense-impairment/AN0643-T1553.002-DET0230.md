### 1. Technique Breakdown: T1553.002

* What it is: Code Signing. Adversaries abuse code signing to bypass security controls (like Windows Defender Application Control/AppLocker) that filter unsigned or untrusted binaries. They accomplish this by signing malicious code with stolen certificates, purchasing certificates using fake identities, or generating self-signed certificates and installing them into the victim's trusted root store.
* Log Source Requirements: Endpoint logs capturing process creation or module loads with associated digital signature metadata (e.g., Sysmon Event ID 7 for Image Load or Event ID 1 for Process Creation).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 7 (Image Loaded) captures the file signature status (`Signed`, `Signature`, `SignatureStatus`) for loaded DLLs and EXEs. Wazuh can parse this to alert on revoked or invalid states.
* NIDS (Suricata + Zeek): NO. Code signing validation is an endpoint-local cryptographic process. Network tools cannot verify the validity or signature status of binaries in transit.
* Log Sources Covered:
  - Sysmon Event ID 13 (registry_set)
  - Sysmon Event ID 7 (image_load)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into registry store monitoring for disallowed certificates and image load signature status monitoring.

Rule 1 of 2: Detect Suspicious or Malicious Code Signing Abuse (Registry Set)
```yaml
title: Detect Suspicious or Malicious Code Signing Abuse (AN0643)
id: a7e3d81b-5c2f-4b92-8c7a-5f6d7e8a9b0e
status: experimental
description: Detects registry modifications under system certificate store paths that register disallowed or untrusted code signing certificates.
author: Krishna Gupta
date: 2026-06-17
logsource:
    category: registry_set
    product: windows
detection:
    selection:
        TargetObject|contains:
            - '\SOFTWARE\Microsoft\SystemCertificates\Disallowed\Certificates\'
            - '\SOFTWARE\Microsoft\SystemCertificates\Untrusted\'
    condition: selection
fields:
    - TargetObject
    - Details
    - Image
    - User
falsepositives:
    - Legitimate administrative certificate revocation distributions.
level: high
tags:
    - attack.defense-evasion
    - attack.t1553.002
    - analytic.an0643
    - detection.det0230
```

Rule 2 of 2: Execution of DLL with Suspicious or Revoked Code Signature (Image Load)
```yaml
title: Execution of DLL with Suspicious or Revoked Code Signature (AN0643-B)
id: 38e3ada9-c0eb-48f2-91a7-56acf95bd518
status: experimental
description: Detects the loading of images (DLLs/EXEs) from user-writable directories that possess an invalid, expired, or explicitly revoked digital signature.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: image_load
    product: windows
detection:
    selection_paths:
        ImageLoaded|contains:
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\Windows\Temp\'
            - '\AppData\Roaming\'
    selection_signature_status:
        SignatureStatus:
            - 'invalid'
            - 'revoked'
            - 'expired'
    condition: selection_paths and selection_signature_status
fields:
    - Image
    - ImageLoaded
    - Signed
    - SignatureStatus
falsepositives:
    - Legacy corporate applications compiled internally with expired certificates executing from user directories.
level: high
tags:
    - attack.defense-evasion
    - attack.t1553.002
    - analytic.an0643
    - detection.det0230
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.
