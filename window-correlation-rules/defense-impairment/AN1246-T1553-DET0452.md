### **1. Technique Breakdown: T1553**

* **What it is:** **Subvert Trust Controls**. Adversaries may subvert trust controls to bypass security mechanisms that rely on digital certificates or code signing. This broad technique includes adding malicious root certificates to the trust store, modifying code signing policies, or installing unsigned drivers.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and Registry modifications (Sysmon Event ID 13).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon can log the execution of certificate utilities like `certutil.exe` and registry changes to the Windows certificate stores (`Root`, `AuthRoot`).
    * **NIDS (Suricata + Zeek): NO.** Trust subversion is an endpoint configuration change.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of `certutil.exe` attempting to add a new root certificate to the local machine store, a common subversion technique.

```yaml
title: Subvert Trust Controls - Malicious Root Cert Install (AN1246)
id: dbaad872-9cc9-4177-ad6d-74d39f8f4a21
status: experimental
description: Detects abnormal installation of root or code-signing certificates using certutil.exe.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_img:
        Image|endswith: '\certutil.exe'
    selection_cmd:
        CommandLine|contains|all:
            - '-addstore'
            - 'Root'
    condition: selection_img and selection_cmd
fields:
    - CommandLine
    - Image
falsepositives:
    - Legitimate administration scripts deploying corporate PKI root certificates.
level: high
tags:
    - attack.defense_evasion
    - attack.t1553
    - analytics.an1246
    - detection.det0452
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Alternate Certificate Installers**
    * *The Issue:* Attackers can use PowerShell cmdlets (`Import-Certificate`) or double-click `.cer` files using the GUI wizard, bypassing `certutil.exe` command-line checks.
    * *The Fix:* Monitor Registry Event logs (Sysmon Event ID 13) for additions to `HKLM\SOFTWARE\Microsoft\SystemCertificates\Root\Certificates\`.

* **Problem 2: Administrative Deployment**
    * *The Issue:* Active Directory Group Policy automatically pushes root certificates, which can create noise if scripts are used locally by IT.
    * *The Fix:* Filter out expected processes like `svchost.exe` handling Group Policy updates and baseline expected `certutil` activity from deployment platforms (like SCCM).

* **Problem 3: User-Level Trust Stores**
    * *The Issue:* Certificates can be added to `HKCU` (Current User) instead of `HKLM` (Local Machine), bypassing machine-level monitoring but still compromising the user's session (e.g., intercepting browser HTTPS traffic).
    * *The Fix:* Ensure registry monitoring covers both `HKLM` and `HKCU` paths for certificate stores.
