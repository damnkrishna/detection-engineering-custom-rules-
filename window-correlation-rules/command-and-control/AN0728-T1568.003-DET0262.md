### **1. Technique Breakdown: T1568.003**

* **What it is:** **Dynamic Resolution: DNS Calculation**. Adversaries derive dynamic command and control ports or IPs mathematically from DNS queries. This is often done by querying DNS TXT records, which can contain base64 encoded payloads or configuration data, or using specific octets from a resolved IP address to determine a custom port number for the subsequent C2 socket connection.
* **Log Source Requirements:** DNS client logs (Sysmon Event ID 22 / Windows Security Event ID 3008) and network connection logs (Sysmon Event ID 3).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 22 logs the DNS query types (such as TXT records) and requesting processes, and Event ID 3 logs subsequent socket connections to resolved IPs.
* **NIDS (Suricata + Zeek): YES.** Zeek `dns.log` captures DNS query types (e.g., TXT) and `conn.log` captures the subsequent socket connections on non-standard ports.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 22 (DNS Query)** to detect DNS queries requesting TXT records (frequently abused for C2 channel commands and DNS calculation parameters) initiated by scripting hosts.

```yaml
title: DNS TXT Query from Scripting Host (AN0728)
id: 9c148ad0-cafa-41e4-8301-28fc980d7c3e
status: experimental
description: Detects DNS queries requesting TXT records initiated by scripting hosts or command line utilities, which can indicate DNS calculation or C2 configuration retrieval.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: dns_query
    product: windows
    # Relies on Sysmon Event ID 22 collected via Wazuh
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\cmd.exe'
    selection_txt:
        # In Sysmon Event ID 22, QueryResults contain TXT records resolved
        QueryResults|contains:
            - 'TXT'
            - 'v=spf1'
    condition: selection_process and selection_txt
fields:
    - Image
    - QueryResults
falsepositives:
    - Domain SPF, DKIM, or domain ownership verification checks executed by administrative mail or network diagnostic scripts.
level: high
tags:
    - attack.command_and_control
    - attack.t1568.003
    - analytics.an0728
    - detection.det0262
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Stateful Multi-Event Correlation Requirements**
* *The Issue:* Real DNS calculation involves comparing the IP resolved in Event ID 22 with the destination IP/Port in Event ID 3. This mathematical verification is too complex for standard stateless Sigma rules, which can lead to missed alerts if the attacker uses a standard A record but connects to derived ports.
* *The Fix:* Implement a stateful correlation rule in the SIEM engine (e.g. using Splunk SPL or Elasticsearch EQL) that extracts the resolved IP from the DNS event, calculates the derived port, and alerts if a network connection matches those specific parameters within a 60-second window.


* **Problem 2: DNS over HTTPS (DoH) / DNS over TLS (DoT)**
* *The Issue:* If the malware uses a public resolver via HTTPS (DoH), the host queries are encrypted and will not appear in local Windows DNS log Event ID 22 or Zeek DNS logs.
* *The Fix:* Enforce the use of internal DNS servers via enterprise Group Policies, block direct egress connections to known public DoH/DoT IPs on the perimeter firewall, and alert on non-browser processes communicating with public DoH endpoints.


* **Problem 3: Administrative Domain Verification Checks**
* *The Issue:* System administrators regularly query TXT records for DNS auditing, SPF verification, or domain configuration validation, generating false alarms.
* *The Fix:* Whitelist known administrative systems and limit this detection to user workstations.
