### **1. Technique Breakdown: T1102.001**

* **What it is:** **Web Service: Dead Drop Resolver**. Adversaries host C2 endpoint IP addresses or connection configurations on high-reputation, legitimate web services (such as GitHub, Pastebin, Reddit, or Twitter). Malicious scripts or binaries execute on the target host and connect to these services to resolve and fetch the secondary C2 IP. Because these web services are trusted by IT departments, network connections to these domains are rarely inspected or blocked.
* **Log Source Requirements:** Endpoint DNS logs (Sysmon Event ID 22) or network logs (Sysmon Event ID 3), combined with process execution metadata.
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 22 logs the queried domain alongside the requesting process path. Wazuh filters these DNS events to alert on anomalies.
* **NIDS (Suricata + Zeek): YES.** Zeek `dns.log` or `http.log`/`ssl.log` logs query domains and external handshakes.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 22 (DNS Query)** to detect scripting hosts or system command-line interpreters querying known dead drop resolver domains.

```yaml
title: Scripting Host Query to Dead Drop Web Service (AN0158)
id: b08fc96e-3217-4b6a-a336-2dd33e36b368
status: experimental
description: Detects scripting hosts or system processes initiating DNS queries to known dead drop resolver domains (e.g., github.com, pastebin.com, reddit.com).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: dns_query
    product: windows
    # Relies on Sysmon Event ID 22 collected via Wazuh
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\cmd.exe'
    selection_domains:
        QueryName|contains:
            - 'github.com'
            - 'raw.githubusercontent.com'
            - 'pastebin.com'
            - 'reddit.com'
            - 'twitter.com'
            - 'instagram.com'
    condition: selection_process and selection_domains
fields:
    - Image
    - QueryName
falsepositives:
    - Legitimate administrative tasks or developers downloading code files and packages.
level: medium
tags:
    - attack.command_and_control
    - attack.t1102.001
    - analytics.an0158
    - detection.det0058
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Use of Custom or Obscure Dead Drop Platforms**
* *The Issue:* Attackers can use smaller, less common web forums, blogs, or obscure paste sites that are not included in the whitelisted domain rules, bypassing the static domain string checks.
* *The Fix:* Implement heuristics that alert on any scripting engine querying external IP addresses or domains that are not part of the local system's baseline, and monitor execution of scripts downloading text files.


* **Problem 2: Domain Fronting / CDN Routing**
* *The Issue:* Attackers can route traffic to a dead drop resolver through a Content Delivery Network (CDN), causing the DNS query to target a benign generic CDN domain name (like `fastly.net` or `cloudfront.net`), obscuring the true destination page.
* *The Fix:* Enable SSL/TLS decryption to inspect the HTTP host header or URI path, and look for anomalous script interactions with generic CDN endpoints.


* **Problem 3: Standard Administrative Scripting Noise**
* *The Issue:* Network engineers and automation tools frequently write scripts that fetch packages or configuration updates directly from public repositories (like GitHub or GitLab).
* *The Fix:* Restrict the rule to monitor standard user workstation subnets, whitelisting developer and automation systems, and require script signing for administrative scripts.
