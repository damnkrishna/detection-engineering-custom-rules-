### **1. Technique Breakdown: T1219**

* **What it is:** **Remote Access Software** (specifically **Remote Desktop/RMM Software**). Adversaries deploy or use legitimate remote monitoring and management (RMM) software (such as TeamViewer, AnyDesk, ScreenConnect, LogMeIn, Splashtop) to establish interactive command-line and desktop control over compromised hosts. Because these tools are commercial software and use standard HTTPS/TLS (port 443) outbound connections, they bypass network firewalls and do not trigger traditional antivirus alerts.
* **Log Source Requirements:** Endpoint logs capturing process creation (Sysmon Event ID 1 / Windows Security Event ID 4688) or network connections (Sysmon Event ID 3).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs the execution of RMM client files and installer packages. Sysmon Event ID 3 captures outbound socket connections to remote control servers. Wazuh aggregates these client activities.
* **NIDS (Suricata + Zeek): YES.** Zeek `ssl.log` and `http.log` record connection handshakes to known RMM server networks.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of unauthorized Remote Management and Monitoring (RMM) and Remote Desktop applications.

```yaml
title: Unauthorized Remote Management and Monitoring Software Execution (AN0714)
id: 19c91359-023b-485a-a4d6-1853da3153f0
status: experimental
description: Detects the execution of known Remote Management and Monitoring (RMM) or Remote Desktop software (e.g., AnyDesk, TeamViewer, ScreenConnect) on unauthorized endpoints, indicating potential remote access hijacks.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_rmm:
        - Image|endswith:
            - '\AnyDesk.exe'
            - '\TeamViewer.exe'
            - '\TeamViewer_Desktop.exe'
            - '\ScreenConnect.Client.exe'
            - '\ScreenConnect.ClientService.exe'
            - '\tvnserver.exe'
            - '\winvnc.exe'
        - OriginalFileName:
            - 'AnyDesk.exe'
            - 'TeamViewer.exe'
            - 'TeamViewer_Desktop.exe'
            - 'ScreenConnect.Client.exe'
            - 'ScreenConnect.ClientService.exe'
            - 'tvnserver.exe'
            - 'winvnc.exe'
    condition: selection_rmm
falsepositives:
    - Authorized IT helpdesk technicians using RMM software for user support and system administration.
level: medium
tags:
    - attack.command_and_control
    - attack.t1219
    - analytics.an0714
    - detection.det0259
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Portable Executable Configurations / Execution from Temp**
* *The Issue:* Many RMM tools (e.g., AnyDesk, TeamViewer QuickSupport) run as stand-alone portable applications without installation, often launching directly from `%TEMP%` or `%USERPROFILE%\Downloads\`. This makes whitelisting based on standard program folders (`C:\Program Files\`) difficult.
* *The Fix:* Implement a companion rule that flags the execution of any binary with RMM-associated properties (OriginalFileName or metadata) executing from user-writable directories.


* **Problem 2: Masquerading and Renamed Clients**
* *The Issue:* Attackers can rename the AnyDesk or TeamViewer executable to a generic file name (e.g., `update.exe`) to evade filename filters.
* *The Fix:* Verify the `OriginalFileName` and `Publisher` signature fields in process creation logs, as these fields remain unchanged regardless of filename overrides.


* **Problem 3: Helpdesk Tool Standardization**
* *The Issue:* Large organizations often use various RMM tools across different business units, creating noise and alert fatigue.
* *The Fix:* Standardize helpdesk tools, whitelist the corporate-approved RMM software, and alert on any usage of non-standard alternatives (e.g., block AnyDesk if the official tool is TeamViewer).
