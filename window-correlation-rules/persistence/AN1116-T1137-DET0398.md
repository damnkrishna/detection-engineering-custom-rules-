# AN1116 - Office Application Startup (T1137)

## Technique Breakdown
Adversaries may abuse generic Microsoft Office application startup behaviors (beyond specific add-ins or forms) to maintain persistence. This can include modifying trusted locations in the registry so that malicious documents execute macros without warnings, or dropping DLLs into directories where Office applications natively load modules. Detection focuses on unexpected additions to `Security\Trusted Locations` in the registry.

## Custom Sigma Rule
```yaml
title: 'AN1116 - Generic Office Application Startup'
id: 'AN1116'
status: experimental
description: 'Detects registry modifications adding new Trusted Locations for Microsoft Office, allowing malicious macros to execute without warnings.'
author: Krishna Gupta
logsource:
  product: windows
  category: registry_set
detection:
  selection:
    TargetObject|contains: '\Software\Microsoft\Office\'
    TargetObject|contains: '\Security\Trusted Locations\'
  selection_event:
    EventType: 'SetValue'
  condition: selection and selection_event
fields:
  - EventID
  - TargetObject
  - Image
  - Details
level: high
tags:
  - attack.persistence
  - attack.t1137
  - analytic.an1116
```

## Blind Spots & Tuning
- IT administrators pushing GPOs that configure enterprise trusted locations (e.g., network shares).
- Tune by whitelisting `Image: C:\Windows\System32\svchost.exe` (if registry changes are made via GPO) or specific trusted paths.
