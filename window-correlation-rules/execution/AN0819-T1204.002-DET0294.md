### **1. Technique Breakdown: T1204.002**

* **What it is:** **User Execution: Malicious File**. Adversaries rely on a user opening a malicious file (e.g., an Office document, PDF, script, or executable) delivered via email, USB, or download. When opened, the file exploits a vulnerability, runs macros, or directly executes malicious code. This typically manifests as a user-facing application (Word, archiver) dropping payloads into user-controlled paths and spawning script engines.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1) and File Creation logs (Sysmon Event ID 11).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon tracks the execution chain (e.g., WinRAR spawning a `.bat` file) and files dropped into `Downloads` or `Temp`.
    * **NIDS (Suricata + Zeek): PARTIAL.** NIDS can detect the malicious file being downloaded (e.g., analyzing an unencrypted email attachment or HTTP download), but not the local execution.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect user-facing applications (like archivers or document readers) spawning shells or script interpreters, indicating the execution of a malicious file.

```yaml
title: User Execution - Malicious File Opened (AN0819)
id: cc9fa89e-4a6f-4d37-8b09-b6732cf0505a
status: experimental
description: Detects a handler application (archiver, Office, PDF reader) spawning a new or unusual child process, indicating execution of a malicious file.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_parent:
        ParentImage|endswith:
            - '\winrar.exe'
            - '\7zFM.exe'
            - '\winzip64.exe'
            - '\explorer.exe'
            - '\winword.exe'
            - '\excel.exe'
            - '\AcroRd32.exe'
    selection_child:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\regsvr32.exe'
            - '\rundll32.exe'
            - '\msiexec.exe'
    condition: selection_parent and selection_child
fields:
    - Image
    - ParentImage
falsepositives:
    - Users legitimately extracting installer scripts from archives and running them.
    - Approved enterprise macros running administrative commands.
level: high
tags:
    - attack.execution
    - attack.t1204.002
    - analytics.an0819
    - detection.det0294
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Explorer.exe Noise**
    * *The Issue:* `explorer.exe` is the parent of almost everything a user double-clicks. Alerting on `explorer.exe -> cmd.exe` will generate massive false positives.
    * *The Fix:* For `explorer.exe` parents, heavily tune the rule to only trigger if the `CommandLine` of the child points to suspicious file extensions (e.g., executing a `.vbs` or `.js` file) AND the file path includes `\Downloads\` or `\AppData\Local\Temp\`.

* **Problem 2: Mark of the Web (MOTW)**
    * *The Issue:* A malicious file downloaded from the internet should have a Zone Identifier. If the file is executed, standard logs don't clearly state its origin.
    * *The Fix:* Utilize Sysmon Event ID 15 (FileCreateStreamHash) to detect the creation of `Zone.Identifier` alternate data streams. Correlate the execution of files that possess a remote MOTW tag.

* **Problem 3: Right-to-Left Override (RTLO) Spoofing**
    * *The Issue:* Attackers spoof file extensions (e.g., `invoice_pdf.exe` obfuscated to look like `invoice.pdf`) to trick users.
    * *The Fix:* Standard logging might just show the execution of an executable. Advanced detection requires rules that explicitly search file names for the Unicode RTLO character (`U+202E`) during File Creation or Process Creation events.
