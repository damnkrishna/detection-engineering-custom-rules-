### 1. Technique Breakdown: T1574.001

* What it is: Hijack Execution Flow: DLL Side-Loading / DLL Hijacking. Adversaries abuse the Windows search order for shared libraries (DLLs) to execute malicious payloads. By copying a legitimate, signed system binary (like `calc.exe` or `notepad.exe`) into a user-writable directory (like `%TEMP%` or `C:\Users\Public\`) and placing a malicious DLL named after a required system dependency in that same directory, the application will load the malicious DLL instead of the legitimate one from `System32`.
* Log Source Requirements: Endpoint logs capturing process creation and command line parameters (specifically targeting OS system binaries executing from non-standard, user-writable paths).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs when system executables run, including their full resolved execution path and original filename (metadata).
* NIDS (Suricata + Zeek): NO. DLL side-loading is an endpoint-local application load process. It produces no network logs.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect when legitimate Windows system utilities are executed from user-writable temporary or profile directories, which is a key indicator of DLL side-loading or hijacking.

```yaml
title: Execution of Legitimate Binary from Suspicious Directory (AN0577)
id: d58f7c8e-3c2f-4d92-8c8d-6f7d8e9a0b0d
status: experimental
description: Detects the execution of legitimate Windows system utilities from user-writable or temporary directories, which commonly indicates DLL side-loading or hijacking.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_system_binaries:
        - Image|endswith:
            - '\calc.exe'
            - '\notepad.exe'
            - '\svchost.exe'
            - '\cmd.exe'
            - '\powershell.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\regsvr32.exe'
            - '\rundll32.exe'
            - '\odbcconf.exe'
            - '\gpupdate.exe'
            - '\taskhost.exe'
            - '\wsmprovhost.exe'
        - OriginalFileName:
            - 'calc.exe'
            - 'NOTEPAD.EXE'
            - 'svchost.exe'
            - 'cmd.exe'
            - 'PowerShell.EXE'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'regsvr32.exe'
            - 'RUNDLL32.EXE'
            - 'odbcconf.exe'
            - 'gpupdate.exe'
            - 'taskhost.exe'
            - 'wsmprovhost.exe'
    selection_suspicious_paths:
        CommandLine|contains:
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\Windows\Temp\'
            - '\AppData\Roaming\'
            - '\ProgramData\'
    filter_legitimate:
        CommandLine|contains:
            - 'C:\Windows\System32\'
            - 'C:\Windows\SysWOW64\'
            - 'C:\Windows\'
    condition: selection_system_binaries and selection_suspicious_paths and not filter_legitimate
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Administrative scripts or legacy installers that package local copies of notepad.exe or other basic system utilities in local folders.
level: high
tags:
    - attack.execution
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1574.001
    - analytic.an0577
    - detection.det0201
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
