### **1. Technique Breakdown: T1574.001**

* **What it is:** **Hijack Execution Flow: DLL Side-Loading / DLL Hijacking**. Adversaries abuse the Windows search order for shared libraries (DLLs) to execute malicious payloads. By copying a legitimate, signed system binary (like `calc.exe` or `notepad.exe`) into a user-writable directory (like `%TEMP%` or `C:\Users\Public\`) and placing a malicious DLL named after a required system dependency in that same directory, the application will load the malicious DLL instead of the legitimate one from `System32`.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (specifically targeting OS system binaries executing from non-standard, user-writable paths).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs when system executables run, including their full resolved execution path and original filename (metadata).
* **NIDS (Suricata + Zeek): NO.** DLL side-loading is an endpoint-local application load process. It produces no network logs.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect when legitimate Windows system utilities are executed from user-writable temporary or profile directories, which is a key indicator of DLL side-loading or hijacking.

```yaml
title: Execution of Legitimate Binary from Suspicious Directory (AN0577)
id: d58f7c8e-3c2f-4d92-8c8d-6f7d8e9a0b0d
status: experimental
description: Detects the execution of legitimate Windows system utilities from user-writable or temporary directories, which commonly indicates DLL side-loading or hijacking.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_system_binaries:
        - Image|endswith:
            - '\calc.exe'
            - '\notepad.exe'
            - '\svchost.exe'
            - '\cmd.exe'
            - '\powershell.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\regsvr32.exe'
            - '\rundll32.exe'
            - '\odbcconf.exe'
            - '\gpupdate.exe'
            - '\taskhost.exe'
            - '\wsmprovhost.exe'
        - OriginalFileName:
            - 'calc.exe'
            - 'NOTEPAD.EXE'
            - 'svchost.exe'
            - 'cmd.exe'
            - 'PowerShell.EXE'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'regsvr32.exe'
            - 'RUNDLL32.EXE'
            - 'odbcconf.exe'
            - 'gpupdate.exe'
            - 'taskhost.exe'
            - 'wsmprovhost.exe'
    selection_suspicious_paths:
        CommandLine|contains:
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\Windows\Temp\'
            - '\AppData\Roaming\'
            - '\ProgramData\'
    filter_legitimate:
        CommandLine|contains:
            - 'C:\Windows\System32\'
            - 'C:\Windows\SysWOW64\'
            - 'C:\Windows\'
    condition: selection_system_binaries and selection_suspicious_paths and not filter_legitimate
falsepositives:
    - Administrative scripts or legacy installers that package local copies of notepad.exe or other basic system utilities in local folders.
level: high
tags:
    - attack.execution
    - attack.persistence
    - attack.privilege_escalation
    - attack.t1574.001
    - analytics.an0577
    - detection.det0201
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Third-Party Executables (Non-OS Binaries)**
* *The Issue:* Attackers also side-load DLLs into trusted third-party software (like Microsoft Teams, OneDrive, Discord, or antivirus updates) that run from user directories by default. This OS-binary command-line rule will not see it.
* *The Fix:* Implement DLL verification via Sysmon Event ID 7 (Image Loaded) to alert on any unsigned DLLs loaded by these third-party programs, or verify their loading hashes against known-good baselines.


* **Problem 2: Obfuscation of Path Variables**
* *The Issue:* Attackers can execute binaries using environment variables or relative paths (e.g., executing `.\calc.exe` from `C:\Users\Public`), meaning the literal `CommandLine` string might not contain the words `\Users\Public\`.
* *The Fix:* Rely on the resolved file path in Sysmon (`Image`), which contains the absolute path of the executing process (e.g., `C:\Users\Public\calc.exe`), ensuring the rule evaluates the absolute process path.


* **Problem 3: False Positives from Development Environments**
* *The Issue:* Developers compiling software or compiling local system mocks may run customized scripts or launch binaries from temporary folders.
* *The Fix:* Restrict this high-severity rule to non-developer hosts, or exclude known development folders (like Visual Studio build directories) from the monitoring scope.
