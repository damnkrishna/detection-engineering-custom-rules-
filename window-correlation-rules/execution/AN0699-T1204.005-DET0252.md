### 1. Technique Breakdown: T1204.005

* What it is: User Execution: Malicious File Installers. Adversaries may trick users into running malicious installers or package managers (like `pip`, `npm`, `msiexec`) that execute malicious code disguised as legitimate software or libraries. In development environments, typosquatting packages in PyPI or NPM leads to immediate code execution upon package installation.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and File Creation logs (Sysmon Event ID 11).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon tracks the execution of `pip.exe`, `npm.cmd`, and `msiexec.exe`, as well as downstream script interpreter spawning and file drops.
    * NIDS (Suricata + Zeek): PARTIAL. NIDS will see HTTP/HTTPS requests to package repositories (like `registry.npmjs.org`), but payload inspection is difficult due to TLS.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of package managers dropping scripts into user directories followed by immediate execution of shells or interpreters.

```yaml
title: Suspicious Execution via Malicious Installer/Package Manager (AN0699)
id: f48b1112-9844-4632-901b-c1284a14f4e8
status: experimental
description: Detects the execution of pip, npm, or MSI installers followed by suspicious child processes (script interpreters) or writes to temporary user directories.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_parent:
        ParentImage|endswith:
            - '\pip.exe'
            - '\npm.cmd'
            - '\msiexec.exe'
    selection_child:
        Image|endswith:
            - '\python.exe'
            - '\node.exe'
            - '\cmd.exe'
            - '\powershell.exe'
            - '\rundll32.exe'
    selection_args:
        CommandLine|contains:
            - 'install'
            - 'setup.py'
            - '/q'
            - '/i'
    condition: selection_parent and selection_child and selection_args
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate software developers installing known packages.
    - Automated CI/CD pipelines deploying software.
level: high
tags:
    - attack.execution
    - attack.t1204.005
    - analytic.an0699
    - detection.det0252
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
