### **1. Technique Breakdown: T1203**

* **What it is:** **Exploitation for Client Execution**. Adversaries exploit software vulnerabilities in client applications (e.g., web browsers, Microsoft Office, PDF readers, Flash players) to execute arbitrary code. A successful exploit often results in the compromised application crashing unexpectedly or spawning an unusual child process (like `cmd.exe` or `powershell.exe`) and writing payloads to disk.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1), Application crash logs (Windows Application Event ID 1000), File Creation logs (Sysmon Event ID 11), and Network logs (Sysmon Event ID 3).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Correlates the crash, the child process spawned by the exploited app, and the file drop.
    * **NIDS (Suricata + Zeek): PARTIAL.** Network sensors might detect the exploitation attempt (e.g., malicious PDF signature) or the subsequent C2 callback.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the behavioral chain resulting from successful exploitation: a vulnerable client application spawning a suspicious shell or script engine.

```yaml
title: Exploitation for Client Execution - Suspicious Child Process (AN0797)
id: ab3c2020-f138-4e89-8d7b-41c1eb9f0a5f
status: experimental
description: Detects a cause-and-effect chain where a client app (Office, PDF reader, browser) spawns an unexpected child process, indicating successful exploitation.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_parent:
        ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\powerpnt.exe'
            - '\AcroRd32.exe'
            - '\iexplore.exe'
            - '\chrome.exe'
            - '\foxitreader.exe'
    selection_child:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\rundll32.exe'
            - '\regsvr32.exe'
    condition: selection_parent and selection_child
fields:
    - Image
    - ParentImage
falsepositives:
    - Legitimate Office macros invoking shells for system administration tasks.
    - PDF readers opening embedded links that legitimately launch helper apps.
level: critical
tags:
    - attack.execution
    - attack.t1203
    - analytics.an0797
    - detection.det0287
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: In-Memory Only Execution (No Child Process)**
    * *The Issue:* Advanced exploits execute malicious shellcode directly within the memory space of the exploited application (e.g., `AcroRd32.exe` making C2 connections directly) without ever spawning a secondary process like `cmd.exe`.
    * *The Fix:* Correlate Sysmon Event ID 3 (Network Connections) originating from client applications to non-standard ports or untrusted IP spaces. Monitor Sysmon Event ID 8 (CreateRemoteThread) for cross-process injection.

* **Problem 2: The Application Crash**
    * *The Issue:* Unstable exploits often crash the host application. While the Sigma rule catches successful child execution, it misses the failed attempts.
    * *The Fix:* Integrate Windows Application Event Log (Event ID 1000 - Application Error) and alert on sudden, repeated crashes of Office or PDF readers associated with a specific user.

* **Problem 3: Approved Macro Usage**
    * *The Issue:* Finance and HR departments frequently use complex Excel macros that legitimately spawn `cmd.exe` or `powershell.exe` to move files or query databases.
    * *The Fix:* Implement strict baseline tuning. If an alert fires for an Excel macro, verify the digital signature of the macro or the specific command-line arguments being passed to the shell, and whitelist approved workflows.
