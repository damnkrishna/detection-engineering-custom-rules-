### 1. Technique Breakdown: T1569.002

* What it is: System Services: Service Execution. Adversaries abuse the Service Control Manager (SCM) to execute commands or maintain persistence by creating and running temporary services.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. SCM child process spawning and administrative service controller invocations are monitored.
  - NIDS (Suricata + Zeek): YES. Remote SCM manipulation over RPC/SMB can be analyzed.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Suspicious Child Process of Service Control Manager
Detects processes spawned directly by the Service Control Manager (`services.exe`) that are not standard Windows service hosts, indicating direct execution via service creation.

```yaml
title: Suspicious Child Process of Service Control Manager (AN1185-A)
id: f023d881-819a-44f2-9ca0-80ef522f0018
status: experimental
description: Detects non-standard binaries spawned directly by services.exe, suggesting malicious service executions.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_parent:
        ParentImage|endswith: '\services.exe'
    filter_standard:
        Image|endswith:
            - '\system32\svchost.exe'
            - '\system32\spoolsv.exe'
            - '\system32\lsass.exe'
            - '\system32\wininit.exe'
            - '\system32\searchindexer.exe'
            - '\system32\taskhostw.exe'
            - '\system32\dllhost.exe'
            - '\system32\sihost.exe'
            - '\system32\mstsc.exe'
            - '\system32\consent.exe'
            - '\system32\smartscreen.exe'
            - '\system32\runtimebroker.exe'
            - '\system32\wbem\WmiPrvSE.exe'
            - '\MsMpEng.exe'
    condition: selection_parent and not filter_standard
fields:
    - Image
    - CommandLine
    - ParentImage
    - User
falsepositives:
    - Standard enterprise software installers registering and launching components during updates.
level: high
tags:
    - attack.execution
    - attack.t1569.002
    - analytic.an1185
    - detection.det0421
```

#### Rule 2 of 2: Service Controller CommandLine Creation
Detects execution of standard administrative tools like `sc.exe` or `net.exe` used to create or alter services with execution path parameters, separating image and original filename checks.

```yaml
title: Service Controller CommandLine Creation (AN1185-B)
id: cbdf2001-a189-4db8-bb9a-7c9802cf0019
status: experimental
description: Detects command-line parameters utilizing sc.exe or net.exe to create or modify service binaries.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\sc.exe'
            - '\net.exe'
            - '\net1.exe'
    selection_orig:
        OriginalFileName:
            - 'sc.exe'
            - 'net.exe'
            - 'net1.exe'
    selection_cli:
        CommandLine|contains:
            - ' binpath='
            - ' create '
            - ' config '
    condition: (selection_images or selection_orig) and selection_cli
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - IT administration scripts registering trusted business applications or service paths.
level: medium
tags:
    - attack.execution
    - attack.t1569.002
    - analytic.an1185
    - detection.det0421
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Software Update Service Registrations
  * The Issue: Upgrades to third-party agents (e.g. Splunk, Tanium, Google Update) frequently create transient services, triggering Rule 1.
  * The Fix: Baseline the approved service executables and add their paths to custom filter whitelists.
* Problem 2: Evasion via Direct Registry Injection
  * The Issue: If the attacker injects service entries directly into `HKLM\SYSTEM\CurrentControlSet\Services` via registry APIs without using `sc.exe`, Rule 2 will not trigger.
  * The Fix: Enable registry monitoring (Event ID 13) for service key creations (as covered in AN1489-A).
