### **1. Technique Breakdown: T1053**

* **What it is:** **Scheduled Task/Job**. Adversaries register scheduled tasks or jobs to execute malicious code automatically on a system. This technique is commonly used for persistence (running code across system reboots), execution (spawning payloads), or privilege escalation (configuring tasks to run under the high-privilege `SYSTEM` context). On Windows, tasks are typically created using the native `schtasks.exe` utility, the legacy `at.exe` utility, or PowerShell Task Scheduler cmdlets.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (specifically targeting command line schedulers or script block logs).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs the invocation of tools like `schtasks.exe` or `at.exe`, and records command-line flags.
* **NIDS (Suricata + Zeek): NO.** Creating scheduled tasks is a host-local configuration action. It produces no direct network traffic.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line registrations or modifications of scheduled tasks using `schtasks.exe`, legacy `at.exe`, or PowerShell Task Scheduler cmdlets.

```yaml
title: Creation of Scheduled Task via CLI (AN0258)
id: c4e3d1b2-2e1f-4b92-8c8d-6f7d8e9a0b0d
status: experimental
description: Detects the command-line creation of scheduled tasks using schtasks.exe, at.exe, or PowerShell cmdlets, which may be used for persistence, execution, or privilege escalation.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_schtasks:
        - Image|endswith: '\schtasks.exe'
        - OriginalFileName: 'schtasks.exe'
    selection_schtasks_args:
        CommandLine|contains:
            - ' /create '
            - ' /change '
    selection_at:
        - Image|endswith: '\at.exe'
        - OriginalFileName: 'at.exe'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_cmdlets:
        CommandLine|contains:
            - 'Register-ScheduledTask'
            - 'New-ScheduledTask'
            - 'Set-ScheduledTask'
    condition: (selection_schtasks and selection_schtasks_args) or selection_at or (selection_powershell and selection_powershell_cmdlets)
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Software installations or administrative scripts that automate task deployment as part of routine deployment operations.
level: medium
tags:
    - attack.execution
    - attack.persistence
    - attack.privilege_escalation
    - attack.t1053.005
    - analytics.an0258
    - detection.det0094
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Task Creation Bypassing CLI Utilities (Task Scheduler COM Interfaces)**
* *The Issue:* Attackers often use Task Scheduler COM interfaces (like `ITaskService` or raw API calls in C/C++ or PowerShell `.NET` types) or directly write XML configurations to load tasks. This bypasses command-line checks entirely because `schtasks.exe` or `powershell.exe` are never invoked.
* *The Fix:* Enable Task Scheduler logging and monitor Windows Security Event ID 4698 (A scheduled task was created). Also audit writes to the Task Scheduler registry directories (e.g., `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\Tasks\`).


* **Problem 2: Execution of Payloads via Legitimate Task Binaries (LOLBins)**
* *The Issue:* Adversaries configure scheduled tasks to launch legitimate system binaries (LOLBins like `mshta.exe`, `rundll32.exe`, or `regsvr32.exe`) which then load malicious scripts or binaries, hiding the true source of the task payload.
* *The Fix:* Correlate process creation logs where the parent process is the Task Scheduler Engine (`taskeng.exe` or `svchost.exe` hosting the Task Scheduler service, spawning sub-processes) and target high-risk child processes.


* **Problem 3: Standard Administrative/Software Noise**
* *The Issue:* Legitimate applications (like browsers, communication apps, or software updates) routinely create scheduled tasks for background updates. This generates substantial event volume.
* *The Fix:* Maintain a repository of authorized task names and paths. Exclude known task patterns or software update binaries (e.g., Google Update, Microsoft Edge Update) from triggering alarms.
