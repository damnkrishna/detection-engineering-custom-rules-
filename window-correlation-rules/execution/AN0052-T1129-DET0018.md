### **1. Technique Breakdown: T1129**

* **What it is:** **Shared Modules**. Adversaries execute malicious payloads by loading them as shared modules (DLLs) into the memory space of trusted processes. This is frequently accomplished via DLL Search Order Hijacking, DLL Side-Loading, or AppInit DLLs. By forcing a signed, legitimate process (like `explorer.exe` or `svchost.exe`) to load a malicious module, the adversary executes code while hiding under the process identity of a trusted Windows system program.
* **Log Source Requirements:** Endpoint logs capturing module/image loads with digital signature verification (specifically Sysmon Event ID 7 - Image Loaded).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 7 (Image Loaded) captures DLL loading events, reporting the path of the loading process, the path of the loaded DLL (`ImageLoaded`), and signature metadata.
* **NIDS (Suricata + Zeek): NO.** Shared module execution is local to the operating system's kernel and memory manager. It produces no network traffic.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 7 (Image Loaded)** to detect instances where high-risk system processes or administrative utilities load unsigned DLLs located within user-writable, temporary, or non-standard directories.

```yaml
title: Loading of Suspicious DLL from User-Writable Directory (AN0052)
id: f47c8d9e-1a2b-3c4d-8e9f-6f7d8e9a0b0d
status: experimental
description: Detects a process loading a shared module (DLL) located in user-writable directories (like AppData, Temp, or Public), which may indicate DLL side-loading or search order hijacking.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: image_load
    product: windows
    # Relies on Sysmon Event ID 7 collected via Wazuh
detection:
    selection_paths:
        ImageLoaded|contains:
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\Windows\Temp\'
            - '\AppData\Roaming\'
    selection_processes:
        Image|endswith:
            - '\explorer.exe'
            - '\svchost.exe'
            - '\cmd.exe'
            - '\powershell.exe'
            - '\rundll32.exe'
            - '\regsvr32.exe'
            - '\mshta.exe'
    selection_signature:
        Signed: 'false'
    condition: selection_paths and selection_processes and selection_signature
fields:
    - Image
    - ImageLoaded
    - Signed
falsepositives:
    - Legitimate software installed in user directories (like local profile applications) loading local DLLs.
level: high
tags:
    - attack.execution
    - attack.t1129
    - analytics.an0052
    - detection.det0018
```

### OCSF Normalized
```xml
title: Loading of Suspicious DLL from User-Writable Directory (OCSF-Normalized)
id: f47c8d9e-1a2b-3c4d-8e9f-6f7d8e9a0b0d
status: experimental
description: Detects processes loading shared modules (DLLs) located in user-writable directories, mapped to OCSF library_activity.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: system
    product: ocsf
    class: library_activity
detection:
    # Based on OCSF mapping, the loaded DLL path is mapped to library.file.path
    selection_paths:
        library.file.path|contains:
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\Windows\Temp\'
            - '\AppData\Roaming\'
            
    # The executing process path is mapped to process.file.path
    selection_processes:
        process.file.path|endswith:
            - '\explorer.exe'
            - '\svchost.exe'
            - '\cmd.exe'
            - '\powershell.exe'
            - '\rundll32.exe'
            - '\regsvr32.exe'
            - '\mshta.exe'
            
    # Checking if the library is not signed (status is invalid or unsigned)
    selection_signature:
        library.file.signature.status:
            - 'invalid'
            - 'unsigned'
            
    condition: selection_paths and selection_processes and selection_signature
fields:
    - library.file.path
    - library.file.signature.status
    - process.file.path
falsepositives:
    - Legitimate software installed in user directories loading local DLLs.
level: high
tags:
    - attack.execution
    - attack.t1129
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Excessive Logging I/O Overhead**
* *The Issue:* Monitoring every image load (Sysmon Event ID 7) globally causes massive performance overhead and log bloat on the endpoints and SIEM.
* *The Fix:* Scope the Sysmon configuration to only log Event ID 7 for high-risk processes (like system utilities, web browsers, or administrative shells) or load events originating from user-writable directories.


* **Problem 2: Signed Malicious DLLs**
* *The Issue:* Attackers can sign their hijacked DLLs using valid, stolen, or self-signed certificates, which will show the signature as valid and bypass the `Signed: false` check.
* *The Fix:* Baseline legitimate DLL loadings in the environment, and correlate any unsigned or recently-signed DLL loads with file integrity monitoring (FIM) or subsequent process behaviors (like spawning cmd shells).


* **Problem 3: Standard Local profile app false positives**
* *The Issue:* Many modern applications (like Slack, Teams, Google Chrome updates) install and run directly from `%APPDATA%` or `%USERPROFILE%\AppData\Local\`, loading many DLLs from user profiles.
* *The Fix:* Whitelist approved vendor application directory sub-paths or signature names (e.g., "Microsoft Corporation", "Google LLC", "Slack Technologies, Inc.").
