### **1. Technique Breakdown: T1574.007**

* **What it is:** **Hijack Execution Flow: Path Interception by PATH Environment Variable**. Adversaries modify the Windows `PATH` environment variable to intercept execution flows. By appending a user-writable folder (like `%TEMP%` or a local program path) to the beginning of the `PATH` variable, the operating system will search that folder first when launching executables. If an administrator or service runs a system tool (like `taskkill` or `ping`) without specifying the full path, the OS will load and execute the attacker's malicious binary of the same name.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (specifically targeting tools that modify system environment variables).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs the execution of utilities like `setx.exe`, `reg.exe`, or PowerShell command-lines modifying environment configurations.
* **NIDS (Suricata + Zeek): NO.** Environment variable configuration is a local operating system task. It generates no network logs.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of command-line tools (`setx.exe`, `reg.exe`, `powershell.exe`) being used to append or modify system/user environment `PATH` variables.

```yaml
title: Environment PATH Variable Modification via CLI (AN0009)
id: c4e3d81b-3f2d-4b92-8c8d-7f7d8e9a0b0d
status: experimental
description: Detects command-line modifications to the system or user environment PATH variables using setx.exe, reg.exe, or PowerShell, which may indicate path interception attempts.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_setx:
        - Image|endswith: '\setx.exe'
        - OriginalFileName: 'setx.exe'
    selection_setx_args:
        CommandLine|contains:
            - ' path '
            - ' PATH '
    selection_reg:
        - Image|endswith:
            - '\reg.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'reg.exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_reg_args:
        CommandLine|contains:
            - 'Session Manager\Environment'
            - '\Environment'
        CommandLine|contains:
            - 'add'
            - 'SetEnvironmentVariable'
            - 'Path'
    condition: (selection_setx and selection_setx_args) or (selection_reg and selection_reg_args)
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Legitimate software installers configuring paths during system integration or administrative path updates.
level: medium
tags:
    - attack.execution
    - attack.persistence
    - attack.privilege_escalation
    - attack.t1574.007
    - analytics.an0009
    - detection.det0004
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct API-Based Environment Manipulation**
* *The Issue:* Attackers can use custom compiled binaries (C#, C++) that call the `.NET` `Environment.SetEnvironmentVariable` API or Win32 `SetEnvironmentVariableW` function at runtime, or directly write to the registry hives, which bypasses command-line utility monitoring completely.
* *The Fix:* Enable registry auditing and monitor Sysmon Event ID 13 (Registry Value Set) or Windows Event ID 4657 targeting the keys `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment` and `HKCU\Environment`.


* **Problem 2: Shell-Specific PATH Modifications**
* *The Issue:* Path variables can be manipulated temporarily for a specific shell session using `SET PATH=...` or `$env:PATH=...` without modifying the permanent system registry keys.
* *The Fix:* Implement PowerShell Script Block Logging (Event ID 4104) and command-line monitoring to detect temporary path hijackings, or monitor process execution patterns of system tools spawned by shells.


* **Problem 3: Installer and Administrator Path Configurations**
* *The Issue:* Developers and installers (like Java, Python, Git) routinely modify system environment variables during setup, which triggers false alerts.
* *The Fix:* Exclude known installer parent processes (like `msiexec.exe` or approved setup files) and monitor only modifications containing user-writable directories (like `%TEMP%` or `%USERPROFILE%` additions).
