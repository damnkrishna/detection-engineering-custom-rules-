### 1. Technique Breakdown: T1106

* What it is: Native API. Adversaries bypass high-level APIs or security agent hooks by invoking Native APIs directly (e.g. via direct syscalls or loading private copies of system DLLs like `ntdll.dll`/`kernel32.dll` from non-standard directories to access unhooked code).
* Log Source Requirements: Sysmon DLL Load events (Event ID 7) and Sysmon Process Access events (Event ID 10).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Non-standard DLL paths and high-privilege virtual memory access handles are monitored.
  - NIDS (Suricata + Zeek): NO. Host-local memory execution.
* Log Sources Covered:
  - Sysmon Event ID 7 (image_load)
  - Sysmon Event ID 10 (process_access)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Hook Evasion via Non-Standard System DLL Load
Detects processes loading critical system libraries (`ntdll.dll`, `kernel32.dll`, `kernelbase.dll`) from non-standard locations (i.e., outside `System32`, `SysWOW64`, and `WinSxS` subdirectories), indicating private DLL mapping attempts to bypass security agent hooks.

```yaml
title: Hook Evasion via Non-Standard System DLL Load (AN1465-A)
id: f023d881-819a-44f2-9ca0-80ef522f0030
status: experimental
description: Detects processes loading critical system libraries from non-standard directories to bypass API hooking engines.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: image_load
    product: windows
detection:
    selection_dll:
        ImageLoaded|endswith:
            - '\ntdll.dll'
            - '\kernel32.dll'
            - '\kernelbase.dll'
    filter_standard_paths:
        ImageLoaded|startswith:
            - 'C:\Windows\System32\'
            - 'C:\Windows\SysWOW64\'
            - 'C:\Windows\WinSxS\'
    condition: selection_dll and not filter_standard_paths
fields:
    - Image
    - ImageLoaded
    - User
falsepositives:
    - Custom diagnostic tools packaged with local runtime dll engines (rare for ntdll/kernel32).
level: critical
tags:
    - attack.execution
    - attack.t1106
    - analytic.an1465
    - detection.det0529
```

#### Rule 2 of 2: Process Access Handle for Direct Syscalls
Detects process access events where a user-space binary requests high-privilege virtual memory write or handle control access targeting native operating system processes, omitting low-privilege VM read flags.

```yaml
title: Process Access Handle for Direct Syscalls (AN1465-B)
id: cbdf2001-a189-4db8-bb9a-7c9802cf0031
status: experimental
description: Detects user-space processes requesting high-privilege write or full control memory access handles targeting standard system processes.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_access
    product: windows
detection:
    selection_access:
        GrantedAccess:
            - '0x1F0FFF'
            - '0x1F1FFF'
            - '0x1410'
            - '0x1F3FFF'
    selection_source_paths:
        SourceImage|contains:
            - '\Users\'
            - '\Temp\'
            - '\AppData\'
    filter_standard:
        SourceImage|endswith:
            - '\chrome.exe'
            - '\firefox.exe'
            - '\msedge.exe'
            - '\MsMpEng.exe'
    condition: selection_access and selection_source_paths and not filter_standard
fields:
    - SourceImage
    - TargetImage
    - GrantedAccess
    - User
falsepositives:
    - Software performance counters or diagnostic monitors launched from local directories.
level: high
tags:
    - attack.execution
    - attack.t1106
    - analytic.an1465
    - detection.det0529
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Developer Machine Noise
  * The Issue: Software developers compiling C++ or C# applications will naturally trigger DLL load and memory access rules.
  * The Fix: Baseline standard developer endpoints or IDE executable paths (`devenv.exe`, `code.exe`) and exclude them from local process monitoring.
* Problem 2: Evasion via Process Hollowing
  * The Issue: If the attacker performs process hollowing, the initial DLL load event will be hidden within the legitimate process launch signature.
  * The Fix: Rely on Parent-Child process verification rules (AN1314-A/B) to detect anomalous shell launches.
