### **1. Technique Breakdown: T1059.007**

* **What it is:** **Command and Scripting Interpreter: JavaScript**. Adversaries use JavaScript (often executed via Windows Script Host binaries like `wscript.exe` and `cscript.exe`, or HTML Applications via `mshta.exe`) to execute malicious code. This is commonly seen in spearphishing campaigns where a user opens an Office document with a macro that drops a `.js` or `.jse` file and executes it.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon tracks executions of `wscript.exe`, `cscript.exe`, and `mshta.exe`, along with their script arguments.
    * **NIDS (Suricata + Zeek): NO.** Local execution of JavaScript is host-level activity.

---

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of Windows Script Host executing JavaScript files, particularly when spawned from suspicious parents or running from user directories.

```yaml
title: Suspicious JavaScript Execution via WSH (AN0733)
id: f42a7862-2f08-4121-81d3-3fc8c21a115d
status: experimental
description: Detects JavaScript execution through wscript.exe, cscript.exe, or mshta.exe, particularly when spawned from Office macros or abnormal user paths.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_wsh:
        Image|endswith:
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
    selection_js:
        CommandLine|contains:
            - '.js'
            - '.jse'
    selection_suspicious:
        - ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\outlook.exe'
        - CommandLine|contains:
            - '\AppData\Local\Temp\'
            - '\Downloads\'
            - '\ProgramData\'
    condition: selection_wsh and selection_js and selection_suspicious
fields:
    - CommandLine
    - Image
    - ParentImage
falsepositives:
    - Legacy enterprise applications relying on local JavaScript automation.
level: high
tags:
    - attack.execution
    - attack.t1059.007
    - analytics.an0733
    - detection.det0264
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Inline Script Execution (Fileless)**
    * *The Issue:* Attackers can execute JavaScript directly from the command line using `mshta javascript:...` or by embedding it in XML files, bypassing the `.js` extension filter.
    * *The Fix:* Add rules specifically targeting `mshta.exe` with `javascript:` or `vbscript:` in the `CommandLine`, regardless of the parent process.

* **Problem 2: AMSI Evasion**
    * *The Issue:* If script content is obfuscated, standard logging won't see the true intent.
    * *The Fix:* Ensure Windows Anti-Malware Scan Interface (AMSI) is integrated with the EDR/Sysmon environment to scan the de-obfuscated script content just before it is executed by the WSH engine.

* **Problem 3: Legitimate Logon Scripts**
    * *The Issue:* Many older Active Directory environments still use `.js` or `.vbs` files for user logon mapping scripts executed from `SYSVOL`.
    * *The Fix:* Baseline logon activities and whitelist script execution where the `CommandLine` points strictly to the corporate `\\domain\SYSVOL\` paths.
