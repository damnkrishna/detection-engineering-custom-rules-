### **1. Technique Breakdown: T1569**

* **What it is:** **System Services**. Adversaries may abuse system services for execution by modifying existing services or creating new ones. This allows them to execute binaries with `SYSTEM` privileges, load kernel drivers, or establish persistence. Commonly abused tools include `sc.exe`, PowerShell, or direct Win32 API calls (e.g., `CreateServiceW`).
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688), Windows System Log (Event ID 7045 - Service Created), and Registry modifications (Sysmon ID 12/13).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon tracks `sc.exe` process execution and registry modifications under `HKLM\System\CurrentControlSet\Services`. System Event ID 7045 logs explicit service creation.
    * **NIDS (Suricata + Zeek): NO.** Service modification is an operating system-level configuration change.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of `sc.exe` creating or modifying services to point to suspicious binaries or scripts.

```yaml
title: System Service Creation or Modification (AN0778)
id: e4b25e1a-965a-4b9e-bb47-798df9b0c2e3
status: experimental
description: Monitor for abnormal creation or modification of Windows services (e.g., via sc.exe) that load non-standard executables.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_sc:
        Image|endswith: '\sc.exe'
    selection_action:
        CommandLine|contains:
            - ' create '
            - ' config '
    selection_suspicious_paths:
        CommandLine|contains:
            - 'binPath='
            - '.bat'
            - '.ps1'
            - '\Temp\'
            - '\Users\Public\'
            - 'C:\ProgramData\'
    condition: selection_sc and selection_action and selection_suspicious_paths
fields:
    - CommandLine
    - Image
falsepositives:
    - Third-party software installers creating legitimate services in non-standard directories.
    - System administrators deploying temporary scripts as services.
level: high
tags:
    - attack.execution
    - attack.t1569
    - analytics.an0778
    - detection.det0279
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct API Usage**
    * *The Issue:* Attackers writing custom malware will call the `CreateService` Windows API directly, bypassing `sc.exe` process creation entirely.
    * *The Fix:* Enable Windows System Event ID 7045 (A service was installed in the system) and alert on services where the `ImagePath` points to unapproved directories (e.g., `%TEMP%`, `C:\Users\`).

* **Problem 2: Registry Manipulation**
    * *The Issue:* Services can be modified by directly editing the `ImagePath` value in the registry under `HKLM\System\CurrentControlSet\Services\<ServiceName>`.
    * *The Fix:* Monitor Sysmon Event ID 13 (Registry Value Set) targeting the `Services` registry hive for unusual executable paths.

* **Problem 3: Legitimate Updater Services**
    * *The Issue:* Software updaters (e.g., Chrome, Adobe) frequently update their service paths or create temporary services.
    * *The Fix:* Baseline known updater executables and digitally verify their signatures before allowing them to bypass the alert.
