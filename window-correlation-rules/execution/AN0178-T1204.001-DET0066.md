### **1. Technique Breakdown: T1204.001**

* **What it is:** **User Execution: Malicious Link**. Adversaries rely upon a user clicking a malicious link, typically delivered via spearphishing emails, SMS, or chat applications. Clicking the link triggers the execution of an exploit in the browser or prompts the download of a malicious payload. Detection focuses on a behavioral chain: a user-facing app launches a URL, subsequently makes an outbound connection to an untrusted domain, and a file is downloaded or executed.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1), Network connection logs (Sysmon Event ID 3), and File creation logs (Sysmon Event ID 11).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon tracks the full behavioral chain from browser launch, to network connection, to file drop.
    * **NIDS (Suricata + Zeek): PARTIAL.** Network monitoring can identify the click to the malicious domain and the subsequent payload download, but cannot correlate it to the exact user process/click action.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1, 3, and 11** (via a correlation engine) to detect the behavioral chain of a browser clicking a link, downloading a payload, and subsequently spawning a script engine or LOLBIN. Due to Sigma's stateless nature, this represents the initial step: a user-facing app spawning a command shell or script engine shortly after web interaction.

```yaml
title: User Execution - Malicious Link Clicking Behavioral Chain (AN0178)
id: fbb7cfc7-1a89-4e7a-97bb-41a4a1d82121
status: experimental
description: Detects a behavioral chain where a user-facing application (browser, email client) spawns suspicious shell utilities, indicating a clicked malicious link resulting in code execution.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_parent:
        ParentImage|endswith:
            - '\chrome.exe'
            - '\firefox.exe'
            - '\msedge.exe'
            - '\outlook.exe'
            - '\iexplore.exe'
    selection_child:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\rundll32.exe'
    condition: selection_parent and selection_child
fields:
    - Image
    - ParentImage
falsepositives:
    - Web browsers launching legitimate helper applications or protocol handlers that utilize cmd.exe or PowerShell.
level: high
tags:
    - attack.execution
    - attack.t1204.001
    - analytics.an0178
    - detection.det0066
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Multi-Stage Payloads and Process Disconnects**
    * *The Issue:* The clicked link might download an `.iso` or `.zip` file. When the user extracts and clicks the inner file, `explorer.exe` becomes the parent process, breaking the direct linkage back to `chrome.exe`.
    * *The Fix:* Utilize Mark-of-the-Web (MOTW) logs or Sysmon File Creation logs (Event ID 11) to track files downloaded by browsers, and alert when a downloaded file is subsequently executed.

* **Problem 2: Browser Protocol Handlers (Noise)**
    * *The Issue:* Legitimate enterprise applications sometimes register custom URI handlers (e.g., `mycorpapp://`) that browsers invoke using `cmd.exe` or `powershell.exe`, creating false positives.
    * *The Fix:* Inspect the `CommandLine` of the child process. Allow-list specific expected URL protocols or application paths associated with known enterprise tools.

* **Problem 3: In-Memory Browser Exploitation**
    * *The Issue:* If the link leads to a 0-day browser exploit, the attacker might execute code directly inside the browser process space (e.g., injecting into a renderer process) without ever spawning `cmd.exe`.
    * *The Fix:* Rely on EDR memory scanning, abnormal network connections originating directly from the browser process to non-web ports (Sysmon Event ID 3), or suspicious DLLs loaded into the browser (Sysmon Event ID 7).
