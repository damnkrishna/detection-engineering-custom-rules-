### **1. Technique Breakdown: T1059.006**

* **What it is:** **Command and Scripting Interpreter: Python**. Adversaries may abuse Python commands and scripts for execution. Python is a powerful interpreter often installed by default on Linux/macOS and frequently deployed in enterprise Windows environments. Attackers can execute malicious scripts directly from memory, spawn shells, or use Python for lateral movement and data exfiltration.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) containing full command-line arguments and parent process lineage.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures executions of `python.exe` or `py.exe`, including the script paths and anomalous parent processes (e.g., Office applications).
    * **NIDS (Suricata + Zeek): NO.** Python execution is a local host activity, though subsequent network behavior (e.g., outbound C2 over raw sockets) might be detected.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of Python interpreters from anomalous parent processes (like Microsoft Office macros or LOLBAS utilities), or executing from suspicious directories.

```yaml
title: Suspicious Python Interpreter Execution (AN0172)
id: 8c8dfa43-6d03-4b08-8f55-1f9e1db285b0
status: experimental
description: Detects Python execution via python.exe or py.exe with anomalous parent lineage (e.g., Office macros, LOLBAS) or execution from unusual directories.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_python:
        Image|endswith:
            - '\python.exe'
            - '\pythonw.exe'
            - '\py.exe'
    selection_parent:
        ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\powerpnt.exe'
            - '\mshta.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\cmd.exe'
            - '\powershell.exe'
    selection_path:
        CommandLine|contains:
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - 'C:\ProgramData\'
    condition: selection_python and (selection_parent or selection_path)
fields:
    - CommandLine
    - Image
    - ParentImage
falsepositives:
    - Legitimate developer scripts running from temp directories.
    - Automated system administration scripts wrapped in batch files.
level: high
tags:
    - attack.execution
    - attack.t1059.006
    - analytics.an0172
    - detection.det0063
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Embedded Python / Bring Your Own Interpreter**
    * *The Issue:* Attackers do not always rely on the system-installed `python.exe`. They may drop a portable version of Python renamed to an innocent-sounding binary (e.g., `update.exe`), bypassing the `Image|endswith` filter.
    * *The Fix:* Modify the rule to look for OriginalFileName metadata in Sysmon Event ID 1 (e.g., `OriginalFileName: python.exe`) or alert on unsigned binaries executing `.py` or `.pyc` files in their command line.

* **Problem 2: Execution via Direct API/Memory**
    * *The Issue:* Using C/C++ loaders to embed the Python C-API (e.g., `libpython.dll`) to run Python code directly in memory without ever spawning a new `python.exe` process.
    * *The Fix:* Monitor for unexpected Image Loads (Sysmon Event ID 7) of `python*.dll` into processes like `svchost.exe` or `explorer.exe`.

* **Problem 3: Widespread Developer Noise**
    * *The Issue:* If the environment hosts software developers or data scientists, Python is launched constantly from `cmd.exe` or `powershell.exe`.
    * *The Fix:* Baseline known developer workstations and restrict alerts to specific high-risk execution chains (e.g., Python spawned by Office) or unexpected outbound network connections immediately following Python process creation.
