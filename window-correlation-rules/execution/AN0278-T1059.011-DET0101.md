### **1. Technique Breakdown: T1059.011**

* **What it is:** **Lua**. Adversaries abuse built-in or dropped Lua interpreters (`lua.exe`, `luac.exe`, `wlua.exe`) to execute Lua scripts (`.lua`). Lua is a lightweight scripting language often embedded in game clients, network software (like Nmap or Wireshark), or security tools. Attackers drop standalone Lua interpreters to execute malicious payload scripts, avoiding detection systems that only monitor PowerShell, VBScript, or command shells.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (specifically targeting standalone Lua execution or interpreters spawned by suspicious parent processes).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs the execution of Lua interpreters, including their command-line arguments and parent process names.
* **NIDS (Suricata + Zeek): NO.** Lua script execution is local. Network logs cannot detect the execution itself (though they might alert on script downloads or C2 network traffic).

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of Lua interpreters spawned by suspicious parent processes (such as Microsoft Office, web servers, or databases) or executing scripts from user-writable directories.

```yaml
title: Suspicious Lua Script Execution (AN0278)
id: d4f9e8a9-2b3c-4d92-8c8d-7f7d8e9a0b0c
status: experimental
description: Detects suspicious execution of Lua interpreters (lua.exe, luac.exe) spawned by web servers, office programs, or executing from user-writable paths.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_images:
        - Image|endswith:
            - '\lua.exe'
            - '\luac.exe'
            - '\wlua.exe'
            - '\luajit.exe'
        - OriginalFileName:
            - 'lua.exe'
            - 'luac.exe'
            - 'wlua.exe'
            - 'luajit.exe'
    selection_suspicious_parents:
        ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\outlook.exe'
            - '\w3wp.exe'
            - '\nginx.exe'
            - '\httpd.exe'
            - '\sqlservr.exe'
    selection_temp_paths:
        CommandLine|contains:
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\Windows\Temp\'
            - '\AppData\Roaming\'
    condition: selection_images and (selection_suspicious_parents or selection_temp_paths)
fields:
    - CommandLine
    - Image
    - OriginalFileName
    - ParentImage
falsepositives:
    - Development environments or legitimate applications utilizing embedded Lua scripting engines (e.g., Nmap scripts, Wireshark plugins).
level: high
tags:
    - attack.execution
    - attack.t1059.011
    - analytics.an0278
    - detection.det0101
```

### OCSF Normalized
```xml
title: Suspicious Lua Script Execution (OCSF-Normalized)
id: d4f9e8a9-2b3c-4d92-8c8d-7f7d8e9a0b0c
status: experimental
description: Detects suspicious execution of Lua interpreters spawned by web servers, office programs, or executing from user-writable paths, mapped to OCSF process_activity.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: system
    product: ocsf
    class: process_activity
detection:
    # Based on OCSF mapping, process identification is under process.file.path
    selection_images:
        process.file.path|endswith:
            - '\lua.exe'
            - '\luac.exe'
            - '\wlua.exe'
            - '\luajit.exe'
            
    # Targeting suspicious parent processes in OCSF unmapped.parent_image
    selection_suspicious_parents:
        unmapped.parent_image|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\outlook.exe'
            - '\w3wp.exe'
            - '\nginx.exe'
            - '\httpd.exe'
            - '\sqlservr.exe'
            
    # Checking command line arguments using OCSF process.cmd_line
    selection_temp_paths:
        process.cmd_line|contains:
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\Windows\Temp\'
            - '\AppData\Roaming\'
            
    condition: selection_images and (selection_suspicious_parents or selection_temp_paths)
fields:
    - unmapped.parent_image
    - process.cmd_line
    - process.file.path
falsepositives:
    - Development environments or legitimate applications utilizing embedded Lua scripting engines.
level: high
tags:
    - attack.execution
    - attack.t1059.011
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Renamed Interpreters**
* *The Issue:* Attackers can rename `lua.exe` to `svchost.exe` or `update.exe` and execute it. If the PE header's original filename is stripped or modified, the `selection_images` block will fail to detect it.
* *The Fix:* Monitor the file extension on command lines (`.lua` or `.luac`) or look for unusual process configurations loading Lua DLLs (like `lua51.dll`, `lua52.dll`, `lua53.dll`, or `luajit.dll`) in Event ID 7 (Image Load) logs.


* **Problem 2: Lua Embedded Inside Compiled Host Application**
* *The Issue:* Instead of running a standalone `lua.exe`, an attacker can use a legitimate, custom-compiled C++ application that links and runs the Lua scripting engine internally. This executes the malicious script without spawning a child `lua.exe` process.
* *The Fix:* Implement file integrity monitoring (FIM) or audit writes of `.lua` files. Enable logging on host applications that embed scripting engines.


* **Problem 3: Nmap / Wireshark false positives**
* *The Issue:* Security analysts or network administrators running Nmap scans (which uses NSE scripts) or analyzing pcaps in Wireshark (which supports Lua plugins) will generate frequent false-positive alerts on their analysis workstations.
* *The Fix:* Filter alerts by analyst hosts or specific development environments where NSE scripts are routinely developed or executed.
