### **1. Technique Breakdown: T1059.003**

* **What it is:** **Command and Scripting Interpreter: Windows Command Shell**. Adversaries use `cmd.exe` or batch files (`.bat`, `.cmd`) to interact with the system, execute programs, or launch subsequent scripts. Because `cmd.exe` is ubiquitous and heavily utilized by the OS, attackers frequently use it to blend in.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures every invocation of `cmd.exe`, including full command-line parameters (like `/c` or `/k`) and the parent process.
    * **NIDS (Suricata + Zeek): NO.** Command shell usage is strictly a local host activity.

---

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect suspicious invocation chains involving `cmd.exe`, particularly when launched by unusual parent processes like Microsoft Office or when using suspicious command-line parameters indicative of evasion.

```yaml
title: Suspicious Windows Command Shell Execution (AN0578)
id: 59a35e4d-080c-43f1-b1e6-b040cf6e3e5c
status: experimental
description: Detects interactive or scripted abuse of cmd.exe, focusing on anomalous parent processes, suspicious command-line flags, or chained execution.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_cmd:
        Image|endswith: '\cmd.exe'
    selection_parent:
        ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\powerpnt.exe'
            - '\mshta.exe'
            - '\wmiprvse.exe'
            - '\spoolsv.exe'
            - '\lsass.exe'
    selection_flags:
        CommandLine|contains:
            - ' /c '
            - ' /k '
            - '^' # Obfuscation using caret
            - '&' # Command chaining
    condition: selection_cmd and (selection_parent or selection_flags)
fields:
    - CommandLine
    - Image
    - ParentImage
falsepositives:
    - Logon scripts executing via wmiprvse.exe.
    - Legacy applications heavily chaining commands with ampersands.
level: high
tags:
    - attack.execution
    - attack.t1059.003
    - analytics.an0578
    - detection.det0202
```

title: Suspicious Windows Command Shell Execution (OCSF-Normalized)
id: 59a35e4d-080c-43f1-b1e6-b040cf6e3e5c

    category: system
    product: ocsf
    class: process_activity

    selection_cmd:
        process.file.path|endswith: '\cmd.exe'

        unmapped.parent_image|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\powerpnt.exe'
            - '\mshta.exe'

        process.cmd_line|contains:
            - ' /c '

    - unmapped.parent_image
    - process.cmd_line
    - process.file.path
falsepositives:
    - Authorized logon scripts.
level: high
tags:
    - attack.execution
    - attack.t1059.003

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Excessive Normal Administrator Noise**
    * *The Issue:* IT administrators and management tools (SCCM, Tanium) use `cmd.exe /c` millions of times a day in large enterprises. Alerting purely on `/c` will flood the SIEM.
    * *The Fix:* Do not alert on `cmd /c` in isolation. Correlate it strictly with unusual parents (like Word or Print Spooler) or highly specific chained commands (e.g., `cmd /c bitsadmin... & powershell...`).

* **Problem 2: Renaming cmd.exe**
    * *The Issue:* Attackers might copy `cmd.exe` to a temporary directory and rename it to `svchost.exe` to bypass `Image|endswith: \cmd.exe` logic.
    * *The Fix:* Utilize the `OriginalFileName` field in Sysmon Event ID 1. No matter what the binary is renamed to, `OriginalFileName` will still be `Cmd.Exe`.

* **Problem 3: Command Obfuscation**
    * *The Issue:* Attackers can heavily obfuscate batch files and command strings using environment variables (`%COMSPEC%`) or caret escaping (`c^m^d^.^e^x^e`), bypassing static string matches.
    * *The Fix:* While basic caret matching helps, robust detection requires dynamic script analysis (AMSI) or alerting on the invocation of common sub-processes spawned by the obfuscated script rather than the shell execution itself.
