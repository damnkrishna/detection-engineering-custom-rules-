### **1. Technique Breakdown: T1574.009**

* **What it is:** **Hijack Execution Flow: Path Interception by Unquoted Path**. Adversaries exploit unquoted service binary paths containing spaces to escalate privileges or establish persistence. When Windows starts a service whose binary path contains spaces and is not enclosed in double quotes (e.g., `C:\Program Files\Custom App\service.exe`), it interprets the spaces as delimiters and attempts to execute files in sequence: first `C:\Program.exe`, then `C:\Program Files\Custom.exe`, and finally `C:\Program Files\Custom App\service.exe`. If an attacker writes a malicious payload to `C:\Program.exe`, it will execute with the service's high privileges (often SYSTEM).
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (specifically targeting service configuration tools creating new services).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) logs the execution of `sc.exe` or PowerShell command-lines creating or editing service definitions.
* **NIDS (Suricata + Zeek): NO.** Creating or editing services is a local operating system administrative task. It generates no network logs.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the command-line creation or modification of Windows services using `sc.exe` where the binary path (`binPath`) contains spaces (e.g., `Program Files`, `Users`) but is not enclosed in double quotes.

```yaml
title: Creation of Service with Unquoted Binary Path via CLI (AN0176)
id: d4f8e8a9-4b3c-4d92-8c8d-7f7d8e9a0b0d
status: experimental
description: Detects command-line service creation or configuration using sc.exe where the binary path contains spaces but lacks double quotes, exposing the system to unquoted service path interception.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_sc:
        - Image|endswith: '\sc.exe'
        - OriginalFileName: 'sc.exe'
    selection_sc_args:
        CommandLine|contains:
            - 'create'
            - 'config'
    selection_binpath:
        CommandLine|contains:
            - 'binpath='
            - 'binPath='
    selection_spaces:
        CommandLine|contains:
            - 'Program Files'
            - 'Documents and Settings'
            - 'Users\'
    filter_quotes:
        CommandLine|contains:
            - '\"'
            - '""'
            - '`"'
            - '\""'
    condition: selection_sc and selection_sc_args and selection_binpath and selection_spaces and not filter_quotes
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Legitimate installers or administrators improperly configuring custom services without double-quoting the paths.
level: medium
tags:
    - attack.execution
    - attack.persistence
    - attack.privilege_escalation
    - attack.t1574.009
    - analytics.an0176
    - detection.det0064
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Registry Service Creation (Bypassing `sc.exe`)**
* *The Issue:* Attackers with administrative privileges can directly write the service registry keys under `HKLM\SYSTEM\CurrentControlSet\Services\` using `reg.exe` or API calls without executing `sc.exe`.
* *The Fix:* Monitor registry changes (Sysmon Event ID 12/13/14) targeting the `ImagePath` key under service definitions, checking if the path contains spaces and lacks quotes.


* **Problem 2: Execution of Intercepted Payload**
* *The Issue:* This rule only flags the *creation* of the unquoted service path. It does not alert when the service restarts and actually executes the intercepted payload (e.g., launching `C:\Program.exe` instead of `C:\Program Files\...\service.exe`).
* *The Fix:* Create a rule targeting the execution of binaries named `Program.exe` or `Common.exe` spawning from root directories (`C:\`) or intermediate directories (`C:\Program Files\Common.exe`), as these are typical locations for unquoted path interception.


* **Problem 3: Legacy Admin/Developer Configuration Noise**
* *The Issue:* Legacy software installers or administrative scripts frequently configure internal services without double quotes, creating persistent false-positive logs.
* *The Fix:* Clean up existing unquoted service paths via GPO/script remediation, and whitelist known-safe internal application names if they cannot be remediated.
