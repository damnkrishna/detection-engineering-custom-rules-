### **1. Technique Breakdown: T1563**

* **What it is:** **Remote Service Session Hijacking**. Adversaries may hijack an existing session of a remote service (such as RDP or ssh) to move laterally and bypass multi-factor authentication or credentials requirements. On Windows, RDP session shadowing (`mstsc.exe /shadow:<session_id>`) allows administrators or attackers to observe or interact with a user's active session. Before hijacking, adversaries typically run query utilities (like `query.exe user`, `qwinsta.exe`, or `qprocess.exe`) to list active terminal sessions and discover session IDs.
* **Log Source Requirements:** Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process paths (`mstsc.exe`, `query.exe`, `qwinsta.exe`) and command line parameters including the `/shadow` parameter.
    * **NIDS (Suricata + Zeek): NO.** RDP shadowing session requests are negotiated locally over RPC/RDP service processes. NIDS can detect the general RDP flow but cannot determine if it represents session shadowing or query commands executed via cmd.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of RDP shadowing commands (`mstsc.exe /shadow`) or session enumeration utilities (`query.exe`, `qwinsta.exe`, `qprocess.exe`).

```yaml
title: Remote Service Session Hijacking via RDP Shadowing (AN0216)
id: a194e271-3ef2-4e0b-8939-a8477d274509
status: experimental
description: Detects RDP session shadowing command executions (mstsc.exe /shadow) or session query utilities (query.exe, qwinsta.exe) that may indicate reconnaissance or hijacking of remote service sessions.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_shadow:
        - Image|endswith: '\mstsc.exe'
        - OriginalFileName: 'mstsc.exe'
    selection_shadow_args:
        CommandLine|contains:
            - '/shadow:'
            - ' /shadow:'
    selection_queries:
        - Image|endswith:
            - '\query.exe'
            - '\qwinsta.exe'
            - '\qprocess.exe'
        - OriginalFileName:
            - 'query.exe'
            - 'qwinsta.exe'
            - 'qprocess.exe'
    condition: (selection_shadow and selection_shadow_args) or selection_queries
falsepositives:
    - Helpdesk personnel shadowing remote sessions for legitimate troubleshooting or administrative support purposes.
level: high
tags:
    - attack.lateral_movement
    - attack.t1563
    - analytics.an0216
    - detection.det0079
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Shadowing Without CLI (Windows Remote Assistance / GUI)**
    * *The Issue:* Administrators or attackers can initiate RDP shadowing or Remote Assistance through GUI shortcuts or MMC console snap-ins. This doesn't involve running `mstsc.exe` with explicit `/shadow` parameters on the command line.
    * *The Fix:* Monitor RPC connections targeting the Terminal Services interface, or enable registry auditing on `HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services\Shadow` which configures RDP shadowing policies.

* **Problem 2: legitimate IT Remote Desktop Support Noise**
    * *The Issue:* Helpdesk technicians routinely run `query session` (`qwinsta`) or use RDP shadowing to assist users. This can generate false alarms.
    * *The Fix:* Filter out processes run by known IT Support or System Administrator groups, or restrict alerts to non-standard parent processes (e.g. `cmd.exe` or `powershell.exe` spawned by web servers or database processes).

* **Problem 3: Custom / Alternate Remote Session Queries**
    * *The Issue:* Attackers can list active sessions using WMI (`Get-WmiObject Win32_LogonSession`) or NetAPI calls (`NetSessionEnum`), bypassing the execution of standard utilities like `query.exe`.
    * *The Fix:* Supplement this rule by monitoring WMI querying events and auditing API calls to `NetSessionEnum` within endpoint security or network traffic logs.
