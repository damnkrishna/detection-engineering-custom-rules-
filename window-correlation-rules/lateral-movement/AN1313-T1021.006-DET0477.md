### 1. Technique Breakdown: T1021.006

* What it is: Remote Services: Windows Remote Management. Adversaries abuse Windows Remote Management (WinRM), a native WS-Management protocol service, to execute commands remotely on hosts. When WinRM is leveraged (e.g., via Enter-PSSession or Invoke-Command), the WinRM service helper host wsmprovhost.exe is spawned on the target system to execute the user's command, often by spawning a child command interpreter shell (cmd.exe or powershell.exe). Monitoring this parent-child relationship helps identify remote PowerShell execution.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) auditing parent-child process setups.
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs the parent process of a newly spawned shell. If the parent is wsmprovhost.exe, it represents WinRM activity. Wazuh aggregates these events.
  * NIDS (Suricata + Zeek): YES. Network logs track WinRM HTTP/HTTPS connections (ports 5985, 5986), but host logs are needed to verify the specific commands launched.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - PowerShell Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Windows Remote Management executions can be detected using process creation and PowerShell script block logs.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring and PowerShell script block logging.

Rule 1 of 2: WinRM Host Spawning Command Shell (Process Creation)
```yaml
title: Lateral Movement - WinRM Host Spawning Command Shell (AN1313)
id: 5e2e6baa-d6d5-4ea9-b545-3afcbca8667a
status: experimental
description: Detects the Windows Remote Management provider host (wsmprovhost.exe) spawning command interpreters (cmd.exe, powershell.exe), indicating active WinRM remote command execution.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
detection:
    selection_parent:
        ParentImage|endswith:
            - '\wsmprovhost.exe'
    selection_child:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_parent and selection_child and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate remote administration or scripting tasks executed by IT support engineers using remote PowerShell.
level: medium
tags:
    - attack.lateral-movement
    - attack.t1021.006
    - analytic.an1313
    - detection.det0477
```

Rule 2 of 2: WinRM Remote Command Execution in Script Block (Script Block)
```yaml

```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Standard IT Administration Overhead (Noise)
  * The Issue: System administrators run massive numbers of remote queries (e.g. check system updates or configurations) via WinRM, causing endless alerting.
  * The Fix: Scope the rule to filter out authorized administrative service accounts or whitelist specific source admin IP ranges.

* Problem 2: Execution inside wsmprovhost process thread
  * The Issue: If the remote PowerShell command runs completely in-memory utilizing standard cmdlets (e.g. Get-Process) without spawning a child process like powershell.exe, this process check will see only wsmprovhost.exe launching, with no child shell.
  * The Fix: Enable PowerShell Script Block Logging (Event ID 4104) to audit the code executed inside the WinRM session thread directly.

* Problem 3: Use of custom WinRM listeners
  * The Issue: If the attacker configures a custom WS-Management listener on a non-standard port or service configuration that does not use wsmprovhost.exe, the process check is bypassed.
  * The Fix: Monitor network sockets (Event ID 3) for the WinRM service daemon (snhost.exe or svchost.exe hosting WinRM) connecting to non-standard remote ports.
