### **1. Technique Breakdown: T1021**

* **What it is:** **Remote Services**. Adversaries leverage valid credentials to log in remotely to endpoints over Windows admin interfaces (like SMB, WMI, or WinRM). Once authenticated via a network logon (Logon Type 3), they perform administrative or execution commands (such as registering services, launching scheduled tasks, or modifying registry persistence) to establish a foothold or run commands.
* **Log Source Requirements:** Windows Security Event Log Event ID 4624 (Successful Logon) and Sysmon process creation logs (Event ID 1) containing Logon ID context.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Security Event ID 4624 captures successful network logons (Type 3) and records the Logon ID. Sysmon Event ID 1 logs process creation events and links them to the initiating Logon ID.
    * **NIDS (Suricata + Zeek): YES.** Network logs track SMB/RPC connection setups, but endpoint logging is required to identify the post-access process executions.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect administrative command-line tools or scripting engines executing within the context of a non-interactive Network Logon session (Logon Type 3, excluding standard system sessions), which suggests remote execution via admin interfaces.

```yaml
title: Lateral Movement - Post-Logon Administrative Process Execution (AN0750)
id: 295b1f0e-d6a4-45ef-ac1e-627aa4c20d04
status: experimental
description: Detects command-line interpreters or administrative utilities executing within a Network Logon session (Type 3, excluding SYSTEM sessions), suggesting remote execution via SMB, WMI, or WinRM.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 and Security Event ID 4624 collected via Wazuh
detection:
    selection_session:
        LogonId|not: '0x3e7' # Exclude standard local SYSTEM session
    selection_executables:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\sc.exe'
            - '\reg.exe'
            - '\schtasks.exe'
            - '\wmic.exe'
            - '\net.exe'
            - '\net1.exe'
        - OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'sc.exe'
            - 'reg.exe'
            - 'schtasks.exe'
            - 'wmic.exe'
            - 'net.exe'
    condition: selection_session and selection_executables
fields:
    - Image
    - LogonId
    - OriginalFileName
falsepositives:
    - Legitimate administrative tasks executed remotely using WinRM/WMI script engines by IT engineers.
    - Automated endpoint management software running scheduled tasks under domain admin contexts.
level: medium
tags:
    - attack.lateral-movement
    - attack.t1021
    - analytics.an0750
    - detection.det0269
```

### OCSF Normalized
```xml
title: Lateral Movement - Post-Logon Administrative Process Execution (OCSF-Normalized)
id: 295b1f0e-d6a4-45ef-ac1e-627aa4c20d04
status: experimental
description: Detects administrative commands running under network logon session contexts, mapped to OCSF process_activity.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: system
    product: ocsf
    class: process_activity
detection:
    # Based on OCSF mapping, process path is process.file.path and session is under actor.user.uid
    selection_executables:
        process.file.path|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\sc.exe'
            - '\reg.exe'
            - '\schtasks.exe'
            - '\wmic.exe'
    selection_session:
        # Excludes default local SYSTEM account
        actor.user.uid|not: 'S-1-5-18'
    condition: selection_executables and selection_session
fields:
    - actor.user.uid
    - process.file.path
falsepositives:
    - Legitimate remote administrative updates or monitoring tools.
level: medium
tags:
    - attack.lateral-movement
    - attack.t1021
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: High volume of WMI/WinRM IT admin automation (Noise)**
    * *The Issue:* Network admins frequently run scripting tasks remotely to audit systems or query logs, generating heavy alert volumes.
    * *The Fix:* Whitelist approved service accounts or source workstations dedicated to automation, and scope alerts to target systems containing critical files.

* **Problem 2: Execution via Interactive RDP sessions**
    * *The Issue:* If the attacker uses Remote Desktop Protocol (RDP) instead of network logins, the logon type is Type 10 (Interactive) rather than Type 3, bypassing this specific rule.
    * *The Fix:* Maintain adjacent rules checking for RDP session logins (Type 10) followed by immediate cmd/powershell execution.

* **Problem 3: Standard user logon scripts**
    * *The Issue:* Active Directory group policy logon scripts spawn shells during standard network logins, generating false positives.
    * *The Fix:* Add explicit path exclusions allowing GPO-managed logon scripts running from system policy directories (like `SYSVOL`).
