### **1. Technique Breakdown: T1563.002**

* **What it is:** **RDP Hijacking** (sub-technique of Remote Service Session Hijacking). Adversaries may hijack an existing Remote Desktop Protocol (RDP) session without needing the target user's password. A common method on Windows involves running the native Terminal Services Session Connection utility `tscon.exe` under high privilege (`SYSTEM` context, e.g. via scheduled task or system service). The attacker uses `tscon.exe <session_id> /dest:<session_name>` to attach the active session of a logged-on user to their own current session, immediately taking control of the user's desktop.
* **Log Source Requirements:** Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process paths (`tscon.exe`) and command line parameters including the `/dest` parameter.
    * **NIDS (Suricata + Zeek): NO.** The actual transfer of sessions using `tscon.exe` is handled internally by the Session Manager service (`smss.exe`) and Terminal Services on the host. It produces no direct network traffic during the session swap itself.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of `tscon.exe` with command line arguments containing `/dest`, which indicates session hijacking or redirection.

```yaml
title: RDP Session Hijacking via tscon (AN1620)
id: cc4f5f9b-2419-4d52-83b2-ae81cd20122c
status: experimental
description: Detects RDP session hijacking attempts using the native Windows tscon.exe utility, which transfers an active terminal session to a different destination session.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection:
        - Image|endswith: '\tscon.exe'
        - OriginalFileName: 'tscon.exe'
    selection_args:
        CommandLine|contains:
            - ' /dest:'
            - '/dest:'
    condition: selection and selection_args
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Legitimate terminal services administration where administrative sessions are transferred or connected by authorized administrators.
level: high
tags:
    - attack.lateral_movement
    - attack.t1563.002
    - analytics.an1620
    - detection.det0588
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Execution Under System Context (Task Scheduler/PsExec/Service)**
    * *The Issue:* To hijack another user's session, `tscon.exe` must run as the `SYSTEM` user. The attacker will usually create a service or scheduled task to launch it. The alert will fire on the process creation of `tscon.exe`, but the immediate precursor execution (creation of the scheduled task or service) may be audited separately.
    * *The Fix:* Correlate this alert with Task Scheduler creation events (Security Event 4698) or Service installation events (Event 7045) targeting `tscon.exe`.

* **Problem 2: API/COM-based Session Redirection**
    * *The Issue:* Attackers can write custom scripts or compiled binaries that call Terminal Services APIs (specifically `WTSConnectSession`) directly. This bypasses command-line auditing of `tscon.exe`.
    * *The Fix:* Enable auditing of API calls inside LSASS or terminal services host processes (`termsrv.dll`), and monitor network session redirections in Event ID 1149 under TerminalServices-RemoteConnectionManager operational logs.

* **Problem 3: legimitate Multi-Session RDS Servers**
    * *The Issue:* On Remote Desktop Session Host (RDSH) servers, admins or logon scripts might use `tscon.exe` to manage sessions, generating high event volume.
    * *The Fix:* Tune the rule by excluding known RDSH management systems, or restrict alerts to non-RDSH server roles (like Domain Controllers or general user workstations).
