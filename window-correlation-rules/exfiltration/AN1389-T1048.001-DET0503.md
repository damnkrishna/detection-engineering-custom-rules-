### 1. Technique Breakdown: T1048.001

* What it is: Exfiltration Over Alternative Protocol: Exfiltration Over Symmetric Encrypted Non-C2 Protocol. Adversaries encrypt stolen files locally using symmetric cryptography (like AES-256) and upload the data via an alternative network protocol or a public file hosting API that is distinct from their primary C2 channel. Because the traffic is encrypted, corporate data loss prevention (DLP) filters cannot read the content or identify sensitive keywords. Detections monitor scripting hosts loading cryptographic DLLs (`bcryptprimitives.dll`, `cryptsp.dll`) to prepare for secure transfers.
* Log Source Requirements: Endpoint image load logs (Sysmon Event ID 7 / Windows Security Event ID 5056) capturing cryptographic DLL loading.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 7 captures DLL load events alongside the calling process name, which allows detection of command-line scripting utilities importing cryptographic functions.
* NIDS (Suricata + Zeek): NO. Local cryptographic processing occurs entirely within the endpoint user-space. Network logs can capture the outbound file upload, but cannot confirm if the payload was encrypted locally using native DLL APIs.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 7 (Image Loaded) to detect command-line interpreters or scripting hosts loading Windows cryptographic DLLs, which indicates symmetric encryption preparations.

```yaml
title: Cryptographic DLL Loaded by Scripting Host (AN1389)
id: 1a59e4fb-05c9-49c1-98ca-bae5c8832b27
status: experimental
description: Detects command-line interpreters or scripting hosts loading Windows cryptographic libraries (e.g., bcryptprimitives.dll, cryptsp.dll), which may indicate symmetric encryption of data prior to exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: image_load
    product: windows
    # Relies on Sysmon Event ID 7
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\cmd.exe'
    selection_dll:
        ImageLoaded|endswith:
            - '\bcrypt.dll'
            - '\bcryptprimitives.dll'
            - '\cryptsp.dll'
            - '\ncrypt.dll'
    condition: selection_process and selection_dll
fields:
    - Image
    - ImageLoaded
    - Signed
    - SignatureStatus
falsepositives:
    - Administrative scripts executing complex hashing routines (e.g. comparing file hashes using Get-FileHash) or managing secure password fields.
level: medium
tags:
    - attack.exfiltration
    - attack.t1048.001
    - analytic.an1389
    - detection.det0503
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.
