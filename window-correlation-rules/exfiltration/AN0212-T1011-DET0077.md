### **1. Technique Breakdown: T1011**

* **What it is:** **Exfiltration Over Other Network Medium**. Adversaries bypass corporate firewall and proxy monitors by exfiltrating data through non-primary network interfaces connected directly to the internet (such as local WiFi hotspots, mobile cellular adapters, or Bluetooth links). Detections focus on identifying command-line configurations of wireless or cellular adapters by execution shells, which indicates out-of-band network preparations.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures execution of `netsh.exe` or PowerShell command lines querying or configuring network interfaces. Wazuh forwards and processes these activities.
* **NIDS (Suricata + Zeek): NO.** Out-of-band network traffic routed through cellular modems or private hotspots does not pass through the enterprise gateway, making network-level boundary inspection impossible.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of `netsh.exe` configuring wireless adapters (WLAN) or PowerShell network adapter cmdlets.

```yaml
title: WiFi or Secondary Network Interface Configuration via CLI (AN0212)
id: fec142f1-c3f4-41db-81ad-e335625fd6d6
status: experimental
description: Detects command-line execution of netsh.exe or PowerShell network cmdlets being used to configure, enable, or connect to wireless (WLAN) or secondary network interfaces, which can be used to bypass corporate network boundaries for exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_netsh:
        - Image|endswith: '\netsh.exe'
        - OriginalFileName: 'netsh.exe'
    selection_netsh_args:
        CommandLine|contains:
            - ' wlan '
            - ' wlan'
            - 'wlan '
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_cmdlets:
        CommandLine|contains:
            - 'NetAdapter'
            - 'NetRoute'
        CommandLine|contains:
            - 'Set-'
            - 'Enable-'
            - 'New-'
    condition: (selection_netsh and selection_netsh_args) or (selection_powershell and selection_powershell_cmdlets)
falsepositives:
    - IT administrators or users troubleshooting mobile workstation wireless connections or configuring VPN routing.
level: medium
tags:
    - attack.exfiltration
    - attack.t1011
    - analytics.an0212
    - detection.det0077
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Pre-Connected Interfaces and Automatic Fallback**
* *The Issue:* If a workstation has a mobile SIM card or cellular adapter already connected and configured with a higher routing metric than the corporate network, Windows may automatically fall back to the cellular network if the primary network is blocked, without spawning configuration commands.
* *The Fix:* Implement a host configuration policy that disables "MinimizeConnections" or disables non-domain wireless connections when connected to a domain network (using Group Policy / GPO).


* **Problem 2: API-Based Routing and Driver Access**
* *The Issue:* Advanced malware can call native Windows WLAN APIs (e.g., `WlanConnect` in `wlanapi.dll`) or directly send control codes (IOCTLs) to network adapters to toggle states, completely bypassing `netsh.exe` or PowerShell command invocation.
* *The Fix:* Audit module load logs (Sysmon Event ID 7) for `wlanapi.dll` loaded by unusual, non-network processes (like `cmd.exe` or `regsvr32.exe`) and monitor modifications to network adapter registry keys under `HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e972-e325-11ce-bfc1-08002be10318}`.


* **Problem 3: Standard Administrative/VPN Scripts**
* *The Issue:* VPN client packages and enterprise network troubleshooting tools run background scripts that routinely reset or probe network interfaces, generating false positives.
* *The Fix:* Baseline and whitelist approved enterprise VPN installers and IT-approved network diagnostic tools based on publisher signatures and program directories.
