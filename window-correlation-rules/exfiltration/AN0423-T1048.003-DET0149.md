### **1. Technique Breakdown: T1048.003**

* **What it is:** **Exfiltration Over Alternative Protocol: Exfiltration Over Unencrypted Non-C2 Protocol**. Adversaries bypass standard C2 communication channels to exfiltrate data using common, unencrypted protocols such as HTTP (port 80), FTP (port 21), or SMTP (port 25). They leverage built-in command-line tools or scripting engines to transmit staged archives to rogue external servers. Since the protocol is unencrypted, network analysis can read payloads, but host-based logs are necessary to identify the initiating processes.
* **Log Source Requirements:** Sysmon network connection logs (Event ID 3) combined with initiating process metadata (Sysmon Event ID 1).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 3 logs outbound TCP/UDP connections along with the parent process, source/destination ports, and IP addresses. Wazuh aggregates these events.
    * **NIDS (Suricata + Zeek): YES.** Zeek `http.log`, `ftp.log`, or `smtp.log` records unencrypted protocol transactions and file uploads in transit.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 3 (Network Connection)** to detect scripting engines or cmdline tools initiating connections over unencrypted protocols (80, 21, 25) to external networks.

```yaml
title: Exfiltration - Outbound Unencrypted Connection by Scripting Host (AN0423)
id: 27ba2a0d-92c4-4a3d-9436-55fc2e0aea6e
status: experimental
description: Detects command interpreters or scripting utilities (PowerShell, cscript, wscript) initiating network connections over unencrypted ports (80, 21, 25) to external IP addresses.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3 collected via Wazuh
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\cmd.exe'
    selection_ports:
        DestinationPort:
            - 21 # FTP
            - 25 # SMTP
            - 80 # HTTP
    filter_internal:
        DestinationIp|startswith:
            - '10.'
            - '192.168.'
            - '172.16.'
            - '172.17.'
            - '172.18.'
            - '172.19.'
            - '172.2'
            - '172.3'
            - '127.'
            - '169.254.'
    condition: selection_process and selection_ports and not filter_internal
fields:
    - DestinationIp
    - DestinationPort
    - Image
falsepositives:
    - Administrative scripts executing HTTP queries to download public updates or syncing time via NTP.
    - Automated system backup tools transferring statistics to internal monitoring servers.
level: high
tags:
    - attack.exfiltration
    - attack.t1048.003
    - analytics.an0423
    - detection.det0149
```

title: Exfiltration - Outbound Unencrypted Connection by Scripting Host (OCSF-Normalized)
id: 27ba2a0d-92c4-4a3d-9436-55fc2e0aea6e

    category: system
    product: ocsf

        process.file.path|endswith:

        activity.dst_endpoint.port:
            - 21
            - 25
            - 80

        activity.dst_endpoint.ip|startswith:
            - '10.'
            - '192.168.'
            - '172.'
            - '127.'

    - activity.dst_endpoint.ip
    - activity.dst_endpoint.port
    - process.file.path

    - Authorized monitoring scripts connecting to public update pools.
level: high
tags:
    - attack.exfiltration
    - attack.t1048.003

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Proxy Servers masking destination port**
    * *The Issue:* If the organization routes all web traffic through an outbound corporate proxy server, the endpoint connects to the proxy IP over port 8080 or 443, hiding the unencrypted port 80/21 destinations from host-level port filters.
    * *The Fix:* Correlate endpoint logs with web proxy server logs to analyze the actual destination scheme and request URI, and monitor proxy authentication headers for non-standard user agents.

* **Problem 2: SMTP authentication scripts**
    * *The Issue:* Legitimate IT notification systems spawn PowerShell scripts to send warning emails via internal SMTP servers over port 25 or 587, triggering false positives.
    * *The Fix:* Add a whitelist filter for authorized internal mail server IP addresses or specific authorized IT admin credentials running SMTP notification tasks.

* **Problem 3: Use of custom port mappings**
    * *The Issue:* Attackers hosting their own FTP or HTTP receivers on non-standard ports (like 8000, 8081, or 2121) bypass the static port filter checks (80, 21, 25).
    * *The Fix:* Complement this rule by identifying any scripting interpreter initiating outbound connections to external IP networks on *any* non-RFC internal address, regardless of destination port.
