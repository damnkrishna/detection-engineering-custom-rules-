### **1. Technique Breakdown: T1048.002**

* **What it is:** **Exfiltration Over Alternative Protocol: Exfiltration Over Asymmetric Encrypted Non-C2 Protocol**. Adversaries encrypt sensitive data using asymmetric cryptography (such as RSA or GPG) before transmitting it externally. By encrypting the data with a public key, the adversary ensures that intermediate network security controls (such as NIDS or DLP) cannot decrypt and inspect the payload, even if they decrypt the outer SSL/TLS tunnel. Host-based detection focuses on identifying processes executing command-line utilities (like `openssl.exe` or `gpg.exe`) or using scripting libraries to encrypt files.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing command line arguments.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs the full command-line arguments, letting defenders detect commands like `gpg --encrypt` or `openssl rsautl`. Wazuh parses these logs to alert.
    * **NIDS (Suricata + Zeek): NO.** Network sensors see only encrypted blobs and cannot detect the asymmetric encryption step on the host.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of encryption tools (like GnuPG, OpenSSL) or scripting utilities containing arguments for asymmetric encryption of files.

```yaml
title: Exfiltration - Asymmetric Encryption of Data Archive (AN1413)
id: 9d8057c6-1ace-4ac8-bad9-12bea82509e0
status: experimental
description: Detects command-line parameters of cryptographic utilities (such as GnuPG, OpenSSL) or scripting utilities indicating asymmetric encryption of files, typically performed prior to exfiltration.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_utilities:
        - Image|endswith:
            - '\gpg.exe'
            - '\gpg2.exe'
            - '\openssl.exe'
        - OriginalFileName:
            - 'gpg.exe'
            - 'gpg2.exe'
            - 'openssl.exe'
    selection_gpg_args:
        CommandLine|contains:
            - ' -e' # encrypt
            - ' --encrypt'
            - ' -r' # recipient (asymmetric identifier)
            - ' --recipient'
    selection_openssl_args:
        CommandLine|contains:
            - ' rsautl'
            - ' pkeyutl'
            - ' -encrypt'
    selection_powershell:
        CommandLine|contains:
            - 'Protect-CmsMessage'
            - 'RSACryptoServiceProvider'
            - 'System.Security.Cryptography.RSA'
    condition: (selection_utilities and (selection_gpg_args or selection_openssl_args)) or selection_powershell
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Legitimate administrative scripts encrypting database backups or logs before archiving them.
    - Software developers signing or encrypting packages during standard release builds.
level: medium
tags:
    - attack.exfiltration
    - attack.t1048.002
    - analytics.an1413
    - detection.det0512
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Encryption via Built-in System Archive tools (zip/7z)**
    * *The Issue:* Attackers often use symmetric encryption (e.g. zip/7z passwords) rather than asymmetric methods because symmetric tools are more common and easier to automate. This rule will miss symmetric encryption flags.
    * *The Fix:* Scope adjacent rules to check for compression utilities using password parameters (e.g. `7z.exe -p`).

* **Problem 2: Execution via Custom Cryptography scripts**
    * *The Issue:* If the attacker executes a python or C# script that imports standard libraries (like PyCryptodome or .NET RSACryptoServiceProvider) to perform encryption, process name filters checking for `gpg.exe` or `openssl.exe` are bypassed.
    * *The Fix:* Monitor PowerShell Script Block Logging (Event ID 4104) and look for imports of cryptographic namespaces combined with file system reads.

* **Problem 3: Standard Password Sync / GPG Tools**
    * *The Issue:* IT support teams routinely use GPG keys to share administrative credentials or backup keys, leading to benign alerts when GPG is run.
    * *The Fix:* Whitelist approved service accounts, or whitelist executions associated with specific internal GPG key recipient email domains.
