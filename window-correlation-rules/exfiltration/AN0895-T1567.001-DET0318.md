### **1. Technique Breakdown: T1567.001**

* **What it is:** **Exfiltration to Code Repository**. Adversaries exfiltrate data by uploading files or source code directly to public, legitimate code repositories (such as GitHub, GitLab, or Bitbucket). They do this using CLI client tools (like `git.exe` or `curl.exe`) or scripting hosts (like PowerShell) to send HTTP POST requests directly to repository APIs. Because these repositories are trusted by IT departments, network connections to these domains are rarely blocked.
* **Log Source Requirements:** Endpoint network connection logs (Sysmon Event ID 3) or DNS queries (Sysmon Event ID 22), combined with initiating process metadata.
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 3 logs outbound network connections containing destination hostnames and initiating process names. Wazuh forwards these to trigger alerts.
* **NIDS (Suricata + Zeek): YES.** Zeek `ssl.log` and `http.log` capture SNI/TLS handshakes and HTTP payloads (target host and method) to public repositories.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 3 (Network Connection)** to detect command-line interpreters, scripting hosts, or file transfer tools initiating network connections to known public code repository domains.

```yaml
title: Outbound Data Exfiltration to Code Repository via CLI (AN0895)
id: dcc44532-0a4a-4cf5-8139-12629817c775
status: experimental
description: Detects command-line interpreters, scripting hosts, or file transfer tools initiating network connections or DNS queries to known public code repository domains (e.g. GitHub, GitLab, Bitbucket), which may indicate data exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3 collected via Wazuh
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\curl.exe'
    selection_domains:
        DestinationHostname|contains:
            - 'github.com'
            - 'gitlab.com'
            - 'bitbucket.org'
            - 'githubusercontent.com'
    condition: selection_process and selection_domains
fields:
    - DestinationHostname
    - Image
falsepositives:
    - Software developers pushing legitimate code updates to corporate repository accounts using scripts or command line git tools.
level: medium
tags:
    - attack.exfiltration
    - attack.t1567.001
    - analytics.an0895
    - detection.det0318
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Developer Workstation Noise**
* *The Issue:* Software developers and DevOps systems routinely push code, download dependencies, and sync with GitHub/GitLab repositories using scripts, producing thousands of false alerts daily.
* *The Fix:* Define static IPs or whitelists for developer subnets, whitelisting approved developers' user accounts, and limit alerting to general administration or non-technical business zones.


* **Problem 2: API Request Size Limitations**
* *The Issue:* Attackers can break files into small chunks and exfiltrate them in small volumes over time, causing individual connection alerts to be dismissed as standard repository synchronizations.
* *The Fix:* Implement threshold-based alerting in the SIEM that triggers if a single workstation uploads a cumulative volume exceeding 50 MB of data to repository domains within a 10-minute window.


* **Problem 3: Use of Unofficial CDNs / Hosting Providers**
* *The Issue:* Attackers can upload data using unofficial CDNs (like static file hosting or caching CDNs) that are not matched by the hardcoded domain strings.
* *The Fix:* Implement SSL decryption to check URL request headers and verify that API tokens match corporate-authorized developer profiles.
