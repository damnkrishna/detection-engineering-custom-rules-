### **1. Technique Breakdown: T1567.002**

* **What it is:** **Exfiltration Over Web Service: Exfiltration to Cloud Storage**. Adversaries exfiltrate data by uploading it directly to public cloud storage providers (such as Mega, Dropbox, OneDrive, Azure Blob, or AWS S3) using command-line synchronization tools (like `rclone.exe`, `megacmd.exe`) or administrative CLI tools (`aws.exe`, `az.exe`). Because cloud storage domains are frequently accessed for legitimate business, these connections are rarely blocked at the perimeter. Host-based process creation and command line parameters are critical to spot these unauthorized tools.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing cloud sync clients and CLI commands.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 records the execution of cloud clients (like `rclone.exe`) along with sync/copy arguments. Wazuh parses and alerts.
    * **NIDS (Suricata + Zeek): YES.** Network logs track large data transfers to cloud service provider domains, but host logs are needed to verify the specific application context.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of command-line cloud sync clients or public cloud provider CLI engines commonly abused for automated exfiltration.

```yaml
title: Exfiltration - Command-Line Cloud Storage Sync Execution (AN1571)
id: 1aac8ec3-0ce5-4498-91da-b1a9f6e59ccc
status: experimental
description: Detects the execution of command-line cloud synchronization tools (like rclone, megacmd) or cloud provider CLI platforms (AWS, Azure) transferring files, indicating potential exfiltration.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_utilities:
        - Image|endswith:
            - '\rclone.exe'
            - '\mega-cmd.exe'
            - '\mega.exe'
            - '\MegaSync.exe'
            - '\aws.exe'
            - '\az.exe'
            - '\gsutil.exe'
        - OriginalFileName:
            - 'rclone.exe'
            - 'mega-cmd.exe'
            - 'mega.exe'
            - 'MegaSync.exe'
            - 'aws.exe'
            - 'az.exe'
            - 'gsutil.py'
    selection_sync_commands:
        CommandLine|contains:
            - ' sync '
            - ' copy '
            - ' upload '
            - ' s3 cp '
            - ' blob upload '
    condition: selection_utilities and selection_sync_commands
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - IT administrators using rclone or cloud CLIs to manage system backups or sync server repositories to enterprise cloud storage.
level: high
tags:
    - attack.exfiltration
    - attack.t1567.002
    - analytics.an1571
    - detection.det0570
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Renamed Utilities**
    * *The Issue:* Attackers routinely rename `rclone.exe` to a generic system utility name (like `svchost.exe` or `update.exe`) to bypass process name signature filters.
    * *The Fix:* Complement this rule by checking the `OriginalFileName` PE header attribute (which remains `rclone.exe` even if the file is renamed) or alerting on any non-standard process making high-volume network socket writes to cloud storage networks.

* **Problem 2: Native Business Sync Tools (OneDrive/SharePoint/Dropbox)**
    * *The Issue:* Enterprise endpoints routinely run OneDrive or Dropbox clients to sync local folders, generating massive amounts of sync traffic. Distinguishing malicious sync from standard operations is difficult.
    * *The Fix:* Baseline the standard enterprise sync locations, and restrict folder creation rights to OneDrive system directories. Alert on rclone or mega sync clients connecting from developer systems.

* **Problem 3: Scripted Web Browser Automations**
    * *The Issue:* If the attacker uses headless browser automation (like Selenium or Playwright) or runs Python scripts with requests libraries to interact directly with the Mega or Dropbox APIs without running their dedicated CLI tools, this process check will see nothing.
    * *The Fix:* Monitor network sockets (Event ID 3) for unexpected scripting engine binaries connecting directly to cloud API IP ranges (like Mega/Dropbox API servers).
