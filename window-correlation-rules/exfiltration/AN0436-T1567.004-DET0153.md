### **1. Technique Breakdown: T1567.004**

* **What it is:** **Exfiltration to Code Repository: Exfiltration Over Webhook**. Adversaries exfiltrate stolen data by posting it directly to public webhook receivers (such as Discord, Slack, or webhook.site). They configure local scripts (e.g., PowerShell or curl) to execute HTTP POST requests containing file payloads targeting the webhook URLs. Because webhook platforms are legitimate and use standard port 443 HTTPS connections, they successfully bypass network boundary controls.
* **Log Source Requirements:** Endpoint network connection logs (Sysmon Event ID 3) or DNS queries (Sysmon Event ID 22), combined with requesting process metadata.
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 3 logs outbound network connections containing destination hostnames and the initiating application path. Wazuh forwards these to trigger alerts.
* **NIDS (Suricata + Zeek): YES.** Zeek `ssl.log` and `http.log` record SSL/TLS SNI negotiations and HTTP methods targeting webhook services.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 3 (Network Connection)** to detect command-line interpreters, scripting hosts, or file transfer tools initiating network connections to known webhook receiver domains.

```yaml
title: Outbound Data Exfiltration via Webhooks (AN0436)
id: 5776895d-a51a-453f-95ca-e0e3611ca031
status: experimental
description: Detects command-line interpreters, scripting hosts, or file transfer tools initiating network connections or DNS queries to known webhook receiver domains (e.g., Discord, Slack, Webhook.site), which may indicate data exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3 collected via Wazuh
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\curl.exe'
    selection_domains:
        DestinationHostname|contains:
            - 'webhook.site'
            - 'hooks.slack.com'
            - 'discord.com'
            - 'discordapp.com'
        CommandLine|contains:
            - 'webhooks'
            - 'webhook'
    condition: selection_process and selection_domains
fields:
    - CommandLine
    - DestinationHostname
    - Image
falsepositives:
    - Legitimate administrative scripts sending automated system notifications to Slack channels.
level: high
tags:
    - attack.exfiltration
    - attack.t1567.004
    - analytics.an0436
    - detection.det0153
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Use of Custom/Private Webhook endpoints**
* *The Issue:* Attackers can host their own webhook receiver server on a private cloud VPS, meaning the destination domain will not match the public lists of Discord, Slack, or webhook.site, bypassing static filters.
* *The Fix:* Complement this rule with detections that monitor any unexpected scripting hosts initiating network connections to external IP addresses that are not in the local system baseline, and monitor execution of scripts downloading files.


* **Problem 2: API Request Obfuscation**
* *The Issue:* Attackers can base64-encode or encrypt the exfiltrated data within HTTP headers or custom parameters, preventing perimeter gateway DLP from reading the payload.
* *The Fix:* Enable SSL/TLS decryption on the proxy gateway to inspect HTTP POST request body sizes, and flag connections transmitting large files to dynamic API endpoints.


* **Problem 3: IT Notification Script Noise**
* *The Issue:* Legitimate IT monitoring scripts routinely post system status notifications or warning flags to corporate Slack channels, generating false positives.
* *The Fix:* Whitelist approved service accounts, statically define approved IT webhook destination URLs, and alert on any usage of non-standard webhook sites (like `webhook.site`).
