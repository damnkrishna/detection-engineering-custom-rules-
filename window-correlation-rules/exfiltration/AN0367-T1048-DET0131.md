### **1. Technique Breakdown: T1048**

* **What it is:** **Exfiltration Over Alternative Protocol**. Adversaries exfiltrate collected data over a protocol different from the primary C2 channel. Typical alternative protocols include FTP, SMTP (email), external SMB shares, or DNS queries. By using these protocols, attackers bypass standard web proxy/HTTPS controls. Detections target scripting interpreters or system utilities initiating connections over ports associated with these protocols.
* **Log Source Requirements:** Endpoint network connection logs (Sysmon Event ID 3 / Windows Security Event ID 5156) containing destination ports, destination IPs, and initiating processes.
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 3 logs the target IP address, destination port, and calling process name. Wazuh correlates these to alert on outbound network traffic anomalies.
* **NIDS (Suricata + Zeek): YES.** Zeek `conn.log` and protocol-specific logs (`ftp.log`, `smtp.log`) record external handshakes and data lengths.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 3 (Network Connection)** to detect outbound connections over alternative data protocols (FTP, SMTP, external SMB) initiated by execution shells and scripting hosts.

```yaml
title: Outbound Alternative Protocol Exfiltration via CLI (AN0367)
id: cc4f5f9b-2419-4d52-83b2-ae81cd20122c
status: experimental
description: Detects command line tools or scripting engines initiating outbound network connections over alternative protocols such as FTP (21), SMTP (25/587), or external SMB (445).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3 collected via Wazuh
detection:
    selection_process:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\rundll32.exe'
            - '\wscript.exe'
            - '\cscript.exe'
    selection_ports:
        DestinationPort:
            - 21  # FTP
            - 25  # SMTP
            - 465 # SMTPS
            - 587 # SMTP Submission
            - 445 # SMB
    filter_local_smb:
        # Filter out local SMB connections to private subnets
        DestinationIp|startswith:
            - '10.'
            - '192.168.'
            - '172.16.'
            - '172.17.'
            - '172.18.'
            - '172.19.'
            - '172.2'
            - '172.3'
            - '127.'
            - 'fe80:'
            - '::1'
    condition: selection_process and selection_ports and not filter_local_smb
fields:
    - DestinationIp
    - DestinationPort
    - Image
falsepositives:
    - Legitimate administrative scripts sending automated email alerts (SMTP) or connecting to external vendor FTP servers.
level: high
tags:
    - attack.exfiltration
    - attack.t1048
    - analytics.an0367
    - detection.det0131
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: DNS Tunneling Exfiltration Bypass**
* *The Issue:* Attackers can encode exfiltrated data inside DNS subdomains (e.g. `query.<encoded_data>.maliciousdomain.com`) and send queries over port 53. Because port 53 is open to the corporate DNS server, the DNS server forwards the query to the attacker's external authoritative server, exfiltrating the data. This bypasses destination port filters since the endpoint only talks to the local DNS server on standard DNS ports.
* *The Fix:* Complement this rule with DNS query length and volume anomaly analysis, flagging processes generating high volumes of TXT/NULL record queries or queries with high string length and entropy.


* **Problem 2: Tunneling alternative protocols over HTTPS**
* *The Issue:* Attackers can wrap alternative protocol payloads (like FTP commands or custom file transfers) within standard HTTPS POST requests (port 443) targeting their server, rendering port-based filters ineffective.
* *The Fix:* Enable SSL/TLS decryption on the perimeter gateway and monitor HTTP request header patterns, and alert on non-browser processes communicating with unclassified external IPs.


* **Problem 3: Administrative Script SMTP Alerts Noise**
* *The Issue:* Network monitoring scripts and automated agents routinely send status email notifications to external services using SMTP ports.
* *The Fix:* Baseline and whitelist approved administrative servers allowed to send outbound email alerts, or restrict alerting to standard workstation zones.
