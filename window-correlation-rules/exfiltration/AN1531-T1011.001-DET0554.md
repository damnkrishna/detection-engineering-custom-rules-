### **1. Technique Breakdown: T1011.001**

* **What it is:** **Exfiltration Over Physical Medium: Bluetooth-Based Data Exfiltration**. Adversaries exfiltrate data from a compromised host to a nearby rogue device (such as a smartphone or laptop) over Bluetooth, bypassing corporate network egress monitoring. On Windows systems, this is typically facilitated using the native Bluetooth File Transfer wizard executable, **`fsquirt.exe`**, or by utilizing command-line tools that interact with Bluetooth APIs.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) auditing user execution of Bluetooth transfer wizards.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process creations, including the path and name of `fsquirt.exe`. Wazuh tracks this event to alert on execution.
    * **NIDS (Suricata + Zeek): NO.** Network security appliances monitor IP network interfaces and cannot audit local Bluetooth radio frequencies.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of the native Windows Bluetooth File Transfer utility (`fsquirt.exe`) which may indicate an attempt to exfiltrate data over a Bluetooth connection.

```yaml
title: Exfiltration - Bluetooth File Transfer Wizard Execution (AN1531)
id: 91c53271-ac89-4ef9-b56a-aa7dcdb1d3cc
status: experimental
description: Detects execution of the native Windows Bluetooth File Transfer Wizard (fsquirt.exe), which can be abused by insiders or threat actors to copy data to nearby mobile devices or laptops.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_process:
        - Image|endswith:
            - '\fsquirt.exe'
        - OriginalFileName:
            - 'fsquirt.exe'
    condition: selection_process
fields:
    - Image
    - OriginalFileName
falsepositives:
    - Legitimate user transferring business files to an authorized corporate mobile device over Bluetooth.
level: high
tags:
    - attack.exfiltration
    - attack.t1011.001
    - analytics.an1531
    - detection.det0554
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Bluetooth Dongle Driver Installation**
    * *The Issue:* If the target system does not have built-in Bluetooth hardware, the attacker must insert a USB Bluetooth dongle first. If the dongle setup driver runs automatically, simply checking for `fsquirt.exe` will miss the device installation phase.
    * *The Fix:* Complement this rule with device installation logging audits (System Event Log Event ID 20001) looking for class `Bluetooth` or matching driver profiles.

* **Problem 2: Execution via Third-Party Bluetooth Managers**
    * *The Issue:* Many hardware vendors (e.g. Intel, Broadcom, Realtek) install custom Bluetooth dashboard software which does not call `fsquirt.exe` for file transfers, bypassing this process-based check.
    * *The Fix:* Add monitoring for processes launched out of vendor Bluetooth installation paths (e.g., `C:\Program Files\Intel\Bluetooth\`) that access local user documents.

* **Problem 3: Standard User convenience transfers (Photos/Contacts)**
    * *The Issue:* Users routinely transfer personal files (e.g., photos or slide decks) between their phones and laptops, causing benign alerts.
    * *The Fix:* Restrict Bluetooth capabilities via Group Policy (GPO) (disabling the `BthServ` service) and treat any execution of `fsquirt.exe` on production/sensitive workstations as a policy violation.
