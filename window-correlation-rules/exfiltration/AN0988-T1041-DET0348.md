### **1. Technique Breakdown: T1041**

* **What it is:** **Exfiltration Over C2 Channel**. Adversaries exfiltrate stolen data by transmitting it directly through their existing command-and-control (C2) communication channel. This avoids establishing new outbound network connections that might trigger perimeter firewall alerts. Host-local detection involves identifying suspicious processes running from non-standard folders (like temp paths, user profile folders) or running as hidden services initiating network connections (Sysmon Event ID 3) and transmitting large payloads.
* **Log Source Requirements:** Sysmon network connection logs (Event ID 3) combined with initiating process metadata (Sysmon Event ID 1).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 3 logs outbound network connections along with the initiating application's file path. Wazuh aggregates these and alerts on connections from high-risk paths.
    * **NIDS (Suricata + Zeek): YES.** Network monitoring can track anomalous traffic volume spikes or beaconing behavior targeting C2 endpoints.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 3 (Network Connection)** to detect processes executing from suspicious or writeable paths (like Temp, AppData, or Public directories) initiating outbound network connections, which may indicate active C2 data exfiltration.

```yaml
title: Exfiltration - Outbound Network Connection from Suspicious Path (AN0988)
id: 55b5d20c-f8f1-4ac6-aff5-af97498c8992
status: experimental
description: Detects processes executing from temp, user appdata, or public directories initiating outbound TCP/UDP connections to external networks, which could indicate data exfiltration over a C2 channel.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3 collected via Wazuh
detection:
    selection_path:
        Image|contains:
            - '\AppData\Local\Temp\'
            - '\Windows\Temp\'
            - '\Users\Public\'
            - '\PerfLogs\'
    filter_internal:
        DestinationIp|startswith:
            - '10.'
            - '192.168.'
            - '172.16.'
            - '172.17.'
            - '172.18.'
            - '172.19.'
            - '172.2'
            - '172.3'
            - '127.'
            - '169.254.'
    condition: selection_path and not filter_internal
fields:
    - DestinationIp
    - Image
falsepositives:
    - Legitimate software auto-updaters (running out of AppData\Local\Temp) downloading application updates.
    - User-run portable applications initiating connections for sync or updates.
level: high
tags:
    - attack.exfiltration
    - attack.t1041
    - analytics.an0988
    - detection.det0348
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Updaters executing from Temp directories (Noise)**
    * *The Issue:* Web browsers (like Chrome/Firefox) or video tools (like Zoom) dynamically drop updaters to `%TEMP%` and download update payloads, generating high rates of false alarms.
    * *The Fix:* Add code-signature validation checks (exclude signed processes from verified software vendors like Google, Mozilla, or Microsoft) or build specific exclusions for known updater names.

* **Problem 2: Sideloaded DLLs in System Folders**
    * *The Issue:* If the C2 agent runs as a sideloaded DLL inside a legitimate system process (e.g. loading a malicious `input.dll` inside `explorer.exe`), the path of the process is `C:\Windows\explorer.exe`, which bypasses the suspicious path check.
    * *The Fix:* Complement this rule by monitoring DLL loads (Sysmon Event ID 7) in system processes and alert on unsigned DLLs loaded from user-writeable paths.

* **Problem 3: Use of Windows System Binaries (LOLBins)**
    * *The Issue:* Attackers can use native utilities (like `bitsadmin.exe` or `certutil.exe`) located in `C:\Windows\System32\` to run transfers. Since the tool is in a secure directory, it will not match the Temp path criteria.
    * *The Fix:* Write specific detection rules checking for LOLBin network actions (e.g. certutil making network connections to external IPs).
