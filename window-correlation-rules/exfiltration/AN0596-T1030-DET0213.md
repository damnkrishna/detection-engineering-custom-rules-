### **1. Technique Breakdown: T1030**

* **What it is:** **Data Transfer Size Limits**. Adversaries bypass data threshold alerts or network monitoring controls (DLP) by dividing large staged archives into smaller, chunked volumes prior to exfiltration. They use compression utilities (like `7z`, `rar`, or `zip`) configured with volume split size arguments (e.g. `-v10m`) or run scripting commands (like PowerShell or python file-reading loops) that read files in binary chunks and write them as split assets.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing command-line arguments.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs the full command-line parameters of execution events, letting security teams inspect flags like `-v` (for 7z split volume sizes).
    * **NIDS (Suricata + Zeek): PARTIAL.** Network logs can detect repeated outbound transfers of identical sizes (chunking behavior), but lack process context.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of compression utilities or command tools with flags indicating multi-volume splitting or chunked file generation.

```yaml
title: Exfiltration - File Compression and Volume Splitting (AN0596)
id: 3c6c5d9e-da5b-4a86-ba1f-6a3104f584db
status: experimental
description: Detects command-line parameters of compression utilities (like 7z, rar) or scripting engines indicating volume-based file splitting or chunking prior to outbound transmission.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_7z:
        Image|endswith:
            - '\7z.exe'
            - '\7za.exe'
            - '\rar.exe'
            - '\zip.exe'
        CommandLine|contains:
            - ' -v' # 7z / rar split volume flag (e.g. -v10m, -v500k)
    selection_scripting:
        CommandLine|contains:
            - '[System.IO.File]::OpenRead'
            - 'ReadCount'
            - 'split -b' # Linux-style split commands ported to Windows
            - ' -split '
    condition: selection_7z or selection_scripting
fields:
    - CommandLine
    - Image
falsepositives:
    - IT administrators packaging large system backup dumps or log files to send to vendor support portals.
    - Software developer build scripts packaging native binaries for release.
level: medium
tags:
    - attack.exfiltration
    - attack.t1030
    - analytics.an0596
    - detection.det0213
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: GUI-Based Compression**
    * *The Issue:* If the attacker uses the graphical user interface of WinRAR or 7-Zip to split and compress archives, the command line parameters may not show the specific flags because the action is handled internally via DLL operations inside the GUI process thread.
    * *The Fix:* Complement this rule by monitoring for high-frequency file creation events (Sysmon Event ID 11) where multiple sequentially-numbered files (e.g., `archive.7z.001`, `archive.7z.002`) are written by the same process in a short window.

* **Problem 2: Execution via Custom Compiled Binaries**
    * *The Issue:* If the attacker writes a custom, compiled C# utility that opens files and splits them into chunks without using known names (like `7z.exe` or PowerShell cmdlets), standard process name/string filters fail.
    * *The Fix:* Scope anomalies to detect high-frequency file reads from sensitive data directories followed by write operations to temporary paths.

* **Problem 3: Standard Backup Automation scripts**
    * *The Issue:* Legitimate enterprise backup products routinely split system backup images (such as `.vmdk` or `.vhdx` files) into multi-gigabyte chunks, causing heavy alerting.
    * *The Fix:* Add exclusions for authorized backup software account credentials, and filter out target file paths that are verified backup shares.
