### 1. Technique Breakdown: T1567.003

* What it is: Exfiltration to Code Repository: Exfiltration to Text Storage Sites. Adversaries exfiltrate sensitive files or credentials by uploading their content as plain text snippets to public paste bins (such as Pastebin, Hastebin, or Ghostbin) where text can be hosted anonymously. Malware scripts read the target files (e.g., configurations, database dumps) and send HTTP POST/PUT requests transmitting the data. Because paste bins are popular and use standard port 443 HTTPS connections, they successfully bypass network inspection.
* Log Source Requirements: Endpoint network connection logs (Sysmon Event ID 3) or DNS queries (Sysmon Event ID 22), combined with requesting process metadata.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 3 logs outbound connection hostnames and the initiating application path. Wazuh aggregates and evaluates these connections.
* NIDS (Suricata + Zeek): YES. Zeek `ssl.log` and `http.log` record SSL/TLS SNI negotiations and HTTP methods targeting paste sites.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 3 (Network Connection) to detect command-line interpreters, scripting hosts, or file transfer tools initiating network connections to known public paste and text storage domains.

```yaml
title: Outbound Data Exfiltration to Paste Sites via CLI (AN0787)
id: aaee7d8e-1a7e-4867-932a-9462b39a6970
status: experimental
description: Detects command-line interpreters, scripting hosts, or file transfer tools initiating network connections or DNS queries to known paste sites (e.g., Pastebin, Hastebin), which may indicate data exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\curl.exe'
    selection_domains:
        DestinationHostname|contains:
            - 'pastebin.com'
            - 'hastebin.com'
            - 'ghostbin.co'
            - 'paste.ee'
            - 'controlc.com'
    condition: selection_process and selection_domains
fields:
    - Image
    - CommandLine
    - User
    - LogonId
    - Initiated
    - SourceIp
    - DestinationIp
    - DestinationPort
:
    - Highly unlikely in standard enterprise environments. Some administration scripts may query paste sites for update configs, but this is a discouraged practice.
level: high
tags:
    - attack.exfiltration
    - attack.t1567.003
    - analytic.an0787
    - detection.det0284
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Dynamic Client IP Range
  * The Issue: Legitimate client processes communicating with external SaaS platforms can generate massive outbound log volumes.
  * The Fix: Baseline client egress destinations, restricting alerts to network connections initiated by execution shells or scripting hosts.

* Problem 2: Encrypted Payload Blind Spots
  * The Issue: Standard port monitoring cannot inspect encrypted TLS/HTTPS payload contents, leaving C2 beaconing undetected.
  * The Fix: Analyze TLS handshake metadata (specifically SNI domain names) and calculate connection frequency or beaconing heuristics.

* Problem 3: Proxy and Gateway Redirection
  * The Issue: Outbound connections routed through internal proxy servers will report the proxy IP as destination, masking the target C2 server.
  * The Fix: Correlate client endpoint process logs with proxy server access logs to resolve the true external destination IP.
