### **1. Technique Breakdown: T1029**

* **What it is:** **Scheduled Transfer**. Adversaries schedule data exfiltration to align with normal business hours or system maintenance windows, making their transfers less noticeable. This is typically implemented via Windows Scheduled Tasks executing script blocks or command utilities (such as `curl.exe`, `powershell.exe`) that initiate file transfers to remote destinations.
* **Log Source Requirements:** Endpoint logs capturing process creation and parent process context (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process spawning by the Task Scheduler engine (`taskeng.exe` or `svchost.exe` hosting Task Scheduler) with full command line parameters.
* **NIDS (Suricata + Zeek): YES (Partial).** Network monitors can identify periodic connection check-ins (beaconing), but host logs are required to confirm the connection originated from a scheduled process.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line file transfer utilities or scripts executing download/upload parameters that are spawned by the Windows Task Scheduler.

```yaml
title: Scheduled File Transfer via CLI (AN1118)
id: a194e271-3ef2-4e0b-8939-a8477d274509
status: experimental
description: Detects command-line execution of file transfer commands or scripting hosts spawned by task schedulers, which may indicate scheduled exfiltration attempts.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_parent:
        ParentImage|endswith:
            - '\taskeng.exe'
            # Windows Task Scheduler engine processes
    selection_cmd:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\curl.exe'
    selection_args:
        CommandLine|contains:
            - 'curl'
            - 'wget'
            - 'UploadFile'
            - 'ftp'
            - 'sftp'
            - 'scp'
            - 'Invoke-WebRequest'
            - 'Invoke-RestMethod'
    condition: selection_parent and selection_cmd and selection_args
fields:
    - CommandLine
    - Image
    - ParentImage
falsepositives:
    - Legitimate enterprise synchronization scripts, monitoring tools, or software update check-ins.
level: medium
tags:
    - attack.exfiltration
    - attack.t1029
    - analytics.an1118
    - detection.det0399
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Modern Windows Task Scheduler Engine Parentage**
* *The Issue:* On modern Windows systems, task scheduling is managed directly by a specific instance of `svchost.exe` rather than the legacy `taskeng.exe`. Since many services run under `svchost.exe`, simple parent checks on `taskeng.exe` will fail on modern endpoints, while checking `svchost.exe` globally causes heavy false alarms.
* *The Fix:* Enable Task Scheduler operational logging (Event ID 4698: A scheduled task was created, and Event ID 200/201 in the TaskScheduler log: Action started/completed) to audit the registration and execution of tasks directly.


* **Problem 2: Execution via Service Injection / WMI Triggers**
* *The Issue:* Attackers can schedule transfers using alternative triggers, such as WMI Event Subscriptions (which execute under `WmiPrvSe.exe`) or registering temporary system services (running under `services.exe`), which bypasses Task Scheduler parenting checks.
* *The Fix:* Complement this rule with detections for WMI bindings and monitor services executing scripts or network connections.


* **Problem 3: Standard IT Update Sync Noise**
* *The Issue:* Legacy enterprise automation tools regularly schedule scripts to run on domain controllers and administrative systems to pull configurations, causing false positives.
* *The Fix:* Restrict this alert to standard workstation subnets, whitelisting administrative servers.
