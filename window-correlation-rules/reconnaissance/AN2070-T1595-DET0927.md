### 1. Technique Breakdown: T1595
* What it is: Active Scanning. Adversaries scan the target organization's public networks to detect open ports, active services, vulnerabilities, and system details. This is an active probe that directly touches the boundary interfaces.
* Log Source Requirements: Firewall and Network IDS logs capturing connection metrics.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): NO. Local host logs do not capture boundary network probes.
  - NIDS (Suricata + Zeek): YES. Zeek dns/http/ssl and Suricata port scan alerts.
* Log Sources Covered:
  - Network IDS logs (Zeek/Suricata) (product: network, service: connection)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

Detects rapid connection bursts to multiple distinct ports from a single external IP address.

```yaml
title: External Port Scanning Detection (AN2070)
id: c1d2e3f4-a5b6-4c7d-8e9f-0a1b2c3d4e5f
status: experimental
description: Detects connection sweeps and port scans against external assets originating from single or multiple IP sources, handling distributed and low-and-slow scanning profiles while whitelisting common public search engines.
author: Krishna Gupta
date: 2026-06-30
logsource:
    product: zeek
    service: conn
detection:
    selection:
        orig_h: '*'  # Source IP
        resp_h: '*'  # Target IP
        proto: 'tcp'
        
    # Fast scan: many ports in short window
    fast_scan:
        selection | count(resp_p) by orig_h > 15 in 60s
        
    # Slow scan: many ports over day
    slow_scan:
        selection | count(resp_p) by orig_h > 50 in 1d
        
    # Distributed scan: many IPs targeting same subnet
    distributed_scan:
        selection | count(orig_h) by resp_h_cidr(/24) > 5 in 60s
    
    filter_legitimate:
        src_ip|cidr:
            - '1.2.3.0/24'      # Censys
            - '4.5.6.0/24'      # Shodan
        or user_agent|contains:
            - 'Shodan'
            - 'Censys'
            - 'nmap'
    
    filter_internal:
        orig_h|cidr: '10.0.0.0/8'  # Internal scans OK
        
    condition: (fast_scan or slow_scan or distributed_scan) and not filter_legitimate and not filter_internal
fields:
    - orig_h
    - resp_h
    - resp_p
    - proto
falsepositives:
    - Authorized internal diagnostic vulnerability scanners.
level: high
tags:
    - attack.reconnaissance
    - attack.t1595
    - analytic.an2070
    - detection.det0927
```

### 2.2 Multi-Stage Correlation Rule: Port Scanning Followed by Connection Attempt / Exploitation

This correlation rule tracks when an external IP address performs port scanning (AN2070) and subsequently establishes a successful socket connection to one of the scanned ports, followed by command execution on the target host within 15 minutes.

```yaml
title: Port Scan Followed by Active Connection and Command Execution (AN2070-Correlation)
id: e1d2e3f4-a5b6-4c7d-8e9f-0a1b2c3d4e5f
status: experimental
description: Correlates initial active scanning with a successful connection handshake and subsequent process execution anomalies on the same target host.
correlation:
    type: temporal
    rules:
        - rule_1: External Port Scanning Detection (AN2070)
        - rule_2: Successful Socket Connection and Sysmon Process Spawning
    group-by:
        - orig_h
        - resp_h
    timespan: 15m
    condition: rule_1 then rule_2 and rule_1.resp_h == rule_2.Computer
level: critical
tags:
    - attack.reconnaissance
    - attack.t1595
    - attack.execution
```

### 3. Blind Spots & Tuning (The "Problems")
* Problem 1: Distributing Scanning
  * The Issue: Red Teams use proxy chains or botnets to scan using multiple IPs.
  * The Fix: Group alerts based on target subnets rather than only single source IPs.
* Problem 2: Slow Scanning
  * The Issue: Scanners check one port per hour (Low and Slow).
  * The Fix: Extend correlation windows to 24 hours.
* Problem 3: Common Cloud Probes
  * The Issue: Internet scanners continuously scan the IP ranges causing high alert volume.
  * The Fix: Ignore scanning from known threat feeds (e.g. Censys, Shodan, Shadowserver) if they are not targeting sensitive systems.
