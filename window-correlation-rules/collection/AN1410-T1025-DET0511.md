### **1. Technique Breakdown: T1025**

* **What it is:** **Data from Removable Media**. Adversaries search for and collect sensitive data stored on removable media devices (such as USB flash drives, external hard drives, or portable media) connected to the compromised host. They utilize scripting engines, command-line utilities (like `xcopy.exe` or `robocopy.exe`), or compression software to automate copying files from these mounted volumes (typically assigned letters like `D:\`, `E:\`, `F:\`, or `G:\` on Windows systems) to local staging folders before exfiltration.
* **Log Source Requirements:** Windows Security Event Log Event ID 4688 or Sysmon process creation logs (Event ID 1) capturing copy utility execution targeting removable drive letters.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process details, capturing command lines copying or compressing files from non-system partition drive letters.
    * **NIDS (Suricata + Zeek): NO.** Removable media access is a local hardware and file-system operation.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command line utilities or scripts targeting common removable media drive letters (`D:\`, `E:\`, `F:\`, `G:\`) to copy or compress files.

```yaml
title: Collection - Data Access and Copy from Removable Media (AN1410)
id: 303d498e-8b55-40be-9148-e3bf8fe22803
status: experimental
description: Detects command-line copy utilities, compression engines, or scripting environments targeting files stored on removable media drive letters, indicating unauthorized data collection.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_utilities:
        - Image|endswith:
            - '\xcopy.exe'
            - '\robocopy.exe'
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\7z.exe'
            - '\tar.exe'
        - OriginalFileName:
            - 'xcopy.exe'
            - 'robocopy.exe'
            - 'cmd.exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
            - '7z.exe'
            - 'tar.exe'
    selection_removable_drives:
        CommandLine|contains:
            - ' D:\'
            - ' E:\'
            - ' F:\'
            - ' G:\'
            - ' H:\'
    condition: selection_utilities and selection_removable_drives
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - IT administrators or users copying personal files or running local script backups from their authorized external drives.
level: medium
tags:
    - attack.collection
    - attack.t1025
    - analytics.an1410
    - detection.det0511
```

### OCSF Normalized
```xml
title: Collection - Data Access and Copy from Removable Media (OCSF-Normalized)
id: 303d498e-8b55-40be-9148-e3bf8fe22803
status: experimental
description: Detects copying from removable media drive paths, mapped to OCSF process_activity.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: system
    product: ocsf
    class: process_activity
detection:
    # Based on OCSF mapping, process path is process.file.path and cmd line is process.cmd_line
    selection_utilities:
        process.file.path|endswith:
            - '\xcopy.exe'
            - '\robocopy.exe'
            - '\cmd.exe'
            - '\powershell.exe'
    selection_removable:
        process.cmd_line|contains:
            - ' D:\'
            - ' E:\'
            - ' F:\'
            - ' G:\'
    condition: selection_utilities and selection_removable
fields:
    - process.cmd_line
    - process.file.path
falsepositives:
    - User file backup or deployment from external drives.
level: medium
tags:
    - attack.collection
    - attack.t1025
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Alternate Removable Drive Letters**
    * *The Issue:* Removable drives can be mounted with drive letters other than `D:` through `H:` (e.g. `X:` or `Z:`), causing the rule to miss copy operations targeting those partitions.
    * *The Fix:* Correlate process actions with system mount logs (Event ID 4624 / 4688 logon/mount sessions, or Event ID 6416 USB device insertion) to dynamically trace the active removable drive letter.

* **Problem 2: Interactive Explorer Copies**
    * *The Issue:* If the user or adversary drags and drops files from a USB drive to a local folder using Windows Explorer, no process command line arguments containing `D:\` or `E:\` will be generated.
    * *The Fix:* Enable file creation audit logging (Sysmon Event ID 11 or Windows Security Event ID 4663) and alert when high-volume files are created locally by `explorer.exe` with a source path on a removable partition.

* **Problem 3: Standard User Activity (Noise)**
    * *The Issue:* Employees copy documents to/from USB drives regularly for work, resulting in frequent alerts.
    * *The Fix:* Implement USB block or read-only policies using Group Policy, and whitelist approved/encrypted enterprise USB device signatures where allowed.
