### **1. Technique Breakdown: T1560.001**

* **What it is:** **Archive Collected Data: Archive via Utility**. Adversaries compress and package staged data using common archive utilities (such as `7-Zip`, `WinRAR`, or native system tools like `tar.exe` or PowerShell `Compress-Archive` cmdlets) prior to exfiltration. Archiving data reduces payload size for transit and can encrypt contents to bypass content inspection controls (DLP). Detection focuses on identifying command lines invoking archiving commands against sensitive directory structures (like user profiles or web roots).
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing command-line parameters.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 provides full command-line arguments, letting security teams audit parameters like `7z.exe a` or `tar.exe -cf`. Wazuh parses these logs.
    * **NIDS (Suricata + Zeek): NO.** Network sensors have no visibility into local command execution or local file system archiving.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of compression utilities or scripting cmdlets with arguments for archiving data.

```yaml
title: Collection - Data Archiving via Utility (AN0831)
id: 1f1ae6a4-b43f-4a79-a08b-b17609983fe5
status: experimental
description: Detects command-line parameters of compression utilities (such as 7z, rar, tar) or PowerShell archiving cmdlets (Compress-Archive) indicating data packaging, typically prior to exfiltration.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_utilities:
        - Image|endswith:
            - '\7z.exe'
            - '\7za.exe'
            - '\rar.exe'
            - '\winrar.exe'
            - '\tar.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - '7z.exe'
            - '7za.exe'
            - 'Rar.exe'
            - 'tar.exe'
    selection_args:
        CommandLine|contains:
            - ' a '       # 7z/Rar add to archive
            - ' -cf '     # tar create file
            - ' -cvf '    # tar verbose create file
            - 'Compress-Archive'
    condition: selection_utilities and selection_args
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Standard administrative backup scripts archiving logs or database files.
    - Software developers creating distribution packages.
level: medium
tags:
    - attack.collection
    - attack.t1560.001
    - analytics.an0831
    - detection.det0298
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: GUI-Based Archiving**
    * *The Issue:* If the user runs the graphical interface of WinRAR or 7-Zip (double-clicking the application icon and using drag-and-drop), the command line arguments will not show the specific flags because the action is handled internally via graphical UI handlers, bypassing cmdline checks.
    * *The Fix:* Complement this rule by monitoring for high-frequency file creation events (Event ID 11) where multiple sequentially-numbered files or files ending in `.zip` are written.

* **Problem 2: Execution of Renamed Binaries**
    * *The Issue:* Attackers can rename `7z.exe` to a generic system utility name (like `sc.exe`) to bypass process name signature filters.
    * *The Fix:* Add checks matching the `OriginalFileName` PE header attribute (which remains `7z.exe` even if the file is renamed).

* **Problem 3: Standard user manual compression (Local folders)**
    * *The Issue:* Users naturally zip folders on their desktop daily to email them, generating heavy false alarms.
    * *The Fix:* Tune the rule to focus alerts on actions targeting critical server paths (e.g. database directories, web root paths) or ignore executions spawned directly by `explorer.exe` (user interactive context).
