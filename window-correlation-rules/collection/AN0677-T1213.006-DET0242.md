### **1. Technique Breakdown: T1213.006**

* **What it is:** **Databases**. Adversaries target database systems to collect sensitive information stored in structured data stores — such as customer records, financial data, credentials, or intellectual property. On Windows, they use database client tools (`sqlcmd.exe`, `isql.exe`, `osql.exe`, `bcp.exe`, `mysql.exe`) to query databases and export results, often initiated from unexpected parent processes like `cmd.exe`, `powershell.exe`, or `explorer.exe`. The exported data is typically written to `.csv`, `.sql`, or `.bak` dump files in user temp directories, and may subsequently be compressed and exfiltrated.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing database client tool invocations with unusual parent processes or output redirection to temp directories.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures `sqlcmd.exe`, `bcp.exe`, and `mysql.exe` executions with full command-line arguments including connection strings and output file paths.
    * **NIDS (Suricata + Zeek): PARTIAL.** Database connections to local or remote SQL servers (ports 1433, 3306) can be detected at the network level, but the content of SQL queries and exported data requires host-based monitoring for attribution.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect database client tools (`sqlcmd.exe`, `bcp.exe`, `osql.exe`, `mysql.exe`) executed by shell or scripting parent processes, or with output redirection to staging directories.

```yaml
title: Suspicious Database Client Execution for Data Collection (AN0677)
id: a101c2ec-d38f-4b32-8240-eecfec02baad
status: experimental
description: Detects database client tools (sqlcmd, bcp, osql, mysql) launched by unexpected parent processes or with output directed to temp/user directories, indicating adversarial database collection.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_db_clients:
        - Image|endswith:
            - '\sqlcmd.exe'
            - '\bcp.exe'
            - '\osql.exe'
            - '\isql.exe'
            - '\mysql.exe'
            - '\mysqldump.exe'
        - OriginalFileName:
            - 'sqlcmd.exe'
            - 'bcp.exe'
            - 'osql.exe'
            - 'isql.exe'
            - 'mysql.exe'
            - 'mysqldump.exe'
    selection_suspicious_parent:
        ParentImage|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\explorer.exe'
    selection_output_to_temp:
        CommandLine|contains:
            - '\Windows\Temp\'
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - ' -o '
            - ' /o '
            - ' > '
    condition: selection_db_clients and (selection_suspicious_parent or selection_output_to_temp)
fields:
    - CommandLine
    - Image
    - OriginalFileName
    - ParentImage
falsepositives:
    - Legitimate DBA or developer scripts using sqlcmd.exe from PowerShell or cmd.exe for authorized database queries, reporting, and export operations.
level: high
tags:
    - attack.collection
    - attack.t1213.006
    - analytics.an0677
    - detection.det0242
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Legitimate DBA and Reporting Scripts**
    * *The Issue:* Database administrators routinely run `sqlcmd.exe` from PowerShell or batch scripts to generate reports, perform maintenance, or export data for BI tools. The parent process (`powershell.exe`, `cmd.exe`) and output redirection are identical to adversarial patterns.
    * *The Fix:* Scope alerts using service account context — flag only when `sqlcmd.exe` or `bcp.exe` is launched by an interactive user account (not a dedicated DBA or reporting service account). Time-based tuning can also help by restricting alerting to non-business hours or outside approved maintenance windows.

* **Problem 2: ODBC/JDBC-based Collection Without SQL Client Tools**
    * *The Issue:* Applications and adversaries can connect to databases using ODBC or JDBC drivers programmatically from Python, .NET, or Java applications without spawning `sqlcmd.exe`. The collection happens entirely within the application process.
    * *The Fix:* Monitor network connections from unexpected processes to database ports (TCP 1433 for MSSQL, 3306 for MySQL, 5432 for PostgreSQL), particularly from processes like `python.exe`, `java.exe`, or PowerShell connecting to internal database servers.

* **Problem 3: Database Backup Tools Masking Collection**
    * *The Issue:* `bcp.exe` (Bulk Copy Program) is also legitimately used by SQL Server backup scripts. An adversary using `bcp.exe` to extract table data in bulk might look identical to a legitimate backup export if the output path is a mapped backup drive.
    * *The Fix:* Correlate `bcp.exe` executions with the specific tables being exported (visible in the command line). Alert on exports targeting high-value table names (e.g., `users`, `passwords`, `accounts`, `customers`) or exports containing large row counts to temporary user directories.
