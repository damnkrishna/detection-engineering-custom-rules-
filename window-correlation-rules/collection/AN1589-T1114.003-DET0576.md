### **1. Technique Breakdown: T1114.003**

* **What it is:** **Email Collection: Email Forwarding Rule**. Adversaries may configure email forwarding or inbox rules within a compromised user's mailbox to automatically redirect incoming emails to an external address controlled by the attacker. They establish these rules using PowerShell Exchange cmdlets (such as `New-InboxRule`, `Set-InboxRule`) or via Exchange Management Shell / Exchange Online. Detection monitors execution of these cmdlets with forwarding-specific flags.
* **Log Source Requirements:** Windows Security Event Log Event ID 4688, Sysmon process creation logs (Event ID 1), or PowerShell Script Block Logging (Event ID 4104) capturing Exchange mailbox configuration commands.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process details, capturing cmdline parameters that construct forwarding rules. PowerShell script block logging audits exact parameters.
    * **NIDS (Suricata + Zeek): NO.** Local execution of cmdlets is a host-only management activity.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect PowerShell cmdlets establishing inbox rules or mailbox properties that automatically forward, redirect, or copy emails to external destinations.

```yaml
title: Collection - Email Inbox Forwarding Rule Creation (AN1589)
id: 455544dd-c688-4806-930c-46eaef99cf7b
status: experimental
description: Detects PowerShell cmdlets (New-InboxRule, Set-InboxRule, Set-Mailbox) executed with parameters configured to forward or redirect emails, suggesting external data redirection.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_cmdlets:
        CommandLine|contains:
            - 'New-InboxRule'
            - 'Set-InboxRule'
            - 'New-TransportRule'
            - 'Set-TransportRule'
            - 'Set-Mailbox'
    selection_forward_flags:
        CommandLine|contains:
            - 'ForwardTo'
            - 'ForwardAsAttachmentTo'
            - 'RedirectTo'
            - 'DeliverToMailboxAndForward'
    condition: selection_powershell and selection_cmdlets and selection_forward_flags
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Exchange administrators configuring legitimate corporate mail routing rules or user out-of-office forwarding.
level: medium
tags:
    - attack.collection
    - attack.t1114.003
    - analytics.an1589
    - detection.det0576
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Rule Creation via Outlook GUI**
    * *The Issue:* If the user or attacker creates the forwarding rule interactively via the Outlook desktop application or Outlook Web App (OWA) interface, no command-line PowerShell cmdlet events are generated on the endpoint.
    * *The Fix:* Monitor Exchange admin audit logs and mailbox audit logs (specifically looking for `New-InboxRule` and `Set-InboxRule` operations performed through OWA or RPC interfaces).

* **Problem 2: Rule Obfuscation via API**
    * *The Issue:* Attackers can interact directly with the Microsoft Graph API or Exchange Web Services (EWS) API using custom applications, bypassing standard Exchange PowerShell cmdlet command logging.
    * *The Fix:* Enable auditing on API access tokens and monitor OAuth application consents that grant `Mail.ReadWrite` permissions.

* **Problem 3: Standard Administrative Tasks**
    * *The Issue:* Service desk staff regularly help users configure automatic email redirects when they leave the organization or go on vacation.
    * *The Fix:* Correlate rule creation with change management tickets or baseline typical administrative source accounts.
