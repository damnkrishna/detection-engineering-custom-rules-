### 1. Technique Breakdown: T1074.002

* What it is: Data Staged: Remote Data Staging. Adversaries copy collected data to a centralized remote staging location (such as a shared folder or storage server inside the compromised network) prior to exfiltration. Staging data remotely helps them aggregate logs or files from multiple systems before transmitting them out-of-band. On Windows systems, this is detected by identifying processes writing data archives (like `.zip`, `.7z`, `.rar`) to remote UNC paths (e.g. `\\server\share\`) or mapping staging drives.
* Log Source Requirements: Sysmon File Creation logs (Event ID 11) or process creation logs (Event ID 1) capturing network drive mappings.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 11 captures file creations targeting UNC paths. Event ID 1 captures command parameters mapping drives (like `net.exe use`). Wazuh manages alerting.
    * NIDS (Suricata + Zeek): YES. Network logs capture SMB file write operations over ports 445/139, which confirms network staging.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 11 (File Creation) to detect local processes writing archive files directly to remote UNC shares.

```yaml
title: Collection - Archive File Written to Remote UNC Share (AN0194)
id: 3520f684-7d35-48a7-8e40-62601ad4d27c
status: experimental
description: Detects processes writing compressed archive files (such as .zip, .7z, .rar) to remote UNC network paths, which may indicate remote data staging prior to exfiltration.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: file_event
    product: windows
    # Relies on Sysmon Event ID 11
detection:
    selection_unc:
        TargetFilename|startswith: '\\'
    selection_archive:
        TargetFilename|endswith:
            - '.zip'
            - '.7z'
            - '.rar'
            - '.tar'
            - '.gz'
            - '.cab'
    filter_system:
 # Exclude standard system processes writing back up shares
        Image|endswith:
            - '\System32\ntbackup.exe'
            - '\System32\wbengine.exe'
    condition: selection_unc and selection_archive and not filter_system
fields:
    - Image
    - TargetFilename
    - User
    - LogonId
falsepositives:
    - administrators copy-pasting system backup zips or patch files to network servers.
    - Automated scheduled backup software copying archives to target backup shares.
level: medium
tags:
    - attack.collection
    - attack.t1074.002
    - analytic.an0194
    - detection.det0071
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Legitimate Installer and Backup Noise
  * The Issue: Backup utilities or system installers frequently write archives or stage folders, generating high-volume false positives.
  * The Fix: Define deployment exclusions for installer parents (such as msiexec.exe or setup.exe) and restrict monitoring to user-writable directories.

* Problem 2: Evasive Staging Paths
  * The Issue: Adversaries may write staged files to unusual directories not covered by static path monitors.
  * The Fix: Monitor global file system writes for compressed extensions (.zip, .7z) originating from shell or scripting host parents.

* Problem 3: In-Memory Collection Bypasses
  * The Issue: Malware executing fully in-memory may stream or exfiltrate data without writing staging files to disk, bypassing file event monitoring.
  * The Fix: Complement directory monitoring with host network egress logging and active memory inspection checks.
