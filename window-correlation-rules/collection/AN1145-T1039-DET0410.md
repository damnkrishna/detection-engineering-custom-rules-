### **1. Technique Breakdown: T1039**

* **What it is:** **Data from Network Shared Drive**. Adversaries search and collect sensitive files (like spreadsheets, text documents, or databases) stored on remote network shared drives rather than on the local host. They copy these remote files to a local directory or local staging area prior to exfiltration. Detection focuses on identifying copy utilities (like `xcopy.exe`, `robocopy.exe`, `copy`) or compression tools executing commands targeting remote UNC paths.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing copy utility command parameters.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures command-line parameters, letting security tools look for copy tools referencing network UNC paths (`\\`).
    * **NIDS (Suricata + Zeek): YES.** Network logs capture SMB file read queries, but host logs confirm the local copy/destination.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of copy utilities or compression engines targeting remote UNC share directories.

```yaml
title: Collection - Copy of Data from Remote UNC Share (AN1145)
id: 95595801-451a-49c7-abcf-9468c52cdd82
status: experimental
description: Detects command-line utilities (robocopy, xcopy, copy) or compression tools targeting remote network shares (UNC paths) to copy files locally, suggesting data harvesting.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_utilities:
        - Image|endswith:
            - '\robocopy.exe'
            - '\xcopy.exe'
            - '\cmd.exe'
            - '\powershell.exe'
            - '\7z.exe'
            - '\tar.exe'
        - OriginalFileName:
            - 'robocopy.exe'
            - 'xcopy.exe'
            - '7z.exe'
            - 'tar.exe'
    selection_unc:
        CommandLine|contains:
            - ' \\' # Space followed by UNC double backslash (denotes target)
    selection_copy_commands:
        CommandLine|contains:
            - 'copy '
            - ' cp '
            - ' -cf '
            - ' a '
    condition: selection_utilities and selection_unc and selection_copy_commands
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - IT administrators running standard network backup sync jobs or deploying software updates from server shares.
level: medium
tags:
    - attack.collection
    - attack.t1039
    - analytics.an1145
    - detection.det0410
```

### OCSF Normalized
```xml
title: Collection - Copy of Data from Remote UNC Share (OCSF-Normalized)
id: 95595801-451a-49c7-abcf-9468c52cdd82
status: experimental
description: Detects copy commands targeting remote network shares, mapped to OCSF process_activity.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: system
    product: ocsf
    class: process_activity
detection:
    # Based on OCSF mapping, process path is process.file.path and cmd line is process.cmd_line
    selection_utilities:
        process.file.path|endswith:
            - '\robocopy.exe'
            - '\xcopy.exe'
            - '\cmd.exe'
            - '\powershell.exe'
    selection_unc:
        process.cmd_line|contains:
            - ' \\'
            - 'copy '
            - ' cp '
    condition: selection_utilities and selection_unc
fields:
    - process.cmd_line
    - process.file.path
falsepositives:
    - Legitimate administrative script copies from remote shares.
level: medium
tags:
    - attack.collection
    - attack.t1039
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Standard Mapped Drive Letters**
    * *The Issue:* If the remote shared folder is mapped to a local drive letter (e.g., `S:\` mapped to `\\server\shared\`), the command-line parameters will show `S:\` rather than `\\`, bypassing the static UNC check.
    * *The Fix:* Add a complementary check looking for copy operations targeting drive letters that belong to mapped network resources, or monitor network share connection setups (Event ID 15 in the Sysmon log).

* **Problem 2: Execution via Explorer GUI**
    * *The Issue:* Users drag-and-drop files from mapped network folders daily using Windows Explorer, which is standard but does not create cmdline parameters.
    * *The Fix:* Monitor file write audits (Event ID 4663) or local EDR indicators for high-volume file copies from remote folders.

* **Problem 3: Scheduled sync tasks (Noise)**
    * *The Issue:* Automated backup tasks syncing server files locally trigger alerts.
    * *The Fix:* Whitelist known signed software client engines (like local synchronization tools) and baseline approved service accounts.
