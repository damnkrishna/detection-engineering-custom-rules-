### **1. Technique Breakdown: T1114.002**

* **What it is:** **Email Collection: Remote Email Collection**. Adversaries target and collect emails from remote mail servers (such as Microsoft Exchange or Office 365) using compromised credentials. They access mail databases programmatically via Exchange Web Services (EWS) API, MAPI, or PowerShell command blocks (using Exchange cmdlets like `Export-Mailbox` or EWS managed APIs). Host-based detection checks for unexpected processes (like scripting engines) loading mail API assemblies or executing exchange query cmdlets.
* **Log Source Requirements:** Windows Security Event Log Event ID 4624 (Logon) or Sysmon process creation logs (Event ID 1) combined with PowerShell script block logs (Event ID 4104).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process details, and PowerShell logging captures the script blocks compiling mail retrieval commands.
    * **NIDS (Suricata + Zeek): YES.** Network filters capture SSL connections to remote mail servers (e.g. `outlook.office365.com`), but cannot easily decode HTTPS encrypted API payloads.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** and **PowerShell Script Block Logging (Event ID 4104)** to detect processes executing remote email queries via Exchange Web Services (EWS) or Exchange cmdlets.

```yaml
title: Collection - Remote Email Collection via Exchange API Query (AN0131)
id: 7f4a20da-cd79-4495-bf8f-a0fd66965c0a
status: experimental
description: Detects command-line parameters or PowerShell script blocks indicating remote email collection via Exchange Web Services (EWS) or Exchange Management cmdlets, indicating potential data theft.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 / PowerShell Event 4104 collected via Wazuh
detection:
    selection_cmd:
        CommandLine|contains:
            - 'Microsoft.Exchange.WebServices.Data'
            - 'Export-Mailbox'
            - 'Search-Mailbox'
            - 'Get-MailboxFolderStatistics'
            - 'ExchangeService'
    selection_powershell:
        EventID: 4104
        ScriptBlockText|contains:
            - 'Microsoft.Exchange.WebServices.Data.ExchangeService'
            - 'Get-Mailbox'
            - 'Export-Mailbox'
            - 'Search-Mailbox'
    condition: selection_cmd or selection_powershell
fields:
    - CommandLine
    - EventID
    - ScriptBlockText
falsepositives:
    - Authorized Exchange administrators running routine mailbox cleanups or compliance exports.
level: high
tags:
    - attack.collection
    - attack.t1114.002
    - analytics.an0131
    - detection.det0048
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Standard IT Migration Scripts**
    * *The Issue:* IT operations run scripts daily to migrate user mailboxes or archive old records, triggering high volumes of false alerts.
    * *The Fix:* Whitelist approved Exchange admin accounts and ensure these tasks run only from designated Exchange administration servers.

* **Problem 2: API Request Obfuscation**
    * *The Issue:* Script blocks can build EWS assembly objects dynamically using base64 or obfuscated strings, bypassing simple text matching.
    * *The Fix:* Enable PowerShell AMSI (Antimalware Scan Interface) monitoring to analyze decrypted script blocks before execution, and monitor EWS connections in Exchange IIS logs.

* **Problem 3: Client-side Outlook sync**
    * *The Issue:* If the attacker accesses emails directly from a local client using standard Outlook sync, no API command triggers are run on the endpoint.
    * *The Fix:* Monitor Mailbox Audit logs (Event ID 4003/4004 in Exchange/M365) to detect non-owner accesses or abnormal download spikes.
