### **1. Technique Breakdown: T1560.003**

* **What it is:** **Archive Collected Data: Archive via Custom Method**. Adversaries may use custom compression or encryption methods (such as custom XOR loops, proprietary encryption/obfuscation algorithms, or custom packing formats) to archive collected data prior to exfiltration. By avoiding standard utilities (like `zip.exe`, `tar.exe`, `7z.exe`), they aim to bypass security controls that monitor standard archive file types or command-line execution patterns. Host-based detection monitors scripting engines loading cryptographic libraries or executing low-level bitwise operations.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) or PowerShell Script Block Logging (Event ID 4104) capturing cryptographic namespace imports or bitwise file operations.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs scripting engine command lines. PowerShell Script Block Logging (Event ID 4104) captures low-level crypto classes.
    * **NIDS (Suricata + Zeek): NO.** Custom local archiving is a host-only activity.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect PowerShell or script engines executing low-level cryptographic or compression APIs to perform custom file archiving/encryption.

```yaml
title: Collection - Archiving or Encryption via Custom Method (AN1213)
id: 159ffe92-2ec0-4e1d-86b4-a3714066b35b
status: experimental
description: Detects PowerShell or scripting engines executing low-level cryptographic or compression APIs to perform custom file archiving/encryption, bypassing standard archiving controls.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
            - 'wscript.exe'
            - 'cscript.exe'
    selection_crypto_api:
        CommandLine|contains:
            - 'Security.Cryptography'
            - 'System.IO.Compression'
            - 'DeflateStream'
            - 'GZipStream'
            - '-bxor'
            - 'Crypt32'
            - 'CryptEncrypt'
            - 'CryptDecrypt'
    condition: selection_powershell and selection_crypto_api
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Legitimate administrative scripts encrypting backup logs or certificates.
    - Software installer scripts deploying compressed components.
level: medium
tags:
    - attack.collection
    - attack.t1560.003
    - analytics.an1213
    - detection.det0438
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Complex Obfuscation of Script Commands**
    * *The Issue:* Attackers can encrypt or obfuscate the script command line (e.g. using string splitting or variable substitution) to evade static signature checks for names like `Security.Cryptography` or `DeflateStream`.
    * *The Fix:* Enable PowerShell Script Block Logging (Event ID 4104) and correlate with AMSI logs (Event ID 1102) to inspect the script block content dynamically after it is decrypted in memory.

* **Problem 2: Proprietary Compiled Binaries**
    * *The Issue:* If the adversary develops a custom C/C++ compiled binary that performs XOR or encryption on local files, the scripting command line matches will not trigger.
    * *The Fix:* Monitor file write frequency and file entropy changes (such as high-entropy writes to temp staging paths) using endpoint protection agents or EDR file telemetry.

* **Problem 3: Standard Administrative Tasks (Noise)**
    * *The Issue:* Many admin utilities (e.g. backup tools, password sync agents) encrypt data locally before sending it to a vault.
    * *The Fix:* Baseline known administrative service accounts and safe directories, excluding them from the rule scope.
