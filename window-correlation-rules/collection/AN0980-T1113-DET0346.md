### **1. Technique Breakdown: T1113**

* **What it is:** **Screen Capture**. Adversaries take screenshots or record video of the screen to gather sensitive information, such as displayed credentials, application windows, or user activity. On Windows endpoints, they use native tools (like Problem Steps Recorder `psr.exe`), third-party admin utilities (like `nircmd.exe`), or scripting commands that call graphics APIs (like `.NET System.Drawing.Graphics.CopyFromScreen`).
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing command line arguments and executing processes.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process details, letting security systems check for `psr.exe` or `CopyFromScreen` commands. Wazuh aggregates these and alerts.
    * **NIDS (Suricata + Zeek): NO.** Network devices cannot audit local physical screen rendering or screen capture actions.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of command-line tools or PowerShell commands commonly used to take screenshots of the system.

```yaml
title: Collection - Screen Capture Utility Execution (AN0980)
id: 19277629-f4d9-48f1-b0f3-345326e2f695
status: experimental
description: Detects command-line utilities (psr.exe, nircmd.exe) or PowerShell scripting commands executing screen capture API calls, suggesting unauthorized information gathering.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_utilities:
        - Image|endswith:
            - '\psr.exe'
            - '\nircmd.exe'
        - CommandLine|contains:
            - 'savescreenshot' # nircmd flag
            - 'savescreenshotwin'
            - 'psr.exe /start' # psr start recording
    selection_powershell:
        CommandLine|contains:
            - 'CopyFromScreen'
            - 'System.Drawing.Graphics'
    condition: selection_utilities or selection_powershell
fields:
    - CommandLine
    - Image
falsepositives:
    - IT administrators using Problem Steps Recorder (psr.exe) to document system issues for helpdesk tickets.
    - Automated user interface testing tools (e.g. Selenium) taking screenshots during tests.
level: medium
tags:
    - attack.collection
    - attack.t1113
    - analytics.an0980
    - detection.det0346
```

    - process.cmd_line
    - process.file.path

tags:

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Win32 API Call (BitBlt)**
    * *The Issue:* If the attacker executes a compiled C/C++ executable that directly loads `gdi32.dll` and calls the `BitBlt` or `CreateCompatibleDC` APIs to capture the screen, no cmdline arguments are generated, bypassing simple string checks.
    * *The Fix:* Complement this rule by detecting unsigned executables that load GDI assemblies from temporary writeable folders.

* **Problem 2: Collaboration tool Screen Sharing**
    * *The Issue:* Legitimate web meeting programs (like Teams, Zoom, Webex) capture the screen continuously during screen sharing sessions, generating normal media loads that must not be blocked.
    * *The Fix:* Restrict exclusions strictly to signed, corporate-approved collaboration applications, and focus alerts on processes executing from user-writeable directories.

* **Problem 3: Snagit / Snipping Tool usage**
    * *The Issue:* Users take manual screenshots daily using standard snipping tools (like `SnippingTool.exe`), generating heavy noise.
    * *The Fix:* Exclude the official Windows Snipping Tool paths and focus rules strictly on command-line utilities, script hosts, and background service accounts.
