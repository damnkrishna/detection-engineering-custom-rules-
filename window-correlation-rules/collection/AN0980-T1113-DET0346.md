### 1. Technique Breakdown: T1113

* What it is: Screen Capture. Adversaries take screenshots or record video of the screen to gather sensitive information, such as displayed credentials, application windows, or user activity. On Windows endpoints, they use native tools (like Problem Steps Recorder `psr.exe`), third-party admin utilities (like `nircmd.exe`), or scripting commands that call graphics APIs (like `.NET System.Drawing.Graphics.CopyFromScreen`).
* Log Source Requirements: Sysmon process creation logs (Event ID 1) capturing command line arguments and executing processes.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs process details, letting security systems check for `psr.exe` or `CopyFromScreen` commands. Wazuh aggregates these and alerts.
    * NIDS (Suricata + Zeek): NO. Network devices cannot audit local physical screen rendering or screen capture actions.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of command-line tools or PowerShell commands commonly used to take screenshots of the system.

```yaml
title: Collection - Screen Capture Utility Execution (AN0980)
id: 19277629-f4d9-48f1-b0f3-345326e2f695
status: experimental
description: Detects command-line utilities (psr.exe, nircmd.exe) or PowerShell scripting commands executing screen capture API calls, suggesting unauthorized information gathering.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_utilities:
        - Image|endswith:
            - '\psr.exe'
            - '\nircmd.exe'
        - CommandLine|contains:
            - 'savescreenshot' # nircmd flag
            - 'savescreenshotwin'
            - 'psr.exe /start' # psr start recording
    selection_powershell:
        CommandLine|contains:
            - 'CopyFromScreen'
            - 'System.Drawing.Graphics'
    condition: selection_utilities or selection_powershell
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - administrators using Problem Steps Recorder (psr.exe) to document system issues for helpdesk tickets.
    - Automated user interface testing tools (e.g. Selenium) taking screenshots during tests.
level: medium
tags:
    - attack.collection
    - attack.t1113
    - analytic.an0980
    - detection.det0346
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
