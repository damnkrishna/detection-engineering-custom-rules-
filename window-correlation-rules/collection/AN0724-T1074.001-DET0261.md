### 1. Technique Breakdown: T1074.001

* What it is: Local Data Staging. Adversaries collect and consolidate sensitive files — documents, credentials, configuration files — into a single local staging directory before exfiltration. Unlike general data staging (T1074), this sub-technique focuses specifically on local host staging: reading files from multiple source locations (Documents, Desktop, network drives) and writing them to a common staging folder (e.g., `%TEMP%`, `C:\Windows\Temp`, `%USERPROFILE%\AppData\Local`). The staged files are often then compressed or encrypted. The detection pattern focuses on detecting bulk file copy or move operations across directories by shell or scripting processes.
* Log Source Requirements: File event logs (Sysmon Event ID 11) detecting mass file write events, and process creation logs (Sysmon Event ID 1) for copy utilities.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 11 captures file creation events, enabling detection of multiple files being written to a staging directory in rapid succession by the same process.
    * NIDS (Suricata + Zeek): NO. Local data staging is a host filesystem operation producing no network traffic.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect bulk file copy commands targeting staging directories, or PowerShell commands reading from multiple source paths and writing to common temp locations.

```yaml
title: Local Data Staging via Bulk File Copy (AN0724)
id: 7ad39912-8653-4336-b015-85a30c5f5489
status: experimental
description: Detects bulk file copy or move operations (xcopy, robocopy, PowerShell Copy-Item) targeting local staging directories (Temp, Public, AppData), indicating adversarial local data consolidation prior to exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_xcopy:
        - Image|endswith: '\xcopy.exe'
        - OriginalFileName: 'xcopy.exe'
    selection_robocopy:
        - Image|endswith: '\robocopy.exe'
        - OriginalFileName: 'robocopy.exe'
    selection_staging_dest:
        CommandLine|contains:
            - '\Windows\Temp'
            - '\AppData\Local\Temp'
            - '\Users\Public'
            - 'C:\Temp'
            - '\ProgramData\'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_ps_copy:
        CommandLine|contains:
            - 'Copy-Item'
            - 'Move-Item'
            - 'cp '
            - 'mv '
    condition: ((selection_xcopy or selection_robocopy) and selection_staging_dest) or (selection_powershell and selection_ps_copy and selection_staging_dest)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - deployment scripts or software installers that bulk-copy files to temp directories during installation or configuration.
level: medium
tags:
    - attack.collection
    - attack.t1074.001
    - analytic.an0724
    - detection.det0261
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
