### **1. Technique Breakdown: T1074.001**

* **What it is:** **Local Data Staging**. Adversaries collect and consolidate sensitive files — documents, credentials, configuration files — into a single local staging directory before exfiltration. Unlike general data staging (T1074), this sub-technique focuses specifically on local host staging: reading files from multiple source locations (Documents, Desktop, network drives) and writing them to a common staging folder (e.g., `%TEMP%`, `C:\Windows\Temp`, `%USERPROFILE%\AppData\Local`). The staged files are often then compressed or encrypted. The detection pattern focuses on detecting bulk file copy or move operations across directories by shell or scripting processes.
* **Log Source Requirements:** File event logs (Sysmon Event ID 11) detecting mass file write events, and process creation logs (Sysmon Event ID 1) for copy utilities.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 11 captures file creation events, enabling detection of multiple files being written to a staging directory in rapid succession by the same process.
    * **NIDS (Suricata + Zeek): NO.** Local data staging is a host filesystem operation producing no network traffic.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect bulk file copy commands targeting staging directories, or PowerShell commands reading from multiple source paths and writing to common temp locations.

```yaml
title: Local Data Staging via Bulk File Copy (AN0724)
id: 7ad39912-8653-4336-b015-85a30c5f5489
status: experimental
description: Detects bulk file copy or move operations (xcopy, robocopy, PowerShell Copy-Item) targeting local staging directories (Temp, Public, AppData), indicating adversarial local data consolidation prior to exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_xcopy:
        - Image|endswith: '\xcopy.exe'
        - OriginalFileName: 'xcopy.exe'
    selection_robocopy:
        - Image|endswith: '\robocopy.exe'
        - OriginalFileName: 'robocopy.exe'
    selection_staging_dest:
        CommandLine|contains:
            - '\Windows\Temp'
            - '\AppData\Local\Temp'
            - '\Users\Public'
            - 'C:\Temp'
            - '\ProgramData\'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_ps_copy:
        CommandLine|contains:
            - 'Copy-Item'
            - 'Move-Item'
            - 'cp '
            - 'mv '
    condition: ((selection_xcopy or selection_robocopy) and selection_staging_dest) or (selection_powershell and selection_ps_copy and selection_staging_dest)
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - IT deployment scripts or software installers that bulk-copy files to temp directories during installation or configuration.
level: medium
tags:
    - attack.collection
    - attack.t1074.001
    - analytics.an0724
    - detection.det0261
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: cmd.exe Internal Copy Command**
    * *The Issue:* The `copy` and `move` commands are internal `cmd.exe` built-ins, not external executables. Using `copy file.txt C:\Temp\` doesn't spawn `xcopy.exe` or any separately logged process — it runs inside `cmd.exe` itself. Standard process creation monitoring won't capture these operations.
    * *The Fix:* Monitor Sysmon Event ID 11 (File Create) for files being written to staging directories like `C:\Windows\Temp` by `cmd.exe`. Correlate with the parent process that spawned `cmd.exe` to identify suspicious origins.

* **Problem 2: Mass File Access Without Copy (In-Place Read)**
    * *The Issue:* Adversaries may read files from their original locations and stream them directly to a network socket or into a memory buffer, without performing any local copy or move operations. No staging directory write events are generated.
    * *The Fix:* Complement this rule with threshold-based alerting: flag processes that open more than 50 unique file handles for reads within 60 seconds, particularly for document file types (`.docx`, `.pdf`, `.xlsx`).

* **Problem 3: Legitimate Robocopy in Enterprise Environments**
    * *The Issue:* IT teams use `robocopy.exe` extensively for file migrations, backup syncing, and profile transfers to/from temp directories. This makes robocopy-based detection inherently noisy.
    * *The Fix:* Restrict alerts to `robocopy.exe` executions initiated by interactive user sessions (not from known deployment or backup service accounts) and where the destination path matches staging indicators but not known server backup locations.
