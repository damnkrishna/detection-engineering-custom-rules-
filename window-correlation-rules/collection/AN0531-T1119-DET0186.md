### **1. Technique Breakdown: T1119**

* **What it is:** **Automated Collection**. Adversaries use scripts or utilities to automatically discover and collect files, clipboard content, or system information at scale. Rather than manually browsing and copying individual files, they run automated commands that recursively search for target file types (e.g., `dir /s /b *.docx`, `Get-ChildItem -Recurse -Filter "*.pdf"`), copy matching files to a staging location, and sometimes capture clipboard data in a loop. This allows rapid bulk collection of sensitive data from a compromised host without significant manual interaction.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) for recursive file enumeration and scripting engine invocations, and PowerShell Script Block Logs (Event ID 4104).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures command-line launches of `dir /s /b`, `tree.exe`, `Get-ChildItem -Recurse`, and similar recursive enumeration commands. Script Block Logging captures PowerShell collection script content.
    * **NIDS (Suricata + Zeek): NO.** Automated local file collection is a host-local operation producing no network traffic during the collection phase.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect recursive file enumeration commands combined with file extension filters typically used for sensitive document collection.

```yaml
title: Automated File Collection via Recursive Enumeration (AN0531)
id: 19266e2c-9b15-4491-ba75-ba2c7f46320f
status: experimental
description: Detects automated collection behavior — recursive directory searches targeting sensitive file extensions (documents, credentials, archives) via cmd.exe or PowerShell — indicative of scripted bulk data collection.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_cmd_recursive:
        - Image|endswith: '\cmd.exe'
        - OriginalFileName: 'Cmd.Exe'
    selection_cmd_args:
        CommandLine|contains:
            - ' /s '
            - ' /S '
    selection_cmd_extensions:
        CommandLine|contains:
            - '*.docx'
            - '*.xlsx'
            - '*.pdf'
            - '*.pst'
            - '*.kdbx'
            - '*.txt'
            - '*.csv'
            - '*.conf'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_ps_recursive:
        CommandLine|contains:
            - '-Recurse'
            - 'Get-ChildItem'
            - 'gci '
            - 'ls -r'
    selection_ps_extensions:
        CommandLine|contains:
            - '*.docx'
            - '*.pdf'
            - '*.pst'
            - '*.kdbx'
            - '*.xlsx'
            - '*.csv'
    condition: (selection_cmd_recursive and selection_cmd_args and selection_cmd_extensions) or (selection_powershell and selection_ps_recursive and selection_ps_extensions)
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - IT administrators running inventory scripts to locate and report on document types for compliance or data governance purposes.
level: medium
tags:
    - attack.collection
    - attack.t1119
    - analytics.an0531
    - detection.det0186
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Compliance and Data Classification Tools**
    * *The Issue:* Data loss prevention (DLP) agents, compliance scanning tools (e.g., Varonis, Spirion), or IT governance scripts regularly enumerate file types across user directories for classification purposes. These generate exactly the same patterns as malicious automated collection.
    * *The Fix:* Allow-list the process paths and service accounts used by approved DLP and classification tools. Focus alerting on recursive searches initiated from interactive user sessions or from unexpected parent processes (e.g., a web application or downloaded binary spawning `cmd.exe /s`).

* **Problem 2: Clipboard Collection Not Captured by File Events**
    * *The Issue:* Automated clipboard harvesting (e.g., using PowerShell `Get-Clipboard` in a loop or `clip.exe`) collects data without performing any filesystem operations. No file event or recursive search is generated, bypassing process-based detection.
    * *The Fix:* Supplement with PowerShell Script Block Logging detection for `Get-Clipboard` in loops (`while`, `for`, scheduled execution patterns). Correlate with outbound data exfiltration within the same session.

* **Problem 3: Custom Compiled Collection Binaries**
    * *The Issue:* Adversaries using post-exploitation frameworks (CobaltStrike, Sliver) often use in-memory BOF (Beacon Object File) modules for file enumeration that don't spawn `cmd.exe` or PowerShell. No process creation event for the enumeration is generated.
    * *The Fix:* Monitor high-volume file access patterns at the Sysmon Event ID 11 level — alert when a single process creates or reads more than 100 files with document extensions within a 60-second window.
