### **1. Technique Breakdown: T1074**

* **What it is:** **Data Staged**. Adversaries aggregate and stage collected data in a central location before exfiltration, often to simplify transfer and avoid repeated connections to the target system. On Windows, this typically involves copying or moving sensitive files (documents, databases, credential stores) into a temporary staging directory, then compressing or archiving them using `7z.exe`, `WinRAR.exe`, or built-in `Compress-Archive` (PowerShell) before sending them out. The staging location is frequently `C:\Windows\Temp`, `%APPDATA%`, or a custom subdirectory under `C:\Users\Public`.
* **Log Source Requirements:** File event logs (Sysmon Event ID 11) detecting file writes to staging directories, and process creation logs (Sysmon Event ID 1) for archiving tools.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 11 captures file creation events (archive files being created in temp directories). Sysmon Event ID 1 captures the launch of compression utilities with file path arguments.
    * **NIDS (Suricata + Zeek): NO.** Data staging is a host-local filesystem operation. Network exfiltration follows staging but is a separate step.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect file compression utilities (`7z.exe`, `WinRAR.exe`, `Compress-Archive`) writing archive files to common staging directories, indicating data aggregation prior to exfiltration.

```yaml
title: Data Staging via Archive Utilities in Temp Directories (AN0040)
id: b5447d20-091e-4b98-9f2b-a5cf6caf2909
status: experimental
description: Detects archiving utilities (7z, WinRAR, PowerShell Compress-Archive) creating archive files in temporary or public staging directories, which may indicate data collection and staging prior to exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_7zip:
        - Image|endswith: '\7z.exe'
        - OriginalFileName: '7z.exe'
    selection_winrar:
        - Image|endswith: '\WinRAR.exe'
        - OriginalFileName: 'WinRAR.exe'
    selection_rar:
        - Image|endswith: '\rar.exe'
        - OriginalFileName: 'rar.exe'
    selection_staging_paths:
        CommandLine|contains:
            - '\Windows\Temp\'
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\ProgramData\'
            - 'C:\Temp\'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_compress_archive:
        CommandLine|contains:
            - 'Compress-Archive'
    condition: ((selection_7zip or selection_winrar or selection_rar) and selection_staging_paths) or (selection_powershell and selection_compress_archive and selection_staging_paths)
falsepositives:
    - Backup software or IT administrators compressing files for routine archival into temp directories during migration tasks.
level: medium
tags:
    - attack.collection
    - attack.t1074
    - analytics.an0040
    - detection.det0014
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Backup Software Archiving to Temp Paths**
    * *The Issue:* Enterprise backup agents (Veeam, Acronis, Windows Backup) frequently write compressed archives to temp directories as intermediate steps before moving them to backup repositories. This generates significant alert noise.
    * *The Fix:* Allow-list known backup service account names and signed backup agent binary paths. Additionally, correlate compression events with subsequent network transfer activity — legitimate backups transfer to known backup server IPs, while adversarial staging often transfers to external or unusual destinations.

* **Problem 2: Custom Archive Utility Names (LOLBin Staging)**
    * *The Issue:* Adversaries may rename `7z.exe` to `update.exe` or use built-in tools like `makecab.exe` (Cabinet archiver, native Windows) or `compact.exe` for staging. These evade binary name checks.
    * *The Fix:* Extend the rule to include `makecab.exe` and `compact.exe`. Additionally, monitor file creation events (Sysmon ID 11) for `.cab`, `.zip`, `.7z`, and `.rar` files appearing in temp directories, regardless of which process created them.

* **Problem 3: In-Memory Staging Without File System Writes**
    * *The Issue:* Advanced adversaries may aggregate collected data entirely in memory (e.g., building an archive buffer in a PowerShell process) and stream it directly over the network without writing the staged archive to disk.
    * *The Fix:* Supplement with network-level monitoring for large outbound data transfers from hosts that recently performed bulk file access (Sysmon Event ID 11 showing many file reads in short succession), especially when the destination IP is external or unusual.
