### **1. Technique Breakdown: T1005**

* **What it is:** **Local Data Collection**. Adversaries search local system directories (such as user desktops, document directories, or mail caches) to collect sensitive files prior to exfiltration. They run command loops (like `dir /s` or `Get-ChildItem` in PowerShell) targeting specific file extensions (such as `.docx`, `.pdf`, `.xlsx`, `.pst`, `.db`) and write these matching paths to a staging file or staging directory.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing command-line parameters, combined with PowerShell Script Block logs (Event ID 4104).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures the search loops containing wildcards (e.g., `*.docx`). Wazuh aggregates these and alerts.
    * **NIDS (Suricata + Zeek): NO.** Network sensors have no visibility into local file search commands or local drive audits.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command shell interpreters running script commands or loops to search and collect documents across the local disk.

```yaml
title: Collection - Search Loop for Sensitive Local Files (AN1070)
id: adaf4deb-c89d-443d-9484-bfd184f8ca45
status: experimental
description: Detects command-line interpreters or scripting hosts executing recursive search commands (like dir /s or Get-ChildItem) targeting sensitive file extensions (e.g. .docx, .xlsx, .pdf, .pst, .db, .key), suggesting data harvesting.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_process:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_search_commands:
        CommandLine|contains:
            - 'dir /s'
            - 'Get-ChildItem'
            - 'findstr'
    selection_extensions:
        CommandLine|contains:
            - '.docx'
            - '.xlsx'
            - '.pdf'
            - '.pst'
            - '.ost'
            - '.key'
            - '.wallet'
            - '.pgp'
    condition: selection_process and selection_search_commands and selection_extensions
fields:
    - CommandLine
    - Image
falsepositives:
    - Administrative search scripts or user-initiated manual command-line lookups for lost local files.
    - Local desktop search indexers or backup scripts running search queries.
level: medium
tags:
    - attack.collection
    - attack.t1005
    - analytics.an1070
    - detection.det0380
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Search via Explorer GUI**
    * *The Issue:* If the attacker uses the built-in Windows Explorer search box (`explorer.exe` search indexer) to locate files, the query runs inside the indexed search service API without spawning command line interpreter commands.
    * *The Fix:* Monitor local file audit logs (Event ID 4663) for high-frequency read operations targeting document files by non-standard processes.

* **Problem 2: Execution in specific directories (Noise)**
    * *The Issue:* Developers and IT admins routinely run search queries inside project folders (like `node_modules` or local git repos) to locate files, triggering massive false alarms.
    * *The Fix:* Scope the rule to ignore search paths containing known development directories or restrict alerting to root drive partitions (e.g. `C:\Users\`).

* **Problem 3: Remote Administration scripts**
    * *The Issue:* Centralized management tools (like Tanium or SCCM) execute inventory searches globally, causing wide-scale false positives.
    * *The Fix:* Add explicit whitelists for official system management agent paths and their designated service account credentials.
