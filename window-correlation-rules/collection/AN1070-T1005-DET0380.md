### 1. Technique Breakdown: T1005

* What it is: Local Data Collection. Adversaries search local system directories (such as user desktops, document directories, or mail caches) to collect sensitive files prior to exfiltration. They run command loops (like `dir /s` or `Get-ChildItem` in PowerShell) targeting specific file extensions (such as `.docx`, `.pdf`, `.xlsx`, `.pst`, `.db`) and write these matching paths to a staging file or staging directory.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) capturing command-line parameters, combined with PowerShell Script Block logs (Event ID 4104).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures the search loops containing wildcards (e.g., `*.docx`). Wazuh aggregates these and alerts.
    * NIDS (Suricata + Zeek): NO. Network sensors have no visibility into local file search commands or local drive audits.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect command shell interpreters running script commands or loops to search and collect documents across the local disk.

```yaml
title: Collection - Search Loop for Sensitive Local Files (AN1070)
id: adaf4deb-c89d-443d-9484-bfd184f8ca45
status: experimental
description: Detects command-line interpreters or scripting hosts executing recursive search commands (like dir /s or Get-ChildItem) targeting sensitive file extensions (e.g. .docx, .xlsx, .pdf, .pst, .db, .key), suggesting data harvesting.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_process:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_search_commands:
        CommandLine|contains:
            - 'dir /s'
            - 'Get-ChildItem'
            - 'findstr'
    selection_extensions:
        CommandLine|contains:
            - '.docx'
            - '.xlsx'
            - '.pdf'
            - '.pst'
            - '.ost'
            - '.key'
            - '.wallet'
            - '.pgp'
    condition: selection_process and selection_search_commands and selection_extensions
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - search scripts or user-initiated manual command-line lookups for lost local files.
    - Local desktop search indexers or backup scripts running search queries.
level: medium
tags:
    - attack.collection
    - attack.t1005
    - analytic.an1070
    - detection.det0380
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
