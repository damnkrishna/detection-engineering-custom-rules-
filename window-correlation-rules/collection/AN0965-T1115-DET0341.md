### **1. Technique Breakdown: T1115**

* **What it is:** **Clipboard Data**. Adversaries collect sensitive information (such as passwords, keys, or proprietary data) by reading the system clipboard. They use native command tools (like `clip.exe`) or execute scripting utilities (such as PowerShell commands accessing the clipboard APIs) to extract the text buffer. Host-based detection checks for command-line strings that call clipboard extraction methods or redirect output from clipboard utilities.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing command line arguments, combined with PowerShell Script Block logs (Event ID 4104).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process details, letting security tools check for `Get-Clipboard` or `clip.exe` commands. Wazuh aggregates these and alerts.
    * **NIDS (Suricata + Zeek): NO.** Network sensors cannot audit local system clipboard activity.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of command-line tools or PowerShell commands retrieving data from the system clipboard.

```yaml
title: Collection - Clipboard Data Retrieval Command (AN0965)
id: 07461075-1fb8-449a-8fea-78b6b9667d5b
status: experimental
description: Detects command-line parameters or PowerShell scripting commands executing clipboard-reading commands (such as Get-Clipboard or clipboard APIs), suggesting unauthorized credential or data harvesting.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_cmd:
        CommandLine|contains:
            - 'Get-Clipboard'
            - 'Windows.Forms.Clipboard'
            - 'clip.exe' # typically used for piping, but checks for direct execution too
    selection_powershell:
        EventID: 4104
        ScriptBlockText|contains:
            - 'Get-Clipboard'
            - 'Windows.Forms.Clipboard'
    condition: selection_cmd or selection_powershell
fields:
    - CommandLine
    - EventID
    - ScriptBlockText
falsepositives:
    - Legitimate user-run administrative helper scripts that query the clipboard for convenience tasks.
level: medium
tags:
    - attack.collection
    - attack.t1115
    - analytics.an0965
    - detection.det0341
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct API Call via compiled executable**
    * *The Issue:* If the attacker executes a compiled C/C++ executable that calls the Win32 API `GetClipboardData` directly, no cmdline string (like `Get-Clipboard`) is written, bypassing process string checks.
    * *The Fix:* Complement this rule by identifying unsigned applications that load User32.dll and dynamically call clipboard APIs, and audit anomalous memory structures.

* **Problem 2: Clipboard Monitoring loops**
    * *The Issue:* An attacker can install a background tool that continuously listens to clipboard update notifications (using `AddClipboardFormatListener`) rather than querying the clipboard manually, which runs silently.
    * *The Fix:* Deploy endpoint security configurations that detect unauthorized API hooking or anomalous background tasks holding open handles to User32.dll resources.

* **Problem 3: Standard developer clipboard integrations**
    * *The Issue:* Developers and IT staff frequently use tools that sync clipboard contents across machines (like Synergy or Ditto) or administrative utilities that read clipboard contents, triggering false alerts.
    * *The Fix:* Exclude known, digitally signed corporate clipboard management applications and baseline authorized administration workstations.
