### **1. Technique Breakdown: T1560.002**

* **What it is:** **Archive Collected Data: Archive via Library**. Adversaries package collected data using compression library interfaces (such as `zlib`, `7-Zip` SDK, or `Ionic.Zip` for .NET) within their custom malware or scripts rather than executing standalone utilities. This allows them to compress files directly in memory or write them to disk without launching command shell utilities, bypassing simple process name filters. Detection focuses on identifying non-standard, unsigned applications loading compression runtime libraries (like `zlib1.dll`, `7z.dll`, `unrar.dll`, or `Ionic.Zip.dll`).
* **Log Source Requirements:** Sysmon Library Load logs (Event ID 7) and process creation logs (Event ID 1).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 7 records process image loads, allowing security tools to detect when an application in a user temp directory loads a compression DLL.
    * **NIDS (Suricata + Zeek): NO.** Network devices cannot audit system dynamic link library loads on physical host systems.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 7 (Library Load)** to detect unsigned or anomalous applications loading common compression or archiving libraries, which may indicate custom data packaging prior to exfiltration.

```yaml
title: Collection - Anomaly Compression Library Load (AN0747)
id: bc15854c-e232-478a-92ac-1f4d96247771
status: experimental
description: Detects unsigned or non-standard executables loading common compression and archiving libraries (zlib, 7z.dll, unrar, Ionic.Zip), indicating potential custom data archiving prior to exfiltration.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: image_load
    product: windows
    # Relies on Sysmon Event ID 7 collected via Wazuh
detection:
    selection_dll:
        ImageLoaded|endswith:
            - '\zlib1.dll'
            - '\zlib.dll'
            - '\7z.dll'
            - '\unrar.dll'
            - '\libzip.dll'
            - '\Ionic.Zip.dll'
    filter_system:
        # Exclude standard system and installer paths
        Image|endswith:
            - '\System32\msiexec.exe'
            - '\Program Files\7-Zip\7zG.exe'
            - '\Program Files\7-Zip\7z.exe'
            - '\Program Files\WinRAR\WinRAR.exe'
            - '\Program Files\Microsoft Office\root\Office16\* '
    condition: selection_dll and not filter_system
fields:
    - Image
    - ImageLoaded
falsepositives:
    - Legitimate software installers compiling or extracting update packages during standard setup.
    - Custom business applications running standard file compression commands.
level: medium
tags:
    - attack.collection
    - attack.t1560.002
    - analytics.an0747
    - detection.det0268
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Standard .NET Framework Classes (No external DLL load)**
    * *The Issue:* If the attacker uses the built-in .NET `System.IO.Compression` namespace, the compilation calls `clbcatq.dll` and other core CLR system assemblies rather than writing separate compression DLL files to the disk. The process checks will see only standard .NET DLL loads.
    * *The Fix:* Enable PowerShell Script Block Logging (Event ID 4104) and look for code queries targeting the `System.IO.Compression` classes.

* **Problem 2: Broad scope of zlib usage**
    * *The Issue:* `zlib.dll` is an extremely common compression library used by hundreds of legitimate applications (e.g. Git, Slack, browsers) to handle web assets, generating heavy noise.
    * *The Fix:* Whitelist known signed software installation folders (like `C:\Program Files\`) and enforce alerts specifically when the binary is running out of user temp directories (`%TEMP%`).

* **Problem 3: Static Linking**
    * *The Issue:* If the custom malware compiles the zlib/compression code statically inside its own binary (rather than loading it dynamically as a `.dll`), no library load event (Event ID 7) will record the DLL name.
    * *The Fix:* Complement this library rule by monitoring file write spikes (Event ID 11) where multiple files are compiled or written in sequence to user paths.
