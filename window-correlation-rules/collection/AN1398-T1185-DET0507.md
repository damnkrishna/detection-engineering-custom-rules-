### **1. Technique Breakdown: T1185**

* **What it is:** **Browser Session Hijacking**. Adversaries hijack browser sessions to steal authentication cookies, session tokens, or credentials, allowing them to impersonate victims and access protected internal or cloud applications (such as intranets, email, or databases). On Windows systems, adversaries with administrative privileges or using specialized tools (like Mimikatz, SharpChromium, or browser-cookie stealers) inject malicious threads or access handles of active browser processes (like `chrome.exe`, `msedge.exe`, `firefox.exe`) to read session data directly from memory or database files.
* **Log Source Requirements:** Sysmon Process Access logs (Event ID 10) or CreateRemoteThread logs (Event ID 8) monitoring access to browser processes from scripting hosts or administrative tools.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 10 captures handles opened to browser processes with write/inject permissions. Event ID 8 captures remote thread injections into browser memory space.
    * **NIDS (Suricata + Zeek): NO.** Process handle access and thread injection are local operating system activities.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 10 (Process Access)** to detect scripting engines, LOLBins, or command interpreters attempting to open handles to active web browsers with query or modification rights.

```yaml
title: Collection - Browser Process Access and Session Hijacking (AN1398)
id: 94dcc953-cee7-4ee6-a844-1e4737bf049d
status: experimental
description: Detects command interpreters, scripting hosts, or common LOLBins opening access handles to web browser processes, which may indicate memory cookie harvesting or process injection.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_access
    product: windows
    # Relies on Sysmon Event ID 10 collected via Wazuh
detection:
    selection_target_browsers:
        TargetImage|endswith:
            - '\chrome.exe'
            - '\msedge.exe'
            - '\firefox.exe'
            - '\brave.exe'
            - '\iexplore.exe'
    selection_source_injectors:
        SourceImage|endswith:
            - '\powershell.exe'
            - '\cmd.exe'
            - '\rundll32.exe'
            - '\regasm.exe'
            - '\regsvcs.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\installutil.exe'
            - '\msbuild.exe'
    condition: selection_target_browsers and selection_source_injectors
fields:
    - SourceImage
    - TargetImage
falsepositives:
    - Legitimate third-party password managers or security agents injecting extensions or hooks into browsers.
    - Official software updates or browser management utilities.
level: high
tags:
    - attack.collection
    - attack.t1185
    - analytics.an1398
    - detection.det0507
```

title: Collection - Browser Process Access and Session Hijacking (OCSF-Normalized)

            - '\powershell.exe'
            - '\cmd.exe'

        # We look for browser strings in target command line or related fields if mapped

    - process.cmd_line

    - Security agent hooks or administrative browser plugins.

    - attack.collection

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Security Agents / Password Managers (Noise)**
    * *The Issue:* Anti-virus, EDR agents, or enterprise password managers (e.g. LastPass, 1Password desktop apps) regularly inspect browser processes or inject helper modules, triggering frequent alerts.
    * *The Fix:* Baseline the environment and whitelist official security agents or password manager binaries by checking their digital signature certificates.

* **Problem 2: Offline Cookie Database Theft**
    * *The Issue:* The adversary can copy the SQLite cookie databases (e.g. `%LocalAppData%\Google\Chrome\User Data\Default\Network\Cookies`) off the disk directly instead of interacting with the running process memory, bypassing process injection logs.
    * *The Fix:* Implement file access auditing (Sysmon Event ID 11) for non-browser processes attempting to read or copy files inside browser profile folders.

* **Problem 3: Standard Browser Update Engine Checks**
    * *The Issue:* Google Update or Microsoft Edge Update services regularly query browser instances to manage updates.
    * *The Fix:* Exclude updates signed by Microsoft or Google from the alert rule.
