### **1. Technique Breakdown: T1489**

* **What it is:** **Service Stop**. Adversaries stop or disable critical endpoint services (such as antivirus programs, firewalls, database servers, or mail transfer agents) to impair system defenses or disrupt business-critical applications (preceding encryption or data destruction). They execute service stops using Windows CLI commands (`sc.exe stop`, `net.exe stop`) or PowerShell commands (`Stop-Service`).
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs the execution of utilities modifying service states. Windows System Event Log ID 7036 (Service entered stopped state) can also verify the stop action.
* **NIDS (Suricata + Zeek): NO.** Stopping local operating system services does not create network logs.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of command-line tools stopping or disabling critical security or infrastructure services.

```yaml
title: Stopping or Disabling Critical System Services via CLI (AN0061)
id: 2fee4075-946d-4115-a345-92d112d3aaae
status: experimental
description: Detects command-line execution of sc.exe, net.exe, or PowerShell cmdlets stopping or disabling critical system services (e.g. anti-virus, firewalls, databases).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_tools:
        - Image|endswith:
            - '\sc.exe'
            - '\net.exe'
            - '\net1.exe'
        - OriginalFileName:
            - 'sc.exe'
            - 'net.exe'
            - 'net1.exe'
    selection_action:
        CommandLine|contains:
            - 'stop'
            - 'config'
    selection_services:
        CommandLine|contains:
            - 'WinDefend'
            - 'MpsSvc'
            - 'Sentinel'
            - 'Wazuh'
            - 'Sysmon'
            - 'CarbonBlack'
            - 'CrowdStrike'
            - 'Sophos'
            - 'MSExchange'
            - 'MSSQL'
            - 'disable'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_args:
        CommandLine|contains:
            - 'Stop-Service'
            - 'Set-Service'
        CommandLine|contains:
            - 'WinDefend'
            - 'MpsSvc'
            - 'Sentinel'
            - 'Wazuh'
            - 'Sysmon'
            - 'Disabled'
    condition: (selection_tools and selection_action and selection_services) or (selection_powershell and selection_powershell_args)
falsepositives:
    - IT administration tasks during database upgrades, security agent updates, or system troubleshooting.
level: high
tags:
    - attack.impact
    - attack.t1489
    - analytics.an0061
    - detection.det0021
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Service Stop API Calls**
* *The Issue:* Attackers can execute compiled binaries (written in C++ or C#) that directly call the Windows Service Control Manager APIs (`OpenSCManager`, `OpenService`, `ControlService` with `SERVICE_CONTROL_STOP`), which stops the service programmatically without executing `sc.exe` or `net.exe` command utilities.
* *The Fix:* Monitor Windows Security Event ID 4697 (A service was installed) or System Event ID 7036 (Service entered stopped state) targeting critical defender or infrastructure service names, and alert if the state transitions to stopped without a matched admin user login context.


* **Problem 2: Killing Service Processes Directly**
* *The Issue:* Attackers with high privileges can bypass service control entirely by terminating the service executable process directly (e.g., using `taskkill /f /im sentinelagent.exe` or killing the PID via PowerShell), which stops the service immediately.
* *The Fix:* Enable auditing of process termination (Event ID 4689) and monitor Sysmon Event ID 1 for termination commands, whitelisting only authorized installer parents (such as `msiexec.exe` or trusted patch installers).


* **Problem 3: Standard IT Upgrades and Agent Maintenance**
* *The Issue:* Security teams routinely upgrade security agents, stopping the local service temporarily during the upgrade process, triggering alerts.
* *The Fix:* Whitelist approved vendor installer processes (like `SentinelInstall.exe`) and check the parent-child lineage to verify the upgrade context.
