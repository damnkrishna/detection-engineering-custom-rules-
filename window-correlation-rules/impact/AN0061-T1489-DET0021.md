### 1. Technique Breakdown: T1489

* What it is: Service Stop. Adversaries stop or disable critical endpoint services (such as antivirus programs, firewalls, database servers, or mail transfer agents) to impair system defenses or disrupt business-critical applications (preceding encryption or data destruction). They execute service stops using Windows CLI commands (sc.exe stop, net.exe stop) or PowerShell commands (Stop-Service).
* Log Source Requirements: Endpoint logs capturing process creation and command line parameters (Sysmon Event ID 1 / Windows Security Event ID 4688) and PowerShell script block logs (Sysmon Event ID 4104).
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 logs the execution of utilities modifying service states. Sysmon Event ID 4104 (Script Block) logs PowerShell scripts stopping services.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Stopping critical services can be detected using process creation and PowerShell script block logs.

### 2. Custom Sigma Rule

The detection logic is split into command-line utility execution and PowerShell script block logging.

Rule 1 of 2: Stopping or Disabling Critical System Services via CLI (Process Creation)
```yaml
title: Stopping or Disabling Critical System Services via CLI (AN0061-A)
id: 2fee4075-946d-4115-a345-92d112d3aaae
status: experimental
description: Detects command-line execution of sc.exe, net.exe, or net1.exe stopping or disabling critical system services (e.g. anti-virus, firewalls, databases).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_tools:
        - Image|endswith:
            - '\sc.exe'
            - '\net.exe'
            - '\net1.exe'
        - OriginalFileName:
            - 'sc.exe'
            - 'net.exe'
            - 'net1.exe'
    selection_action:
        CommandLine|contains:
            - 'stop'
            - 'config'
    selection_services:
        CommandLine|contains:
            - 'WinDefend'
            - 'MpsSvc'
            - 'Sentinel'
            - 'Wazuh'
            - 'Sysmon'
            - 'CarbonBlack'
            - 'CrowdStrike'
            - 'Sophos'
            - 'MSExchange'
            - 'MSSQL'
            - 'disable'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_tools and selection_action and selection_services and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - IT administration tasks during database upgrades, security agent updates, or system troubleshooting.
level: high
tags:
    - attack.impact
    - attack.t1489
    - analytic.an0061
    - detection.det0021
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Direct Service Stop API Calls
  * The Issue: Attackers can execute compiled binaries (written in C++ or C#) that directly call the Windows Service Control Manager APIs programmatically without executing sc.exe or net.exe.
  * The Fix: Monitor Windows Security Event ID 4697 (A service was installed) or System Event ID 7036 (Service entered stopped state) targeting critical services.

* Problem 2: Killing Service Processes Directly
  * The Issue: Attackers can terminate the service executable process directly using taskkill or other process termination APIs.
  * The Fix: Enable auditing of process termination (Event ID 4689) and monitor Sysmon Event ID 1 for termination commands.

* Problem 3: Standard IT Upgrades and Agent Maintenance
  * The Issue: Security teams routinely upgrade security agents, stopping the local service temporarily during the upgrade process, triggering alerts.
  * The Fix: Whitelist approved vendor installer processes and check the parent-child lineage to verify the upgrade context.
