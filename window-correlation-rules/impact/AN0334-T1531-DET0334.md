### 1. Technique Breakdown: T1531

* What it is: Account Access Removal. Adversaries delete or disable local or domain user accounts (particularly administrator accounts) to lock out legitimate system administrators, prevent incident response recovery, or disrupt business operations. They execute account deactivations or deletions using command-line administrative tools (net.exe user <username> /delete or /active:no) or PowerShell cmdlets (Remove-LocalUser, Disable-LocalUser).
* Log Source Requirements: Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688) and PowerShell script block logs (Sysmon Event ID 4104).
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 logs CLI command parameters for user configuration utilities. Sysmon Event ID 4104 (Script Block) logs PowerShell script-based user management actions.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: User account access removal activity can be detected using process creation and PowerShell script block logs.

### 2. Custom Sigma Rule

The detection logic is split into command-line execution monitoring and script block content monitoring.

Rule 1 of 2: User Account Access Removal via CLI (Process Creation)
```yaml
title: User Account Access Removal via CLI (AN0334-A)
id: e7428d4c-c06b-4e08-b6d4-17fe9e06bd25
status: experimental
description: Detects command-line execution of net.exe or net1.exe used to delete, disable, or deactivate user accounts, which can be abused to lock out administrators.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_net:
        - Image|endswith:
            - '\net.exe'
            - '\net1.exe'
        - OriginalFileName:
            - 'net.exe'
            - 'net1.exe'
    selection_net_user:
        CommandLine|contains:
            - 'user'
    selection_net_action:
        CommandLine|contains:
            - '/delete'
            - 'active:no'
            - '/active:no'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_net and selection_net_user and selection_net_action and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate administrative account management tasks or automated user lifecycle provisioning scripts disabling inactive accounts.
level: high
tags:
    - attack.impact
    - attack.t1531
    - analytic.an0334
    - detection.det0334
```

Rule 2 of 2: User Account Access Removal via PowerShell Script Block (Script Block)
```yaml

```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Direct Active Directory LDAP/API Deletions
  * The Issue: Attackers can write scripts using LDAP API protocols or ADSI COM interfaces in .NET to delete/disable domain accounts directly without spawning CLI processes.
  * The Fix: Monitor Windows Security Event ID 4726 (A user account was deleted) and Event ID 4725 (A user account was disabled) on Domain Controllers.

* Problem 2: Local SAM API Bypasses
  * The Issue: Attackers can directly call Windows SAM APIs using compiled binaries to delete local accounts.
  * The Fix: Monitor Windows Security Event ID 4726 on endpoints and audit changes to HKLM\SAM\SAM.

* Problem 3: Automated HR/Identity Provisioning Noise
  * The Issue: HR integration scripts automatically disable or remove accounts during standard offboarding, causing false alarms.
  * The Fix: Whitelist known identity sync service accounts and administrative server IPs.
