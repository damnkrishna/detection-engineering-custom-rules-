### 1. Technique Breakdown: T1499.003

* What it is: Endpoint Denial of Service: Application Exhaustion Flood. Adversaries target application services (such as web servers, database endpoints, or custom enterprise APIs) with high-rate connection requests to consume execution threads, socket tables, or CPU.
* Log Source Requirements: Sysmon Network Connection events (Event ID 3) / Web Server Logs.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. High volume connections to local listening application ports can be captured by local endpoint network logs.
  - NIDS (Suricata + Zeek): YES. Rapid connection attempts targeting application ports are highly visible on network interfaces.
* Log Sources Covered:
  - Sysmon Event ID 3 (network_connection)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: High Connection Burst to Web Server Port
Detects network connections targeting local web server ports (80, 443, 8080, 8443) initiated by non-webserver, non-browser process engines, designed for SIEM-side volume aggregation.

```yaml
title: High Connection Burst to Web Server Port (AN1165-A)
id: f8041fd7-61e2-4cb0-ab40-24d5cc7a7938
status: experimental
description: Detects process connections targeting web ports. Pair with SIEM-side volume checks to detect flood attempts.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: network_connection
    product: windows
detection:
    selection_ports:
        DestinationPort:
            - 80
            - 443
            - 8080
            - 8443
    filter_browsers:
        Image|endswith:
            - '\chrome.exe'
            - '\firefox.exe'
            - '\msedge.exe'
    filter_webservers:
        # Exclude loopbacks or proxy traffic from webservers
        Image|endswith:
            - '\w3wp.exe'
            - '\nginx.exe'
            - '\httpd.exe'
            - '\tomcat.exe'
    condition: selection_ports and not (filter_browsers or filter_webservers)
fields:
    - Image
    - DestinationIp
    - DestinationPort
    - User
falsepositives:
    - Administrative update engines or development tools communicating with web services.
level: low
tags:
    - attack.impact
    - attack.t1499.003
    - analytic.an1165
    - detection.det0415
```

#### Rule 2 of 2: High Connection Burst to Database Server Port
Detects connection events targeting database server ports (1433, 3306, 5432, 1521) initiated by non-database, non-standard system interpreters. Designed for SIEM-side aggregation.

```yaml
title: High Connection Burst to Database Server Port (AN1165-B)
id: d886baae-081e-4ca1-aa0a-d5ab6d019b5d
status: experimental
description: Detects connection events targeting SQL or database ports. Pair with SIEM aggregation.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: network_connection
    product: windows
detection:
    selection_ports:
        DestinationPort:
            - 1433
            - 3306
            - 5432
            - 1521
    filter_db_engines:
        # Exclude connections made directly by database engines or drivers
        Image|endswith:
            - '\sqlserver.exe'
            - '\mysqld.exe'
            - '\postgres.exe'
            - '\oracle.exe'
    condition: selection_ports and not filter_db_engines
fields:
    - Image
    - DestinationIp
    - DestinationPort
    - User
falsepositives:
    - Application server database pooling clients or custom reporting scripts.
level: low
tags:
    - attack.impact
    - attack.t1499.003
    - analytic.an1165
    - detection.det0415
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Application Server Connection Pool Burst
  * The Issue: Custom application backends opening pools of connections to local databases will trigger false alarms under Rule 2.
  * The Fix: Baseline the approved application server IP addresses and binary images, and add them to custom database filter lists.
* Problem 2: SIEM-Side Aggregation Requirement
  * The Issue: Single connections targeting local ports trigger these rules.
  * The Fix: Configure a SIEM aggregation requiring more than 1000 connections from a single host process to a specific port within a 10-second window: `count(DestinationIp) by Image > 1000 in 10s`.
