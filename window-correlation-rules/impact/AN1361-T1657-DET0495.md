### 1. Technique Breakdown: T1657

* What it is: Financial Theft. Adversaries target retail endpoints, Point of Sale (POS) terminals, or billing servers to tamper with database transaction tables, modify accounting settings, or scrape credit card data from RAM, resulting in financial loss.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688, and Sysmon File Creation/Modification events (Event ID 11).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Scraping tools and database file writes are tracked.
  - NIDS (Suricata + Zeek): NO. Host-local application manipulation.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 11 (file_event)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: Point-of-Sale RAM Scraper Process Creation
Detects execution of processes or command-line parameters associated with known POS memory scrapers (e.g. Dexter, Alina, BlackPOS), requiring both the tool identity (Image or OriginalFileName) AND specific POS arguments.

```yaml
title: Point-of-Sale RAM Scraper Process Creation (AN1361-A)
id: 2796ca36-ebb5-4b99-867d-88bfca247223
status: experimental
description: Detects command-line execution of Point-of-Sale memory scrapers or tools scanning memory handles.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\alina.exe'
            - '\dexter.exe'
            - '\blackpos.exe'
            - '\poscard.exe'
            - '\memdump.exe'
    selection_orig:
        OriginalFileName:
            - 'alina.exe'
            - 'dexter.exe'
            - 'blackpos.exe'
            - 'poscard.exe'
            - 'memdump.exe'
    selection_cli:
        CommandLine|contains:
            - 'pos-scrape'
            - 'card-grab'
            - 'track2'
            - 'dump-ram'
    filter_installers:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_images or selection_orig) and selection_cli and not filter_installers
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Diagnostic tools or memory debuggers run by retail application support teams during maintenance.
level: critical
tags:
    - attack.impact
    - attack.t1657
    - analytic.an1361
    - detection.det0495
```

#### Rule 2 of 2: Transaction Database File Manipulation
Detects unexpected modifications to SQL or local database transaction files within POS/retail checkouts by non-standard systems, using scoped folder paths.

```yaml
title: Transaction Database File Manipulation (AN1361-B)
id: 9548c1a0-97a9-4889-bad9-bead0aa58409
status: experimental
description: Detects direct file writes or modifications to POS database files by interpreters or non-db binaries.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: file_event
    product: windows
detection:
    selection_paths:
        TargetFilename|contains:
            - '\pos_db\'
            - '\retail_sales\'
            - '\checkout_data\'
    selection_exts:
        TargetFilename|endswith:
            - '.mdf'
            - '.ldf'
            - '.db'
            - '.sqlite'
    filter_db_processes:
        Image|endswith:
            - '\sqlserver.exe'
            - '\mysqld.exe'
            - '\postgres.exe'
            - '\pos_service.exe'
    condition: selection_paths and selection_exts and not filter_db_processes
fields:
    - TargetFilename
    - Image
    - User
falsepositives:
    - Standard checkout terminal patches or software migrations updating db structures.
level: high
tags:
    - attack.impact
    - attack.t1657
    - analytic.an1361
    - detection.det0495
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative POS Updates
  * The Issue: Official upgrades to POS terminal databases will trigger Rule 2.
  * The Fix: Whitelist the signing certificate or process hashes of corporate software deployment agents (such as SCCM).
* Problem 2: Encryption or Hashing of Card Data
  * The Issue: Scrapers writing card data to encrypted archives can bypass pattern checks.
  * The Fix: Implement EID 8 and EID 10 monitoring (as in AN1097) to flag scraper injection attempts before data is staged.
