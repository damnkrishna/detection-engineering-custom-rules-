### 1. Technique Breakdown: T1565

* What it is: Data Manipulation. Adversaries modify structured data (such as SQL databases, SQLite files, audit logs, or financial logs) to cause operational disruption, alter transaction details, or conceal evidence of their activity. Detections monitor local file modification events targeting database formats (.db, .sqlite, .mdf) or audit logs (.evtx) by non-standard command shells or scripting engines, as well as process creation command lines invoking database utilities or event log wiping tools.
* Log Source Requirements: Endpoint logs capturing file creation, modification, or write events (Sysmon Event ID 11 / Windows Security Event ID 4663) and process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 11 logs file path names, extensions, and writing processes. Sysmon Event ID 1 captures database or log management CLI command execution.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Log Sources Covered:
  - Sysmon Event ID 11 (file_event)
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Database or log file modification activity can be detected using file event and process creation logs.

### 2. Custom Sigma Rule

The detection logic is split into file modification monitoring and command-line execution monitoring.

Rule 1 of 2: Database or Log File Modification by Non-Database Process via File Event (File Event)
```yaml
title: Database or Log File Modification by Non-Database Process via File Event (AN0162-A)
id: 8d8ac882-8adc-4630-bf06-7df142bfe220
status: experimental
description: Detects command-line interpreters or scripting hosts modifying or creating database files (e.g., .db, .sqlite, .mdf) or system log files (.evtx), which can indicate unauthorized data manipulation or log tempering.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: file_event
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
    selection_files:
        TargetFilename|endswith:
            - '.db'
            - '.sqlite'
            - '.sqlite3'
            - '.mdf'
            - '.ldf'
            - '.mdb'
            - '.accdb'
            - '.evtx'
    condition: selection_process and selection_files
fields:
    - Image
    - TargetFilename
falsepositives:
    - Legitimate administration scripts managing local SQLite databases or backing up event log files (.evtx).
level: medium
tags:
    - attack.impact
    - attack.t1565
    - analytic.an0162
    - detection.det0162
```

Rule 2 of 2: Database or Log File Modification by Non-Database Process via CLI (Process Creation)
```yaml
title: Database or Log File Modification by Non-Database Process via CLI (AN0162-B)
id: 6a8118fd-9db5-430b-8029-bed701b7c385
status: experimental
description: Detects command-line commands attempting to manipulate databases or clear Windows event logs using utilities like wevtutil or database engines.
author: Krishna Gupta
date: 2026-06-16
logsource:
    category: process_creation
    product: windows
detection:
    selection_tools:
        - Image|endswith:
            - '\wevtutil.exe'
            - '\sqlite3.exe'
        - OriginalFileName:
            - 'wevtutil.exe'
            - 'sqlite3.exe'
    selection_commands:
        CommandLine|contains:
            - ' cl '
            - 'clear-eventlog'
            - 'clear-log'
            - 'update '
            - 'delete '
    condition: selection_tools or selection_commands
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - User
falsepositives:
    - Legitimate event log rotations or database maintenance scripts.
level: medium
tags:
    - attack.impact
    - attack.t1565
    - analytic.an0162
    - detection.det0162
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Database Engine API Execution (SQL Injection)
  * The Issue: If the attacker has access to a database console they can modify data inside database tables by running standard SQL queries inside the database process, which does not spawn scripting hosts, bypassing file modification audits.
  * The Fix: Enable query auditing within the DBMS itself.

* Problem 2: Log Wiping via Clear-EventLog API
  * The Issue: Attackers can clear Windows event logs using built-in APIs, which wipes the .evtx file without spawning separate file modification events.
  * The Fix: Monitor the execution of wevtutil.exe with clearing arguments and audit Security Event ID 1102.

* Problem 3: Standard Application Database Syncs
  * The Issue: Many desktop applications use local SQLite databases, causing false alerts if scripts access them.
  * The Fix: Restrict this rule to monitor changes to high-value server directories such as %SystemRoot%\System32\Winevt\Logs\.
