### **1. Technique Breakdown: T1495**

* **What it is:** **Firmware Corruption**. Adversaries modify or corrupt system firmware (such as UEFI, BIOS, or hard drive controller firmware) to make the target system completely inoperable and brick the hardware. In Windows environments, firmware or boot sequence tampering is preceded by command-line execution of tools like `bcdedit.exe` to modify the Boot Configuration Data (BCD) store, disabling boot recovery menus (`recoveryenabled No`) or configuring the OS to ignore boot failures (`bootstatuspolicy ignoreallfailures`), preventing recovery.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures `bcdedit.exe` executions with full command parameters. Wazuh aggregates these to flag BCD store tampering.
* **NIDS (Suricata + Zeek): NO.** Local Boot Configuration Data modification is entirely offline and generates no network telemetry.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of `bcdedit.exe` modifying boot configurations to disable recovery features or ignore boot status failures.

```yaml
title: Boot Configuration Tampering via Bcdedit (AN0474)
id: faad8c3b-e2ea-49f3-ba30-8d52b2a73e47
status: experimental
description: Detects command-line modifications using bcdedit.exe to disable boot recovery options, disable safe boot configurations, or set anomalous boot configurations, which is typical of destructive ransomware and system disruption.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_bcdedit:
        - Image|endswith: '\bcdedit.exe'
        - OriginalFileName: 'bcdedit.exe'
    selection_args:
        CommandLine|contains:
            - '/set'
            - '/deletevalue'
        CommandLine|contains:
            - 'recoveryenabled'
            - 'bootstatuspolicy'
            - 'ignoreallfailures'
            - 'safeboot'
    condition: selection_bcdedit and selection_args
falsepositives:
    - IT administrators configuring boot options during OS installation or system maintenance.
level: high
tags:
    - attack.impact
    - attack.t1495
    - analytics.an0474
    - detection.det0167
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Registry/API BCD Modifications**
* *The Issue:* The Boot Configuration Data store is mapped to a registry hive under `HKLM\BCD`. Attackers can use administrative scripts or custom tools to write directly to these registry paths without launching `bcdedit.exe`, bypassing command-line process monitors.
* *The Fix:* Enable registry auditing on the path `HKLM\BCD` and monitor Sysmon Event ID 13 (Registry Value Set) for changes inside the BCD registry paths.


* **Problem 2: Vendor Firmware Utilities**
* *The Issue:* Attackers can use vendor-specific BIOS/UEFI flashing utilities (e.g., Lenovo, Dell, HP UEFI update binaries) downloaded onto the host to directly corrupt or flash the BIOS without modifying BCD settings.
* *The Fix:* Audit the installation and execution of known vendor firmware tools, whitelisting only official corporate update installers.


* **Problem 3: Standard IT OS Deployment and Patching**
* *The Issue:* Automated OS deployment tools and IT patch management services regularly run scripts that adjust boot loader parameters during system upgrades, generating false alerts.
* *The Fix:* Whitelist known SCCM or domain deployment service accounts, and restrict alerting to systems outside of approved system maintenance hours.
