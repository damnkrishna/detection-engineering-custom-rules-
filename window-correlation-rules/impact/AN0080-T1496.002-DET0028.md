### **1. Technique Breakdown: T1496.002**

* **What it is:** **Resource Hijacking: Joint Bandwidth Hijacking**. Adversaries hijack a compromised system's network bandwidth to run proxy services (known as proxyjacking, e.g., Honeygain, EarnApp, PacketStream) or execute botnet-driven scanning tasks. This allows the attacker to monetize the victim's internet connection or route malicious traffic through their IP space, resulting in severe performance degradation and reputation blacklisting. Detections monitor the execution of known bandwidth-sharing or high-volume scanning binaries.
* **Log Source Requirements:** Endpoint logs capturing process creation (Sysmon Event ID 1 / Windows Security Event ID 4688) or network connection logs (Sysmon Event ID 3).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs the execution of proxyjacking and scanning client files. Sysmon Event ID 3 captures outbound socket connections to bandwidth-sharing coordinator nodes. Wazuh aggregates these activities.
* **NIDS (Suricata + Zeek): YES.** Zeek `conn.log` and `http.log`/`ssl.log` record connection handshakes to known proxyjacking domain endpoints.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of known bandwidth sharing, proxyjacking, or unauthorized massive scanning utilities.

```yaml
title: Execution of Bandwidth Hijacking or Proxyjacking Software (AN0080)
id: e7856938-b0cf-4af8-8c19-49f93161f756
status: experimental
description: Detects command-line execution of known proxyjacking, bandwidth sharing, or botnet scanning software, which is used for bandwidth hijacking and resource abuse.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_rmm:
        - Image|endswith:
            - '\honeygain.exe'
            - '\packetstream.exe'
            - '\peer2profit.exe'
            - '\earnapp.exe'
            - '\iproyal.exe'
            - '\masscan.exe'
        - OriginalFileName:
            - 'honeygain.exe'
            - 'packetstream.exe'
            - 'peer2profit.exe'
            - 'earnapp.exe'
            - 'iproyal.exe'
            - 'masscan.exe'
    condition: selection_rmm
falsepositives:
    - Highly unlikely in enterprise environments. Standard employees should not be running bandwidth-sharing applications.
level: high
tags:
    - attack.impact
    - attack.t1496.002
    - analytics.an0080
    - detection.det0028
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: In-Memory Script-Based Bandwidth Hijacking**
* *The Issue:* Attackers can execute proxy client code in-memory (e.g., loading a Docker container or using compiled scripts in Python/Go) without writing a stand-alone binary like `honeygain.exe` to disk, avoiding standard process name blocks.
* *The Fix:* Complement this rule with network-level telemetry monitoring, checking for sustained outbound TCP/UDP sessions to known proxy network controller IP subnets.


* **Problem 2: Execution of Renamed Proxy Clients**
* *The Issue:* Attackers can download a proxy client, rename it to a generic system binary (like `svchost.exe`), and execute it to bypass process name filters.
* *The Fix:* Inspect the `OriginalFileName` and digital signature publisher metadata fields in Sysmon Event ID 1 process logs, which remain unchanged despite renaming.


* **Problem 3: Authorized Security Scanning Noise**
* *The Issue:* Authorized corporate security teams or automated asset discovery scanners may run `masscan` or `nmap` during regular audits, generating false positives.
* *The Fix:* Whitelist approved vulnerability scanning hosts and audit user accounts.
