### **1. Technique Breakdown: T1485**

* **What it is:** **Data Destruction**. Adversaries permanently delete or overwrite sensitive files, directories, or backups on host machines to cause operational disruption or to cover evidence of intrusion. To ensure files cannot be recovered, they employ file wiping utilities (such as `sdelete.exe` or `cipher.exe /w`) or delete Windows Volume Shadow Copies (`vssadmin.exe delete shadows`, `wmic shadowcopy delete`) to remove local system backup states.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs parent processes, target processes, and command line parameters for shadow copy management or wiper tools. Wazuh aggregates these activities.
* **NIDS (Suricata + Zeek): NO.** Local backup deletions and disk overwrites are offline events that generate no network telemetry.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the execution of command-line tools wiping files or deleting Volume Shadow Copies.

```yaml
title: File Wiping or Volume Shadow Copy Deletion (AN0411)
id: 6fcfff22-6761-4c74-9049-cd66a7daa6cd
status: experimental
description: Detects command-line execution of tools used for data destruction, such as sdelete, cipher /w, or commands deleting Volume Shadow Copies (vssadmin, wmic).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_shadow:
        CommandLine|contains:
            - 'delete shadows'
            - 'shadowcopy delete'
            - 'delete catalog'
            - 'resize shadowstorage'
    selection_wipers:
        - Image|endswith:
            - '\sdelete.exe'
        - CommandLine|contains:
            - 'cipher.exe /w'
            - 'cipher /w'
    condition: selection_shadow or selection_wipers
falsepositives:
    - Legitimate administrative scripts purging old backup catalogs or system shadow storages during system upgrades.
level: high
tags:
    - attack.impact
    - attack.t1485
    - analytics.an0411
    - detection.det0146
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Raw Disk Access API Wiping**
* *The Issue:* Attackers can write custom malware that bypasses command line utilities entirely, writing zeros or random data directly to disk blocks using Win32 raw handle APIs (`CreateFile` with `\\.\PhysicalDrive0`), which does not call `sdelete` or `cipher`.
* *The Fix:* Enable auditing for raw block access (such as monitoring Sysmon Event ID 9: Raw Access Read, or Event ID 10 for process access) and block non-system processes accessing local drives raw.


* **Problem 2: PowerShell API Shadow Deletions**
* *The Issue:* Instead of using `vssadmin` or `wmic` command lines, attackers can invoke WMI or CIM classes in PowerShell directly (e.g. `Get-WmiObject Win32_ShadowCopy | ForEach-Object { $_.Delete() }`), which bypasses simple CLI string checks for `delete shadows`.
* *The Fix:* Enable PowerShell Script Block Logging (Event ID 4104) and create alerts for scripts calling `Win32_ShadowCopy` delete methods.


* **Problem 3: Standard IT Disk Cleanup Noise**
* *The Issue:* Automated disk space reclaim scripts or Microsoft SCCM software deployment agents may resize shadow storage or run disk cleanup scripts, causing false positives.
* *The Fix:* Whitelist approved backup service accounts and check parent process signatures.
