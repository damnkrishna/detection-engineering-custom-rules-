### 1. Technique Breakdown: T1667

* What it is: Email Bombing. Adversaries send a high volume of emails to target addresses or use local relays to flood mail systems, aiming to exhaust mail queues, crash mail gateways, or distract security operations.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688, and Sysmon Network Connection events (Event ID 3).
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Tool executions and network connection frequencies are tracked.
  - NIDS (Suricata + Zeek): YES. Mail flooding traffic can be flagged at the network boundary.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 3 (network_connection)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 2: High Frequency SMTP Tool Execution
Detects the process creation of command-line email utilities or script execution commonly used for generating bulk mail traffic, requiring both tool identity and specific SMTP arguments.

```yaml
title: High Frequency SMTP Tool Execution (AN1008-A)
id: 53a5ccc0-c21f-4461-afba-a992c2dcd02b
status: experimental
description: Detects command-line execution of mail tools or scripting wrappers attempting to generate high-frequency email traffic.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\swaks.exe'
            - '\sendmail.exe'
            - '\postfix.exe'
            - '\blat.exe'
            - '\mailsend.exe'
    selection_orig:
        OriginalFileName:
            - 'swaks.exe'
            - 'sendmail.exe'
            - 'postfix.exe'
            - 'blat.exe'
            - 'mailsend.exe'
    selection_cli:
        CommandLine|contains:
            - 'Send-MailMessage'
            - ' -smtp '
            - ' -mailfrom '
            - ' -to '
            - ' -server '
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_images or selection_orig) and selection_cli and not filter_installer
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Administrative notifications or monitoring alerts launched by automated scripts.
level: medium
tags:
    - attack.impact
    - attack.t1667
    - analytic.an1008
    - detection.det0355
```

#### Rule 2 of 2: Outbound Mail Connection Burst
Detects network connections to default SMTP ports (25, 465, 587) from non-standard email applications. This rule should be paired with SIEM-side volume aggregation.

```yaml
title: Outbound Mail Connection Burst (AN1008-B)
id: b293efd0-6e6f-4fb0-b672-3ace1501b614
status: experimental
description: Detects outbound network connections to SMTP ports (25, 465, 587) from non-standard email applications. This rule should be aggregated in the SIEM layer to count burst patterns.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: network_connection
    product: windows
detection:
    selection_ports:
        DestinationPort:
            - 25
            - 465
            - 587
    filter_clients:
        Image|endswith:
            - '\outlook.exe'
            - '\thunderbird.exe'
            - '\msedge.exe'
            - '\chrome.exe'
    condition: selection_ports and not filter_clients
fields:
    - Image
    - DestinationIp
    - DestinationPort
    - User
falsepositives:
    - Developer machines testing local mail routing setup or diagnostic testing.
level: low
tags:
    - attack.impact
    - attack.t1667
    - analytic.an1008
    - detection.det0355
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Loops vs. Attacks
  * The Issue: Backup scripts or alert tools sending system diagnostics can trigger Rule 1.
  * The Fix: Baseline administrative script directories and restrict execution contexts or add their paths to custom exclusions.
* Problem 2: SIEM-Side Aggregation Requirement
  * The Issue: Rule 2 matches single outbound connection events.
  * The Fix: Configure a SIEM aggregation rule requiring more than 200 outbound mail connections from a single non-standard process within a 1-minute window to alert on a network flood: `count(DestinationIp) by Image > 200 in 1m`.
