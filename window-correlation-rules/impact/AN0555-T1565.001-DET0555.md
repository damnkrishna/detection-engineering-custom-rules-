### **1. Technique Breakdown: T1565.001**

* **What it is:** **Stored Data Manipulation**. Adversaries modify business-critical stored data (such as Office documents, PDF sheets, or text databases) to disrupt operations, alter business communications, or plant malicious macros/payloads. Under Windows, they use command-line shells or scripting engines to scan directories and modify file contents. Detections monitor local file modification events targeting document formats (`.docx`, `.xlsx`, `.pdf`) by execution shells.
* **Log Source Requirements:** Endpoint logs capturing file creation, modification, or write events (Sysmon Event ID 11 / Windows Security Event ID 4663).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 11 logs file path names, extensions, and writing processes. Wazuh aggregates these activities to detect unauthorized writes.
* **NIDS (Suricata + Zeek): NO.** Local stored file manipulation occurs entirely within the host filesystem. Network tools can audit file transfers, but cannot track local file modifications.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 11 (File Create)** to detect business office document files (`.docx`, `.xlsx`, `.pdf`) being created or modified by scripting hosts or command-line interpreters.

```yaml
title: Stored Office Document Modification by Scripting Host (AN0555)
id: cc64d033-ce6a-4013-9aea-ac2a69e251ed
status: experimental
description: Detects command-line interpreters or scripting hosts creating or modifying business-critical office documents (e.g. .docx, .xlsx, .pdf), which can indicate unauthorized stored data manipulation.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: file_event
    product: windows
    # Relies on Sysmon Event ID 11 collected via Wazuh
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
    selection_files:
        TargetFilename|endswith:
            - '.docx'
            - '.xlsx'
            - '.pptx'
            - '.pdf'
            - '.odt'
            - '.ods'
    condition: selection_process and selection_files
falsepositives:
    - Legitimate enterprise automation scripts performing automated report compilation, PDF generation, or document migration.
level: medium
tags:
    - attack.impact
    - attack.t1565.001
    - analytics.an0555
    - detection.det0555
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Bulk Encryption (Ransomware) Detection Overlaps**
* *The Issue:* Ransomware encrypts office documents in bulk, which generates a large volume of file write and rename logs. This rule will alert on ransomware encryption processes, but simple single-event rules can cause high noise.
* *The Fix:* Implement a rate-limiting or threshold correlation in the SIEM that triggers if a process modifies more than 20 unique office documents within 10 seconds.


* **Problem 2: Use of Legitimate Document Editors**
* *The Issue:* If the attacker executes their file manipulation using official MS Office macro scripts (VBA) inside Word or Excel, the writing process will be `winword.exe` or `excel.exe` rather than command-line hosts, bypassing scripting host filters.
* *The Fix:* Enable VBA macro auditing (Security Event ID 4104 / Office telemetry logs) and monitor execution of macro-enabled documents spawned from internet-downloaded templates.


* **Problem 3: Standard Reporting Services**
* *The Issue:* SQL Server Reporting Services (SSRS) or automated corporate dashboard tools regularly export reports to PDF or Excel formats.
* *The Fix:* Whitelist known report-generation service accounts and restrict alerting to user-writable directories (like `%TEMP%` or `%APPDATA%`).
