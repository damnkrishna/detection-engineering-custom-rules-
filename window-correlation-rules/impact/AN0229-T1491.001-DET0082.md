### **1. Technique Breakdown: T1491.001**

* **What it is:** **Internal Defacement**. Adversaries modify the UI displays of internal systems or user endpoints to convey a message (such as ransom instructions, political statements, or compromise alerts). In Windows environments, this includes hijacking the system pre-logon warning message by altering registry values `legalnoticecaption` and `legalnoticetext` under `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System`, or modifying the user desktop wallpaper registry keys under `HKCU\Control Panel\Desktop\wallpaper` via scripting tools.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs process spawning of tools modifying registry parameters. Additionally, Sysmon Event ID 13 (Registry Value Set) can track direct value changes.
* **NIDS (Suricata + Zeek): NO.** Local registry modifications for login banners or wallpapers do not generate network logs.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line modifications altering Windows logon warning banners or wallpaper configurations.

```yaml
title: Registry Modification for System Logon Defacement (AN0229)
id: b80628f8-3a02-490f-9ef3-bcaabaf1b5ff
status: experimental
description: Detects command-line registry modifications targeting Windows logon legal notice banners or wallpaper registry values, which can indicate system defacement.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_cmd:
        CommandLine|contains:
            - 'Policies\System'
            - 'Control Panel\Desktop'
        CommandLine|contains:
            - 'legalnoticecaption'
            - 'legalnoticetext'
            - 'wallpaper'
        CommandLine|contains:
            - 'reg'
            - 'add'
            - 'Set-ItemProperty'
            - 'New-ItemProperty'
    condition: selection_cmd
falsepositives:
    - IT administration deploying corporate warning banners or setting default company wallpapers.
level: medium
tags:
    - attack.impact
    - attack.t1491.001
    - analytics.an0229
    - detection.det0082
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Registry API Overrides**
* *The Issue:* Attackers can use compiled binaries calling native Win32 APIs (like `RegSetValueExW`) directly to rewrite the legal notice and wallpaper keys without executing `reg.exe` or PowerShell commands, bypassing process creation audits.
* *The Fix:* Enable registry auditing and monitor Sysmon Event ID 13 (Registry Value Set) targeting the path `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System` and `HKCU\Control Panel\Desktop\`.


* **Problem 2: Group Policy Object (GPO) Overrides**
* *The Issue:* If the attacker has compromised the Active Directory Domain Controller, they can deploy logon banners and wallpapers globally using a Domain GPO. Local registry monitors on workstations will see these writes as legitimate GPO applications (originating from `gpsvc` / `svchost.exe`), making local CLI alerts ineffective.
* *The Fix:* Monitor active directory policy changes (Security Event ID 5136 / Event ID 4713) and audit changes to GPO templates in the domain controller SYSVOL share.


* **Problem 3: Standard Corporate Wallpaper / Policy Updates**
* *The Issue:* IT departments regularly modify corporate login notices and change corporate wallpapers during company updates, generating false alarms.
* *The Fix:* Whitelist official IT deployment service accounts, and verify change management logs during GPO pushes.
