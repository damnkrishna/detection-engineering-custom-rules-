### 1. Technique Breakdown: T1491.001

* What it is: Internal Defacement. Adversaries modify the UI displays of internal systems or user endpoints to convey a message (such as ransom instructions, political statements, or compromise alerts). In Windows environments, this includes hijacking the system pre-logon warning message by altering registry values legalnoticecaption and legalnoticetext under HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System, or modifying the user desktop wallpaper registry keys under HKCU\Control Panel\Desktop\wallpaper.
* Log Source Requirements: Registry modification logs (Sysmon Event ID 13) and host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688) tracking execution.
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 13 (Registry Set) is perfectly suited to track direct value modifications to defacement keys. Sysmon Event ID 1 captures command-line registry utilities or powershell cmdlets attempting these modifications.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Log Sources Covered:
  - Sysmon Event ID 13 (registry_set)
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Registry-based system defacement modifications can be detected using registry set and process creation logs.

### 2. Custom Sigma Rule

The detection logic is split into registry modification monitoring and command-line execution monitoring.

Rule 1 of 2: Registry Modification for System Logon Defacement via Registry Set (Registry Set)
```yaml
title: Registry Modification for System Logon Defacement via Registry Set (AN0229-A)
id: b80628f8-3a02-490f-9ef3-bcaabaf1b5ff
status: experimental
description: Detects registry modifications targeting Windows logon legal notice banners or wallpaper registry values, which can indicate system defacement.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: registry_set
    product: windows
detection:
    selection_target:
        TargetObject|contains:
            - '\Policies\System\legalnoticecaption'
            - '\Policies\System\legalnoticetext'
            - '\Control Panel\Desktop\wallpaper'
    condition: selection_target
fields:
    - TargetObject
    - Image
    - User
falsepositives:
    - IT administration deploying corporate warning banners or setting default company wallpapers.
level: medium
tags:
    - attack.impact
    - attack.t1491.001
    - analytic.an0229
    - detection.det0082
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Direct Registry API Overrides
  * The Issue: Attackers can call native Win32 APIs directly to rewrite the logon notice and wallpaper keys without executing reg.exe or PowerShell.
  * The Fix: Rely on registry set monitoring (Rule 1) to catch direct API value modifications.

* Problem 2: Group Policy Object (GPO) Overrides
  * The Issue: If attackers compromise a Domain Controller, they can deploy defacement settings via domain GPOs, which look like legitimate GPO applications on the endpoints.
  * The Fix: Monitor active directory policy changes (Event ID 5136 / Event ID 4713) on the Domain Controller.

* Problem 3: Standard Corporate Wallpaper / Policy Updates
  * The Issue: IT departments modify login notices and corporate wallpapers, causing false alarms.
  * The Fix: Whitelist authorized IT administrator credentials and deployment service accounts.
