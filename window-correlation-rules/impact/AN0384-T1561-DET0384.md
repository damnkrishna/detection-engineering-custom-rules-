### 1. Technique Breakdown: T1561

* What it is: Disk Wipe. Adversaries destroy primary storage volumes, logical partitions, or Master Boot Records (MBR) on targeted systems, making the hosts completely unbootable and destroying all stored data. Under Windows, they abuse built-in utilities (like `diskpart.exe`, `format.com`, or `fsutil.exe`) to execute destructive routines (such as partition deletions, disk cleans, or volume dismounts).
* Log Source Requirements: Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures the invocation of disk utility tools along with destructive CLI arguments. Wazuh forwards these to alert on system destruction behavior.
* NIDS (Suricata + Zeek): NO. Disk formatting and MBR destruction occur entirely locally on the storage subsystem and generate no network logs.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of disk formatting, partition deletion, or raw disk management utilities (`diskpart.exe`, `format.com`, `fsutil.exe`) with destructive arguments.

```yaml
title: Disk Wiping and Partition Destruction Utilities (AN0384)
id: 09df714a-0a0c-42f4-b9a0-439b48288311
status: experimental
description: Detects command-line execution of disk formatting, partition management, or raw volume dismounting tools (such as diskpart, format, fsutil) used in disk wiping.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_diskpart:
        - Image|endswith:
            - '\diskpart.exe'
            - '\format.com'
            - '\fsutil.exe'
        - OriginalFileName:
            - 'diskpart.exe'
            - 'format.com'
            - 'fsutil.exe'
    selection_args:
        CommandLine|contains:
            - 'clean'
            - 'delete partition'
            - 'format'
            - 'dismount'
            - 'volume dismount'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_diskpart and selection_args and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - IT administrators formatting external drives or scripting storage setups on new server clusters.
level: high
tags:
    - attack.impact
    - attack.t1561
    - analytic.an0384
    - detection.det0384
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Raw Driver/Kernel Level MBR Wiping
  * The Issue: Destroyers like NotPetya or HermeticWiper write directly to the MBR sector (\\.\PhysicalDrive0) using low-level API operations or load customized unsigned drivers to gain direct sector-level write permissions, completely bypassing standard high-level CLI utilities like diskpart.exe.
  * The Fix: Enable auditing for raw block access (Sysmon Event ID 9: Raw Access Read) and monitor for processes opening handles to raw physical drives.

* Problem 2: PowerShell CIM/WMI Storage Management
  * The Issue: Attackers can use PowerShell CIM/WMI cmdlets (like Clear-Disk, Remove-Partition, Format-Volume) to wipe disks, which does not spawn diskpart.exe or format.com, bypassing utility name filters.
  * The Fix: Enable PowerShell Script Block Logging (Event ID 4104) and monitor scripts invoking storage-management namespaces.

* Problem 3: IT Automated OS Deployment
  * The Issue: Staging servers and OS imaging systems routinely execute disk cleaning and partitioning scripts, creating regular alerts.
  * The Fix: Whitelist imaging servers and deployment accounts.
