### 1. Technique Breakdown: T1546.001

* What it is: Event Triggered Execution: Change Default File Association. When a user double-clicks or opens a file, the Windows operating system executes the default application associated with that file extension (e.g., Notepad for `.txt` files). Adversaries modify these default associations (stored in registry hives under `HKLM\SOFTWARE\Classes` or `HKCU\Software\Classes`) using utilities like `assoc.exe` or `ftype.exe`, or registry modifications. This causes a malicious binary to run whenever a specific, commonly-opened file type is loaded.
* Log Source Requirements: Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs process execution of `assoc.exe`, `ftype.exe`, and registry editing commands. Sysmon Event ID 13 (Registry Value Set) also records specific value modifications.
* NIDS (Suricata + Zeek): NO. Changing default file associations is a local configuration task and produces no network-level indicators.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of `assoc.exe` or `ftype.exe` command-line tools, or registry modifications targeting default application handlers.

```yaml
title: Change Default File Association via CLI (AN0170)
id: 13284360-c20f-4a2b-8220-0967f42fbd90
status: experimental
description: Detects command-line execution of assoc.exe or ftype.exe, or reg.exe modifications to system file association keys, which can be abused for privilege escalation and persistence.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_tools:
        - Image|endswith:
            - '\assoc.exe'
            - '\ftype.exe'
        - OriginalFileName:
            - 'assoc.exe'
            - 'ftype.exe'
    selection_reg:
        - Image|endswith:
            - '\reg.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'reg.exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_reg_args:
        CommandLine|contains:
            - '\Software\Classes\'
            - 'HKCR\'
        CommandLine|contains:
            - '\shell\open\command'
        CommandLine|contains:
            - 'reg'
            - 'add'
            - 'Set-ItemProperty'
            - 'New-ItemProperty'
    condition: selection_tools or (selection_reg and selection_reg_args)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate application installers altering default handlers during setup (e.g., PDF readers, web browsers, text editors).
level: medium
tags:
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1546.001
    - analytic.an0170
    - detection.det0061
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
