### **1. Technique Breakdown: T1055.001**

* **What it is:** **Process Injection: Dynamic-link Library Injection**. Adversaries inject a path to a malicious DLL into the memory space of a remote process and force that process to load the DLL. This is commonly done by allocating memory (`VirtualAllocEx`), writing the DLL path string (`WriteProcessMemory`), and then calling `CreateRemoteThread` passing the address of `LoadLibraryA` (or `LoadLibraryW`) as the thread's start routine. This forces the target process to load and execute the attacker's DLL.
* **Log Source Requirements:** Sysmon Event ID 8 (CreateRemoteThread), Sysmon Event ID 7 (Image Loaded).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 8 captures the remote thread creation, and the `StartAddress` often points directly to `LoadLibrary`.
    * **NIDS (Suricata + Zeek): NO.** Local memory execution.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 8 (CreateRemoteThread)** to detect cross-process thread creation where the thread's starting address points directly to the `LoadLibrary` function, a hallmark of classic DLL injection.

```yaml
title: Suspicious Remote Thread Creation (LoadLibrary Injection) (AN1095)
id: fbbcc3f9-676b-4e6c-a8eb-8b0ab3606f1d
status: experimental
description: Detects DLL injection by monitoring CreateRemoteThread events where the StartAddress points to LoadLibrary functions.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: create_remote_thread
    product: windows
    # Relies on Sysmon Event ID 8 collected via Wazuh
detection:
    selection_target:
        TargetImage|endswith:
            - '\explorer.exe'
            - '\svchost.exe'
            - '\lsass.exe'
    selection_start_function:
        StartFunction:
            - 'LoadLibraryA'
            - 'LoadLibraryW'
            - 'LoadLibraryExA'
            - 'LoadLibraryExW'
            - 'LdrLoadDll'
    filter_known:
        SourceImage|endswith:
            - '\MsMpEng.exe'
    condition: selection_target and selection_start_function and not filter_known
fields:
    - SourceImage
    - TargetImage
    - StartFunction
falsepositives:
    - EDR agents injecting introspection DLLs into processes.
    - Some legacy video game anti-cheat engines.
level: critical
tags:
    - attack.privilege_escalation
    - attack.defense_evasion
    - attack.t1055.001
    - analytics.an1095
    - detection.det0389
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Reflective DLL Injection**
    * *The Issue:* The classic `LoadLibrary` injection leaves the malicious DLL on disk (a high risk for the attacker). Reflective DLL injection avoids this by manually loading the DLL entirely from memory without calling `LoadLibrary` or registering the DLL with the OS loader. This bypasses the `StartFunction` filter in the Sigma rule.
    * *The Fix:* For reflective injection, the `StartFunction` field in Event ID 8 will often be blank or resolve to an unbacked memory region. Create a parallel rule alerting when `StartFunction` is missing/null AND `TargetImage` is `explorer.exe` or `svchost.exe`.

* **Problem 2: Asynchronous Procedure Calls (APC) Fallback**
    * *The Issue:* If an attacker cannot use `CreateRemoteThread` because it's blocked by an EDR, they may queue an APC (`QueueUserAPC`) pointing to `LoadLibraryA` in an existing thread. Event ID 8 is not generated.
    * *The Fix:* Utilize Sysmon Event ID 7 (Image Loaded) and look for unsigned or highly unusual DLLs loading into core system processes (`explorer.exe`), regardless of how the thread was invoked.
