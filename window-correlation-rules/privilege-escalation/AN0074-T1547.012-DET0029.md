### 1. Technique Breakdown: T1547.012

* What it is: Boot or Logon Autostart Execution: Print Processors. The Windows print spooler service (spoolsv.exe) loads printer drivers and print processors during system startup or printer service initialization. Print processors are DLLs responsible for converting print job data into printer-ready formats. Adversaries can achieve privilege escalation and persistence by installing a malicious DLL as a custom print processor. They register it under the registry path HKLM\SYSTEM\CurrentControlSet\Control\Print\Environments\Windows x64\Print Processors\<CustomProcessor>\.
* Log Source Requirements: Endpoint logs capturing process creation events and registry modification events.
* Coverage Check:
  - HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs CLI command lines modifying spooler registry paths. Sysmon Event ID 13 captures direct registry writes under Print Processor keys.
  - NIDS (Suricata + Zeek): NO. Host-level printer subsystem activity.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 13 (registry_set)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring of registry command tools, and direct registry set monitoring of print processor registry paths.

Rule 1 of 2: Custom Print Processor Installation via CLI (Process Creation)
```yaml
title: Custom Print Processor Installation via CLI (AN0074)
id: 93287008-6346-4506-9e4f-7362444b1e7c
status: experimental
description: Detects command-line registry modifications adding custom print processors under the Windows spooler environment registry path, which can be abused for privilege escalation and persistence.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_cmd:
        CommandLine|contains:
            - 'Control\Print\Environments\'
        CommandLine|contains:
            - 'Print Processors'
        CommandLine|contains:
            - 'reg'
            - 'add'
            - 'Set-ItemProperty'
            - 'New-ItemProperty'
    condition: selection_cmd
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate printer drivers or software installer configuring spoolers.
level: high
tags:
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1547.012
    - analytic.an0074
    - detection.det0029
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  - The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes, or base64 encoding.
  - The Fix: Implement PowerShell Script Block Logging.

* Problem 2: Administrative Activity Noise
  - The Issue: IT administrators legitimately configure spooler drivers.
  - The Fix: Restrict to non-standard environments or baseline approved software setups.

* Problem 3: Masquerading via Renamed Binaries
  - The Issue: Attackers rename registry tools to bypass path-based filters.
  - The Fix: Match on OriginalFileName in process creation logs.
