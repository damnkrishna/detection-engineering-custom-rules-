### **1. Technique Breakdown: T1547.012**

* **What it is:** **Boot or Logon Autostart Execution: Print Processors**. The Windows print spooler service (`spoolsv.exe`) loads printer drivers and print processors during system startup or printer service initialization. Print processors are DLLs responsible for converting print job data into printer-ready formats. Adversaries can achieve privilege escalation and persistence by installing a malicious DLL as a custom print processor. They register it under the registry path `HKLM\SYSTEM\CurrentControlSet\Control\Print\Environments\Windows x64\Print Processors\<CustomProcessor>\`. When the Spooler service starts or restarts, it loads the DLL and executes it in the `SYSTEM` context.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 logs CLI command lines using `reg.exe` or PowerShell modifying the Windows spooler environment paths. Additionally, Sysmon Event ID 11 (File Create) and Event ID 7 (Image Loaded) can capture DLL creation under `%SystemRoot%\System32\spool\prtprocs\x64\` and its subsequent load by `spoolsv.exe`.
* **NIDS (Suricata + Zeek): NO.** Installing print processors is entirely local to the Windows print subsystem and generates no network events.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line modifications registering custom print processors in the printer spooler registry keys.

```yaml
title: Custom Print Processor Installation via CLI (AN0074)
id: 93287008-6346-4506-9e4f-7362444b1e7c
status: experimental
description: Detects command-line registry modifications adding custom print processors under the Windows spooler environment registry path, which can be abused for privilege escalation and persistence.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_cmd:
        CommandLine|contains:
            - 'Control\Print\Environments\'
        CommandLine|contains:
            - 'Print Processors'
        CommandLine|contains:
            - 'reg'
            - 'add'
            - 'Set-ItemProperty'
            - 'New-ItemProperty'
    condition: selection_cmd
fields:
    - CommandLine
falsepositives:
    - Legitimate software installers configuring printer software or official print driver installations.
level: high
tags:
    - attack.persistence
    - attack.privilege_escalation
    - attack.t1547.012
    - analytics.an0074
    - detection.det0029
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct Registry API Overrides**
* *The Issue:* Attackers can bypass command line logging entirely by writing a native C/C++ or C# program that registers the print processor using native APIs (such as `RegCreateKeyEx` or `AddPrintProcessor` API).
* *The Fix:* Enable registry auditing and monitor Sysmon Event ID 12 (Registry Object Added/Deleted) and Event ID 13 (Registry Value Set) targeting the path `HKLM\SYSTEM\CurrentControlSet\Control\Print\Environments\`.


* **Problem 2: Masquerading and File Creation**
* *The Issue:* Attacking binaries can overwrite an existing legitimate print processor DLL (like `winprint.dll`) to avoid adding a new subkey, or the DLL can be dropped in a remote location and loaded from there, bypassing print directory monitoring.
* *The Fix:* Monitor file write events (Sysmon Event ID 11) inside `%SystemRoot%\System32\spool\prtprocs\` and DLL load events (Sysmon Event ID 7) by `spoolsv.exe` where the loaded DLL signature is invalid, unsigned, or loaded from an unexpected path.


* **Problem 3: Standard Printer Installation Noise**
* *The Issue:* Enterprise systems that regularly push network printer configurations or deploy new physical printers will trigger print processor setup events.
* *The Fix:* Audit print driver updates, verify publisher signatures on loaded print processors, and whitelist print installer executables (like `printui.dll` or signed vendor installers).
