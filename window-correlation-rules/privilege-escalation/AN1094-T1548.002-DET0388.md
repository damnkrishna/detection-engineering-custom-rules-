### **1. Technique Breakdown: T1548.002**

* **What it is:** **Bypass User Account Control**. Windows User Account Control (UAC) allows a program to run with administrative privileges if approved by the user. Adversaries bypass this mechanism by exploiting auto-elevating programs that run with High Integrity without prompting. They do this by modifying registry entries (e.g., `isolatedCommand`, `DelegateExecute`, or `shell\open\command` keys) under the current user hive (`HKCU`), causing the auto-elevating binary to load a custom command instead of the default.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures command line arguments for tools modifying registry keys (`reg.exe`, `powershell.exe`). Sysmon Event ID 13 (Registry Value Set) also tracks direct registry modifications.
* **NIDS (Suricata + Zeek): NO.** Registry modifications are internal Windows operating system events and do not generate network activity.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line registry modifications targeting auto-elevation keys like `isolatedCommand`, `DelegateExecute`, or shell command overrides.

```yaml
title: Registry Modification for UAC Bypass (AN1094)
id: f70aef68-a67d-46d0-97bb-8d2d5a5a632a
status: experimental
description: Detects command-line registry modifications targeting UAC auto-elevation registry paths such as isolatedCommand, DelegateExecute, or shell\open\command keys under the user hive.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_cmd:
        CommandLine|contains:
            - '\shell\open\command'
            - '\isolatedCommand'
            - '\DelegateExecute'
        CommandLine|contains:
            - 'reg'
            - 'add'
            - 'Set-ItemProperty'
            - 'New-ItemProperty'
            - 'setx'
    condition: selection_cmd
fields:
    - CommandLine
falsepositives:
    - Legitimate installers or administration scripts executing setup tasks.
level: high
tags:
    - attack.privilege_escalation
    - attack.defense_evasion
    - attack.t1548.002
    - analytics.an1094
    - detection.det0388
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Native API/Direct Registry Modifications**
* *The Issue:* Attackers can bypass command-line detection completely by writing compiled binaries (C/C++ or C#) that interact directly with the registry using standard Win32 APIs (e.g., `RegSetValueExW`) or .NET classes (`Microsoft.Win32.Registry`), which does not spawn `reg.exe` or `powershell.exe`.
* *The Fix:* Enable registry auditing and monitor Sysmon Event ID 12 (Registry Object Added/Deleted) and Event ID 13 (Registry Value Set) targeting the path `HKCU\Software\Classes\`.


* **Problem 2: Masquerading and Obfuscation**
* *The Issue:* String checks for registry paths or key names can be bypassed using registry path aliases (e.g., `HKCR` instead of `HKCU\Software\Classes`) or obfuscating cmdlet parameters in PowerShell (e.g., string concatenation or base64 encoding).
* *The Fix:* Implement PowerShell Script Block Logging (Event ID 4104) and ensure registry path normalization is performed on the SIEM parser side before matching strings.


* **Problem 3: Standard User Key Modifications**
* *The Issue:* Since `HKCU` is fully writable by standard (non-elevated) users, legitimate administrative scripts executed under standard user contexts may occasionally register application handlers, generating false alarms.
* *The Fix:* Scope the rule to flag executions from non-standard folders (like `%TEMP%` or `%APPDATA%`) and prioritize alerts where the parent process is a web browser or office application.
