### **1. Technique Breakdown: T1055**

* **What it is:** **Process Injection**. This is the parent technique for all forms of process injection. Adversaries inject malicious code into the address space of another running process. This masks the execution under a legitimate process (evading process-based detections) and may also grant access to the memory, network connections, and privileges of the target process. Methods include DLL injection, PE injection, Thread Execution Hijacking, and Process Hollowing.
* **Log Source Requirements:** Process creation logs (Sysmon Event ID 1), Remote Thread Creation logs (Sysmon Event ID 8), Process Access logs (Sysmon Event ID 10), Image Load logs (Sysmon Event ID 7).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event IDs 8 and 10 provide broad, generic coverage for most forms of process injection by monitoring handles opened to remote processes and remote threads created.
    * **NIDS (Suricata + Zeek): NO.** Local memory manipulation.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 8 (CreateRemoteThread)** to generically detect the final stage of most traditional process injection techniques: creating a thread in another process.

```yaml
title: Generic Process Injection (Remote Thread Creation) (AN1399)
id: fbbcc3f9-676b-4e6c-a8eb-8b0ab3606f1d
status: experimental
description: Detects generic process injection by correlating remote thread creation (CreateRemoteThread) into common target processes.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: create_remote_thread
    product: windows
    # Relies on Sysmon Event ID 8 collected via Wazuh
detection:
    selection_target:
        TargetImage|endswith:
            - '\explorer.exe'
            - '\svchost.exe'
            - '\lsass.exe'
            - '\winlogon.exe'
            - '\spoolsv.exe'
            - '\services.exe'
            - '\taskhostw.exe'
    filter_known_injectors:
        SourceImage|endswith:
            - '\MsMpEng.exe'
            - '\csrss.exe'
            - '\wbemprox.exe'
            - '\WmiPrvSE.exe'
            - '\taskmgr.exe'
    condition: selection_target and not filter_known_injectors
fields:
    - SourceImage
    - TargetImage
falsepositives:
    - Antivirus and EDR software.
    - Advanced system monitoring tools (e.g., Process Hacker, Sysinternals).
level: high
tags:
    - attack.privilege_escalation
    - attack.defense_evasion
    - attack.t1055
    - analytics.an1399
    - detection.det0508
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Evasion of CreateRemoteThread**
    * *The Issue:* Modern malware avoids `CreateRemoteThread` because it is heavily monitored. Attackers use APC Injection (`QueueUserAPC`), Thread Hijacking (`SetThreadContext`), or early bird injection which do not trigger Event ID 8.
    * *The Fix:* Broaden detection by monitoring Sysmon Event ID 10 (ProcessAccess) for memory writing permissions (`PROCESS_VM_WRITE`) combined with Sysmon Event ID 7 (Image Load) for unsigned DLLs entering `explorer.exe`.

* **Problem 2: Whitelisting Blind Spots**
    * *The Issue:* The rule whitelists `MsMpEng.exe` (Windows Defender). If an attacker exploits a vulnerability in Defender or performs DLL hijacking to run their code *inside* Defender, they can inject anywhere without triggering this rule.
    * *The Fix:* Avoid blanket exclusions of binaries based solely on name. Correlate with the binary's cryptographic signature. Only exclude `MsMpEng.exe` if it is signed by Microsoft AND running from its official `Program Files` directory.

* **Problem 3: In-Process Injection (Reflective)**
    * *The Issue:* An attacker executes a malicious macro in Word. The macro allocates memory inside `winword.exe` and executes shellcode there. Because there is no *cross-process* boundary crossed, Sysmon 8 and 10 will not trigger.
    * *The Fix:* In-process injection requires memory scanning for RWX (Read-Write-Execute) memory regions or monitoring for unusual outbound network connections (Sysmon Event ID 3) directly from the initially compromised process (`winword.exe`).
