### 1. Technique Breakdown: T1078.002

* What it is: Valid Accounts: Domain Accounts. Adversaries compromise domain accounts (specifically Domain Administrators) to move laterally across an Active Directory environment, execute remote commands, and access sensitive resources. Under standard security best practices, Domain Administrator accounts should only log onto Domain Controllers or secure administrative jump boxes. A Domain Admin logging onto standard workstations or member servers suggests lateral movement or credential harvesting.
* Log Source Requirements: Windows Security Event Log capturing authentication events (Event ID 4624 for successful logon) containing user names, domain names, logon types, and source IP addresses.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Windows Security Event ID 4624 tracks domain account logon attempts on endpoints. Wazuh aggregates these logs.
* NIDS (Suricata + Zeek): YES (Partial). Network monitoring can capture Kerberos ticket requests (AS-REQ/TGS-REQ) and NTLM session handshakes, but endpoint-level logging is necessary to confirm successful host access.

### 2. Custom Sigma Rule

This rule utilizes Windows Security Event ID 4624 (Successful Logon) to detect network or remote interactive logons using domain administrator accounts onto non-domain-controller workstations or member servers.

```yaml
title: Domain Administrator Logon on Workstation (AN0590)
id: 447dcbae-8166-4d6e-9980-8b9914df56b6
status: experimental
description: Detects successful remote network or RDP logons by domain administrator accounts onto standard workstation or member server endpoints, which may indicate lateral movement.
author: Krishna Gupta
date: 2026-06-07
logsource:
    product: windows
    service: security
    # Relies on Windows Security Event ID 4624
detection:
    selection_event:
        EventID: 4624
    selection_logon_type:
        LogonType:
            - 3 # Network
            - 10 # Remote Interactive
    selection_domain_admin:
        TargetUserName|contains:
            - 'da_'
            - 'domainadmin'
            - 'domadmin'
    selection_domain:
 # Check that it's a domain account, not local
        TargetDomainName|contains:
            - 'NT AUTHORITY'
            - 'NT Service'
            - 'Window Manager'
    condition: selection_event and selection_logon_type and selection_domain_admin and not selection_domain
fields:
    - EventID
    - LogonType
    - TargetDomainName
    - TargetUserName
falsepositives:
    - Authorized emergency troubleshooting by domain administrators directly on user workstations.
level: high
tags:
    - attack.defense-evasion
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1078.002
    - analytic.an0590
    - detection.det0210
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.
