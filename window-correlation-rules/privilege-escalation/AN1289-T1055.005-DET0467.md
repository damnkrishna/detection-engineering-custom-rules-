### **1. Technique Breakdown: T1055.005**

* **What it is:** **Process Injection: Thread Local Storage**. Adversaries may inject malicious code by manipulating the Thread Local Storage (TLS) callbacks of a Portable Executable (PE). Before the main entry point (`main()` or `DllMain()`) of a Windows executable is reached, the OS executes TLS callbacks to initialize thread-specific data. Attackers can hijack these callbacks in a suspended process (often combined with Process Hollowing) to execute their payload prior to the primary application logic, effectively evading security products that hook the main entry point.
* **Log Source Requirements:** Advanced EDR telemetry (API hooking, memory scanning), Sysmon Event ID 10 (ProcessAccess).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES (Partial).** Sysmon logs `ProcessAccess` (Event ID 10) to the target process. It does not native log PE header modifications or TLS callback executions.
    * **NIDS (Suricata + Zeek): NO.** Local memory execution.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 10 (ProcessAccess)** to detect suspicious access requests targeting common injection candidate processes, serving as an early indicator of memory manipulation required to rewrite TLS structures.

```yaml
title: Suspicious Process Access indicating TLS Callback Injection (AN1289)
id: fbbcc3f9-676b-4e6c-a8eb-8b0ab3606f1d
status: experimental
description: Detects process access indicative of memory modifications to PE headers and TLS directory structures for injection.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_access
    product: windows
    # Relies on Sysmon Event ID 10 collected via Wazuh
detection:
    selection_target:
        TargetImage|endswith:
            - '\svchost.exe'
            - '\explorer.exe'
            - '\dllhost.exe'
            - '\notepad.exe'
    selection_access:
        GrantedAccess|contains:
            - '0x1F0FFF' # All Access
            - '0x143A'   # VM Write
    filter_known:
        SourceImage|endswith:
            - '\MsMpEng.exe'
            - '\csrss.exe'
            - '\services.exe'
    condition: selection_target and selection_access and not filter_known
fields:
    - SourceImage
    - TargetImage
    - GrantedAccess
falsepositives:
    - Debugging software attaching to processes to read/write memory.
    - Security products scanning memory.
level: high
tags:
    - attack.privilege_escalation
    - attack.defense_evasion
    - attack.t1055.005
    - analytics.an1289
    - detection.det0467
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Sysmon Limitations for In-Memory Structures**
    * *The Issue:* Sysmon Event ID 10 is too generic. Modifying the `IMAGE_TLS_DIRECTORY` inside the PE headers of a remote process occurs entirely in memory and is indistinguishable from standard Process Hollowing using just Sysmon.
    * *The Fix:* Employ an EDR solution that performs periodic memory scanning of running processes. The EDR should look for discrepancies between the PE headers loaded in memory versus the PE headers of the binary on disk, specifically flagging unexpected TLS callbacks.

* **Problem 2: Execution Before the Hook**
    * *The Issue:* EDRs often place their user-mode API hooks during the initialization of `ntdll.dll` or at the application's entry point. Because TLS callbacks execute *before* the entry point, the malicious code can execute, disable the EDR hooks in memory, and then proceed cleanly.
    * *The Fix:* Utilize Kernel-level monitoring (ETW Threat Intelligence) for process creation and thread initialization, which cannot be easily unhooked from user-mode TLS callbacks.

* **Problem 3: Legitimate Uses of TLS**
    * *The Issue:* Many legitimate applications (like Delphi compiled programs or certain DRM systems) utilize TLS callbacks for normal initialization logic.
    * *The Fix:* Do not alert simply because a TLS callback exists. Alert only when a remote process accesses the memory space of a suspended process to *dynamically alter* those callbacks.
