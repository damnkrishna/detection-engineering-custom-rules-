### **1. Technique Breakdown: T1546.008**

* **What it is:** **Event Triggered Execution: Accessibility Features**. Windows accessibility tools (e.g., Sticky Keys `sethc.exe`, Utility Manager `utilman.exe`, On-Screen Keyboard `osk.exe`, Magnifier `magnify.exe`) can be launched using key combinations before a user logs in. Adversaries exploit this behavior by replacing these binary files with a command prompt (`cmd.exe`) or modifying the Image File Execution Options (IFEO) registry keys to assign a "Debugger" string pointing to a shell. When the accessibility feature is activated from the logon screen, Windows executes the shell instead, granting the attacker a `SYSTEM` shell.
* **Log Source Requirements:** Endpoint logs capturing process creation and command line parameters (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures parent process paths, target process paths, and command-line arguments. This allows detection of accessibility binaries spawning command interpreters, or registry tools writing to IFEO keys.
* **NIDS (Suricata + Zeek): NO.** Accessibility feature abuse is entirely local to the Windows subsystem and logon screen. No network-level events are generated.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect accessibility features spawning command shells, or command-line registry operations configuring debugger overrides under the Image File Execution Options registry key.

```yaml
title: Accessibility Features Abuse Detection (AN0094)
id: 6f7f8d19-1145-45ad-9984-63649b4f8ace
status: experimental
description: Detects command-line execution of registry commands setting debugger options for accessibility binaries (like sethc.exe or utilman.exe), or detects accessibility applications launching shell interpreters.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_parent:
        ParentImage|endswith:
            - '\sethc.exe'
            - '\utilman.exe'
            - '\osk.exe'
            - '\magnify.exe'
            - '\narrator.exe'
            - '\displayswitch.exe'
            - '\AtBroker.exe'
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_ifeo:
        CommandLine|contains:
            - 'Image File Execution Options'
        CommandLine|contains:
            - 'debugger'
        CommandLine|contains:
            - 'sethc.exe'
            - 'utilman.exe'
            - 'osk.exe'
            - 'magnify.exe'
            - 'narrator.exe'
            - 'displayswitch.exe'
            - 'AtBroker.exe'
    condition: selection_parent or selection_ifeo
fields:
    - CommandLine
    - Image
    - ParentImage
falsepositives:
    - Highly unlikely. Accessibility features spawning shell commands or registry debugging modifications on these paths are not standard administrative practices.
level: critical
tags:
    - attack.persistence
    - attack.privilege_escalation
    - attack.t1546.008
    - analytics.an0094
    - detection.det0042
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Direct File Replacement Bypass**
* *The Issue:* If the attacker replaces the physical file (e.g., replaces `sethc.exe` with a renamed `cmd.exe` on disk), the process creation log will show the image executing as `%SystemRoot%\System32\sethc.exe` with `winlogon.exe` as parent. Because no child process like `cmd.exe` is explicitly spawned, the parenting check is bypassed.
* *The Fix:* Implement file integrity monitoring (FIM) or audit write access permissions to the `%SystemRoot%\System32\` folder, and monitor Sysmon Event ID 1 and compare the digital signature / OriginalFileName metadata field (which will show `cmd.exe` even if the file is renamed to `sethc.exe`).


* **Problem 2: API-Based Registry Hijacks**
* *The Issue:* Attackers can use Win32 APIs or scripting frameworks to modify the registry `Debugger` key directly without using command line tools, bypassing the command-line string-based checks.
* *The Fix:* Enable registry auditing on the keys `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options` and monitor Sysmon Event ID 13 (Registry Value Set) for changes to the `debugger` value under accessibility tool subkeys.


* **Problem 3: Custom/Third-Party Accessibility Software**
* *The Issue:* Custom screen reader packages or system administration tools that utilize the pre-logon screen environment may configure custom debugging or monitoring hooks, triggering false alerts.
* *The Fix:* Restrict exclusions to verified, cryptographically signed binaries executing from approved directories, and ensure that only known enterprise management binaries are excluded.
