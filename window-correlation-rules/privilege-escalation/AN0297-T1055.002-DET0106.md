### **1. Technique Breakdown: T1055.002**

* **What it is:** **Process Injection: Portable Executable Injection**. Adversaries allocate memory in a remote process (e.g., `VirtualAllocEx`), write a malicious PE file or shellcode into that space (`WriteProcessMemory`), and execute it by creating a new remote thread (`CreateRemoteThread`). This runs the malware in the context of the target process, evading defenses that monitor the original malware executable.
* **Log Source Requirements:** Sysmon Event ID 8 (CreateRemoteThread).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 8 specifically records when a process creates a thread in another process.
    * **NIDS (Suricata + Zeek): NO.** This is entirely an in-memory local host execution technique.

---

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 8 (CreateRemoteThread)** to detect cross-process thread creation targeting critical system binaries.

```yaml
title: Suspicious Remote Thread Creation (PE Injection) (AN0297)
id: f43e2a1b-7890-4c12-b345-6d7e8f9a0b1c
status: experimental
description: Detects PE injection where a process initiates a new thread (CreateRemoteThread) in another live process, executing injected code.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: create_remote_thread
    product: windows
    # Relies on Sysmon Event ID 8 collected via Wazuh
detection:
    selection_target:
        TargetImage|endswith:
            - '\explorer.exe'
            - '\svchost.exe'
            - '\lsass.exe'
            - '\winlogon.exe'
            - '\spoolsv.exe'
            - '\services.exe'
    filter_known_injectors:
        SourceImage|endswith:
            - '\MsMpEng.exe'
            - '\csrss.exe'
            - '\wbemprox.exe'
    condition: selection_target and not filter_known_injectors
fields:
    - SourceImage
    - TargetImage
    - StartAddress
falsepositives:
    - Antivirus solutions inspecting processes.
    - Legitimate Windows subsystems (csrss) creating threads.
level: high
tags:
    - attack.privilege_escalation
    - attack.defense_evasion
    - attack.t1055.002
    - analytics.an0297
    - detection.det0106
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Sysmon Blindness to NtCreateThreadEx**
    * *The Issue:* While Sysmon catches standard `CreateRemoteThread` API calls, attackers can bypass this by calling the lower-level undocumented API `NtCreateThreadEx` directly.
    * *The Fix:* Ensure EDR sensors monitor kernel-level thread creation callbacks (`PsSetCreateThreadNotifyRoutine`) rather than relying purely on user-mode API hooking.

* **Problem 2: Module-less Start Addresses**
    * *The Issue:* The Sigma rule triggers on any remote thread to `explorer.exe`. This is noisy.
    * *The Fix:* Leverage the `StartAddress` field in Event ID 8. Legitimate threads almost always start at an exported function inside a known DLL (e.g., `kernel32.dll!LoadLibraryW`). Injected PE payloads often start at an unbacked memory address (e.g., `0x000000000A1B2C3D`). Alert heavily when `StartAddress` does not resolve to a known module on disk.
