### **1. Technique Breakdown: T1133**

* **What it is:** **External Remote Services**. Adversaries leverage external-facing remote access solutions (such as virtual private networks (VPNs) or remote desktop protocols (RDP)) to gain initial access to the internal network. Once they successfully authenticate using compromised credentials, they immediately initiate host reconnaissance by spawning built-in system administration utilities (`whoami.exe`, `net.exe`, `ipconfig.exe`, `nltest.exe`) from the remote session shell.
* **Log Source Requirements:** Windows Security Event Log Event ID 4624 (Logon) combined with Sysmon process creation logs (Event ID 1).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Windows Security log captures remote RDP connections (Logon Type 10) and network logins (Logon Type 3) along with the source IP address. Sysmon Event ID 1 captures the user session initiating system discovery commands.
    * **NIDS (Suricata + Zeek): YES.** Network logs track RDP and VPN connections to gateways, but host logs are needed to correlate the logon with subsequent shell actions.

### **2. Custom Sigma Rule**

This rule utilizes **Windows Security Event ID 4624 (Logon)** and **Sysmon Event ID 1 (Process Creation)** to detect successful remote desktop logons (Logon Type 10) or network logons (Logon Type 3) immediately followed by the execution of system discovery commands within the same user session.

```yaml
title: External Remote Services - Suspicious Command Execution Post-Remote Logon (AN1004)
id: 5caaaa9d-ec1b-4eda-b30d-c638d1b44c1f
status: experimental
description: Detects the execution of system discovery or network configuration commands shortly after a successful RDP (Logon Type 10) or Network (Logon Type 3) logon event, indicating post-intrusion reconnaissance.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 and Security Event ID 4624 collected via Wazuh
detection:
    selection_logon_context:
        # Check if process runs under a session initiated via remote logon
        # Logon Type 10 is Remote Interactive (RDP)
        LogonId|not: '0x3e7' # Exclude SYSTEM session
    selection_commands:
        - Image|endswith:
            - '\whoami.exe'
            - '\net.exe'
            - '\net1.exe'
            - '\ipconfig.exe'
            - '\nltest.exe'
            - '\systeminfo.exe'
            - '\quser.exe'
            - '\query.exe'
            - '\qwinsta.exe'
        - OriginalFileName:
            - 'whoami.exe'
            - 'net.exe'
            - 'net1.exe'
            - 'ipconfig.exe'
            - 'nltest.exe'
            - 'systeminfo.exe'
    condition: selection_logon_context and selection_commands
fields:
    - Image
    - LogonId
    - OriginalFileName
falsepositives:
    - IT administrators logging in remotely to troubleshoot system issues or gather host configuration metrics.
level: high
tags:
    - attack.initial-access
    - attack.t1133
    - analytics.an1004
    - detection.det0354
```

### OCSF Normalized
```xml
title: External Remote Services - Suspicious Command Execution Post-Remote Logon (OCSF-Normalized)
id: 5caaaa9d-ec1b-4eda-b30d-c638d1b44c1f
status: experimental
description: Detects system discovery commands executed during remote login sessions, mapped to OCSF process_activity.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: system
    product: ocsf
    class: process_activity
detection:
    # Under standard OCSF mapping, user session info and command executions are captured in process_activity
    selection_commands:
        process.file.path|endswith:
            - '\whoami.exe'
            - '\net.exe'
            - '\ipconfig.exe'
            - '\nltest.exe'
            - '\systeminfo.exe'
    selection_remote_session:
        # Excludes standard SYSTEM context and checks process execution context
        actor.user.uid|not: 'S-1-5-18'
    condition: selection_commands and selection_remote_session
fields:
    - actor.user.uid
    - process.file.path
falsepositives:
    - Legitimate administrative remote sessions running system baseline commands.
level: high
tags:
    - attack.initial-access
    - attack.t1133
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Administrative Script Automation**
    * *The Issue:* Automated IT monitoring servers use remote service accounts (Logon Type 3) to run routine inventory scripts (gathering network or user info), triggering high volumes of false alerts.
    * *The Fix:* Whitelist approved service account user names and exclude inventory script execution paths (e.g. paths matching corporate asset management agents).

* **Problem 2: Tunneling RDP over SSH / HTTP (Port Forwarding)**
    * *The Issue:* If an attacker tunnels RDP traffic through an local SSH tunnel or reverse HTTP proxy on the host, the Security log will record the Logon Type 10 source IP as local host (`127.0.0.1` or `::1`), hiding the external source.
    * *The Fix:* Monitor network socket creations by remote access processes or SSH services, and alert on connections to `127.0.0.1` on port 3389.

* **Problem 3: Use of Administrative API Interfaces (WMI/WinRM)**
    * *The Issue:* If the attacker connects via WinRM (PowerShell Remoting) or WMI rather than interactive RDP, the shell commands run under `wsmprovhost.exe` or `wmiprvse.exe` contexts, which may run silently without triggering desktop session baselines.
    * *The Fix:* Enable PowerShell operational log auditing (Event ID 4104) and monitor process spawns originating from the WinRM parent process (`wsmprovhost.exe`).
