### **1. Technique Breakdown: T1669**

* **What it is:** **Wi-Fi Networks**. Adversaries leverage rogue Wi-Fi access points (like Evil Twins) or connect corporate laptops to unauthorized, unencrypted public wireless networks to intercept traffic, perform man-in-the-middle (MitM) attacks, or bypass corporate egress filters. Detection involves monitoring Windows WLAN connection logs or detecting processes executing wireless profile queries (e.g. `netsh wlan show profiles`).
* **Log Source Requirements:** Windows WLAN-AutoConfig Operational event logs (Event ID 8001) or Sysmon process creation logs (Event ID 1) checking command line arguments.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures network configuration queries (like `netsh.exe wlan`). Windows WLAN-AutoConfig logs record wireless SSID/BSSID associations.
    * **NIDS (Suricata + Zeek): NO.** Network sensors do not have visibility into the local wireless interface card associations of corporate endpoints.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** and **WLAN-AutoConfig Event ID 8001** to detect wireless network commands or connections to open, untrusted, or anomalous Wi-Fi SSIDs.

```yaml
title: Wi-Fi Network Anomalies - Connection to Rogue Access Point or Profile Query (AN1476)
id: b9492d1a-e7b8-4529-a03d-0998833258c3
status: experimental
description: Detects processes executing wireless profile queries or WLAN auto-config events logging successful connection to unsecured (open) networks.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: system
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\netsh.exe'
        CommandLine|contains:
            - 'wlan'
            - 'show profiles'
            - 'show networks'
            - 'export profile'
    selection_wlan_log:
        EventID: 8001
        Provider_Name: 'Microsoft-Windows-WLAN-AutoConfig'
        # AuthAlgorithm value 1 represents Open/None encryption in WLAN AutoConfig schema
        AuthAlgorithm: 1
    condition: selection_process or selection_wlan_log
fields:
    - AuthAlgorithm
    - CommandLine
    - EventID
    - Image
    - Provider_Name
falsepositives:
    - Legitimate administrator troubleshooting network connectivity or user connecting to authorized guest Wi-Fi at a corporate branch.
level: medium
tags:
    - attack.initial-access
    - attack.t1669
    - analytics.an1476
    - detection.det0536
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: VPN Autoconnect masking Open Wi-Fi risk**
    * *The Issue:* If a corporate device connects to an open airport Wi-Fi, but a split-tunnel VPN automatically connects and encrypts all outbound traffic, the immediate exposure to MitM is minimized, but an alert is still generated.
    * *The Fix:* Correlate WLAN open network connection events (Event ID 8001) with the subsequent establishment of a secure VPN tunnel (e.g. looking for VPN virtual adapter activations or IP changes).

* **Problem 2: SSID Spoofing (Evil Twin with encryption)**
    * *The Issue:* If an attacker sets up a rogue access point spoofing the corporate SSID and using WPA2-Enterprise with a rogue authentication server (Evil Twin), the connection will not be registered as an "Open" network, bypassing open-security checks.
    * *The Fix:* Monitor for changes in the BSSID MAC address (checking if the access point MAC belongs to the authorized corporate AP infrastructure baseline) and report on BSSID mismatches.

* **Problem 3: netsh Command Obfuscation**
    * *The Issue:* Attackers can retrieve wireless profiles by querying registry keys directly (`HKLM\Software\Microsoft\WlanSvc\Interfaces\`) rather than running `netsh.exe wlan`, rendering process command line filters blind.
    * *The Fix:* Add monitoring for registry reads or queries targeting the WLAN Interfaces registry paths by non-system processes.
