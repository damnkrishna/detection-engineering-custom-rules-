### **1. Technique Breakdown: T1195.001**

* **What it is:** **Supply Chain Compromise: Compromise Software Dependencies and Development Tools**. Adversaries target software dependencies or packages (e.g., npm, pip, PyPI, NuGet, Maven) to inject malicious payloads. During the installation phase (e.g., post-install scripts or initial package builds), these package managers execute local commands that spawn unexpected shell interpreters, scripting tools, or network utilities to download secondary implants or exfiltrate environment variables.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1) capturing parent-child process relationships.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures parent process command lines and paths (e.g., `npm` or `pip` executing under node/python) spawning shells or download utilities like `curl.exe` or `certutil.exe`.
    * **NIDS (Suricata + Zeek): PARTIAL.** Network tools can flag outbound traffic to suspicious external repos or pastebins during build steps, but they lack visibility into the developer endpoint process execution context.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect software development tools or package managers (such as Node/npm, Python/pip, NuGet, etc.) spawning command-line interpreters or networking programs, which indicates suspicious execution via build or installation hooks.

```yaml
title: Supply Chain Tampering - Suspicious Process Spawned by Development Tool (AN0021)
id: 50f3bf00-e552-4dab-a402-9b891308bc44
status: experimental
description: Detects package managers or development builds (like npm, pip, nuget, maven, gradle, python, node) spawning suspicious command interpreters, script engines, or network download utilities.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_parent:
        ParentImage|endswith:
            - '\node.exe'
            - '\npm.cmd'
            - '\pip.exe'
            - '\python.exe'
            - '\python3.exe'
            - '\nuget.exe'
            - '\mvn.cmd'
            - '\gradle.bat'
            - '\msbuild.exe'
    selection_child:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\curl.exe'
            - '\certutil.exe'
            - '\bitsadmin.exe'
        - OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'mshta.exe'
            - 'curl.exe'
            - 'certutil.exe'
            - 'bitsadmin.exe'
    condition: selection_parent and selection_child
fields:
    - Image
    - OriginalFileName
    - ParentImage
falsepositives:
    - Legitimate post-install build scripts run by developers (e.g., compiling native C++ bindings for Node modules).
level: medium
tags:
    - attack.initial-access
    - attack.t1195.001
    - analytics.an0021
    - detection.det0009
```

### OCSF Normalized
```xml
title: Supply Chain Tampering - Suspicious Process Spawned by Development Tool (OCSF-Normalized)
id: 50f3bf00-e552-4dab-a402-9b891308bc44
status: experimental
description: Detects package managers spawning suspicious shell processes or script engines, mapped to OCSF process_activity.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: system
    product: ocsf
    class: process_activity
detection:
    # Under standard OCSF mapping, the parent image is actor.process.file.path and the child is process.file.path
    selection_parent:
        actor.process.file.path|endswith:
            - '\node.exe'
            - '\npm.cmd'
            - '\pip.exe'
            - '\python.exe'
            - '\nuget.exe'
            - '\msbuild.exe'
    selection_child:
        process.file.path|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\curl.exe'
    condition: selection_parent and selection_child
fields:
    - actor.process.file.path
    - process.file.path
falsepositives:
    - Developers running build installations containing legitimate shell calls for compiling packages.
level: medium
tags:
    - attack.initial-access
    - attack.t1195.001
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Developer Custom Scripts (Post-install Noise)**
    * *The Issue:* Many NPM packages or Python packages legitimately use install hooks to run configure scripts or compile platform-dependent source code. This results in false alerts.
    * *The Fix:* Baseline the environment to whitelist known developer build servers or specific directories where builds are run, or filter commands that contain common compilers (like `node-gyp`).

* **Problem 2: Execution in Hidden Python Venvs**
    * *The Issue:* If python is running from a local, user-created virtual environment (`venv\Scripts\python.exe`), the parent image might not be standard system-installed `python.exe`, bypassing static path checks.
    * *The Fix:* Match parent process images ending with `\python.exe` and `\python3.exe` wildcard paths (e.g., `*\python.exe`), rather than relying on absolute system directory listings.

* **Problem 3: Direct Download in Build Runner Memory**
    * *The Issue:* If the tampered library downloads malicious modules directly in-memory using an HTTP request within the node/python runtime itself (rather than spawning shell utilities), no child process is created.
    * *The Fix:* Enable system network connection logging for developer tools (like node.exe and python.exe) and alert on connections to unknown domains.
