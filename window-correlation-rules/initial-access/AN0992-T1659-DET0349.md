### **1. Technique Breakdown: T1659**

* **What it is:** **Content Injection**. Adversaries insert malicious content (such as scripts, redirection links, or iframes) into web pages or web application code. On Windows systems hosting web applications (e.g., IIS, Apache, or Nginx), this often manifests as unauthorized processes (such as scripting hosts, shells, or downloaded utilities) modifying or writing to files within the web server root directories (e.g., `C:\inetpub\wwwroot\`, `C:\xampp\htdocs\`).
* **Log Source Requirements:** Windows Sysmon File Creation and Modification events (Event ID 11 / Event ID 2), combined with initiating process metadata (Sysmon Event ID 1).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 11 tracks file creation events, and Event ID 2 tracks file modification. Wazuh aggregates these and alerts based on the writing process and directory path.
    * **NIDS (Suricata + Zeek): PARTIAL.** Network monitoring can detect anomalous web requests or malicious scripts in transit, but cannot easily detect file-level writes to local disk paths.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 11 (File Creation)** or **Event ID 2 (File Modification)** to detect non-standard processes (like shells or scripting utilities) writing or modifying web content files (`.html`, `.js`, `.php`, `.aspx`) in local web server directories.

```yaml
title: Content Injection - Unauthorized Process Writing Web Content (AN0992)
id: 5213048d-466e-4f0d-a442-e0287b6d8324
status: experimental
description: Detects command-line interpreters or scripting hosts modifying or creating files within local web server roots (e.g., C:\inetpub\wroot, C:\xampp\htdocs), indicating potential content injection or defacement.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: file_event
    product: windows
    # Relies on Sysmon Event ID 11 / Event ID 2 collected via Wazuh
detection:
    selection_path:
        TargetFilename|contains:
            - '\inetpub\wwwroot\'
            - '\xampp\htdocs\'
            - '\apache\htdocs\'
            - '\nginx\html\'
    selection_extension:
        TargetFilename|endswith:
            - '.html'
            - '.htm'
            - '.js'
            - '.aspx'
            - '.asp'
            - '.php'
            - '.jsp'
    selection_process:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\curl.exe'
    condition: selection_path and selection_extension and selection_process
fields:
    - Image
    - TargetFilename
falsepositives:
    - Legitimate administrative deployments or manual updates of web assets by admins using command shell scripts.
level: high
tags:
    - attack.initial-access
    - attack.t1659
    - analytics.an0992
    - detection.det0349
```

### OCSF Normalized
```xml
title: Content Injection - Unauthorized Process Writing Web Content (OCSF-Normalized)
id: 5213048d-466e-4f0d-a442-e0287b6d8324
status: experimental
description: Detects command-line interpreters or scripting hosts modifying or creating files within local web server roots, mapped to OCSF file_activity.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: system
    product: ocsf
    class: file_activity
detection:
    # Based on OCSF mapping, the writing process is under process.file.path and the file location is under file.path
    selection_path:
        file.path|contains:
            - '\inetpub\wwwroot\'
            - '\xampp\htdocs\'
            - '\apache\htdocs\'
            - '\nginx\html\'
    selection_extension:
        file.path|endswith:
            - '.html'
            - '.htm'
            - '.js'
            - '.aspx'
            - '.asp'
            - '.php'
            - '.jsp'
    selection_process:
        process.file.path|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
    condition: selection_path and selection_extension and selection_process
fields:
    - file.path
    - process.file.path
falsepositives:
    - Admin-led manual script deployments or automated CI/CD file drops.
level: high
tags:
    - attack.initial-access
    - attack.t1659
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: CI/CD Automated Agent Noise**
    * *The Issue:* Deployment tools or agents (like Jenkins, GitLab runner, or Azure DevOps agents) running local commands/scripts regularly update files in the web root directories, generating high numbers of false alerts.
    * *The Fix:* Scope the rule to ignore updates written by authorized CI/CD application paths or service accounts explicitly designated for deployment.
    * *Alternative Tuning:* Limit alerting to interactive shells only (checking for interactive logon session IDs associated with the process).

* **Problem 2: Alternate Web Root Configurations**
    * *The Issue:* The rule relies on standard directory paths. If the web server uses custom paths (e.g., `D:\WebSites\CustomRoot\`), this rule will not trigger.
    * *The Fix:* Customize the directory filter lists to reflect actual web server configurations in the environment, or monitor file writes to paths mapped in active IIS/Apache config configurations.

* **Problem 3: Direct Web Server Exploit (In-Memory)**
    * *The Issue:* If an attacker exploits a remote code execution vulnerability (e.g., Log4j or Apache Struts) and dynamically modifies in-memory responses rather than writing to files, this rule will not trigger.
    * *The Fix:* Deploy endpoint security monitoring for web server parent-child relationships and monitor outbound HTTP traffic originating from the web server application pool.
