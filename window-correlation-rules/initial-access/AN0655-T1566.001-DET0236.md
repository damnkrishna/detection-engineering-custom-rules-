### 1. Technique Breakdown: T1566.001

* What it is: Phishing: Spearphishing Attachment. Adversaries send emails containing malicious attachments (such as macro-enabled spreadsheets, script files, shortcuts, or disk images like `.iso` and `.img`) to establish a foothold. When the user opens the email or attempts to view the attachment, the email client (e.g., Outlook) writes the attachment file to the local disk (specifically to temporary download paths or temporary internet cache directories).
* Log Source Requirements: Sysmon File Creation logs (Event ID 11) and Sysmon process creation logs (Event ID 1).
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 11 records the mail client process writing to disk. Sysmon Event ID 1 records the execution of processes directly from the mail attachment cache directory.
  * NIDS (Suricata + Zeek): YES. Network intrusion sensors analyze SMTP/IMAP streams and extract attachments, but endpoint-based process execution logs are necessary to verify execution.
* Log Sources Covered:
  - Sysmon Event ID 11 (file_event)
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Spearphishing attachment deployment and execution can be detected using file creation and process creation logs.

### 2. Custom Sigma Rule

The detection logic is split into monitoring mail clients writing dangerous attachments to disk, and monitoring executions from temporary mail cache directories.

Rule 1 of 2: Spearphishing Attachment - Dangerous File Written by Mail Client (File Event)
```yaml
title: Spearphishing Attachment - Dangerous File Written by Mail Client (AN0655-A)
id: d47d228b-7ef5-41fc-9a4a-a5fff86b09f6
status: experimental
description: Detects email client processes (e.g., outlook.exe, thunderbird.exe) writing files with dangerous or executable extensions (e.g., .exe, .lnk, .vbs, .hta, .iso, .img, .bat) to the file system.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: file_event
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\outlook.exe'
            - '\thunderbird.exe'
            - '\foxmail.exe'
    selection_extensions:
        TargetFilename|endswith:
            - '.exe'
            - '.lnk'
            - '.vbs'
            - '.vbe'
            - '.js'
            - '.jse'
            - '.hta'
            - '.iso'
            - '.img'
            - '.bat'
            - '.cmd'
            - '.scr'
            - '.wsf'
            - '.chm'
    condition: selection_process and selection_extensions
fields:
    - Image
    - TargetFilename
    - User
    - LogonId
falsepositives:
    - Users saving legitimate business files or software installers received via corporate emails.
level: high
tags:
    - attack.initial-access
    - attack.t1566.001
    - analytic.an0655
    - detection.det0236
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: High Volume of Legitimate Zip / Executable Transfers
  * The Issue: Developers and IT staff frequently share utility scripts (like `.bat` or `.ps1`) or software updates inside `.zip` files via email, leading to high rates of false alarms.
  * The Fix: Scope exclusions based on user groups (e.g. whitelist specific IT administrators or developer security groups) or target folders (e.g. ignore downloads saved directly to secure development sandboxes).

* Problem 2: Encrypted / Password-Protected Zip files
  * The Issue: Email gateway scanners cannot open password-protected zip archives, and endpoints will only see a standard `.zip` file written to disk. The malicious payload inside is invisible until extracted.
  * The Fix: Correlate the initial `.zip` write by Outlook with subsequent extraction actions and process executions from the extraction directories (e.g. `7z.exe` or Explorer writing to Temp paths).

* Problem 3: Webmail Phishing downloads
  * The Issue: If a user accesses their email via webmail (e.g. Outlook Web App in Chrome) rather than a local client app, the browser process (`chrome.exe`) writes the file, not `outlook.exe`.
  * The Fix: Deploy endpoint monitoring rules checking browser file writes (`chrome.exe`) that target download folders containing high-risk extensions, and correlate this with browser-initiated process activity.
