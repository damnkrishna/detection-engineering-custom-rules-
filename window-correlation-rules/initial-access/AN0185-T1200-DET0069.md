### **1. Technique Breakdown: T1200**

* **What it is:** **Hardware Additions**. Adversaries introduce physical computer components (such as USB keystroke injection dongles, rogue Wi-Fi/network cards, or custom hardware expansion boards) directly into endpoints to bypass local policy restrictions or establish out-of-band communication. Detecting these additions requires auditing system plug-and-play (PnP) event logs or driver installation sequences.
* **Log Source Requirements:** Windows System Event Log or DriverFrameworks-UserMode Operational logs capturing new hardware installation events (Event ID 20001 or Event ID 400).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Windows UserPnp logs capture Event ID 20001 when a driver installation is attempted for a new device. Sysmon Event ID 1 can also capture the execution of driver installation utilities like `drvinst.exe` or `pnputil.exe`.
    * **NIDS (Suricata + Zeek): NO.** Network security devices cannot directly audit physical hardware insertions.

### **2. Custom Sigma Rule**

This rule utilizes **Windows System Event ID 20001 (Device Driver Installation)** to detect driver installations for USB devices or virtual network adapters that may indicate unauthorized hardware additions.

```yaml
title: Unauthorized Hardware Addition - New Device Driver Installed (AN0185)
id: 036cb390-2835-40c6-b484-0f68c7f02cb9
status: experimental
description: Detects driver installation events for new USB mass storage devices, network adapters, or human interface devices (HIDs) that could represent rogue hardware additions.
author: Krishna Gupta
date: 2026-06-08
logsource:
    product: windows
    service: system
detection:
    selection_pnp:
        EventID: 20001
        Source: 'Microsoft-Windows-UserPnp'
    selection_device_types:
        - Description|contains:
            - 'USB Mass Storage'
            - 'Virtual Network'
            - 'USB Input Device'
            - 'Human Interface Device'
        - DeviceInstanceID|contains:
            - 'USBSTOR'
            - 'USB\VID_'
    condition: selection_pnp and selection_device_types
fields:
    - Description
    - DeviceInstanceID
    - EventID
    - Source
falsepositives:
    - Users connecting standard peripheral devices (keyboards, mice, USB thumb drives) for legitimate work.
level: low
tags:
    - attack.initial-access
    - attack.t1200
    - analytics.an0185
    - detection.det0069
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: High Volume of Standard USB insertions**
    * *The Issue:* Employees plug in standard mice, keyboards, and flash drives daily, generating large numbers of benign events that hide actual malicious devices (like Rubber Ducky).
    * *The Fix:* Scope the rule to flag only unexpected VID/PID combinations that are not baselined in the corporate network, or correlate hardware insertion with immediate shell spawning (Sysmon Event ID 1).

* **Problem 2: Driver Pre-installation**
    * *The Issue:* If a driver for a rogue USB device is already present on the Windows host, Windows will configure it without triggering a new driver installation event (Event ID 20001).
    * *The Fix:* Complement this rule by monitoring kernel PNP device configuration events (Event ID 1 or 12 in the Kernel-PnP log) which fire every time a device is plugged in, regardless of whether it's a first-time install.

* **Problem 3: Virtualization Layer Guest Passthrough**
    * *The Issue:* In VM environments, a user passing a USB device through to a guest OS may not trigger standard hardware events on the physical hypervisor, or vice-versa.
    * *The Fix:* Deploy hypervisor-level audits for USB controller attachment commands and enforce local VM agent monitoring inside VM guests.
