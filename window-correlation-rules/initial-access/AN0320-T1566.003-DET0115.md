### 1. Technique Breakdown: T1566.003

* What it is: Spearphishing via Service. Adversaries deliver spearphishing payloads or links via third-party web services (e.g., personal webmail like Gmail/Outlook, social media like LinkedIn/Twitter, or messaging platforms like Discord, Slack, Telegram, and Teams) rather than traditional enterprise email. This sub-technique bypasses enterprise email gateway controls. The detection focuses on identifying suspicious activity originating from web browser processes or chat/messaging applications, such as downloading and executing scripting interpreters, shells, or anomalous binaries.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) and file creation logs (Event ID 11) for web browsers and messaging clients.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures command-line execution and parent-child process relationships (e.g., `chrome.exe` spawning `powershell.exe`). Event ID 11 captures file creations in download or app data paths.
    * NIDS (Suricata + Zeek): PARTIAL. Network monitoring can identify connections to known messaging API endpoints (e.g., Discord attachments or Telegram bot API) or high-reputation file-sharing sites, but SSL/TLS encryption prevents payload inspection, making host-based endpoint logs essential.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect common web browsers or chat/messaging clients spawning interpreter shells, script hosts, or other highly suspicious binaries.

```yaml
title: Spearphishing via Service - Suspicious Child Process Spawned by Browser or Chat Application (AN0320)
id: afefec05-6c0e-4398-ab51-a6707768c253
status: experimental
description: Detects suspicious child processes (like cmd.exe, powershell.exe, wscript.exe, rundll32.exe) spawned by web browsers or collaboration/chat applications (Discord, Slack, Telegram, Teams), which indicates browser-initiated exploit execution or user execution of phishing attachments.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_parent:
        ParentImage|endswith:
 # Web Browsers
            - '\chrome.exe'
            - '\msedge.exe'
            - '\firefox.exe'
            - '\brave.exe'
            - '\opera.exe'
 # Chat & Collaboration Clients
            - '\discord.exe'
            - '\slack.exe'
            - '\teams.exe'
            - '\Telegram.exe'
            - '\WhatsApp.exe'
            - '\zoom.exe'
    selection_child:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\rundll32.exe'
            - '\regsvr32.exe'
            - '\certutil.exe'
            - '\bitsadmin.exe'
            - '\curl.exe'
            - '\scrcons.exe'
        - OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'mshta.exe'
            - 'rundll32.exe'
            - 'regsvr32.exe'
            - 'certutil.exe'
            - 'bitsadmin.exe'
            - 'curl.exe'
    condition: selection_parent and selection_child
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate user actions such as developer utilities running via local browser-based IDEs (e.g., Jupyter Notebooks or VS Code Web).
    - Auto-update mechanisms for messaging applications that spawn command-line execution or self-update scripts.
level: high
tags:
    - attack.initial-access
    - attack.t1566.003
    - analytic.an0320
    - detection.det0115
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Legitimate Browser Extensions or Web Apps Spawning Shells
  * The Issue: Web developers using tools like Jupyter Notebooks, VS Code Server, or certain local-host admin panels (running inside a browser) legitimately trigger the execution of terminal shells (`cmd.exe`, `powershell.exe`) and compilers. This produces false positives.
  * The Fix: Scope the rules to ignore executions where the parent process is running under developer account contexts or specific directories (e.g., local VS Code installations). Tune by examining the command line arguments; for instance, Jupyter notebook subprocesses will typically have command-lines referencing local python packages or configurations.

* Problem 2: Execution via Intermediate File Double-Click
  * The Issue: When a user downloads a malicious attachment (e.g., a `.lnk`, `.bat`, or `.exe` file) from LinkedIn or Discord, they often double-click the file in their file explorer (`explorer.exe`) or extract it from a zip file. In this case, the parent process of the malicious payload is `explorer.exe` or `7zFM.exe`, not the browser or chat app. The direct link to the initial access source is lost.
  * The Fix: Correlate file download events (Sysmon Event ID 11) from browser or chat processes writing to `%USERPROFILE%\Downloads\` or `%USERPROFILE%\AppData\Local\Temp\` with subsequent process creations (Event ID 1) from the same path within a short window (e.g., 5 to 10 minutes).

* Problem 3: Client Self-Updates
  * The Issue: Applications like Slack, Discord, and Telegram utilize GitHub-style electron auto-updaters. These clients regularly spawn installer scripts, PowerShell commands, and helper processes to download and apply updates, triggering the parent-child rule.
  * The Fix: Build strict exclusions based on the command-line arguments and file signatures of the updater binaries. For example, Discord updates typically run under specific update parameters (e.g., `--update` or containing `Squirrel`). Filter out known, signed update programs executing from user appdata folders.
