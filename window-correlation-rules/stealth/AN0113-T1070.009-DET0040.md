### **1. Technique Breakdown: T1070.009**

* **What it is:** **Clear Persistence**. Adversaries remove artifacts they previously planted for persistence — such as scheduled tasks, registry run keys, services, or startup folder binaries — to cover their tracks and hinder forensic investigation after completing their objectives. On Windows, removal commands include `sc.exe delete <service>`, `schtasks.exe /delete /tn <task>`, `reg.exe delete <key>`, or PowerShell equivalents (`Remove-Item`, `Unregister-ScheduledTask`). The detection pattern focuses on deletion of known persistence mechanisms rather than creation.
* **Log Source Requirements:** Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688), Windows Security Event ID 4698/4699 (scheduled task created/deleted), and System Event Log for service deletion.
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures `sc.exe delete`, `schtasks.exe /delete`, and `reg.exe delete` commands with full command-line arguments. Windows Security Event ID 4699 logs scheduled task deletion events.
    * **NIDS (Suricata + Zeek): NO.** Persistence artifact removal is a host-local operation that produces no network traffic.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect the deletion of common persistence artifacts including scheduled tasks, registry run keys, and services.

```yaml
title: Persistence Artifact Removal for Anti-Forensics (AN0113)
id: caaa5221-d01d-464d-84f0-059649a56d14
status: experimental
description: Detects adversary activity removing persistence artifacts such as scheduled tasks, services, or registry run keys using sc delete, schtasks /delete, or reg delete — indicative of anti-forensic cleanup.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_sc_delete:
        - Image|endswith: '\sc.exe'
        - OriginalFileName: 'sc.exe'
    selection_sc_args:
        CommandLine|contains: ' delete '
    selection_schtasks_delete:
        - Image|endswith: '\schtasks.exe'
        - OriginalFileName: 'schtasks.exe'
    selection_schtasks_args:
        CommandLine|contains: ' /delete '
    selection_reg_delete:
        - Image|endswith: '\reg.exe'
        - OriginalFileName: 'reg.exe'
    selection_reg_args:
        CommandLine|contains:
            - ' delete '
            - '\Run\'
            - '\RunOnce\'
            - '\Services\'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_args:
        CommandLine|contains:
            - 'Unregister-ScheduledTask'
            - 'Remove-Item.*Run'
            - 'sc.exe delete'
    condition: (selection_sc_delete and selection_sc_args) or (selection_schtasks_delete and selection_schtasks_args) or (selection_reg_delete and selection_reg_args) or (selection_powershell and selection_powershell_args)
falsepositives:
    - Software uninstallers that clean up scheduled tasks or services as part of legitimate removal operations.
level: medium
tags:
    - attack.defense_evasion
    - attack.t1070.009
    - analytics.an0113
    - detection.det0040
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: High Volume from Software Uninstallers**
    * *The Issue:* Nearly every software uninstaller deletes its scheduled maintenance tasks and services as part of normal removal. `schtasks /delete` and `sc delete` are extremely common, making blanket monitoring very noisy.
    * *The Fix:* Correlate deletion events with the preceding creation events. Flag cases where a persistence artifact (service, task, or run key) was created within the same session or within a short lookback window (e.g. 24 hours) and is then deleted — this sequence is more characteristic of malware cleanup than legitimate uninstallation.

* **Problem 2: Registry Persistence Removal via Direct API**
    * *The Issue:* Sophisticated adversaries may remove registry run keys directly using Windows Registry API calls (`RegDeleteKey`, `RegDeleteValue`) from a compiled binary, bypassing `reg.exe` entirely.
    * *The Fix:* Enable Sysmon Registry Monitoring (Event IDs 12, 13, 14) to detect direct registry key/value deletions under `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` and related persistence paths, regardless of the process that performed them.

* **Problem 3: Fileless Persistence Removal (WMI Subscriptions)**
    * *The Issue:* Adversaries using WMI event subscriptions for persistence remove them using WMI queries (`Get-WMIObject -Query "SELECT..." | Remove-WmiObject`), which may not involve `sc.exe` or `reg.exe`.
    * *The Fix:* Monitor WMI Activity Operational Event ID 5861 for deletion of WMI event filters and consumers, and correlate with Sysmon Event ID 19/20/21 (WMI subscription events).
