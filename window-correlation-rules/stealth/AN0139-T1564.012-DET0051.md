### **1. Technique Breakdown: T1564.012**

* **What it is:** **File/Path Exclusions**. Adversaries exploit the fact that security tools (antivirus engines, EDR agents) maintain exclusion lists — directories, file paths, or extensions that are excluded from scanning or monitoring. By placing malicious files in excluded paths (e.g., `C:\Windows\Temp`, Exchange server directories, or custom AV exclusion paths set by admins), adversaries ensure their payloads are not scanned or detected. They may also actively add new exclusions using `powershell.exe Add-MpPreference` or registry modifications to create blind spots for their malware.
* **Log Source Requirements:** Sysmon process creation logs (Event ID 1), Windows Security Event ID 4688 (process creation), and file events (Sysmon Event ID 11).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures PowerShell `Add-MpPreference -ExclusionPath` commands. File creation events (Event ID 11) can detect binaries written to known AV-excluded paths.
    * **NIDS (Suricata + Zeek): NO.** Writing files to excluded paths or modifying AV exclusion lists are host-local operations.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect adversarial attempts to add Windows Defender exclusion paths or place executable files into commonly excluded directories to evade antivirus scanning.

```yaml
title: AV Exclusion Path Addition or Abuse (AN0139)
id: c81c3cc0-464e-4e7b-b40b-fabc5fda3eb8
status: experimental
description: Detects adversarial modification of Windows Defender exclusion lists via PowerShell Add-MpPreference, or execution of binaries from paths commonly excluded from AV scanning (e.g., C:\Windows\Temp, Exchange directories).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_add_exclusion:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_add_exclusion_args:
        CommandLine|contains:
            - 'Add-MpPreference'
            - '-ExclusionPath'
            - '-ExclusionExtension'
            - '-ExclusionProcess'
            - 'ExclusionPath'
    selection_excluded_paths:
        Image|contains:
            - '\Windows\Temp\'
            - '\AppData\Local\Temp\'
            - '\ProgramData\Microsoft\Windows\Start Menu\'
            - '\Users\Public\'
            - '\Recycle.Bin\'
        Image|endswith:
            - '.exe'
            - '.dll'
    filter_system:
        Image|startswith:
            - 'C:\Windows\System32\'
            - 'C:\Windows\SysWOW64\'
    condition: (selection_add_exclusion and selection_add_exclusion_args) or (selection_excluded_paths and not filter_system)
falsepositives:
    - Legitimate software installers placing executables in temp directories as part of installation workflows, or enterprise IT adding managed AV exclusions via deployment scripts.
level: high
tags:
    - attack.defense_evasion
    - attack.t1564.012
    - analytics.an0139
    - detection.det0051
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Registry-Based Exclusion Addition**
    * *The Issue:* Adversaries can add Windows Defender exclusions directly via registry modifications (`HKLM\SOFTWARE\Microsoft\Windows Defender\Exclusions\Paths`) without using PowerShell cmdlets. This bypasses detection rules targeting `Add-MpPreference`.
    * *The Fix:* Monitor Sysmon Registry Event ID 13 (RegistryValueSet) for writes to `HKLM\SOFTWARE\Microsoft\Windows Defender\Exclusions\` by processes other than Windows Defender's own service (`MsMpEng.exe`).

* **Problem 2: Legitimate Enterprise AV Exclusion Management**
    * *The Issue:* Enterprise IT teams routinely add AV exclusions for database servers (SQL Server directories), antivirus compatibility paths, or application performance paths. These generate alerts from legitimate management scripts.
    * *The Fix:* Maintain an approved list of IT service account names and management tool paths permitted to modify AV exclusions. Alert only when `Add-MpPreference` is invoked from unexpected contexts (e.g., from a user's interactive session, or a web application's worker process).

* **Problem 3: Third-Party AV Exclusion Manipulation**
    * *The Issue:* This rule targets Windows Defender/MpPreference. Adversaries targeting environments with third-party AV products (Symantec, CrowdStrike, McAfee) will use vendor-specific commands or registry paths to add exclusions, completely bypassing this detection.
    * *The Fix:* Extend coverage to monitor registry paths and configuration files for other installed AV vendors, and alert on modifications by non-AV processes to known vendor exclusion configuration locations.
