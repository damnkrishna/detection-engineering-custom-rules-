### 1. Technique Breakdown: T1090.003 & T1136.001

* **Description**: Detects multiple outbound connections (3+ within 5 minutes) to known Tor directory/entry nodes (Zeek), followed by the creation of a new local user account (Sysmon Event ID 1 / Security Event 4720) on the target host within 30 minutes, indicating remote persistence setup over anonymous tunnels.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Zeek connection logs mapping target IPs to threat intelligence Tor node databases, requiring daily threat intelligence feed updates and source direction anchoring.
  * Sysmon Process Creation (Event ID 1) with `net.exe user /add` commands (excluding execution by SYSTEM service accounts) or Windows Security Event ID 4720.
* **Coverage Check**:
  * HIDS (Sysmon + Security Logs): YES. Logs user account creation.
  * NIDS (Zeek): YES. Identifies outbound TLS sessions to Tor entry relays.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Threat Intel Feed Staleness**
  * *Issue*: Tor relays change IPs daily. If the threat intel lists matching IP addresses are stale, the rule will have false negatives (missing new nodes) or false positives (matching expired nodes).
  * *Fix*: Operationalize daily updates to the NIDS threat intelligence feed (daily sync for directory and exit node databases).
* **Problem 2: Authorized Testing/Privacy Software**
  * *Issue*: Privacy researchers or authorized penetrators might use Tor browsers, generating Tor sessions and testing user creation scripts.
  * *Fix*: Scope the detection alert to exclude designated laboratory subnets, and ensure outbound directionality checks (`entity_key_direction: "source"`) are enabled to separate initiating nodes from internal relay nodes.
