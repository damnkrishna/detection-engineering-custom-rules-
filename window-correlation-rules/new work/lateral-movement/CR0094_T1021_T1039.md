### 1. Technique Breakdown: T1021.001 & T1039

* **Description**: Detects Remote Desktop Protocol (RDP) connection establishment on port 3389 (target direction) followed by file creation or transfer events of payload file extensions originating from the redirected client drive (`\\tsclient\`) on the target host within 30 minutes, indicating lateral data transfer or payload staging.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Zeek connection logs auditing RDP sessions on port 3389 with target direction.
  * Sysmon File Create (Event ID 11) where the file directory path contains `\\tsclient\` and the file has an executable/payload extension.
* **Coverage Check**:
  * HIDS (Sysmon): YES. Sysmon logs file creations and paths. Files copied from a redirected client drive appear with paths containing `\\tsclient\`.
  * NIDS (Zeek): YES. Captures RDP protocol connections.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Administrators Copying Utility Files**
  * *Issue*: Administrators routinely use drive redirection to copy installation files or scripts from their laptops to servers during sessions, causing false positives.
  * *Fix*: Restrict the file write checks (Stage 1) to ignore benign file extensions like `.txt` or `.log`, focusing primarily on executables (`.exe`, `.dll`, `.ps1`, `.bat`).
* **Problem 2: Client Drive Access Indicators**
  * *Issue*: Opening folders on the redirected drive without copying files might sometimes trigger file lookup events.
  * *Fix*: Confirm that the Sysmon event in Stage 1 is an explicit write or creation (Event ID 11) rather than just process access (Event ID 10) or file read events.
