### 1. Technique Breakdown: T1021.003 & T1047

* **Description**: Detects lateral movement where an attacker utilizes Windows Management Instrumentation (WMI) to execute commands remotely. This involves an inbound RPC connection on port 135 (target direction) followed by `wmiprvse.exe` spawning process shells (such as `cmd.exe`, `powershell.exe`, `pwsh.exe`, `cscript.exe`, or `wscript.exe`) on the target host within 15 minutes.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Zeek connection logs auditing RPC traffic on port 135 with target anchoring.
  * Sysmon Process Creation (Event ID 1) where the parent process is `wmiprvse.exe` and the spawned process is a shell or scripting interpreter.
* **Coverage Check**:
  * HIDS (Sysmon): YES. Processes spawned via WMI run as children of `wmiprvse.exe` and are audited in process logs.
  * NIDS (Zeek): YES. Captures RPC connections and WMI DCOM interfaces over port 135.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: WMI-Based Systems Management Tools**
  * *Issue*: Enterprise management tools (e.g. SCCM, Microsoft Intune, SCOM) use WMI queries and execute management shells routinely on hosts.
  * *Fix*: Tune the rule by excluding known management service accounts, or specific well-known argument signatures belonging to these agents.
* **Problem 2: Broad Parent Process Checking**
  * *Issue*: Sometimes benign applications spawn `wmiprvse.exe` to query local hardware or system details which can create noise.
  * *Fix*: Ensure the correlation requires the *initial network port 135 RPC session* to be present in Stage 0, which isolates local-only query activity.
