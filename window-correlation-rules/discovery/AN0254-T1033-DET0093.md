### **1. Technique Breakdown: T1033**

* **What it is:** **System Owner/User Discovery**. Adversaries enumerate the current user context, logged-on users, or domain accounts to understand who is operating a system, identify high-value targets, or tailor further lateral movement. On Windows, typical methods include `whoami.exe`, `query.exe user`, `quser.exe`, `net.exe user`, or WMI/PowerShell queries (`Get-WmiObject Win32_ComputerSystem`, `Get-LocalUser`, `Get-ADUser`).
* **Log Source Requirements:** Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures the execution of enumeration utilities like `whoami.exe`, `quser.exe`, and `net.exe` including their full command-line arguments.
    * **NIDS (Suricata + Zeek): NO.** Local user enumeration using built-in utilities produces no outbound network traffic. Remote WMI or LDAP queries may leave network traces, but host-side auditing is required to tie them to specific processes.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect execution of user enumeration utilities commonly used by adversaries to identify system owners or user accounts.

```yaml
title: System Owner and User Discovery via Built-in Utilities (AN0254)
id: c6fff3c0-354a-42c2-962d-bbfd96eb62e6
status: experimental
description: Detects adversarial execution of built-in user enumeration tools (whoami, quser, query user, net user) or PowerShell cmdlets used to discover local and domain user accounts.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_whoami:
        - Image|endswith: '\whoami.exe'
        - OriginalFileName: 'whoami.exe'
    selection_quser:
        - Image|endswith:
            - '\quser.exe'
            - '\query.exe'
        - OriginalFileName:
            - 'quser.exe'
            - 'query.exe'
    selection_net:
        - Image|endswith: '\net.exe'
        - OriginalFileName: 'net.exe'
    selection_net_args:
        CommandLine|contains:
            - ' user'
            - ' localgroup'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_args:
        CommandLine|contains:
            - 'Get-LocalUser'
            - 'Get-ADUser'
            - 'Win32_ComputerSystem'
            - 'Win32_UserAccount'
    condition: selection_whoami or selection_quser or (selection_net and selection_net_args) or (selection_powershell and selection_powershell_args)
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - IT administrators executing user discovery commands for asset inventory or helpdesk support activities.
level: low
tags:
    - attack.discovery
    - attack.t1033
    - analytics.an0254
    - detection.det0093
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: High Volume from Legitimate Admin Activity**
    * *The Issue:* `whoami.exe` is an extremely common command invoked by login scripts, automation platforms, and system health tools. Monitoring it without context generates overwhelming alert volumes.
    * *The Fix:* Tune the rule by correlating alerts with unusual parent processes (e.g. web server processes, remote shell sessions, or applications spawning `whoami.exe`). Also consider threshold-based alerting: flag when the same host executes multiple discovery commands within a 60-second window.

* **Problem 2: WMI or PowerShell Remoting Silently Executing Queries**
    * *The Issue:* Adversaries may invoke WMI user queries remotely via `wmic.exe /node:<target>` or PowerShell Remoting (`Invoke-Command`), making the source process on the attacker's machine harder to trace on the victim.
    * *The Fix:* Monitor Windows Remote Management (WinRM) Event ID 4 (WSMan operational) and WMI activity logs (Event ID 5858 in Microsoft-Windows-WMI-Activity) for remote user enumeration queries on victim systems.

* **Problem 3: LDAP-based User Enumeration**
    * *The Issue:* Adversaries targeting domain-joined environments often enumerate users via LDAP queries directly against Active Directory (e.g. `ldapsearch` or custom .NET LDAP clients), bypassing `net.exe` and PowerShell AD cmdlets entirely.
    * *The Fix:* Enable Domain Controller Security Auditing for Directory Service Access (Event ID 4662) with SACL filtering on user object containers to detect bulk LDAP reads from non-authorized hosts.
