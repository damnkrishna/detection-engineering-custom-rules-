### **1. Technique Breakdown: T1518.002**

* **What it is:** **Backup Software Discovery**. Adversaries enumerate backup solutions installed on a host or domain to identify and subsequently disable or destroy backup data before launching ransomware or destructive attacks. Knowing which backup products are deployed (e.g. Veeam, Acronis, Windows Server Backup, ShadowProtect, CrashPlan) allows adversaries to target their specific service names, processes, or registry entries. Common enumeration methods include querying services (`sc.exe query`, `tasklist.exe /SVC`), registry (`reg.exe query`), or PowerShell WMI queries for known backup product names.
* **Log Source Requirements:** Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures execution of `sc.exe`, `reg.exe`, `wmic.exe`, and PowerShell along with their command-line arguments targeting backup software paths.
    * **NIDS (Suricata + Zeek): NO.** Backup software enumeration using service control or registry queries is a host-local operation.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect execution of service, registry, or WMI queries targeting well-known backup software product names and registry paths.

```yaml
title: Backup Software Discovery via CLI and Registry (AN0240)
id: 55e1a399-cba0-444a-99f8-a9545d607475
status: experimental
description: Detects adversarial enumeration of installed backup software using service queries, registry reads, or WMI commands targeting known backup product names (Veeam, Acronis, Windows Backup, ShadowProtect).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_sc:
        - Image|endswith: '\sc.exe'
        - OriginalFileName: 'sc.exe'
    selection_sc_backup:
        CommandLine|contains:
            - 'VeeamBackup'
            - 'AcrSch2Svc'
            - 'WBENGINE'
            - 'BackupExecAgentAccelerator'
            - 'ShadowProtect'
            - 'vss'
    selection_reg:
        - Image|endswith: '\reg.exe'
        - OriginalFileName: 'reg.exe'
    selection_reg_backup:
        CommandLine|contains:
            - '\Veeam'
            - '\Acronis'
            - '\CrashPlan'
            - '\BackupExec'
            - '\ShadowProtect'
            - '\WindowsImageBackup'
    selection_wmic:
        - Image|endswith: '\wmic.exe'
        - OriginalFileName: 'wmic.exe'
    selection_wmic_backup:
        CommandLine|contains:
            - 'Veeam'
            - 'Acronis'
            - 'BackupExec'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_backup:
        CommandLine|contains:
            - 'Veeam'
            - 'Acronis'
            - 'BackupExec'
            - 'ShadowProtect'
            - 'WindowsServerBackup'
            - 'wbadmin'
    condition: (selection_sc and selection_sc_backup) or (selection_reg and selection_reg_backup) or (selection_wmic and selection_wmic_backup) or (selection_powershell and selection_powershell_backup)
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Backup administrators checking backup software status, or deployment scripts verifying backup agent installation during provisioning.
level: high
tags:
    - attack.discovery
    - attack.t1518.002
    - analytics.an0240
    - detection.det0088
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Backup Software Discovery is a Precursor to Destruction**
    * *The Issue:* By itself, querying backup software is not necessarily malicious. The alert value is highest when combined with subsequent backup disruption events (service stops, VSS deletion, registry modifications). Treating it as a standalone alert creates noise.
    * *The Fix:* Implement a correlated detection rule that triggers when backup software discovery is followed within 60 minutes by VSS deletion commands (`vssadmin.exe delete shadows`, `wmic shadowcopy delete`) or service stop events for backup service names.

* **Problem 2: Ransomware Using Compiled Enumeration Modules**
    * *The Issue:* Modern ransomware families often enumerate backup software using compiled lookup tables of service names and process names queried through Windows API calls (e.g. `OpenService()`, `EnumServicesStatus()`), without invoking `sc.exe` or `reg.exe`.
    * *The Fix:* Monitor Sysmon Event ID 10 (ProcessAccess) for `services.exe` being accessed by non-SCM processes with high query rights, and correlate with known ransomware behavioral patterns.

* **Problem 3: Backup Agent Self-Checks**
    * *The Issue:* Veeam, Acronis, and similar backup tools run internal health check processes that may themselves query other installed backup products or their own service status, generating false positives from legitimate backup agent processes.
    * *The Fix:* Allow-list service account contexts and signed binary paths associated with known backup vendor processes. Restrict alerting to cases where the querying process is a command shell, scripting engine, or an unknown binary.
