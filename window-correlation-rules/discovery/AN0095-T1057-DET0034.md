### 1. Technique Breakdown: T1057

* What it is: Process Discovery. Adversaries enumerate running processes on a target host to identify active security tools, running services, or user applications. The information helps adversaries determine if a host is being monitored, which security products are active, or where to inject malicious code. Common enumeration tools include `tasklist.exe`, `wmic.exe process list`, or PowerShell's `Get-Process` cmdlet.
* Log Source Requirements: Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures spawning of `tasklist.exe`, `wmic.exe`, and PowerShell along with their command-line arguments.
    * NIDS (Suricata + Zeek): NO. Process enumeration is a host-local operation that produces no network traffic.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect execution of common process discovery utilities used by adversaries to enumerate active processes on a host.

```yaml
title: Process Discovery via Enumeration Utilities (AN0095)
id: 42ac3a50-9a37-4862-a1e8-6aec1b8b786f
status: experimental
description: Detects adversarial execution of process enumeration tools (tasklist.exe, wmic process, Get-Process) used to discover running processes on a compromised host.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_tasklist:
        - Image|endswith: '\tasklist.exe'
        - OriginalFileName: 'tasklist.exe'
    selection_wmic:
        - Image|endswith: '\wmic.exe'
        - OriginalFileName: 'wmic.exe'
    selection_wmic_args:
        CommandLine|contains:
            - ' process'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_args:
        CommandLine|contains:
            - 'Get-Process'
            - 'Get-WmiObject Win32_Process'
            - 'Get-CimInstance Win32_Process'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_tasklist or (selection_wmic and selection_wmic_args) or (selection_powershell and selection_powershell_args)) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - System administrators running process inventories for health checks, or monitoring tools that periodically enumerate running services.
level: medium
tags:
    - attack.discovery
    - attack.t1057
    - analytic.an0095
    - detection.det0034
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Volume Noise from Monitoring and Backup Tools
  * The Issue: Enterprise monitoring agents (like SCCM, SolarWinds, Nagios, or endpoint telemetry tools) regularly run tasklist.exe or WMI process queries as part of scheduled health checks, generating high alert noise.
  * The Fix: Implement allow-listing of known monitoring agent processes, service accounts, and signed binary paths. Restrict alerting to suspicious parent processes (e.g. browser processes, downloaded scripts, or Office applications spawning tasklist.exe).

* Problem 2: In-Memory Process Enumeration via API
  * The Issue: Sophisticated adversaries may call CreateToolhelp32Snapshot() or NtQuerySystemInformation() API functions directly in compiled payloads, bypassing tasklist.exe entirely. These calls won't be captured by process creation monitoring.
  * The Fix: Deploy EDR solutions with API hooking capabilities, or monitor Sysmon Event ID 10 (ProcessAccess) for processes accessing all other running processes with PROCESS_QUERY_INFORMATION rights.

* Problem 3: Remote Process Discovery via WMI or PsExec
  * The Issue: Adversaries can remotely enumerate running processes on victim hosts using WMI remote execution (e.g. wmic /node:<target> process list) from a beachhead machine. The query executes on the target with WMI service as the process owner.
  * The Fix: Monitor WMI Activity logs (Microsoft-Windows-WMI-Activity/Operational, Event ID 5861) on target machines for remote process enumeration, and correlate with active network connections to the WMI ports (TCP 135, dynamic RPC).
