### **1. Technique Breakdown: T1482**

* **What it is:** **Domain Trust Discovery**. Adversaries enumerate domain trust relationships to identify forest or domain boundaries they can pivot across. By discovering which domains trust each other (and the direction of that trust), adversaries identify targets for Kerberoasting, cross-domain lateral movement, or privilege escalation to forest root domains. Common enumeration methods include `nltest.exe /domain_trusts`, PowerShell Active Directory cmdlets (`Get-ADTrust`), or native Win32 API functions (`DsEnumerateDomainTrusts`, `NetEnumerateTrustedDomains`).
* **Log Source Requirements:** Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and PowerShell Script Block Logs (Event ID 4104).
* **Coverage Check:**
    * **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 captures execution of `nltest.exe` and PowerShell AD cmdlets along with their full command-line arguments.
    * **NIDS (Suricata + Zeek): NO.** Domain trust enumeration using local utilities generates no distinctive network traffic. LDAP queries to domain controllers for trust objects may be observable on the wire, but require host correlation.

### **2. Custom Sigma Rule**

This rule utilizes **Sysmon Event ID 1 (Process Creation)** to detect command-line execution of domain trust discovery utilities and PowerShell Active Directory cmdlets targeting trust enumeration.

```yaml
title: Domain Trust Discovery via nltest and PowerShell (AN0016)
id: 3d153687-ea2c-4828-ac64-2935d5b45f61
status: experimental
description: Detects adversarial execution of nltest.exe, dsquery.exe, or PowerShell AD cmdlets used to enumerate Active Directory domain trust relationships.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_nltest:
        - Image|endswith: '\nltest.exe'
        - OriginalFileName: 'nltest.exe'
    selection_nltest_args:
        CommandLine|contains:
            - '/domain_trusts'
            - '/trusted_domains'
            - '/all_trusts'
    selection_dsquery:
        - Image|endswith: '\dsquery.exe'
        - OriginalFileName: 'dsquery.exe'
    selection_dsquery_args:
        CommandLine|contains: 'trustedDomain'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_args:
        CommandLine|contains:
            - 'Get-ADTrust'
            - 'Get-NetDomainTrust'
            - 'Get-DomainTrust'
            - 'DSEnumerateDomainTrusts'
            - 'NetEnumerateTrustedDomains'
    condition: (selection_nltest and selection_nltest_args) or (selection_dsquery and selection_dsquery_args) or (selection_powershell and selection_powershell_args)
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Domain administrators running trust enumeration during Active Directory health assessments or federation setup tasks.
level: medium
tags:
    - attack.discovery
    - attack.t1482
    - analytics.an0016
    - detection.det0007
```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: Trust Enumeration via .NET Managed Code**
    * *The Issue:* Adversaries using post-exploitation frameworks (like CobaltStrike or Metasploit) can call `System.DirectoryServices.ActiveDirectory.Domain.GetCurrentDomain().GetAllTrustRelationships()` in compiled .NET assemblies executed in-memory. No process creation event for `nltest.exe` or `dsquery.exe` will be generated.
    * *The Fix:* Monitor PowerShell Script Block Logging (Event ID 4104) for `.DirectoryServices.ActiveDirectory` class instantiation patterns, and use memory scanning or ETW-based detection for suspicious managed code loading.

* **Problem 2: BloodHound/SharpHound Trust Enumeration**
    * *The Issue:* Tools like SharpHound enumerate domain trusts through LDAP queries and SAMR RPC calls, generating many small LDAP requests rather than a single `nltest.exe` run. Individual queries are difficult to distinguish from normal AD replication traffic.
    * *The Fix:* Alert on large-volume LDAP read patterns from workstations within short time windows on domain controllers, or deploy honeypot AD objects (deceptive trust relationships that no legitimate tool should query).

* **Problem 3: Legitimate Active Directory Management**
    * *The Issue:* Active Directory administrators or federation tools (e.g. ADFS configuration wizards) routinely run `nltest.exe /domain_trusts` or `Get-ADTrust` during federation setup, health checks, or disaster recovery testing.
    * *The Fix:* Scope alerts to non-privileged user contexts by correlating with the account SID, and restrict alerting to executions from user workstations rather than domain controller or ADFS server hosts.
