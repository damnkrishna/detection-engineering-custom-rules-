### **1. Technique Breakdown: T1003.002**

* **What it is:** **OS Credential Dumping: Security Account Manager (SAM)**. Adversaries target the SAM database on Windows to extract local account credentials (NTLM hashes). This allows them to crack passwords offline or use the hashes directly for pass-the-hash attacks. The most common method is exporting the `SAM`, `SYSTEM`, and `SECURITY` registry hives using built-in tools like `reg.exe`.
* **Log Source Requirements:** This is purely an endpoint-level execution technique. It requires process creation monitoring with command-line arguments enabled, or registry access auditing.
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** This is exactly what Sysmon Event ID 1 (Process Creation) and Event ID 12/13 (Registry Events) are built for. Wazuh will easily collect and forward these events.
* **NIDS (Suricata + Zeek): NO.** Dumping local registry hives generates no network traffic. Your NIDS stack is blind to this specific action (though it might catch the subsequent exfiltration of the dumped files if sent unencrypted).

### **2. Custom Sigma Rule**

This rule leverages **Sysmon Event ID 1 (Process Creation)** to catch the most common execution method: an adversary using `reg.exe` to save the hives to disk. It incorporates your specific Analytics and Detection IDs.

```yaml
title: Suspicious SAM Registry Hive Export (AN0235)
id: 5a415a72-68c8-4720-8025-a6abfa7216dc
status: experimental
description: Detects attempts to export the SAM, SYSTEM, or SECURITY registry hives using the reg.exe command line utility, indicating potential credential dumping (T1003.002).
author: Krishna Gupta
date: 2026-06-05
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_img:
        - Image|endswith: '\reg.exe'
        - OriginalFileName: 'reg.exe'
    selection_action:
        CommandLine|contains|all:
            - 'save'
    selection_target:
        CommandLine|contains:
            - 'HKLM\SAM'
            - 'HKLM\SYSTEM'
            - 'HKLM\SECURITY'
            - 'hklm\sam'
            - 'hklm\system'
            - 'hklm\security'
    condition: selection_img and selection_action and selection_target
fields:
    - CommandLine
    - Image
    - OriginalFileName
falsepositives:
    - Legitimate system backup operations or imaging tools.
    - Rare administrative troubleshooting by IT personnel.
level: high
tags:
    - attack.credential_access
    - attack.t1003.002
    - analytics.an0235
    - detection.det0085

```

### **3. Blind Spots & Tuning (The "Problems")**

While the rule above catches the "script kiddie" or standard automated playbook approaches, it has distinct limitations that an advanced adversary will abuse.

* **Problem 1: Evasion via Volume Shadow Copies (VSS)**
* *The Issue:* Attackers don't have to use `reg.exe`. They can use `vssadmin` or WMI to create a volume shadow copy and simply copy the raw SAM files directly out of `C:\Windows\System32\config\`.
* *The Fix:* You will need a separate correlation rule looking for `vssadmin.exe create shadow` combined with copy commands pointing to the `\System32\config` directory.


* **Problem 2: API Abuse (In-Memory Dumping)**
* *The Issue:* Sophisticated malware or tools like Mimikatz don't spawn `reg.exe`. They make direct Windows API calls (like `RegSaveKey`) to dump the hives. Process creation logs (Event ID 1) will be completely blind to this.
* *The Fix:* You need to tune Sysmon to capture Event ID 10 (Process Access) targeting LSASS, or enable rigorous Registry Auditing (Event IDs 12, 13, 14) for the specific SAM/SYSTEM paths.


* **Problem 3: Command Line Obfuscation**
* *The Issue:* `cmd.exe` allows for string splitting and character insertion. An attacker executing `r^e^g s^a^v^e HKLM\SAM` will bypass the literal string matches in the Sigma rule.
* *The Fix:* If your SIEM/Wazuh setup supports regex, transition the string matching to account for wildcard characters, or rely heavily on `OriginalFileName: 'reg.exe'` to catch renamed binaries.


* **Problem 4: False Positives from Backups**
* *The Issue:* Enterprise backup solutions (like Veeam, Acronis, or even built-in Windows Server Backup) frequently access these hives.
* *The Fix:* You will need to baseline your environment and add exclusions (e.g., `filter_backups: ParentImage|startswith: 'C:\Program Files\YourBackupVendor\'`) to prevent alert fatigue.
