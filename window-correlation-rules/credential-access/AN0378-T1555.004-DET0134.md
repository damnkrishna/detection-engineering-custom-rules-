### **1. Technique Breakdown: T1555.004**

* **What it is:** **Credentials from Password Stores: Windows Credential Manager**. Adversaries attempt to extract passwords and credential materials stored securely in the Windows Credential Manager (the "Vault"). This vault often contains saved RDP credentials, network share passwords, and web credentials. Attackers typically use native "Living off the Land" (LotL) binaries like `cmdkey.exe` or `vaultcmd.exe` to enumerate and dump these.
* **Log Source Requirements:** This requires endpoint telemetry focused on process creation and command-line execution arguments.
* **Coverage Check:**
* **HIDS (Sysmon + Wazuh): YES.** Sysmon Event ID 1 (Process Creation) is perfectly suited to catch the execution of `cmdkey.exe` or `vaultcmd.exe` when paired with enumeration flags. Wazuh will ingest this seamlessly.
* **NIDS (Suricata + Zeek): NO.** Querying the local Windows Credential Manager happens entirely on the host machine. There is no network traffic generated during the enumeration phase, meaning your network sensors will not see this activity.

### **2. Custom Sigma Rule**

This rule uses **Sysmon Event ID 1 (Process Creation)** to detect the execution of native Windows binaries commonly abused to list stored credentials in the vault.

```yaml
title: Suspicious Windows Credential Manager Access (AN0378)
id: f3b91a7e-2c8d-4a1f-9e6b-5d4c8a2f1e0d
status: experimental
description: Detects command-line operations attempting to enumerate or extract stored credentials from the Windows Credential Manager (Vault) using native utilities, indicating potential credential theft (T1555.004).
author: Krishna Gupta
date: 2026-06-05
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 collected via Wazuh
detection:
    selection_tools:
        - Image|endswith: 
            - '\cmdkey.exe'
            - '\vaultcmd.exe'
        - OriginalFileName: 
            - 'cmdkey.exe'
            - 'vaultcmd.exe'
    selection_args:
        CommandLine|contains:
            - '/list'
            - '/l'
    condition: selection_tools and selection_args
falsepositives:
    - IT administrators troubleshooting network drive mappings or RDP access.
    - Automated deployment scripts configuring persistent network share access.
level: high
tags:
    - attack.credential_access
    - attack.t1555.004
    - analytics.an0378
    - detection.det0134

```

### **3. Blind Spots & Tuning (The "Problems")**

* **Problem 1: API Abuse (The Mimikatz Problem)**
* *The Issue:* Just like with SAM dumping and browser stealing, advanced attackers don't rely on `cmdkey.exe`. Specialized tools or in-memory scripts (like Mimikatz's `dpapi` and `vault` modules, or `Invoke-WCMDump`) use direct Windows API calls (such as `CredEnumerateW`) to pull the credentials. Sysmon Event ID 1 won't see any command-line execution because the LotL binaries were bypassed entirely.
* *The Fix:* You would need to hunt for the actual vault files being accessed by unusual processes. The physical vault files live in `C:\Users\<user>\AppData\Local\Microsoft\Vault`. You can enable Object Access Auditing on that folder, but it is notoriously noisy.


* **Problem 2: Offline Vault Extraction**
* *The Issue:* An attacker might simply compress and exfiltrate the entire `\Microsoft\Vault` directory and the user's DPAPI master keys to decrypt the vault offline on their own machine.
* *The Fix:* You will need a supplementary rule looking for archiving tools (like `tar.exe` or `7z.exe`) pointing at those specific AppData or ProgramData vault paths.


* **Problem 3: False Positives from Logon Scripts**
* *The Issue:* In many enterprise environments, login scripts (GPO-driven `.bat` or `.ps1` files) use `cmdkey` to automatically mount user-specific network drives upon boot. This will trigger your rule constantly.
* *The Fix:* You will need to baseline your environment. If `cmdkey` is used legitimately, you'll need to add filters allowing it *only* if the Parent Process is the specific management agent or logon script handler (e.g., `filter_legit_script: ParentImage|endswith: '\userinit.exe'`).
