### 1. Technique Breakdown: T1621

* What it is: Multi-Factor Authentication Request Generation (commonly known as MFA Fatigue or MFA Spamming). Adversaries who have already compromised a user's primary password repeatedly spam the user's mobile device with MFA push notifications. The goal is to annoy, confuse, or exhaust the user into accidentally (or intentionally) tapping "Approve" just to make the notifications stop.
* Log Source Requirements: This attack happens entirely at the authentication boundary. It requires Identity Provider (IdP) logs (e.g., Azure AD, Okta, Duo) or VPN Gateway authentication logs.
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): NO. Sysmon and Microsoft Defender cannot see this because the attack does not execute on the local Windows endpoint; it targets the cloud/IdP infrastructure and the user's phone.
  * Windows Security Logs: NO. Standard Active Directory Event Logs (such as Event IDs 4625, 4771, 4776) only log primary authentication credential validation (passwords). If the password is correct, successful authentication events are logged, but standard Windows Event Logs do not capture secondary MFA challenge requests, approvals, or push timeouts.
* Conclusion: This technique is not detectable from Sysmon, Windows Security, or Defender logs.

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Push Notification Fatigue Evasion
  * The Issue: Because the authentication challenge occurs out-of-band on a user's mobile device, standard host-based intrusion detection systems (HIDS) have a complete blind spot for this activity.
  * The Fix: Pivot to cloud Identity Provider (IdP) logs (like Azure AD Sign-in logs or Okta System logs) and implement alerting for users experiencing multiple authentication prompts followed by a successful login. Additionally, enforce Number Matching in Authenticator apps to prevent accidental approval.
