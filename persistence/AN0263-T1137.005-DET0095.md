# AN0263 - Office Application Startup: Outlook Rules (T1137.005)

## Technique Breakdown
Adversaries can use malicious Outlook rules to achieve persistence and execute code. Rules can be configured to start an application, execute macros, or forward emails when specific conditions are met. These rules are stored in the user's mailbox and backed by local registry configurations. Defenders should monitor registry modifications targeting Outlook Rules keys or specific process chains where Outlook spawns unusual child processes (e.g., cmd.exe, powershell.exe).

## Custom Sigma Rule

```yaml
id: 'AN0263'
status: experimental

  product: windows
  category: registry_set

    EventType: 'SetValue'
  condition: selection_registry and selection_event

  - EventID
  - TargetObject

  - Details
```


## Blind Spots & Tuning
- Legitimate Outlook rule creation by end users may interact with the registry in similar ways, though most modern rule changes are handled within the mailbox database.
- Tuning is required to establish a baseline of normal user Outlook interaction vs scripted registry injections.
