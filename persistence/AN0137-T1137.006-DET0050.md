### 1. Technique Breakdown: T1137.006

* What it is: Add-ins. Adversaries abuse Microsoft Office add-in mechanisms to achieve persistent code execution that triggers each time an Office application is launched. Add-in formats include Word WLL files (.wll), Excel XLL files (.xll), VBA add-ins (.xlam, .dotm), and COM-based add-ins registered in the Windows Registry. Adversaries drop a malicious add-in DLL or document into trusted add-in directories (e.g., %APPDATA%\Microsoft\Word\Startup\, %APPDATA%\Microsoft\Excel\XLSTART\) or add registry keys pointing to their payload.
* Log Source Requirements: Endpoint registry modification monitoring logs and file event logs capturing Office startup directory writes.
* Coverage Check:
  - HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 12/13 monitors registry modifications, and Event ID 11 captures file creation events.
  - NIDS (Suricata + Zeek): NO. Host-level operations.
* Log Sources Covered:
  - Sysmon Event ID 13 (registry_set)
  - Sysmon Event ID 11 (file_event)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into registry modification monitoring of Office add-in registration paths, and file creation monitoring of add-in extension file drops.

Rule 1 of 2: Malicious Office Add-in Registry Persistence (Registry Set)
```yaml
title: Malicious Office Add-in Registry Persistence (AN0137)
id: 0eb25533-0c04-4068-8d7b-d704d5df8077
status: experimental
description: Detects registry modifications creating or updating Office add-in registration keys, indicating persistence establishment.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: registry_set
    product: windows
detection:
    selection_office_addin:
        TargetObject|contains:
            - '\SOFTWARE\Microsoft\Office\Word\Addins\'
            - '\SOFTWARE\Microsoft\Office\Excel\Addins\'
            - '\SOFTWARE\Microsoft\Office\Outlook\Addins\'
            - '\SOFTWARE\Microsoft\Office\PowerPoint\Addins\'
    condition: selection_office_addin
fields:
    - TargetObject
    - Image
    - User
    - LogonId
falsepositives:
    - Standard installation of enterprise approved Office add-ins.
level: high
tags:
    - attack.persistence
    - attack.t1137.006
    - analytic.an0137
    - detection.det0050
```

Rule 2 of 2: Malicious Office Add-in Drop for Persistence (File Event)
```yaml
title: Malicious Office Add-in Drop for Persistence (AN0137-B)
id: f491ca8d-71b3-4f9c-be82-f5da771bc39a
status: experimental
description: Detects drops of WLL, XLL, XLAM, or DOTM add-in files to Word, Excel, or PowerPoint startup directories.
author: Krishna Gupta
date: 2026-06-17
logsource:
    category: file_event
    product: windows
detection:
    selection_addin_paths:
        TargetFilename|contains:
            - '\Microsoft\Word\Startup\'
            - '\Microsoft\Excel\XLSTART\'
            - '\Microsoft\AddIns\'
            - '\Microsoft\Office\Root\Office16\STARTUP\'
    selection_addin_extensions:
        TargetFilename|endswith:
            - '.wll'
            - '.xll'
            - '.xlam'
            - '.dotm'
            - '.ppam'
            - '.ppa'
    filter_office_updater:
        Image|contains:
            - '\OfficeClickToRun.exe'
            - '\OfficeC2RClient.exe'
            - '\setup.exe'
    condition: (selection_addin_paths or selection_addin_extensions) and not filter_office_updater
fields:
    - Image
    - TargetFilename
falsepositives:
    - Sanctioned Office add-in installation or automated deployment.
level: high
tags:
    - attack.persistence
    - attack.t1137.006
    - analytic.an0137
    - detection.det0050
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Legitimate Office Add-in Deployment
  - The Issue: Organizations deploy approved add-ins via administrative tools.
  - The Fix: Maintain an allow-list of approved add-in filenames.

* Problem 2: Registry-Registered COM Add-ins
  - The Issue: COM add-ins are registered via keys and do not generate file event drops in startup directories.
  - The Fix: Registry rule covers registry creation.

* Problem 3: Office Application Child Process Spawning Detection
  - The Issue: File drop rule doesn't catch execution when Office runs.
  - The Fix: Monitor Office applications spawning shells.
