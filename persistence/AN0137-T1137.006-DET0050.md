### 1. Technique Breakdown: T1137.006

* What it is: Add-ins. Adversaries abuse Microsoft Office add-in mechanisms to achieve persistent code execution that triggers each time an Office application is launched. Add-in formats include Word WLL files (`.wll`), Excel XLL files (`.xll`), VBA add-ins (`.xlam`, `.dotm`), and COM-based add-ins registered in the Windows Registry. Adversaries drop a malicious add-in DLL or document into trusted add-in directories (e.g., `%APPDATA%\Microsoft\Word\Startup\`, `%APPDATA%\Microsoft\Excel\XLSTART\`) or add registry keys pointing to their payload. When the user opens Word or Excel, the add-in is automatically loaded, executing the adversary's payload — often spawning a scripting engine or network connection.
* Log Source Requirements: Sysmon file event logs (Event ID 11) for add-in file drops, Sysmon registry monitoring (Event IDs 12/13) for add-in registry key modifications, and process creation logs (Event ID 1) for Office apps spawning unexpected child processes.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 11 captures files written to Office startup directories. Sysmon Event ID 13 captures registry writes registering add-in paths. Sysmon Event ID 1 captures child processes spawned by `WINWORD.EXE` or `EXCEL.EXE`.
    * NIDS (Suricata + Zeek): NO. Add-in file drops and registry modifications are host-local operations producing no network traffic.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 11 (File Create) to detect files with Office add-in extensions being written to Office startup directories, and Sysmon Event ID 1 to detect Office applications spawning unexpected shell child processes upon add-in load.

```yaml
title: Malicious Office Add-in Drop for Persistence (AN0137)
id: 0eb25533-0c04-4068-8d7b-d704d5df8077
status: experimental
description: Detects adversarial Office add-in persistence via file drops of WLL/XLL/XLAM/DOTM files to Office startup directories, or Office applications spawning unexpected shell child processes upon add-in execution.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: file_event
    product: windows
    # Relies on Sysmon Event ID 11
detection:
    selection_addin_paths:
        TargetFilename|contains:
            - '\Microsoft\Word\Startup\'
            - '\Microsoft\Excel\XLSTART\'
            - '\Microsoft\AddIns\'
            - '\Microsoft\Office\Root\Office16\STARTUP\'
    selection_addin_extensions:
        TargetFilename|endswith:
            - '.wll'
            - '.xll'
            - '.xlam'
            - '.dotm'
            - '.ppam'
            - '.ppa'
    filter_office_updater:
        Image|contains:
            - '\OfficeClickToRun.exe'
            - '\OfficeC2RClient.exe'
            - '\setup.exe'
    condition: (selection_addin_paths or selection_addin_extensions) and not filter_office_updater
fields:
    - Image
    - TargetFilename
falsepositives:
    - Legitimate Office add-in installation by sanctioned IT tools or enterprise add-in deployment packages.
level: high
tags:
    - attack.persistence
    - attack.t1137.006
    - analytic.an0137
    - detection.det0050
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Legitimate Office Add-in Deployment
  * The Issue: Organizations deploy approved add-ins (e.g., DocuSign, Adobe Acrobat PDF Maker, Grammarly) via Group Policy or IT deployment tools, which write XLL/XLAM files to Office startup directories. These trigger the detection rule.
  * The Fix: Maintain an allow-list of approved add-in filenames and their expected deployment process paths (e.g., Group Policy scripts, SCCM agents). Restrict alerts to add-in drops performed by interactive user sessions, script interpreters, or unknown processes.

* Problem 2: Registry-Registered COM Add-ins
  * The Issue: COM-based add-ins are registered via registry keys (HKCU\SOFTWARE\Microsoft\Office\<version>\<App>\AddIns\) rather than file drops to startup directories. These don't generate file event alerts for the add-in drop itself.
  * The Fix: Add a complementary rule monitoring Sysmon Registry Event ID 13 (RegistryValueSet) for modifications to Office add-in registry paths (\Office\Word\AddIns\, \Office\Excel\AddIns\) by processes other than the Office suite itself.

* Problem 3: Office Application Child Process Spawning Detection
  * The Issue: The file drop rule catches the persistence installation, but not the payload execution when Office loads the add-in. A user may open Word days later, triggering the payload — and only process lineage (Word → cmd/powershell) signals the execution.
  * The Fix: Complement with a process creation rule detecting WINWORD.EXE or EXCEL.EXE as parent process spawning cmd.exe, powershell.exe, wscript.exe, cscript.exe, or rundll32.exe — a strong indicator of add-in payload execution.
