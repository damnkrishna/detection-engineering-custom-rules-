### 1. Technique Breakdown: T1614

* What it is: System Location Discovery. Adversaries may gather information in an attempt to calculate the geographical location of a victim in order to infer their operational environment.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688 / PowerShell Event ID 4104.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. PowerShell and reg.exe command lines are captured.
  - NIDS (Suricata + Zeek): NO. Host-local discovery.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 1: System Locale and Keyboard Layout Discovery
Detects queries for regional/locale settings via registry or PowerShell, used by malware to determine victim geography.

```yaml
title: System Locale and Keyboard Layout Discovery (AN2088)
id: b2c3d4e5-f6a7-8901-bcde-f01234567891
status: experimental
description: Detects command-line queries of Windows locale, keyboard layout, or timezone registry keys used to determine system geographic location. Covers renamed binaries via OriginalFileName to resist trivial binary-rename evasion.
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_reg:
        Image|endswith:
            - '\reg.exe'
    selection_reg_ofn:
        OriginalFileName: 'reg.exe'
    selection_reg_cli:
        CommandLine|contains:
            - 'International'
            - 'Keyboard Layout'
            - 'TimeZoneInformation'
    selection_ps:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_ps_ofn:
        OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.exe'
    selection_ps_cli:
        CommandLine|contains:
            - 'Get-Culture'
            - 'Get-WinSystemLocale'
            - 'CurrentCulture'
            - 'TimeZone'
    selection_wmic:
        Image|endswith:
            - '\wmic.exe'
    selection_wmic_ofn:
        OriginalFileName: 'wmic.exe'
    selection_wmic_cli:
        CommandLine|contains:
            - 'os get locale'
    condition: ((selection_reg or selection_reg_ofn) and selection_reg_cli) or ((selection_ps or selection_ps_ofn) and selection_ps_cli) or ((selection_wmic or selection_wmic_ofn) and selection_wmic_cli)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - Application installers configuring locale-specific defaults.
level: low
tags:
    - attack.discovery
    - attack.t1614
    - analytic.an2088
    - detection.det0945
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Win32 API Calls
  * The Issue: Malware calling `GetSystemDefaultLCID()` or `GetLocaleInfo()` directly bypasses process-level detection.
  * The Fix: Requires API-level monitoring via EDR or memory analysis.
* Problem 2: WMI Queries
  * The Issue: `wmic os get locale` achieves the same result without registry access.
  * The Fix: Add a WMIC-based detection block or rely on a generic WMIC monitoring rule.
* Problem 3: OriginalFileName availability
  * The Issue: OriginalFileName is only present when PE metadata is intact.
  * The Fix: Treat Image and OriginalFileName as complementary — either match alone is sufficient.
