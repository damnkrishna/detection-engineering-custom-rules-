### 1. Technique Breakdown: T1120

* What it is: Peripheral Device Discovery. Adversaries may attempt to gather information about attached peripheral devices (e.g., USB drives, cameras).
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688 / PowerShell Event ID 4104.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. PowerShell script block contents and process command lines are captured.
  - NIDS (Suricata + Zeek): NO. Host-local discovery.
* Log Sources Covered:
  - PowerShell Event ID 4104 (script_block)
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 1: Peripheral Device Discovery via PowerShell or WMI
Detects queries for Plug and Play (PnP) entities, often used to enumerate attached USB drives or hardware tokens.

```yaml
title: Peripheral Device Discovery via PowerShell or WMI (AN2086)
id: cbdf2001-a189-4db8-bb9a-7c9802cf0050
status: experimental
description: Detects command-line execution or PowerShell script blocks querying Win32_PnPEntity to enumerate peripheral devices. Covers renamed binaries via OriginalFileName to resist trivial binary-rename evasion.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_wmic:
        Image|endswith:
            - '\wmic.exe'
    selection_wmic_ofn:
        OriginalFileName: 'wmic.exe'
    selection_wmic_cli:
        CommandLine|contains:
            - 'path win32_pnpentity'
    selection_powershell:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_ps_ofn:
        OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.exe'
    selection_ps_cli:
        CommandLine|contains:
            - 'Get-PnpDevice'
            - 'Win32_PnPEntity'
    condition: ((selection_wmic or selection_wmic_ofn) and selection_wmic_cli) or ((selection_powershell or selection_ps_ofn) and selection_ps_cli)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - Device management software or driver update utilities auditing attached hardware.
level: low
tags:
    - attack.discovery
    - attack.t1120
    - analytic.an2086
    - detection.det0943
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Native API Abstraction
  * The Issue: If the attacker uses C/C++ malware with `SetupDiGetClassDevs` to query devices directly, it will not trigger command-line or script block rules.
  * The Fix: Requires EDR or API hooking to monitor hardware device enumeration at the Win32 API level.
* Problem 2: Registry Enumeration
  * The Issue: Attackers can manually read `HKLM\SYSTEM\CurrentControlSet\Enum\USBSTOR` to find historically attached USB devices.
  * The Fix: Monitor registry access to the `USBSTOR` hive using Sysmon Event ID 12 (Registry Event).
* Problem 3: OriginalFileName availability
  * The Issue: OriginalFileName is only present in Sysmon logs when PE metadata is intact; packed or hollowed binaries may lack it.
  * The Fix: Treat the Image and OriginalFileName paths as complementary — either catch alone is sufficient.
