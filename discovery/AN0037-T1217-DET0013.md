### 1. Technique Breakdown: T1217

* What it is: Browser Information Discovery. Adversaries access local browser artifact directories (such as Chrome, Edge, or Firefox profile folders) to enumerate bookmarks, browsing history, saved passwords, cookies, or autofill data. This information can reveal visited internal portals, credentials, or session tokens. On Windows, these artifacts are stored in user profile directories like `%LOCALAPPDATA%\Google\Chrome\User Data\`, `%APPDATA%\Mozilla\Firefox\Profiles\`, or `%LOCALAPPDATA%\Microsoft\Edge\User Data\`.
* Log Source Requirements: File event logs (Sysmon Event ID 11) and Process Creation logs (Sysmon Event ID 1) showing command-line access to browser profile directories.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 11 captures file-level operations. Event ID 1 logs CLI copy or query operations targeting these directories.
    * NIDS (Suricata + Zeek): NO. Local browser file access is host-local.
* Log Sources Covered:
    - Sysmon Event ID 1 (process_creation)
    - Sysmon Event ID 11 (file_event)
* Log Sources Missing / Unused:
    - None.

### 2. Custom Sigma Rule

The detection logic is split into two rules targeting file modification events and command-line copy/query executions targeting browser profile directories separately.

Rule 1 of 2: Browser Artifact Access for Reconnaissance (File Event)
```yaml
title: Browser Artifact Access for Reconnaissance (AN0037-A)
id: 9509315a-1c36-45ed-924e-490db67b3716
status: experimental
description: Detects non-browser processes accessing local browser profile artifact directories (Chrome, Edge, Firefox) which may indicate browser information discovery for credential theft or reconnaissance.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: file_event
    product: windows
    # Relies on Sysmon Event ID 11
detection:
    selection_browser_paths:
        TargetFilename|contains:
            - '\Google\Chrome\User Data\'
            - '\Microsoft\Edge\User Data\'
            - '\Mozilla\Firefox\Profiles\'
            - '\Opera Software\Opera Stable\'
            - '\BraveSoftware\Brave-Browser\User Data\'
    selection_browser_files:
        TargetFilename|endswith:
            - '\Login Data'
            - '\Cookies'
            - '\History'
            - '\Bookmarks'
            - '\Web Data'
            - 'places.sqlite'
            - 'key4.db'
            - 'logins.json'
    filter_browsers:
        Image|endswith:
            - '\chrome.exe'
            - '\msedge.exe'
            - '\firefox.exe'
            - '\brave.exe'
            - '\opera.exe'
    condition: (selection_browser_paths or selection_browser_files) and not filter_browsers
fields:
    - Image
    - TargetFilename
falsepositives:
    - Backup software copying browser profile directories, or legitimate password manager tools accessing browser databases.
level: high
tags:
    - attack.discovery
    - attack.t1217
    - analytic.an0037
    - detection.det0013
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Backup Software Accessing Browser Profiles
  * The Issue: Enterprise backup agents (e.g. Veeam, Acronis) or Windows Backup copy entire user profile directories including browser folders as part of regular scheduled backups.
  * The Fix: Identify and allow-list the process paths and service accounts used by approved backup tools. Restrict alerting to non-scheduled, non-backup process contexts.

* Problem 2: In-Memory Credential Extraction Without File Access
  * The Issue: Advanced credential theft tools (like LaZagne or SharpChrome) may load the encrypted browser database into memory, decrypt it, and extract credentials without creating new file events that would trigger file creation/write detection rules.
  * The Fix: Supplement with Sysmon Event ID 10 (ProcessAccess) to detect handle opens to browser database files, and correlate with memory injection or ReadProcessMemory calls on browser processes.

* Problem 3: Browser Data Copied to Another Directory First
  * The Issue: Attackers may first copy the browser database file to a temp directory (e.g., %TEMP%\Login_copy.db) and then extract credentials from the copy. The copy operation may produce a file create event in %TEMP% rather than the browser profile.
  * The Fix: Monitor file copy operations that source from browser profile directories, regardless of destination path. Correlate file creation in %TEMP% with SQLite database file extensions (.db, .sqlite).
