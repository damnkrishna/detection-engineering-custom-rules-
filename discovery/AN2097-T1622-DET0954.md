### 1. Technique Breakdown: T1622

* What it is: Debugger Evasion. Adversaries may employ various means to detect and avoid debuggers to prevent reverse engineering or dynamic analysis.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Process command lines querying debug-related artifacts are captured.
  - NIDS (Suricata + Zeek): NO. Host-local discovery.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 1: Debugger Presence Check via Registry or NtGlobalFlag
Detects command-line queries for debugger-related registry keys or process heap flags used by malware to check if it is being analyzed.

```yaml
title: Debugger Presence Check via Registry or Process Query (AN2097)
id: e1f2a3b4-c5d6-7890-4567-890000000010
status: experimental
description: Detects command-line queries targeting debugger artifacts in the registry (Image File Execution Options, postmortem debugger) used by malware to determine if it is being debugged. Covers renamed binaries via OriginalFileName to resist trivial binary-rename evasion.
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_reg:
        Image|endswith:
            - '\reg.exe'
    selection_reg_ofn:
        OriginalFileName: 'reg.exe'
    selection_reg_cli:
        CommandLine|contains:
            - 'Image File Execution Options'
            - 'AeDebug'
            - 'GlobalFlag'
            - 'postmortem'
    condition: (selection_reg or selection_reg_ofn) and selection_reg_cli
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - Developers configuring just-in-time (JIT) debugging for application crash handling.
level: medium
tags:
    - attack.defense_evasion
    - attack.t1622
    - analytic.an2097
    - detection.det0954
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: IsDebuggerPresent API
  * The Issue: The most common debugger check — calling `IsDebuggerPresent()` or `CheckRemoteDebuggerPresent()` — leaves no registry or command-line trace.
  * The Fix: Requires EDR API-level hooking to detect calls to those specific Win32 debug-check functions.
* Problem 2: Heap Flag Checks
  * The Issue: Malware checking NtGlobalFlag (0x70) directly via memory reading bypasses this rule.
  * The Fix: Memory forensics tools or kernel-level introspection are required to catch this technique variant.
* Problem 3: OriginalFileName availability
  * The Issue: OriginalFileName is only present when PE metadata is intact.
  * The Fix: Treat Image and OriginalFileName as complementary — either match alone is sufficient.
