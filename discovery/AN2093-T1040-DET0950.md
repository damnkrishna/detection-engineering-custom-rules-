### 1. Technique Breakdown: T1040

* What it is: Network Sniffing. Adversaries may sniff network traffic to capture information about an environment, including authentication material passed over the network.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Process command lines for known packet capture utilities are captured.
  - NIDS (Suricata + Zeek): NO. NIDS itself is the target tool class; anomaly detection on the host is required.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 1: Network Packet Capture Tool Execution
Detects the execution of well-known packet capture utilities on a Windows endpoint where they are not expected.

```yaml
title: Network Packet Capture Tool Execution (AN2093)
id: a7b8c9d0-e1f2-3456-0123-456789000006
status: experimental
description: Detects the execution of network packet capture binaries such as tshark, windump, or tcpdump on a Windows host, indicating potential credential harvesting or network reconnaissance.
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\tshark.exe'
            - '\windump.exe'
            - '\tcpdump.exe'
            - '\rawcap.exe'
            - '\pktmon.exe'
    selection_ofn:
        OriginalFileName:
            - 'tshark.exe'
            - 'windump.exe'
            - 'tcpdump.exe'
            - 'rawcap.exe'
            - 'PktMon.exe'
    condition: selection_images or selection_ofn
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - Network engineers or security analysts running authorized packet captures for diagnostics.
level: high
tags:
    - attack.credential_access
    - attack.discovery
    - attack.t1040
    - analytic.an2093
    - detection.det0950
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Raw Socket Sniffing
  * The Issue: Custom malware can open raw sockets using `WSASocket` with `SOCK_RAW` without invoking any external tool.
  * The Fix: Requires kernel-level monitoring (e.g. Windows Filtering Platform callouts) to detect raw socket creation.
* Problem 2: Built-in pktmon Whitelisting
  * The Issue: `pktmon.exe` is a Microsoft-signed Windows built-in, so it may be running legitimately on some servers.
  * The Fix: Baseline normal `pktmon.exe` usage in your environment and alert only on non-baseline hosts or unusual command-line arguments.
* Problem 3: OriginalFileName availability
  * The Issue: OriginalFileName is only present when PE metadata is intact.
  * The Fix: Treat Image and OriginalFileName as complementary — either match alone is sufficient.
