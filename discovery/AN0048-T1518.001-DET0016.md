### 1. Technique Breakdown: T1518.001

* What it is: Security Software Discovery. Adversaries enumerate installed or running security products — such as antivirus engines, endpoint detection & response (EDR) agents, host-based firewalls, or SIEM agents — to understand what defenses are in place. This shapes their evasion strategy (e.g. choosing an implant that bypasses the detected AV). Common enumeration approaches include sc.exe query for services, wmic.exe product queries, netsh.exe advfirewall show allprofiles, tasklist.exe /SVC, or PowerShell WMI queries targeting known vendor product names.
* Log Source Requirements: Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688), PowerShell Script Block Logs (Event ID 4104), and Registry Set Events (Sysmon Event ID 13).
* Coverage Check:
    * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 captures execution of sc.exe, netsh.exe, wmic.exe, and PowerShell. Event ID 4104 logs script block details. Event ID 13 logs registry modifications.
    * Windows Security Logs: PARTIAL. Security logs EID 4688 captures command lines if enabled.
* Log Sources Covered:
    - Sysmon Event ID 1 (process_creation)
    - PowerShell Event ID 4104 (ps_script)
    - Sysmon Event ID 13 (registry_set)
* Log Sources Missing / Unused:
    - None.

### 2. Custom Sigma Rule

The detection logic is split into three rules to target process execution, scripting block contents, and registry access separately.

Rule 1 of 3: Security Software Discovery Commands (Process Creation)
```yaml
title: Security Software Discovery via Service and WMI Queries (AN0048-A)
id: 335045c9-a938-4b62-b143-907fec6d30fd
status: experimental
description: Detects adversarial enumeration of installed security products (antivirus, EDR, firewall) using sc.exe query, wmic product, netsh advfirewall, or PowerShell WMI queries.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_sc:
        - Image|endswith: '\sc.exe'
        - OriginalFileName: 'sc.exe'
    selection_sc_args:
        CommandLine|contains: ' query'
    selection_netsh:
        - Image|endswith: '\netsh.exe'
        - OriginalFileName: 'netsh.exe'
    selection_netsh_args:
        CommandLine|contains: 'advfirewall'
    selection_wmic:
        - Image|endswith: '\wmic.exe'
        - OriginalFileName: 'wmic.exe'
    selection_wmic_args:
        CommandLine|contains:
            - ' product '
            - 'AntiVirusProduct'
            - 'FirewallProduct'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_args:
        CommandLine|contains:
            - 'AntiVirusProduct'
            - 'FirewallProduct'
            - 'Get-MpComputerStatus'
            - 'SecurityCenter2'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: ((selection_sc and selection_sc_args) or (selection_netsh and selection_netsh_args) or (selection_wmic and selection_wmic_args) or (selection_powershell and selection_powershell_args)) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - IT administrators running service inventories, vulnerability scanners, or endpoint health check scripts enumerating installed security products.
level: medium
tags:
    - attack.discovery
    - attack.t1518.001
    - analytic.an0048
    - detection.det0016
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: High Noise from sc.exe query
  * The Issue: sc.exe query is one of the most common commands in enterprise environments, run by software installers, monitoring agents, and health scripts constantly. This makes it extremely noisy without additional context.
  * The Fix: Narrow the detection to sc.exe query with specific arguments that target known AV/EDR service names (e.g. sc query MsSense, sc query WinDefend, sc query McAfeeAgent). Alternatively, alert only when sc.exe query is run by unusual parent processes (e.g. script interpreters, downloaded executables).

* Problem 2: Security Product Enumeration via Registry Reads
  * The Issue: Attackers can enumerate security software registry keys directly (e.g. HKLM\SOFTWARE\Microsoft\Windows Defender, HKLM\SOFTWARE\McAfee) via read operations to identify installed products. Since registry_set only logs modifications (Event ID 13), read-only enumeration is missed.
  * The Fix: Implement registry auditing for read access on critical security paths, or monitor process command-line arguments querying registry values (e.g., reg.exe query HKLM\SOFTWARE\Microsoft\Windows Defender).

* Problem 3: Kernel-Level or BYOVD Enumeration
  * The Issue: Sophisticated adversaries may use Bring Your Own Vulnerable Driver (BYOVD) techniques to load a kernel driver that queries running processes at the kernel level, bypassing user-space service query utilities.
  * The Fix: Monitor for kernel driver loading events (Sysmon Event ID 6 - Driver Loaded) for drivers that are not in the Windows Driver Signature catalog, and correlate with subsequent security tool disablement events.
