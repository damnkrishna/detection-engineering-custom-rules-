### 1. Technique Breakdown: T1654

* What it is: Log Enumeration. Adversaries may enumerate system and service logs to find useful data, identify security tooling, or assess forensic visibility before executing further attack phases.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Process command lines are captured.
  - NIDS (Suricata + Zeek): NO. Host-local discovery.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

#### Rule 1 of 1: Windows Event Log Enumeration
Detects the use of `wevtutil.exe` or PowerShell to query or export Windows event logs.

```yaml
title: Windows Event Log Enumeration (AN2091)
id: e5f6a7b8-c9d0-1234-ef01-234567890004
status: experimental
description: Detects command-line utilities enumerating or exporting Windows event logs, used by attackers to assess security tooling and forensic visibility. Covers renamed binaries via OriginalFileName to resist trivial binary-rename evasion.
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_wevtutil:
        Image|endswith:
            - '\wevtutil.exe'
    selection_wevtutil_ofn:
        OriginalFileName: 'wevtutil.exe'
    selection_wevtutil_cli:
        CommandLine|re:
            - '(?i)wevtutil(\.exe)?\s+(el|gl|qe|epl)\b'
    selection_ps:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_ps_ofn:
        OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.exe'
    selection_ps_cli:
        CommandLine|contains:
            - 'Get-EventLog'
            - 'Get-WinEvent'
    condition: ((selection_wevtutil or selection_wevtutil_ofn) and selection_wevtutil_cli) or ((selection_ps or selection_ps_ofn) and selection_ps_cli)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - SOC analysts or automated monitoring scripts reviewing event logs for incident investigation.
level: medium
tags:
    - attack.discovery
    - attack.t1654
    - analytic.an2091
    - detection.det0948
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Overlap with Log Clearing (T1070.001)
  * The Issue: Adversaries may enumerate logs immediately before clearing them; both actions look similar at the command-line level.
  * The Fix: Correlate this rule with Sysmon Event ID 104 (EventLog Cleared) or wevtutil `cl` (clear) commands to detect a recon-then-wipe sequence.
* Problem 2: Direct API Access
  * The Issue: Malware using the `OpenEventLog()` / `ReadEventLog()` Win32 API directly bypasses command-line detection.
  * The Fix: Requires EDR-level API hooking or monitoring of process handle access to the EventLog service.
* Problem 3: OriginalFileName availability
  * The Issue: OriginalFileName is only present when PE metadata is intact.
  * The Fix: Treat Image and OriginalFileName as complementary — either match alone is sufficient.
