### 1. Technique Breakdown: T1046

* What it is: Network Service Discovery. Adversaries may attempt to get a listing of services listening on remote hosts and local network infrastructure devices.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Process command lines are captured.
  - NIDS (Suricata + Zeek): YES. Port scanning activity can be directly observed.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - Network logs (Zeek conn.log) for port scan detection are typically handled by standalone NIDS rules rather than Sigma host rules.

### 2. Custom Sigma Rule

#### Rule 1 of 1: Local Network Service Port Discovery
Detects the use of `netstat` to discover listening ports and associated PIDs on the local system.

```yaml
title: Local Network Service Port Discovery (AN2080)
id: cbdf2001-a189-4db8-bb9a-7c9802cf0044
status: experimental
description: Detects command-line execution of netstat to enumerate active listening ports and established connections. Covers renamed netstat.exe via OriginalFileName to resist trivial binary-rename evasion.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_image:
        Image|endswith:
            - '\netstat.exe'
    selection_ofn:
        OriginalFileName: 'netstat.exe'
    selection_cli:
        CommandLine|contains:
            - '-an'
            - '-ano'
            - '-anbo'
            - '-na'
    condition: (selection_image or selection_ofn) and selection_cli
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - System administrators troubleshooting application port conflicts.
level: low
tags:
    - attack.discovery
    - attack.t1046
    - analytic.an2080
    - detection.det0937
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: High False Positive Rate
  * The Issue: `netstat` is a standard diagnostic tool used daily.
  * The Fix: This rule is low severity and intended as context for correlation. If `netstat` runs immediately after a Word macro execution, the risk score is elevated in the SIEM.
* Problem 2: Remote Port Scanning
  * The Issue: This rule only catches local listening port enumeration. Remote port scanning (e.g. Nmap) bypasses this.
  * The Fix: Implement NIDS (Suricata) rules to detect high-frequency SYN packets originating from a single host.
* Problem 3: OriginalFileName availability
  * The Issue: OriginalFileName is only present in Sysmon logs when PE metadata is intact; packed or hollowed binaries may lack it.
  * The Fix: Treat the Image and OriginalFileName paths as complementary — either catch alone is sufficient.
