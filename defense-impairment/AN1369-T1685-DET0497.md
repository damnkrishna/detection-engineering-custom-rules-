### 1. Technique Breakdown: T1685

* What it is: Disable or Modify Tools. Adversaries may disable or modify security tools (AV, EDR, Sysmon, firewalls) to avoid detection. This includes killing processes, stopping services, altering registry keys (like disabling Windows Defender), or tampering with exclusion lists.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1), Service logs (System Event ID 7036/7045), and Registry modification logs (Sysmon Event ID 13).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon captures command-line attempts to stop services or kill processes (`net stop`, `taskkill`) and registry changes to security tools.
    * NIDS (Suricata + Zeek): NO. Tool modification is a host-centric activity.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect common command-line execution attempting to disable or kill known security services or processes.

```yaml
title: Disable or Modify Tools - Kill Security Process (AN1369)
id: f9dbce1d-6526-4d04-ae6f-0050cd6edc33
status: experimental
description: Detects command-line execution attempting to stop services or kill processes associated with security tools (AV, EDR, Sysmon).
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_tool:
        Image|endswith:
            - '\taskkill.exe'
            - '\net.exe'
            - '\net1.exe'
            - '\sc.exe'
    selection_target:
        CommandLine|contains:
            - 'WinDefend'
            - 'MsMpEng'
            - 'Sysmon'
            - 'Sentinel'
            - 'CrowdStrike'
    condition: selection_tool and selection_target
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - System administrators uninstalling or upgrading endpoint security software.
level: high
tags:
    - attack.defense-evasion
    - attack.t1685
    - analytic.an1369
    - detection.det0497
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
