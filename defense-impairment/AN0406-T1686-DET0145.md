### 1. Technique Breakdown: T1686

* What it is: Disable or Modify System Firewall. Adversaries disable or modify system firewalls to permit network traffic that would otherwise be blocked. They do this to enable command-and-control (C2) communication, permit inbound lateral movement (RDP, WinRM, SMB), or allow file exfiltration. On Windows, this is commonly done by executing commands via `netsh.exe`, PowerShell cmdlets like `Set-NetFirewallProfile`, or stopping the Windows Defender Firewall service (`mpssvc`).
* Log Source Requirements: Endpoint logs capturing process creation and command line parameters (specifically targeting tools that modify firewall profiles or stop the firewall service).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs the execution of utilities like `netsh.exe`, `sc.exe`, or PowerShell commands modifying firewall states.
* NIDS (Suricata + Zeek): NO. Firewall configuration modification is a local host action. It does not produce a distinct network signature (though network tools may capture the resulting unauthorized traffic that is allowed through the firewall).
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 13 (registry_set)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring and registry modification monitoring of system firewall configurations.

Rule 1 of 2: Disabling or Tampering with Windows Firewall (Process Creation)
```yaml
title: Disabling or Tampering with Windows Firewall (AN0406)
id: d58b1c2a-3e2f-4a3b-9c8d-5f6d7e8a9b0c
status: experimental
description: Detects command-line operations that attempt to disable, modify, or stop the Windows Defender Firewall service or profiles using netsh.exe, PowerShell, or service control utilities.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_netsh:
        - Image|endswith: '\netsh.exe'
        - OriginalFileName: 'netsh.exe'
    selection_netsh_args:
        CommandLine|contains|all:
            - 'advfirewall'
            - 'set'
            - 'state'
            - 'off'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_cmdlets:
        CommandLine|contains:
            - 'Set-NetFirewallProfile'
            - 'Disable-NetFirewallRule'
            - 'Remove-NetFirewallRule'
    selection_powershell_args:
        CommandLine|contains:
            - 'False'
            - 'off'
    selection_service_control:
        - Image|endswith:
            - '\sc.exe'
            - '\net.exe'
        - OriginalFileName:
            - 'sc.exe'
            - 'net.exe'
    selection_service_args:
        CommandLine|contains|all:
            - 'mpssvc'
        CommandLine|contains:
            - 'stop'
            - 'disable'
    condition: (selection_netsh and selection_netsh_args) or (selection_powershell and selection_powershell_cmdlets and selection_powershell_args) or (selection_service_control and selection_service_args)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate administrative troubleshooting or network configuration scripts that temporarily disable profiles or remove rules.
level: high
tags:
    - attack.defense-evasion
    - attack.t1686
    - analytic.an0406
    - detection.det0145
```

Rule 2 of 2: Windows Firewall Registry Modification (Registry Set)
```yaml
title: Windows Firewall Registry Modification (AN0406-B)
id: 1a69eefa-323e-4868-88f2-b2f944eb114e
status: experimental
description: Detects registry modifications under Windows Firewall settings, indicating programmatic disabling or altering of local firewall policies.
author: Krishna Gupta
date: 2026-06-17
logsource:
    category: registry_set
    product: windows
detection:
    selection:
        TargetObject|contains:
            - '\System\CurrentControlSet\Services\SharedAccess\Parameters\FirewallPolicy\'
    condition: selection
fields:
    - TargetObject
    - Details
    - Image
    - User
falsepositives:
    - Centralized configuration via Active Directory Group Policies or local system modifications by administrative tools.
level: high
tags:
    - attack.defense-evasion
    - attack.t1686
    - analytic.an0406
    - detection.det0145
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
