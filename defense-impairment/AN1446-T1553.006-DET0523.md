### 1. Technique Breakdown: T1553.006

* What it is: Subvert Trust Controls: Code Signing Policy Modification. Adversaries modify system policies to allow the execution of unsigned or improperly signed code. On Windows, this often involves modifying Boot Configuration Data (BCD) using `bcdedit.exe` to disable Driver Signature Enforcement (DSE) or enable Test Signing. This allows the loading of malicious kernel-level drivers.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 easily captures the execution of `bcdedit.exe` and its command-line parameters.
    * NIDS (Suricata + Zeek): NO. BCD modification is entirely a host-level OS activity.

### 2. Custom Sigma Rule

```yaml
title: Code Signing Policy Modification - Bcdedit DSE Disable (AN1446)
id: a247b82d-97a0-454b-b565-cbf635164f85
status: experimental
description: Detects command-line execution of bcdedit.exe attempting to disable Driver Signature Enforcement or enable test signing.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_img:
        Image|endswith: '\bcdedit.exe'
    selection_cmd:
        CommandLine|contains:
            - 'loadoptions DDISABLE_INTEGRITY_CHECKS'
            - 'testsigning on'
            - 'nointegritychecks on'
    condition: selection_img and selection_cmd
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Kernel developers testing custom unsigned drivers on non-production development machines.
level: high
tags:
    - attack.defense-evasion
    - attack.t1553.006
    - analytic.an1446
    - detection.det0523
```
