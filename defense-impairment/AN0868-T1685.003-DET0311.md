### 1. Technique Breakdown: T1685.003

* What it is: Disable or Modify Tools: Modify or Spoof Tool UI. Adversaries may modify or spoof the user interface of security tools to hide their activities. This involves showing a false "healthy" or "active" status for tools like Windows Defender, even when the underlying security services (e.g., WinDefend, MsMpEng.exe) are stopped or disabled.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and System logs for service states.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 can monitor the execution of UI components, and Windows System logs can monitor the actual service states (Event ID 7036 for service stops).
    * NIDS (Suricata + Zeek): NO. UI spoofing and service state manipulation are strictly host-level activities.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) and service state logs to detect scenarios where security UI components are running, but the underlying engines are suspiciously stopped or disabled.

```yaml
title: Disable or Modify Tools - Spoof Tool UI (AN0868)
id: 5a8b2734-abc9-482d-88b6-96a84c2f42d2
status: experimental
description: Detects inconsistencies between reported sensor health and actual process/service state, suggesting UI spoofing.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_ui:
        Image|endswith:
            - '\SecurityHealthSystray.exe'
            - '\MSASCui.exe'
    selection_cmd:
        CommandLine|contains:
            - 'spoof'
            - 'hidden'
            - 'disable'
    condition: selection_ui and selection_cmd
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Administrative troubleshooting of security tool UI components.
level: medium
tags:
    - attack.defense-evasion
    - attack.t1685.003
    - analytic.an0868
    - detection.det0311
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
