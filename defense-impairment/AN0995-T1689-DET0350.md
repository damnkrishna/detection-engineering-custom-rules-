### 1. Technique Breakdown: T1689

* What it is: Downgrade Attack. Adversaries downgrade or force the use of legacy versions of applications or system features (like PowerShell v2) that lack modern security monitoring, logging (like Script Block Logging), or protections (like AMSI).
* Log Source Requirements: Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and PowerShell operational logs (Event ID 400).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures command-line arguments specifying older versions (e.g., `powershell.exe -version 2`).
    * NIDS (Suricata + Zeek): NO. Executing downgraded tools is a host-level activity.

---

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of PowerShell with flags explicitly requesting an older version, typically Version 2, which bypasses modern logging.

```yaml
title: Downgrade Attack - PowerShell v2 Execution (AN0995)
id: fbbbb76c-3a8c-4a1e-8488-8120ec2c5d14
status: experimental
description: Detects the execution of PowerShell explicitly requesting version 2 or legacy binaries, bypassing modern security logging.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_ps:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_args:
        CommandLine|contains|all:
            - '-version'
            - '2'
    condition: selection_ps and selection_args
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legacy enterprise scripts that explicitly require PowerShell v2 for compatibility.
level: high
tags:
    - attack.defense-evasion
    - attack.t1689
    - analytic.an0995
    - detection.det0350
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
