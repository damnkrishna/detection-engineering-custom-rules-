### 1. Technique Breakdown: T1686.003

* What it is: Disable or Modify System Firewall: Windows Host Firewall. Adversaries modify Windows Defender Firewall settings using tools like `netsh` or `Set-NetFirewallRule` to allow malicious inbound connections (e.g., for C2 or lateral movement) or to prevent outbound telemetry.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1) and Windows Security Event Log (Event ID 4946 - A change has been made to Windows Firewall exception list).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Windows Security log intrinsically captures Event ID 4946 for rule additions/modifications. Sysmon Event ID 1 logs the execution of CLI tools used to manage the firewall.
    * NIDS (Suricata + Zeek): NO. Firewall rule manipulation is an endpoint configuration change.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect command-line execution of native tools attempting to modify Windows Firewall rules.

```yaml
title: Disable or Modify Windows Host Firewall (AN2043)
id: f42a7862-2f08-4121-81d3-3fc8c21a115c
status: experimental
description: Detects command-line execution of netsh or PowerShell attempting to modify Windows Firewall rules or profiles.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_netsh:
        Image|endswith: '\netsh.exe'
        CommandLine|contains|all:
            - 'advfirewall'
            - 'firewall'
        CommandLine|contains:
            - 'add rule'
            - 'set rule'
            - 'delete rule'
            - 'set currentprofile'
            - 'state=off'
    selection_powershell:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        CommandLine|contains:
            - 'New-NetFirewallRule'
            - 'Set-NetFirewallRule'
            - 'Remove-NetFirewallRule'
            - 'Set-NetFirewallProfile'
    condition: selection_netsh or selection_powershell
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - IT administrators configuring network access for new applications.
    - Software installers automatically adding necessary firewall exceptions during deployment.
level: high
tags:
    - attack.defense-evasion
    - attack.t1686.003
    - analytic.an2043
    - detection.det0901
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
