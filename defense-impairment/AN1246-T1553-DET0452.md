### 1. Technique Breakdown: T1553

* What it is: Subvert Trust Controls. Adversaries may subvert trust controls to bypass security mechanisms that rely on digital certificates or code signing. This broad technique includes adding malicious root certificates to the trust store, modifying code signing policies, or installing unsigned drivers.
* Log Source Requirements: Process creation logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and Registry modifications (Sysmon Event ID 13).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon can log the execution of certificate utilities like `certutil.exe` and registry changes to the Windows certificate stores (`Root`, `AuthRoot`).
    * NIDS (Suricata + Zeek): NO. Trust subversion is an endpoint configuration change.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of `certutil.exe` attempting to add a new root certificate to the local machine store, a common subversion technique.

```yaml
title: Subvert Trust Controls - Malicious Root Cert Install (AN1246)
id: dbaad872-9cc9-4177-ad6d-74d39f8f4a21
status: experimental
description: Detects abnormal installation of root or code-signing certificates using certutil.exe.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_img:
        Image|endswith: '\certutil.exe'
    selection_cmd:
        CommandLine|contains|all:
            - '-addstore'
            - 'Root'
    condition: selection_img and selection_cmd
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate administration scripts deploying corporate PKI root certificates.
level: high
tags:
    - attack.defense-evasion
    - attack.t1553
    - analytic.an1246
    - detection.det0452
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
