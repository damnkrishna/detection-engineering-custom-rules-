### 1. Technique Breakdown: T1074

* What it is: Data Staged. Adversaries aggregate and stage collected data in a central location before exfiltration, often to simplify transfer and avoid repeated connections to the target system. On Windows, this typically involves copying or moving sensitive files (documents, databases, credential stores) into a temporary staging directory, then compressing or archiving them using 7z.exe, WinRAR.exe, or built-in Compress-Archive (PowerShell) before sending them out. The staging location is frequently C:\Windows\Temp, %APPDATA%, or a custom subdirectory under C:\Users\Public.
* Log Source Requirements: Endpoint logs capturing process creation events and file creation events.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs when compression utilities run targeting temp folders, and Event ID 11 (File Event) logs when staged archive files are written.
* NIDS (Suricata + Zeek): NO. Offline, local host actions.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 11 (file_event)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring of archiving utility executions targeting staging paths, and file write events capturing archive files created in temporary or public directories.

Rule 1 of 2: Data Staging via Archive Utilities in Temp Directories (Process Creation)
```yaml
title: Data Staging via Archive Utilities in Temp Directories (AN0040)
id: b5447d20-091e-4b98-9f2b-a5cf6caf2909
status: experimental
description: Detects archiving utilities (7z, WinRAR, PowerShell Compress-Archive) creating archive files in temporary or public staging directories, which may indicate data collection and staging prior to exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_7zip:
        - Image|endswith: '\7z.exe'
        - OriginalFileName: '7z.exe'
    selection_winrar:
        - Image|endswith: '\WinRAR.exe'
        - OriginalFileName: 'WinRAR.exe'
    selection_rar:
        - Image|endswith: '\rar.exe'
        - OriginalFileName: 'rar.exe'
    selection_staging_paths:
        CommandLine|contains:
            - '\Windows\Temp\'
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - '\ProgramData\'
            - 'C:\Temp\'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_compress_archive:
        CommandLine|contains:
            - 'Compress-Archive'
    condition: ((selection_7zip or selection_winrar or selection_rar) and selection_staging_paths) or (selection_powershell and selection_compress_archive and selection_staging_paths)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - IT administrators compressing files for routine archival into temp directories during migration tasks.
level: medium
tags:
    - attack.collection
    - attack.t1074
    - analytic.an0040
    - detection.det0014
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
