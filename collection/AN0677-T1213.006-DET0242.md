### 1. Technique Breakdown: T1213.006

* What it is: Databases. Adversaries target database systems to collect sensitive information stored in structured data stores — such as customer records, financial data, credentials, or intellectual property. On Windows, they use database client tools (`sqlcmd.exe`, `isql.exe`, `osql.exe`, `bcp.exe`, `mysql.exe`) to query databases and export results, often initiated from unexpected parent processes like `cmd.exe`, `powershell.exe`, or `explorer.exe`. The exported data is typically written to `.csv`, `.sql`, or `.bak` dump files in user temp directories, and may subsequently be compressed and exfiltrated.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) capturing database client tool invocations with unusual parent processes or output redirection to temp directories.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures `sqlcmd.exe`, `bcp.exe`, and `mysql.exe` executions with full command-line arguments including connection strings and output file paths.
    * NIDS (Suricata + Zeek): PARTIAL. Database connections to local or remote SQL servers (ports 1433, 3306) can be detected at the network level, but the content of SQL queries and exported data requires host-based monitoring for attribution.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect database client tools (`sqlcmd.exe`, `bcp.exe`, `osql.exe`, `mysql.exe`) executed by shell or scripting parent processes, or with output redirection to staging directories.

```yaml
title: Suspicious Database Client Execution for Data Collection (AN0677)
id: a101c2ec-d38f-4b32-8240-eecfec02baad
status: experimental
description: Detects database client tools (sqlcmd, bcp, osql, mysql) launched by unexpected parent processes or with output directed to temp/user directories, indicating adversarial database collection.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_db_clients:
        - Image|endswith:
            - '\sqlcmd.exe'
            - '\bcp.exe'
            - '\osql.exe'
            - '\isql.exe'
            - '\mysql.exe'
            - '\mysqldump.exe'
        - OriginalFileName:
            - 'sqlcmd.exe'
            - 'bcp.exe'
            - 'osql.exe'
            - 'isql.exe'
            - 'mysql.exe'
            - 'mysqldump.exe'
    selection_suspicious_parent:
        ParentImage|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\explorer.exe'
    selection_output_to_temp:
        CommandLine|contains:
            - '\Windows\Temp\'
            - '\AppData\Local\Temp\'
            - '\Users\Public\'
            - ' -o '
            - ' /o '
            - ' > '
    condition: selection_db_clients and (selection_suspicious_parent or selection_output_to_temp)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - DBA or developer scripts using sqlcmd.exe from PowerShell or cmd.exe for authorized database queries, reporting, and export operations.
level: high
tags:
    - attack.collection
    - attack.t1213.006
    - analytic.an0677
    - detection.det0242
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
