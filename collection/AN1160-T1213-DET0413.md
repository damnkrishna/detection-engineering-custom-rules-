### 1. Technique Breakdown: T1213

* What it is: Data from Information Repositories. Adversaries target and collect data from information repositories (like SharePoint, Confluence, internal wikis, or database repositories) to harvest intellectual property, credentials, or network diagrams. They may programmatically download directories or query tables using command-line tools (e.g. `sqlcmd.exe`), PowerShell scripts containing SharePoint client APIs (such as `Microsoft.SharePoint.Client`), or command-line web clients (e.g. `curl.exe`, `wget.exe`, `Invoke-WebRequest`).
* Log Source Requirements: Windows Security Event Log Event ID 4688 or Sysmon process creation logs (Event ID 1) capturing command-line parameters of database or repository query tools.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs process details, capturing cmdline parameters that query or download from internal information systems.
    * NIDS (Suricata + Zeek): YES. Network filters capture high-volume HTTP/HTTPS requests to internal wikis or database ports (1433, 1521, 3306), indicating mass enumeration.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect processes executing command-line query tools or script engines targeting common information repository endpoints or using database query switches.

```yaml
title: Collection - Programmatic or Excessive Information Repository Access (AN1160)
id: 8f491583-6eee-4ecf-b2c8-5de62ff0c09f
status: experimental
description: Detects command-line utilities, PowerShell commands, or database clients targeting SharePoint, Confluence, or SQL databases to gather sensitive repository data.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1 / Security Event ID 4688
detection:
    selection_db_clients:
        - Image|endswith:
            - '\sqlcmd.exe'
            - '\osql.exe'
            - '\mysql.exe'
            - '\psql.exe'
        - OriginalFileName:
            - 'sqlcmd.exe'
            - 'osql.exe'
            - 'mysql.exe'
            - 'psql.exe'
    selection_repo_keywords:
        CommandLine|contains:
            - 'sharepoint'
            - 'confluence'
            - 'spweb'
            - 'spsite'
            - 'spfolder'
            - 'spfile'
            - 'Invoke-Sqlcmd'
            - 'Invoke-RestMethod'
            - 'Invoke-WebRequest'
    condition: selection_db_clients or selection_repo_keywords
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - administrators running routine maintenance scripts.
    - Automated system backup or synchronization tasks connecting to databases/SharePoint.
level: medium
tags:
    - attack.collection
    - attack.t1213
    - analytic.an1160
    - detection.det0413
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
