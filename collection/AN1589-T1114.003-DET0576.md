### 1. Technique Breakdown: T1114.003

* What it is: Email Collection: Email Forwarding Rule. Adversaries may configure email forwarding or inbox rules within a compromised user's mailbox to automatically redirect incoming emails to an external address controlled by the attacker. They establish these rules using PowerShell Exchange cmdlets (such as `New-InboxRule`, `Set-InboxRule`) or via Exchange Management Shell / Exchange Online. Detection monitors execution of these cmdlets with forwarding-specific flags.
* Log Source Requirements: Windows Security Event Log Event ID 4688, Sysmon process creation logs (Event ID 1), or PowerShell Script Block Logging (Event ID 4104) capturing Exchange mailbox configuration commands.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs process details, capturing cmdline parameters that construct forwarding rules. PowerShell script block logging audits exact parameters.
    * NIDS (Suricata + Zeek): NO. Local execution of cmdlets is a host-only management activity.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect PowerShell cmdlets establishing inbox rules or mailbox properties that automatically forward, redirect, or copy emails to external destinations.

```yaml
title: Collection - Email Inbox Forwarding Rule Creation (AN1589)
id: 455544dd-c688-4806-930c-46eaef99cf7b
status: experimental
description: Detects PowerShell cmdlets (New-InboxRule, Set-InboxRule, Set-Mailbox) executed with parameters configured to forward or redirect emails, suggesting external data redirection.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_cmdlets:
        CommandLine|contains:
            - 'New-InboxRule'
            - 'Set-InboxRule'
            - 'New-TransportRule'
            - 'Set-TransportRule'
            - 'Set-Mailbox'
    selection_forward_flags:
        CommandLine|contains:
            - 'ForwardTo'
            - 'ForwardAsAttachmentTo'
            - 'RedirectTo'
            - 'DeliverToMailboxAndForward'
    condition: selection_powershell and selection_cmdlets and selection_forward_flags
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - administrators configuring legitimate corporate mail routing rules or user out-of-office forwarding.
level: medium
tags:
    - attack.collection
    - attack.t1114.003
    - analytic.an1589
    - detection.det0576
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
