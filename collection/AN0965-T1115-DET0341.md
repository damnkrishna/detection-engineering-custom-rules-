### 1. Technique Breakdown: T1115

* What it is: Clipboard Data. Adversaries collect sensitive information (such as passwords, keys, or proprietary data) by reading the system clipboard. They use native command tools (like `clip.exe`) or execute scripting utilities (such as PowerShell commands accessing the clipboard APIs) to extract the text buffer. Host-based detection checks for command-line strings that call clipboard extraction methods or redirect output from clipboard utilities.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) capturing command line arguments, combined with PowerShell Script Block logs (Event ID 4104).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs process details, letting security tools check for `Get-Clipboard` or `clip.exe` commands. Wazuh aggregates these and alerts.
    * NIDS (Suricata + Zeek): NO. Network sensors cannot audit local system clipboard activity.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of command-line tools or PowerShell commands retrieving data from the system clipboard.

```yaml
title: Collection - Clipboard Data Retrieval Command (AN0965)
id: 07461075-1fb8-449a-8fea-78b6b9667d5b
status: experimental
description: Detects command-line parameters or PowerShell scripting commands executing clipboard-reading commands (such as Get-Clipboard or clipboard APIs), suggesting unauthorized credential or data harvesting.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_cmd:
        CommandLine|contains:
            - 'Get-Clipboard'
            - 'Windows.Forms.Clipboard'
            - 'clip.exe' # typically used for piping, but checks for direct execution too
    selection_powershell:
        EventID: 4104
        ScriptBlockText|contains:
            - 'Get-Clipboard'
            - 'Windows.Forms.Clipboard'
    condition: selection_cmd or selection_powershell
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - user-run administrative helper scripts that query the clipboard for convenience tasks.
level: medium
tags:
    - attack.collection
    - attack.t1115
    - analytic.an0965
    - detection.det0341
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
