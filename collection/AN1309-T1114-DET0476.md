### 1. Technique Breakdown: T1114

* What it is: Email Collection. Adversaries may search local system directories or Exchange servers for email databases (such as Outlook `.pst` or `.ost` files) to extract sensitive emails, contacts, and calendar items. They copy these files to local staging folders using command-line utilities (like `xcopy.exe` or `robocopy.exe`), PowerShell scripting, or custom malware. They may also set up malicious inbox rules or auto-forwarding settings to exfiltrate email traffic in real time.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) capturing command lines referencing Outlook data files, or Sysmon File Creation/Access events (Event ID 11) capturing access to `.pst`/`.ost` by non-Outlook processes.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs process details, capturing command lines that copy or compress `.pst` or `.ost` files. Sysmon Event ID 11 can be tuned to detect non-Outlook processes opening email store databases.
    * NIDS (Suricata + Zeek): NO. Local database discovery and copying are host-only filesystem operations.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect command-line utilities (e.g., copy utilities, scripting engines, compression tools) referencing Outlook Personal Folders (`.pst`) or Offline Folder (`.ost`) files.

```yaml
title: Collection - Local Email Database Access and Collection (AN1309)
id: e0be8fe4-ec61-4434-ae75-81f12e9e3a67
status: experimental
description: Detects command-line utilities or scripting engines (cmd, powershell, xcopy, robocopy, 7z) referencing Outlook .pst or .ost files, suggesting local email harvesting.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_utilities:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\xcopy.exe'
            - '\robocopy.exe'
            - '\7z.exe'
            - '\tar.exe'
        - OriginalFileName:
            - 'cmd.exe'
            - 'PowerShell.EXE'
            - 'pwsh.dll'
            - 'xcopy.exe'
            - 'robocopy.exe'
            - '7z.exe'
            - 'tar.exe'
    selection_email_extensions:
        CommandLine|contains:
            - '.pst'
            - '.ost'
    filter_outlook:
 # Exclude official outlook operations
        Image|endswith:
            - '\OFFICE15\OUTLOOK.EXE'
            - '\OFFICE16\OUTLOOK.EXE'
            - '\outlook.exe'
    condition: selection_utilities and selection_email_extensions and not filter_outlook
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - backup scripts copying user Outlook data during migrations or system upgrades.
    - Local desktop search indexers or antivirus software scanning local mail folders.
level: high
tags:
    - attack.collection
    - attack.t1114
    - analytic.an1309
    - detection.det0476
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
