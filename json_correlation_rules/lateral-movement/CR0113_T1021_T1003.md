### 1. Technique Breakdown: T1021.001, T1003.001 & T1572

* **Description**: Detects lateral movement where an attacker utilizes a port forwarding mechanism to perform a Remote Desktop Protocol (RDP) logon on the local loopback interface (protocol tunneling), followed by LSASS memory dumping to harvest credentials.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Windows Security/Sysmon logs auditing local loopback RDP connections (Logon Type 10/3 from `127.0.0.1` or `::1`).
  * Sysmon Process Access Event ID 10 targeting `lsass.exe` with credential-dumping access rights (`0x1010`).
* **Coverage Check**:
  * HIDS (Sysmon + Windows Security logs): YES. Captures local loopback logons and LSASS handle requests.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Legitimate Administrative Port Forwarding**
  * *Issue*: System administrators may configure port forwarding using standard utilities for remote troubleshooting, resulting in false alerts on Stage 0.
  * *Fix*: Baseline and whitelist authorized administrative user accounts or designated administrative source IP ranges.
* **Problem 2: Security and Diagnostic Scanners Accessing LSASS**
  * *Issue*: Local antivirus, EDR software, and diagnostic tools regularly query processes, including LSASS, which can cause false positives in Stage 1.
  * *Fix*: Ignore LSASS access events originating from verified, digitally-signed endpoint security binaries (e.g., `MsMpEng.exe`).
