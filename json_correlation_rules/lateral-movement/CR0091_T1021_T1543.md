### 1. Technique Breakdown: T1021.002 & T1543.003

* **Description**: Detects lateral movement where an attacker writes an executable payload via SMB administrative shares, followed by registering it as a system service (e.g. standard PsExec behavior) on the target host within 15 minutes.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Suricata signatures detecting write operations to administrative SMB shares (like `ADMIN$`, `C$`).
  * Windows System Log Event ID 7045 (New Service Created) or Sysmon Event ID 1 (Process Create) tracking `services.exe` spawning a temporary binary.
* **Coverage Check**:
  * HIDS (Sysmon + Windows Event logs): YES. Captures new service registrations and process spawns under `services.exe`.
  * NIDS (Suricata): YES. Detects the initial SMB connection and administrative share payload copy.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Authorized Remote Admin Tool Execution**
  * *Issue*: Administrators may legitimately use PsExec or PAExec tools to manage remote machines, leading to false alerts.
  * *Fix*: Filter out known admin usernames or source systems (jump boxes) from triggering this alert sequence.
* **Problem 2: Automated Deployment Agents**
  * *Issue*: Deployment software (e.g. Microsoft SCCM, PDQ Deploy) installs and uninstalls temporary services when executing tasks.
  * *Fix*: Add exclusions for known agent service names or signed executables.
