### 1. Technique Breakdown: T1563.002 & T1078

* **Description**: Detects RDP session activity followed by the execution of `tscon.exe` under the SYSTEM context to hijack an active disconnected session without authentication, bypassing login prompts.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Zeek connection logs auditing active RDP connections.
  * Sysmon Process Creation (Event ID 1) where `tscon.exe` is launched, and the executing account/privilege is SYSTEM.
* **Coverage Check**:
  * HIDS (Sysmon): YES. Sysmon logs the process integrity level and username (SYSTEM) when `tscon.exe` is run.
  * NIDS (Zeek): YES. Corroborates that RDP traffic was recently established or active on the host.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Shadowing Session Support**
  * *Issue*: Helpdesk administrators legitimately shadow or disconnect user sessions using `tscon.exe` during standard support tickets.
  * *Fix*: Whitelist authorized administrative source networks or specific support accounts if shadowing is standard policy.
* **Problem 2: Command Line Parameter Variations**
  * *Issue*: Attackers can rename `tscon.exe` or execute it without using the literal string `tscon` in the name, relying on API hijacking.
  * *Fix*: Supplement this check by monitoring the specific API calls or service triggers (like creation of temporary remote-session service commands).
