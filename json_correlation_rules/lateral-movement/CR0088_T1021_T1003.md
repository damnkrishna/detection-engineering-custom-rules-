### 1. Technique Breakdown: T1021.005, T1003.001 & T1572

* **Description**: Detects lateral movement where an attacker utilizes SSH tunneling to pivot into a machine via Remote Desktop Protocol (RDP) on the local loopback interface (protocol tunneling), followed by LSASS memory dumping to harvest credentials.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Zeek network connection logs (detecting inbound SSH session).
  * Windows Security/Sysmon logs auditing local loopback RDP connections (Logon Type 10/3 from `127.0.0.1` or `::1`).
  * Sysmon Process Access Event ID 10 targeting `lsass.exe` with credential-dumping access rights (`0x1010`).
* **Coverage Check**:
  * HIDS (Sysmon + Windows Security logs): YES. Captures local loopback logons and LSASS handle requests.
  * NIDS (Zeek): YES. Captures SSH connection traffic on port 22.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Legitimate Local Port Forwarding by Admins**
  * *Issue*: Administrators may tunnel RDP over SSH for secure remote server administration, leading to false positives.
  * *Fix*: Exclude connections associated with recognized administrative usernames or authorized remote-access tool source IPs in the Stage 1 parameters.
* **Problem 2: Security Agent Diagnostics Scanning LSASS**
  * *Issue*: Endpoint antivirus or EDR agents regularly query LSASS handle info, triggering false alerts on Stage 2.
  * *Fix*: Add filter constraints to ignore LSASS access events originating from signed security binaries (e.g. `MsMpEng.exe` or third-party EDR services).
