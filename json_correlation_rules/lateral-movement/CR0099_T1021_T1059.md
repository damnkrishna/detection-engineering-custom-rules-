### 1. Technique Breakdown: T1021.004 & T1059.001

* **Description**: Detects an incoming SSH connection (Zeek) followed by the execution of a PowerShell interpreter (`powershell.exe` or `pwsh.exe`) under the OpenSSH Server parent process (`sshd.exe`) on the target host within 15 minutes.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Zeek connection logs auditing active SSH traffic on port 22.
  * Sysmon Process Creation (Event ID 1) where the parent process is `sshd.exe` and the spawned child process is `powershell.exe` or `pwsh.exe`.
* **Coverage Check**:
  * HIDS (Sysmon): YES. Sysmon accurately logs the parent-child relationship of `sshd.exe` spawning PowerShell shells.
  * NIDS (Zeek): YES. Identifies the network SSH connection to the server.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Cross-Platform Admin Administration**
  * *Issue*: Administrators managing mixed Linux/Windows environments may use OpenSSH on Windows and log in using PowerShell Core, triggering this rule.
  * *Fix*: Filter out known administrative accounts or exclude SSH connections originating from secure administrator VLAN subnets.
* **Problem 2: Non-standard SSH Ports**
  * *Issue*: If the OpenSSH server runs on a port other than 22, Zeek might log it as generic TCP traffic unless application-layer protocol parsing triggers.
  * *Fix*: Ensure Zeek SSH analyzer triggers on protocol identification rather than hardcoded port numbers.
