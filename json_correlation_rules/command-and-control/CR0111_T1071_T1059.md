### 1. Technique Breakdown: T1071.002 & T1059.001

* **Description**: Detects outbound Internet Relay Chat (IRC) connection activity (Zeek) followed by the execution of a PowerShell interpreter running an inline execution block (`Invoke-Expression` / `IEX`) on the target host within 15 minutes, indicating botnet-style command and control.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Zeek connection/service logs auditing IRC port connections (6667, 6697).
  * Sysmon Process Creation (Event ID 1) where the command line contains `IEX` or `Invoke-Expression`.
* **Coverage Check**:
  * HIDS (Sysmon): YES. Processes launching shells with IEX arguments are logged.
  * NIDS (Zeek): YES. Identifies standard IRC application protocol layer headers.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Chat Client Usage**
  * *Issue*: Users running legitimate IRC clients to join developer channels can trigger Stage 0.
  * *Fix*: Restrict the Stage 1 condition to only trigger on process spawns with scripting engines and command arguments running inline execution loops.
* **Problem 2: Obfuscated IEX Syntax**
  * *Issue*: Adversaries can bypass simple string checks for `iex` or `Invoke-Expression` by using variable construction or character arrays (e.g. `&( $ShellId[1]+$ShellId[13]+'x')`).
  * *Fix*: Look for highly obfuscated PowerShell execution patterns or base64 decoding arguments in addition to simple contains filters.
