### 1. Technique Breakdown: T1095 & T1572

* **Description**: Detects outbound traffic on non-standard network ports (Zeek) followed by local administrative commands executing `netsh.exe` to configure port forwarding/proxying (Sysmon) on the target host within 15 minutes.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Zeek connection logs auditing outbound network sessions on non-standard/uncommon ports.
  * Sysmon Process Creation (Event ID 1) auditing `netsh.exe` with arguments containing `portproxy` or `v4tov4`.
* **Coverage Check**:
  * HIDS (Sysmon): YES. Tracks process command lines for netsh configurations.
  * NIDS (Zeek): YES. Identifies anomalies in outbound ports and connection durations.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Legitimate Port Mapping Configurations**
  * *Issue*: Hyper-V networking, WSL, or docker environments configure netsh portproxy mappings automatically, creating noise.
  * *Fix*: Exclude the local subnet or specific system service accounts that spawn virtualization helpers.
* **Problem 2: Tunneling Over Common Ports**
  * *Issue*: Attackers can tunnel traffic over standard allowed ports (such as port 443) which bypasses Stage 0's non-standard port check.
  * *Fix*: Look for anomalous protocol behavior (e.g. non-SSL protocol over port 443) rather than checking solely the port number.
