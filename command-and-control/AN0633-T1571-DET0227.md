### 1. Technique Breakdown: T1571

* What it is: Non-Standard Port. Adversaries use non-standard ports to conduct C2 communications to bypass ingress/egress port filtering at firewall boundaries, evade signature-based detection systems, or tunnel commands. For instance, they may run HTTP traffic over port 4444 or 9001 instead of ports 80/443. Outbound connections or process configurations targeting high, non-standard destination ports represent primary indicators of compromise.
* Log Source Requirements: Endpoint logs capturing network connection details (Sysmon Event ID 3 / Windows Security Event ID 5156) and process creation logs (Sysmon Event ID 1).
* Coverage Check:
    * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 3 logs destination port metadata. Event ID 1 logs process creation command arguments.
    * Windows Security Logs: PARTIAL. Security logs EID 4688 captures command lines if enabled.
* Log Sources Covered:
    - Sysmon Event ID 3 (network_connection)
    - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
    - None.

### 2. Custom Sigma Rule

The detection logic is split into two rules targeting network socket connections and command-line configurations separately.

Rule 1 of 2: Outbound Network Connection via Non-Standard Port (Network Connection)
```yaml
title: Outbound Network Connection via Non-Standard Port (AN0633-A)
id: 1ccd6559-05f0-47cf-abc7-3a782e5f696b
status: experimental
description: Detects outbound network connections initiated by system processes or office applications on atypical/non-standard port ranges, which can indicate C2 encapsulation or protocol tunneling.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3
detection:
    selection_process:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\rundll32.exe'
            - '\regsvr32.exe'
            - '\mshta.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\winword.exe'
            - '\excel.exe'
    selection_ports:
        DestinationPort:
            - 4444
            - 4445
            - 5555
            - 8000
            - 8080
            - 8443
            - 8888
            - 9001
            - 9999
    condition: selection_process and selection_ports
fields:
    - Image
    - CommandLine
    - User
    - DestinationHostname
    - DestinationIp
    - DestinationPort
    - Initiated
    - SourceIp
    - SourcePort
falsepositives:
    - Internal developer services, staging environments, or management servers (e.g. Jenkins, Tomcat, VMware console) running on custom ports.
level: high
tags:
    - attack.command-and-control
    - attack.t1571
    - analytic.an0633
    - detection.det0227
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Protocol Mimicry on Standard Ports
  * The Issue: Attackers can tunnel non-standard protocols (e.g., custom shell sessions or SSH) over standard ports like 80 (HTTP) or 443 (HTTPS), which bypasses destination-port-based rules.
  * The Fix: Implement Application Layer Protocol Inspection (using NIDS/Suricata) to check if the payload header matches the expected protocol for the port (e.g., alerting on SSH handshakes executing on port 80 or 443).

* Problem 2: Use of Dynamic High Ports
  * The Issue: Attackers can configure their listeners to listen on dynamic ephemeral ports (ports 49152 to 65535) that vary per connection, avoiding static list of targeted ports.
  * The Fix: Monitor and alert on any system process (like cmd.exe or powershell.exe) initiating connection to any port other than a strict whitelist of administrative services (such as LDAP 389/636, SMB 445, HTTP 80/443).

* Problem 3: Administration Console Noise
  * The Issue: System administrators and developers routinely connect to server dashboards (like Jenkins on 8080, Splunk on 8000) from their workstations, triggering false alerts.
  * The Fix: Baseline legitimate destination domains/hosts for these services and whitelist them, or restrict the rule to standard user profiles.
