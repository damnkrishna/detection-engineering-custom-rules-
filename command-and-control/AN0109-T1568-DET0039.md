### 1. Technique Breakdown: T1568

* What it is: Dynamic Resolution. Adversaries configure malware to generate C2 domain names dynamically using Domain Generation Algorithms (DGA). This bypasses static firewall blocks and IP domain blacklists because the malware queries a sequence of pseudo-random, high-entropy domains to find the active C2. DGA activity often manifests as system processes that typically perform no internet activity (e.g., calc.exe, notepad.exe) generating DNS queries or initiating network connections.
* Log Source Requirements: Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and Network Connection logs (Sysmon Event ID 3).
* Coverage Check:
    * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 captures process creation. Event ID 3 logs outbound network connections.
    * Windows Security Logs: PARTIAL. Security logs EID 4688 captures command lines if enabled.
* Log Sources Covered:
    - Sysmon Event ID 3 (network_connection)
    - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
    - None.

### 2. Custom Sigma Rule

The detection logic is split into two rules to target network connections and suspicious process execution contexts separately.

Rule 1 of 2: DNS Connection from Non-Network System Utility (Network Connection)
```yaml
title: DNS Connection from Non-Network System Utility (AN0109-A)
id: 6878c28a-8d5f-4fa8-89ee-0893ee93f26f
status: experimental
description: Detects network connections targeting standard DNS port 53 initiated by Windows system utilities that typically perform no network communications, indicating potential process injection or tunneling.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3
detection:
    selection_process:
        Image|endswith:
            - '\calc.exe'
            - '\notepad.exe'
            - '\mspaint.exe'
            - '\regedit.exe'
            - '\systeminfo.exe'
            - '\tasklist.exe'
            - '\chkdsk.exe'
    selection_port:
        DestinationPort: 53
    condition: selection_process and selection_port
fields:
    - Image
    - CommandLine
    - User
    - DestinationIp
    - DestinationPort
    - Initiated
    - SourceIp
falsepositives:
    - Extremely rare. Standard system applications like calc or notepad do not make DNS queries or open port 53.
level: high
tags:
    - attack.command-and-control
    - attack.t1568
    - analytic.an0109
    - detection.det0039
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Process Masquerading / Execution of Renamed Binaries
  * The Issue: Attackers can rename their malicious binary to look like a legitimate browser (e.g., renaming malware.exe to chrome.exe and running it from a user folder), which bypasses audits checking only for non-network system names.
  * The Fix: Audit the binary path and digital signature of the calling process, ensuring that only verified browsers executing from standard application folders are whitelisted.

* Problem 2: Tunneling DNS Queries (DNS over HTTPS / DoH)
  * The Issue: Modern operating systems and browsers support DNS over HTTPS (DoH), which wraps DNS queries inside encrypted HTTPS POST/GET requests (port 443) to public resolvers (like Cloudflare 1.1.1.1 or Google 8.8.8.8). This completely bypasses local DNS query port 53 monitoring.
  * The Fix: Disable DNS over HTTPS via domain Group Policy (GPO) to force endpoints to use internal corporate DNS servers, and monitor outbound port 443 traffic to public DoH resolver IPs.

* Problem 3: Crash Dump/Windows Error Reporting Noise
  * The Issue: When Windows utilities crash, the OS spawns werfault.exe which connects to Microsoft error reporting domains (e.g., watson.telemetry.microsoft.com), which can cause false alarms if not filtered properly.
  * The Fix: Whitelist official Microsoft telemetry and error reporting domains in the connection filter.
