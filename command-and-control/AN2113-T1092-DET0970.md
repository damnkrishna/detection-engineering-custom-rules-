### 1. Technique Breakdown: T1092

* What it is: Communication Through Removable Media. Adversaries may use removable media (such as USB drives) to transfer data, drop commands, or execute malicious payloads on air-gapped systems or heavily restricted network segments. This is detected by monitoring the execution of interpreters or binary payloads launched from removable disk volumes.
* Log Source Requirements:
  * Sysmon Process Creation (Event ID 1) to audit command-line paths and binary directories on non-system drives.
* Coverage Check:
  * HIDS (Sysmon): YES. Processes launched from non-standard partitions or USB drive letters generate process creation logs.
  * NIDS (Zeek/Suricata): NO. USB execution is entirely local to the host.
* Log Sources Covered:
  * Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  * None.

### 2. Custom Sigma Rule

The following rule monitors for the execution of command shells, interpreters, or executable files launched directly from secondary drive letters (D:\ through Z:\) which often represent newly attached removable media or external volumes.

```yaml
title: Script or Binary Execution from Removable Media Path (AN2113)
id: d4e5f6a7-b8c9-4d0e-9f0a-1b2c3d4e5f90
status: experimental
description: "Detects the execution of scripting interpreters (PowerShell, CMD, WScript, CScript) or executable binaries located on removable drive paths (such as D:\\ through Z:\\), which is a common indicator of adversaries running payloads or transferring files from physical media on air-gapped systems."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_interpreters:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
    selection_interpreters_ofn:
        OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.exe'
            - 'Cmd.Exe'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'mshta.exe'
    selection_removable_cli:
        CommandLine|re:
            - '(?i)\s+[D-Z]:\\(?!Program Files|Windows)'
    selection_direct_exec:
        Image|re: '(?i)^[D-Z]:\\(?!Program Files|Windows).+\.exe'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (((selection_interpreters or selection_interpreters_ofn) and selection_removable_cli) or selection_direct_exec) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - User
falsepositives:
    - IT administrators running scripts or installing tools from a mounted network drive or secondary partition that is assigned a drive letter between D and Z.
    - Standard software installers that extract to or run from secondary volumes.
level: medium
tags:
    - attack.command-and-control
    - attack.t1092
    - analytic.an2113
    - detection.det0970
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Fixed secondary hard drives (D:\)
  * The Issue: Many enterprise computers have fixed secondary data drives (D:\ or E:\) where users store data and run tools legitimately, generating high false positives.
  * The Fix: Exclude specific known folders on secondary drives (e.g. `D:\Data\`) or map drive types using registry logs to determine if the drive is a removable USB disk vs. a fixed SSD.
* Problem 2: LNK shortcuts or autorun triggers
  * The Issue: If the attacker drops an LNK file that triggers an execution path, the command line structure might vary from standard parameters.
  * The Fix: Combine this rule with Sysmon Event ID 11 (File Event) rules to monitor the dropping of `.lnk` or `.inf` (autorun) files onto removable drives.
* Problem 3: PowerShell script block bypass
  * The Issue: If a script block is loaded directly into memory from a script on a USB drive without the drive letter appearing in the process creation command line (e.g. using `Get-Content`), this rule will not trigger.
  * The Fix: Enable PowerShell Script Block Logging (Event ID 4104) and look for script text containing file read operations on drive letters `[D-Z]:\`.
