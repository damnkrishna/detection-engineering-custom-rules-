### 1. Technique Breakdown: T1219

* What it is: Remote Access Software. Adversaries deploy or use legitimate remote monitoring and management (RMM) software (such as TeamViewer, AnyDesk, ScreenConnect, LogMeIn, Splashtop) to establish interactive command-line and desktop control over compromised hosts. Because these tools are commercial software and use standard HTTPS/TLS (port 443) outbound connections, they bypass network firewalls and do not trigger traditional antivirus alerts.
* Log Source Requirements: Host process creation and command line logs (Sysmon Event ID 1 / Windows Security Event ID 4688) and Network Connection logs (Sysmon Event ID 3).
* Coverage Check:
    * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 logs the execution of RMM client files. Sysmon Event ID 3 captures outbound socket connections to remote control servers.
    * Windows Security Logs: PARTIAL. Security logs EID 4688 captures command lines if enabled.
* Log Sources Covered:
    - Sysmon Event ID 1 (process_creation)
    - Sysmon Event ID 3 (network_connection)
* Log Sources Missing / Unused:
    - None.

### 2. Custom Sigma Rule

The detection logic is split into two rules targeting process creation and network connections separately.

Rule 1 of 2: Unauthorized Remote Management and Monitoring Software Execution (Process Creation)
```yaml
title: Unauthorized Remote Management and Monitoring Software Execution (AN0714-A)
id: 19c91359-023b-485a-a4d6-1853da3153f0
status: experimental
description: Detects the execution of known Remote Management and Monitoring (RMM) or Remote Desktop software (e.g., AnyDesk, TeamViewer, ScreenConnect) on unauthorized endpoints, indicating potential remote access hijacks.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_rmm:
        - Image|endswith:
            - '\AnyDesk.exe'
            - '\TeamViewer.exe'
            - '\TeamViewer_Desktop.exe'
            - '\ScreenConnect.Client.exe'
            - '\ScreenConnect.ClientService.exe'
            - '\tvnserver.exe'
            - '\winvnc.exe'
        - OriginalFileName:
            - 'AnyDesk.exe'
            - 'TeamViewer.exe'
            - 'TeamViewer_Desktop.exe'
            - 'ScreenConnect.Client.exe'
            - 'ScreenConnect.ClientService.exe'
            - 'tvnserver.exe'
            - 'winvnc.exe'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: selection_rmm and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Authorized IT helpdesk technicians using RMM software for user support and system administration.
level: medium
tags:
    - attack.command-and-control
    - attack.t1219
    - analytic.an0714
    - detection.det0259
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Portable Executable Configurations / Execution from Temp
  * The Issue: Many RMM tools (e.g., AnyDesk, TeamViewer QuickSupport) run as stand-alone portable applications without installation, often launching directly from %TEMP% or %USERPROFILE%\Downloads\. This makes whitelisting based on standard program folders (C:\Program Files\) difficult.
  * The Fix: Implement a companion rule that flags the execution of any binary with RMM-associated properties (OriginalFileName or metadata) executing from user-writable directories.

* Problem 2: Masquerading and Renamed Clients
  * The Issue: Attackers can rename the AnyDesk or TeamViewer executable to a generic file name (e.g., update.exe) to evade filename filters.
  * The Fix: Verify the OriginalFileName and Publisher signature fields in process creation logs, as these fields remain unchanged regardless of filename overrides.

* Problem 3: Helpdesk Tool Standardization
  * The Issue: Large organizations often use various RMM tools across different business units, creating noise and alert fatigue.
  * The Fix: Standardize helpdesk tools, whitelist the corporate-approved RMM software, and alert on any usage of non-standard alternatives (e.g., block AnyDesk if the official tool is TeamViewer).
