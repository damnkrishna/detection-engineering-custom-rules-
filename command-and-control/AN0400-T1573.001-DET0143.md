### 1. Technique Breakdown: T1573.001

* What it is: Encrypted Channel: Symmetric Cryptography. Adversaries encrypt their Command and Control (C2) traffic using symmetric encryption algorithms (e.g., AES or RC4) to evade signature-based network inspection. Malware binaries running on Windows often call built-in cryptographic libraries (CNG/CryptoAPI) by loading DLLs such as bcryptprimitives.dll, bcrypt.dll, or cryptsp.dll. When non-cryptographic system binaries (like calc.exe or notepad.exe) load these DLLs and subsequently open network sockets, it indicates process injection and custom C2 encryption.
* Log Source Requirements: Endpoint image load logs (Sysmon Event ID 7 / Windows Security Event ID 5056) and Network Connection logs (Sysmon Event ID 3).
* Coverage Check:
    * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 7 captures DLL loading events. Event ID 3 logs outbound network connections.
    * Windows Security Logs: PARTIAL. Security logs Event ID 5056 captures image loads if configured.
* Log Sources Covered:
    - Sysmon Event ID 7 (image_load)
    - Sysmon Event ID 3 (network_connection)
* Log Sources Missing / Unused:
    - None.

### 2. Custom Sigma Rule

The detection logic is split into two rules targeting DLL loading events and outbound network connections separately.

Rule 1 of 2: Cryptographic DLL Loaded by Non-Cryptographic Process (Image Load)
```yaml
title: Cryptographic DLL Loaded by Non-Cryptographic Process (AN0400-A)
id: d65fc1b9-dd4b-4bdd-ab18-32dd8a011503
status: experimental
description: Detects standard system applications that typically perform no cryptographic operations loading Windows cryptographic DLLs (e.g., bcryptprimitives.dll, cryptsp.dll), which may indicate encrypted C2 beaconing.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: image_load
    product: windows
    # Relies on Sysmon Event ID 7
detection:
    selection_process:
        Image|endswith:
            - '\calc.exe'
            - '\notepad.exe'
            - '\mspaint.exe'
            - '\write.exe'
            - '\wordpad.exe'
    selection_dll:
        ImageLoaded|endswith:
            - '\bcrypt.dll'
            - '\bcryptprimitives.dll'
            - '\cryptsp.dll'
            - '\ncrypt.dll'
    condition: selection_process and selection_dll
fields:
    - Image
    - ImageLoaded
    - Signed
    - SignatureStatus
falsepositives:
    - Extremely rare. Standard system applications like calc or notepad have no native reason to load cryptographic libraries.
level: high
tags:
    - attack.command-and-control
    - attack.t1573.001
    - analytic.an0400
    - detection.det0143
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: In-Memory / Custom Cryptography Implementation
  * The Issue: Attackers can write their own custom symmetric encryption routine (like a simple XOR or lightweight AES implementation in pure assembly/C) directly inside their payload code. This executes completely in memory without loading standard Windows DLLs (like bcrypt.dll), bypassing this image-load rule.
  * The Fix: Complement this detection with network-level payload entropy analysis (using Suricata/Zeek) to identify connections transmitting high-entropy (randomized) data payloads.

* Problem 2: Performance Overhead of Image Load Logging
  * The Issue: Sysmon Event ID 7 (Image Loaded) tracks every DLL load on the system, which generates massive log volumes and CPU overhead if enabled globally.
  * The Fix: Scope Sysmon configuration tightly to only monitor image loads for specific high-risk system processes (e.g. notepad.exe, calc.exe, shell hosts) rather than logging DLL loads for all applications.

* Problem 3: Crash Reporting / Watson Telemetry
  * The Issue: When standard processes crash, werfault.exe or telemetry DLLs may load cryptographic primitives for secure transmission of logs, producing false alerts.
  * The Fix: Verify that the cryptographic DLL is loaded directly by the core utility thread, and exclude child crash dump processes.
