### 1. Technique Breakdown: T1105

* What it is: Ingress Tool Transfer. Adversaries transfer files (tools, exploits, payloads, or scripts) from external systems into a compromised corporate host. They abuse native Windows utilities (LOLBins) like `certutil.exe`, `bitsadmin.exe`, `curl.exe`, or scripting environments like PowerShell to connect to their external infrastructure and download malicious files onto the filesystem.
* Log Source Requirements: Endpoint logs capturing process creation and command line arguments (Sysmon Event ID 1 / Windows Security Event ID 4688), or file creation logs (Sysmon Event ID 11).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs CLI command line parameters used for download. Sysmon Event ID 11 logs subsequent file creations. Wazuh alerts on suspicious download utility arguments.
* NIDS (Suricata + Zeek): YES. Zeek `http.log` and `ssl.log` record outbound file transfers and source domains.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect the execution of download tools and LOLBins executing CLI options that perform file downloads from remote sources.

```yaml
title: Ingress Tool Transfer via CLI (AN0165)
id: af786a16-8f71-487d-ac77-ab55ea6c5937
status: experimental
description: Detects command-line execution of tools (like certutil, bitsadmin, curl, or powershell) performing ingress tool transfers from external locations.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_certutil:
        - Image|endswith: '\certutil.exe'
        - OriginalFileName: 'certutil.exe'
    selection_certutil_args:
        CommandLine|contains:
            - 'urlcache'
            - 'split'
    selection_bitsadmin:
        - Image|endswith: '\bitsadmin.exe'
        - OriginalFileName: 'bitsadmin.exe'
    selection_bitsadmin_args:
        CommandLine|contains:
            - 'transfer'
            - 'download'
    selection_curl:
        - Image|endswith:
            - '\curl.exe'
            - '\wget.exe'
        - OriginalFileName:
            - 'curl.exe'
            - 'wget.exe'
    selection_curl_args:
        CommandLine|contains:
            - 'http://'
            - 'https://'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_args:
        CommandLine|contains:
            - 'DownloadFile'
            - 'DownloadString'
            - 'Invoke-WebRequest'
            - 'iwr'
            - 'wget'
            - 'curl'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: ((selection_certutil and selection_certutil_args) or (selection_bitsadmin and selection_bitsadmin_args) or (selection_curl and selection_curl_args) or (selection_powershell and selection_powershell_args)) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate administration scripts downloading program updates or installing software dependencies.
level: high
tags:
    - attack.command-and-control
    - attack.t1105
    - analytic.an0165
    - detection.det0060
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Alternate Data Stream (ADS) Downloads
  * The Issue: Attackers can download tools directly into NTFS Alternate Data Streams (e.g., writing the payload to C:\Windows\Temp\benign.txt:malicious.exe) which hides the executable payload from normal file explorers and makes detection of file creation harder.
  * The Fix: Monitor file creation events (Sysmon Event ID 11) that contain a colon (:) in the target path, indicating writing to an Alternate Data Stream, and analyze parent-child lineage.

* Problem 2: Inline Script Downloads / Memory Only Injection
  * The Issue: Payloads can be executed in-memory (e.g., using PowerShell IEX (New-Object System.Net.WebClient).DownloadString(...)) without writing any physical file to disk, bypassing file creation detectors.
  * The Fix: Enable PowerShell Script Block Logging (Event ID 4104) to audit scripts executing in memory and track outbound network socket activities by powershell.exe.

* Problem 3: Automated Developer/DevOps Environment Noise
  * The Issue: Software developers and DevOps build pipelines frequently download packages (npm, pip, NuGet, curl) during standard compilation tasks, generating noisy alerts.
  * The Fix: Whitelist approved build machines and staging environments, or filter out connections targeting official package repository domains (like pypi.org, npmjs.org).
