### 1. Technique Breakdown: T1029

* What it is: Scheduled Transfer. Adversaries schedule data exfiltration to align with normal business hours or system maintenance windows, making their transfers less noticeable. This is typically implemented via Windows Scheduled Tasks executing script blocks or command utilities (such as curl.exe, powershell.exe) that initiate file transfers to remote destinations. Detections monitor scheduled processes executing transfer cmdlets/arguments, or scheduled task XML files written to the Tasks directory.
* Log Source Requirements: Endpoint logs capturing process creation events and file creation events.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs process spawning by the Task Scheduler engine with transfer arguments, and Event ID 11 (File Event) logs task definition XML file writes under System32\Tasks.
* NIDS (Suricata + Zeek): YES (Partial). Outbound network traffic can indicate periodic beaconing.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 11 (file_event)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring of Task Scheduler spawning transfer utilities, and file event monitoring of scheduled task definitions written to disk.

Rule 1 of 2: Scheduled File Transfer via CLI (Process Creation)
```yaml
title: Scheduled File Transfer via CLI (AN1118)
id: a194e271-3ef2-4e0b-8939-a8477d274509
status: experimental
description: Detects command-line execution of file transfer commands or scripting hosts spawned by task schedulers, which may indicate scheduled exfiltration attempts.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_parent:
        ParentImage|endswith:
            - '\taskeng.exe'
    selection_cmd:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\curl.exe'
    selection_args:
        CommandLine|contains:
            - 'curl'
            - 'wget'
            - 'UploadFile'
            - 'ftp'
            - 'sftp'
            - 'scp'
            - 'Invoke-WebRequest'
            - 'Invoke-RestMethod'
    condition: selection_parent and selection_cmd and selection_args
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate enterprise synchronization scripts, monitoring tools, or software update check-ins.
level: medium
tags:
    - attack.exfiltration
    - attack.t1029
    - analytic.an1118
    - detection.det0399
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.

### 4. Test Cases (Engine Pipeline Verification)

#### True Positives
* True Positive 1: Scheduled File Transfer via CLI (Rule 1)
  * The Log: Process Activity executing curl.exe spawned by taskeng.exe.
  * Expected Outcome: Matches `selection_parent`, `selection_cmd`, and `selection_args`. MUST trigger an alert.

* True Positive 2: Scheduled Task Staging File Creation (Rule 2)
  * The Log: File Activity creating an XML file in `System32\Tasks\`.
  * Expected Outcome: Matches `selection_paths`. MUST trigger an alert.

* True Positive 3: Malformed JSON Robustness Test (Rule 1)
  * The Log: Process Activity simulating TP-01 but intentionally omitting the `actor` object entirely.
  * Expected Outcome: Engine parser should degrade gracefully and still trigger the alert. MUST trigger an alert.

* True Positive 4: Schema Type Validation Failure (Rule 1)
  * The Log: Exact match of TP-01, but `activity_id` is passed as a string `"1"` instead of an integer `1`.
  * Expected Outcome: Tests if the engine's JSON parser crashes on type mismatches or coerces the type gracefully. MUST trigger an alert.

* True Positive 5: Exact Duplicate Event (Rule 1)
  * The Log: Exact duplicate of TP-01 with the exact same timestamp.
  * Expected Outcome: Tests if the engine's deduplication window correctly suppresses identical events.

#### True Negatives
* True Negative 1: Manual curl execution (Rule 1 Filter)
  * The Log: Process Activity executing curl.exe spawned by cmd.exe (not taskeng.exe).
  * Expected Outcome: Fails to match `selection_parent`. MUST NOT trigger an alert.
