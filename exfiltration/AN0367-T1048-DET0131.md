### 1. Technique Breakdown: T1048

* What it is: Exfiltration Over Alternative Protocol. Adversaries exfiltrate collected data over a protocol different from the primary C2 channel. Typical alternative protocols include FTP, SMTP (email), external SMB shares, or DNS queries. Detections target processes initiating connections over ports associated with these protocols, or CLI execution of transfer utilities like ftp.exe or curl.exe.
* Log Source Requirements: Endpoint logs capturing network connection events and process creation events.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 3 (Network Connection) logs outbound connections over alternative protocols (ports 21, 25, 445) initiated by execution shells, and Event ID 1 (Process Creation) captures execution of transfer utilities.
* NIDS (Suricata + Zeek): YES. Network boundary logs capture protocol handshakes and data lengths.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 3 (network_connection)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into outbound network connections over alternative protocols initiated by scripting hosts, and process creation events of built-in/dropped network transfer utilities.

Rule 1 of 2: Outbound Alternative Protocol Exfiltration via CLI (Network Connection)
```yaml
title: Outbound Alternative Protocol Exfiltration via CLI (AN0367)
id: cc4f5f9b-2419-4d52-83b2-ae81cd20122c
status: experimental
description: Detects command line tools or scripting engines initiating outbound network connections over alternative protocols such as FTP (21), SMTP (25/587), or external SMB (445).
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\rundll32.exe'
            - '\wscript.exe'
            - '\cscript.exe'
    selection_ports:
        DestinationPort:
            - 21  # FTP
            - 25  # SMTP
            - 465 # SMTPS
            - 587 # SMTP Submission
            - 445 # SMB
    filter_local_smb:
        DestinationIp|startswith:
            - '10.'
            - '192.168.'
            - '172.16.'
            - '172.17.'
            - '172.18.'
            - '172.19.'
            - '172.2'
            - '172.3'
            - '127.'
            - 'fe80:'
            - '::1'
    condition: selection_process and selection_ports and not filter_local_smb
fields:
    - Image
    - CommandLine
    - User
    - LogonId
    - Initiated
    - SourceIp
    - DestinationIp
    - DestinationPort
falsepositives:
    - Administrative scripts sending automated alerts or connecting to external vendor FTP servers.
level: high
tags:
    - attack.exfiltration
    - attack.t1048
    - analytic.an0367
    - detection.det0131
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Dynamic Client IP Range
  * The Issue: Legitimate client processes communicating with external SaaS platforms can generate massive outbound log volumes.
  * The Fix: Baseline client egress destinations, restricting alerts to network connections initiated by execution shells or scripting hosts.

* Problem 2: Encrypted Payload Blind Spots
  * The Issue: Standard port monitoring cannot inspect encrypted TLS/HTTPS payload contents, leaving C2 beaconing undetected.
  * The Fix: Analyze TLS handshake metadata (specifically SNI domain names) and calculate connection frequency or beaconing heuristics.

* Problem 3: Proxy and Gateway Redirection
  * The Issue: Outbound connections routed through internal proxy servers will report the proxy IP as destination, masking the target C2 server.
  * The Fix: Correlate client endpoint process logs with proxy server access logs to resolve the true external destination IP.
