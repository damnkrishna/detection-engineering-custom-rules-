### 1. Technique Breakdown: T1567.001

* What it is: Exfiltration Over Web Service: Exfiltration to Cloud Storage. Adversaries exfiltrate data by uploading files or source code directly to public, legitimate code repositories (such as GitHub, GitLab, or Bitbucket). They do this using CLI client tools (like git.exe or curl.exe) or scripting hosts (like PowerShell) to send HTTP POST requests directly to repository APIs. Because these repositories are trusted by IT departments, network connections to these domains are rarely blocked.
* Log Source Requirements: Endpoint logs capturing network connection events and process creation events.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 3 (Network Connection) logs outbound network connections containing destination hostnames and initiating process names, and Event ID 1 (Process Creation) logs commands referencing repository domains.
* NIDS (Suricata + Zeek): YES. TLS handshake metadata and SNI hostnames reveal connections to public code repository domains.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 3 (network_connection)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into outbound network connections to public code repositories initiated by scripting hosts, and process creation events of scripting hosts executing commands that target repositories.

Rule 1 of 2: Outbound Data Exfiltration to Code Repository via CLI (Network Connection)
```yaml
title: Outbound Data Exfiltration to Code Repository via CLI (AN0895)
id: dcc44532-0a4a-4cf5-8139-12629817c775
status: experimental
description: Detects command-line interpreters, scripting hosts, or file transfer tools initiating network connections or DNS queries to known public code repository domains (e.g. GitHub, GitLab, Bitbucket), which may indicate data exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\curl.exe'
    selection_domains:
        DestinationHostname|contains:
            - 'github.com'
            - 'gitlab.com'
            - 'bitbucket.org'
            - 'githubusercontent.com'
    condition: selection_process and selection_domains
fields:
    - Image
    - CommandLine
    - User
    - LogonId
    - Initiated
    - SourceIp
    - DestinationIp
    - DestinationPort
falsepositives:
    - Software developers pushing legitimate code updates to corporate repository accounts using scripts or command line git tools.
level: medium
tags:
    - attack.exfiltration
    - attack.t1567.001
    - analytic.an0895
    - detection.det0318
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Dynamic Client IP Range
  * The Issue: Legitimate client processes communicating with external SaaS platforms can generate massive outbound log volumes.
  * The Fix: Baseline client egress destinations, restricting alerts to network connections initiated by execution shells or scripting hosts.

* Problem 2: Encrypted Payload Blind Spots
  * The Issue: Standard port monitoring cannot inspect encrypted TLS/HTTPS payload contents, leaving C2 beaconing undetected.
  * The Fix: Analyze TLS handshake metadata (specifically SNI domain names) and calculate connection frequency or beaconing heuristics.

* Problem 3: Proxy and Gateway Redirection
  * The Issue: Outbound connections routed through internal proxy servers will report the proxy IP as destination, masking the target C2 server.
  * The Fix: Correlate client endpoint process logs with proxy server access logs to resolve the true external destination IP.

### 4. Test Cases (Engine Pipeline Verification)

#### True Positives
* True Positive 1: Outbound Data Exfiltration to Code Repository (Rule 1)
  * The Log: Network Activity from curl.exe connecting to github.com.
  * Expected Outcome: Matches `selection_process` and `selection_domains`. MUST trigger an alert.

* True Positive 2: Code Repository Exfiltration Command Execution (Rule 2)
  * The Log: Process Activity executing curl.exe with github.com in args.
  * Expected Outcome: Matches `selection_process_image` and `selection_args`. MUST trigger an alert.

* True Positive 3: Malformed JSON Robustness Test (Rule 1)
  * The Log: Network Activity simulating TP-01 but intentionally omitting the `actor` object entirely.
  * Expected Outcome: Engine parser should degrade gracefully and still trigger the alert. MUST trigger an alert.

* True Positive 4: Schema Type Validation Failure (Rule 1)
  * The Log: Exact match of TP-01, but `activity_id` is passed as a string `"1"` instead of an integer `1`.
  * Expected Outcome: Tests if the engine's JSON parser crashes on type mismatches or coerces the type gracefully. MUST trigger an alert.

* True Positive 5: Exact Duplicate Event (Rule 1)
  * The Log: Exact duplicate of TP-01 with the exact same timestamp.
  * Expected Outcome: Tests if the engine's deduplication window correctly suppresses identical events.

#### True Negatives
* True Negative 1: Legitimate Domain (Rule 1 Filter)
  * The Log: Network Activity from curl.exe to example.com.
  * Expected Outcome: Fails to match `selection_domains`. MUST NOT trigger an alert.
