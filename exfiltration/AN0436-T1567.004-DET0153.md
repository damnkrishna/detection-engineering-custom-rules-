### 1. Technique Breakdown: T1567.004

* What it is: Exfiltration to Code Repository: Exfiltration Over Webhook. Adversaries exfiltrate stolen data by posting it directly to public webhook receivers (such as Discord, Slack, or webhook.site). They configure local scripts (e.g., PowerShell or curl) to execute HTTP POST requests containing file payloads targeting the webhook URLs. Because webhook platforms are legitimate and use standard port 443 HTTPS connections, they successfully bypass network boundary controls.
* Log Source Requirements: Endpoint network connection logs (Sysmon Event ID 3) or DNS queries (Sysmon Event ID 22), combined with requesting process metadata.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 3 logs outbound network connections containing destination hostnames and the initiating application path. Wazuh forwards these to trigger alerts.
* NIDS (Suricata + Zeek): YES. Zeek `ssl.log` and `http.log` record SSL/TLS SNI negotiations and HTTP methods targeting webhook services.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 3 (Network Connection) to detect command-line interpreters, scripting hosts, or file transfer tools initiating network connections to known webhook receiver domains.

```yaml
title: Outbound Data Exfiltration via Webhooks (AN0436)
id: 5776895d-a51a-453f-95ca-e0e3611ca031
status: experimental
description: Detects command-line interpreters, scripting hosts, or file transfer tools initiating network connections or DNS queries to known webhook receiver domains (e.g., Discord, Slack, Webhook.site), which may indicate data exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\curl.exe'
    selection_domains:
        DestinationHostname|contains:
            - 'webhook.site'
            - 'hooks.slack.com'
            - 'discord.com'
            - 'discordapp.com'
        CommandLine|contains:
            - 'webhooks'
            - 'webhook'
    condition: selection_process and selection_domains
fields:
    - Image
    - CommandLine
    - User
    - LogonId
    - Initiated
    - SourceIp
    - DestinationIp
    - DestinationPort
:
    - Legitimate administrative scripts sending automated system notifications to Slack channels.
level: high
tags:
    - attack.exfiltration
    - attack.t1567.004
    - analytic.an0436
    - detection.det0153
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Dynamic Client IP Range
  * The Issue: Legitimate client processes communicating with external SaaS platforms can generate massive outbound log volumes.
  * The Fix: Baseline client egress destinations, restricting alerts to network connections initiated by execution shells or scripting hosts.

* Problem 2: Encrypted Payload Blind Spots
  * The Issue: Standard port monitoring cannot inspect encrypted TLS/HTTPS payload contents, leaving C2 beaconing undetected.
  * The Fix: Analyze TLS handshake metadata (specifically SNI domain names) and calculate connection frequency or beaconing heuristics.

* Problem 3: Proxy and Gateway Redirection
  * The Issue: Outbound connections routed through internal proxy servers will report the proxy IP as destination, masking the target C2 server.
  * The Fix: Correlate client endpoint process logs with proxy server access logs to resolve the true external destination IP.
