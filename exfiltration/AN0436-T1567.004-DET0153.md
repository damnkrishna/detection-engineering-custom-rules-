### 1. Technique Breakdown: T1567.004

* What it is: Exfiltration Over Web Service: Exfiltration to Cloud Storage. Adversaries exfiltrate stolen data by posting it directly to public cloud storage or webhook receivers. They configure local scripts (e.g., PowerShell or curl) to execute HTTP POST requests containing file payloads targeting webhook URLs or cloud APIs. Because webhook platforms are legitimate and use standard port 443 HTTPS connections, they successfully bypass network boundary controls.
* Log Source Requirements: Endpoint logs capturing network connection events and process creation events.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 3 (Network Connection) logs outbound connections containing destination hostnames initiated by execution shells, and Event ID 1 (Process Creation) logs commands executing POST/PUT requests to webhook domains.
* NIDS (Suricata + Zeek): YES. TLS handshake metadata and SNI hostnames reveal webhook service connections.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 3 (network_connection)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into outbound network connections to webhook APIs initiated by scripting hosts, and process creation events of scripting hosts executing commands that mention webhook domains.

Rule 1 of 2: Outbound Data Exfiltration via Webhooks (Network Connection)
```yaml
title: Outbound Data Exfiltration via Webhooks (AN0436)
id: 5776895d-a51a-453f-95ca-e0e3611ca031
status: experimental
description: Detects command-line interpreters, scripting hosts, or file transfer tools initiating network connections to known webhook receiver domains (e.g., Discord, Slack, Webhook.site), which may indicate data exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: network_connection
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\curl.exe'
    selection_domains:
        DestinationHostname|contains:
            - 'webhook.site'
            - 'hooks.slack.com'
            - 'discord.com'
            - 'discordapp.com'
    condition: selection_process and selection_domains
fields:
    - Image
    - CommandLine
    - User
    - LogonId
    - Initiated
    - SourceIp
    - DestinationIp
    - DestinationPort
falsepositives:
    - Legitimate administrative scripts sending automated system notifications to Slack channels.
level: high
tags:
    - attack.exfiltration
    - attack.t1567.004
    - analytic.an0436
    - detection.det0153
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Dynamic Client IP Range
  * The Issue: Legitimate client processes communicating with external SaaS platforms can generate massive outbound log volumes.
  * The Fix: Baseline client egress destinations, restricting alerts to network connections initiated by execution shells or scripting hosts.

* Problem 2: Encrypted Payload Blind Spots
  * The Issue: Standard port monitoring cannot inspect encrypted TLS/HTTPS payload contents, leaving C2 beaconing undetected.
  * The Fix: Analyze TLS handshake metadata (specifically SNI domain names) and calculate connection frequency or beaconing heuristics.

* Problem 3: Proxy and Gateway Redirection
  * The Issue: Outbound connections routed through internal proxy servers will report the proxy IP as destination, masking the target C2 server.
  * The Fix: Correlate client endpoint process logs with proxy server access logs to resolve the true external destination IP.
