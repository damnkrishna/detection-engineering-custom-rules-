### 1. Technique Breakdown: T1011

* What it is: Exfiltration Over Other Network Medium. Adversaries bypass corporate firewall and proxy monitors by exfiltrating data through non-primary network interfaces connected directly to the internet (such as local WiFi hotspots, mobile cellular adapters, or Bluetooth links). Detections focus on identifying command-line configurations of wireless adapters or registry modifications of Bluetooth drivers, indicating out-of-band network staging.
* Log Source Requirements: Endpoint logs capturing process creation and registry modifications.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 (Process Creation) logs commands querying/configuring wireless interfaces, and Event ID 13 (Registry Set) logs Bluetooth service configuration modifications.
* NIDS (Suricata + Zeek): NO. Traffic bypasses corporate security boundary proxies and gateways.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 13 (registry_set)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring of wireless network interface configuration tools, and registry set monitoring of Bluetooth driver/port modifications.

Rule 1 of 2: WiFi or Secondary Network Interface Configuration via CLI (Process Creation)
```yaml
title: WiFi or Secondary Network Interface Configuration via CLI (AN0212)
id: fec142f1-c3f4-41db-81ad-e335625fd6d6
status: experimental
description: Detects command-line execution of netsh.exe or PowerShell network cmdlets being used to configure, enable, or connect to wireless (WLAN) or secondary network interfaces, which can be used to bypass corporate network boundaries for exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_netsh:
        - Image|endswith: '\netsh.exe'
        - OriginalFileName: 'netsh.exe'
    selection_netsh_args:
        CommandLine|contains:
            - ' wlan '
            - ' wlan'
            - 'wlan '
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_noun:
        CommandLine|contains:
            - 'NetAdapter'
            - 'NetRoute'
    selection_powershell_verb:
        CommandLine|contains:
            - 'Set-'
            - 'Enable-'
            - 'New-'
    condition: (selection_netsh and selection_netsh_args) or (selection_powershell and (selection_powershell_noun and selection_powershell_verb))
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - IT administrators or users troubleshooting mobile workstation wireless connections or configuring VPN routing.
level: medium
tags:
    - attack.exfiltration
    - attack.t1011
    - analytic.an0212
    - detection.det0077
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.

### 4. Test Cases (Engine Pipeline Verification)

#### True Positives
* True Positive 1: WiFi Configuration via Netsh (Rule 1)
  * The Log: Process Activity executing netsh.exe with 'wlan' arguments.
  * Expected Outcome: Matches `selection_netsh` and `selection_netsh_args`. MUST trigger an alert.

* True Positive 2: Bluetooth Registry Configuration (Rule 2)
  * The Log: Registry Activity modifying BTHPORT paths.
  * Expected Outcome: Matches `selection_bth`. MUST trigger an alert.

* True Positive 3: Malformed JSON Robustness Test (Rule 1)
  * The Log: Process Activity simulating TP-01 but intentionally omitting the `actor` object entirely.
  * Expected Outcome: Engine parser should degrade gracefully and still trigger the alert. MUST trigger an alert.

* True Positive 4: Schema Type Validation Failure (Rule 1)
  * The Log: Exact match of TP-01, but `activity_id` is passed as a string `"1"` instead of an integer `1`.
  * Expected Outcome: Tests if the engine's JSON parser crashes on type mismatches or coerces the type gracefully. MUST trigger an alert.

* True Positive 5: Exact Duplicate Event (Rule 1)
  * The Log: Exact duplicate of TP-01 with the exact same timestamp.
  * Expected Outcome: Tests if the engine's deduplication window correctly suppresses identical events.

#### True Negatives
* True Negative 1: Netsh IP Configuration (Rule 1 Filter)
  * The Log: Process Activity running netsh.exe but configuring IP routing (no 'wlan').
  * Expected Outcome: Fails to match `selection_netsh_args`. MUST NOT trigger an alert.
