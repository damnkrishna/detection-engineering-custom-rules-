### 1. Technique Breakdown: T1052.001

* What it is: Exfiltration Over Physical Medium: Exfiltration over USB. Adversaries exfiltrate data by writing files directly to USB mass storage devices. To accelerate data collection and minimize interactive steps, they often execute automated command-line copy tools (like robocopy.exe, xcopy.exe) or custom scripts to scan and copy targeted files directly to plugged-in USB drives. Detections monitor file writes onto removable drive paths by these copy utilities or the process execution command lines.
* Log Source Requirements: Endpoint logs capturing file creation events and process creation events.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 11 (File Event) logs when copy utilities write files to USB drive paths, and Event ID 1 (Process Creation) logs copy command-line executions targeting removable storage.
* NIDS (Suricata + Zeek): NO. Offline, local host actions.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 11 (file_event)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into monitoring files written to removable storage paths by copy utilities, and process creation events of copy utilities targeting removable storage drive letters.

Rule 1 of 2: File Copy to USB Storage via CLI (File Event)
```yaml
title: File Copy to USB Storage via CLI (AN0616)
id: 44e824ce-8c28-4fb8-ba3b-b05838ce6d7d
status: experimental
description: Detects command line execution of file copy utilities (xcopy, robocopy) or scripting engines writing files to USB/removable storage drive letters.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: file_event
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\xcopy.exe'
            - '\robocopy.exe'
            - '\powershell.exe'
            - '\cmd.exe'
    selection_paths:
        TargetFilename|startswith:
            - 'D:\'
            - 'E:\'
            - 'F:\'
            - 'G:\'
            - 'H:\'
            - 'I:\'
            - 'J:\'
    condition: selection_process and selection_paths
fields:
    - Image
    - TargetFilename
    - User
    - LogonId
falsepositives:
    - Legitimate IT administration or users manually backing up files using command line copy tools to external media.
level: medium
tags:
    - attack.exfiltration
    - attack.t1052.001
    - analytic.an0616
    - detection.det0220
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Legitimate Installer and Backup Noise
  * The Issue: Backup utilities or system installers frequently write archives or stage folders, generating high-volume false positives.
  * The Fix: Define deployment exclusions for installer parents (such as msiexec.exe or setup.exe) and restrict monitoring to user-writable directories.

* Problem 2: Evasive Staging Paths
  * The Issue: Adversaries may write staged files to unusual directories not covered by static path monitors.
  * The Fix: Monitor global file system writes for compressed extensions (.zip, .7z) originating from shell or scripting host parents.

* Problem 3: In-Memory Collection Bypasses
  * The Issue: Malware executing fully in-memory may stream or exfiltrate data without writing staging files to disk, bypassing file event monitoring.
  * The Fix: Complement directory monitoring with host network egress logging and active memory inspection checks.

### 4. Test Cases (Engine Pipeline Verification)

#### True Positives
* True Positive 1: File Copy to USB Storage via CLI (Rule 1)
  * The Log: File Activity by xcopy to `D:\`.
  * Expected Outcome: Matches `selection_process_image` (re-used name logic) and `selection_paths`. MUST trigger an alert.

* True Positive 2: CLI Copy Command Targeting Removable Media (Rule 2)
  * The Log: Process Activity executing xcopy targeting `D:\`.
  * Expected Outcome: Matches `selection_process_image` and `selection_paths`. MUST trigger an alert.

* True Positive 3: Malformed JSON Robustness Test (Rule 1)
  * The Log: File Activity simulating TP-01 but intentionally omitting the `actor` object entirely.
  * Expected Outcome: Engine parser should degrade gracefully and still trigger the alert. MUST trigger an alert.

* True Positive 4: Schema Type Validation Failure (Rule 1)
  * The Log: Exact match of TP-01, but `activity_id` is passed as a string `"1"` instead of an integer `1`.
  * Expected Outcome: Tests if the engine's JSON parser crashes on type mismatches or coerces the type gracefully. MUST trigger an alert.

* True Positive 5: Exact Duplicate Event (Rule 1)
  * The Log: Exact duplicate of TP-01 with the exact same timestamp.
  * Expected Outcome: Tests if the engine's deduplication window correctly suppresses identical events.

#### True Negatives
* True Negative 1: Local Drive Copy (Rule 2 Filter)
  * The Log: Process Activity executing xcopy targeting `C:\Temp`.
  * Expected Outcome: Fails to match `selection_paths`. MUST NOT trigger an alert.
