### 1. Technique Breakdown: T1048.003

* What it is: Exfiltration Over Alternative Protocol: Exfiltration Over Unencrypted Non-C2 Protocol. Adversaries bypass standard C2 communication channels to exfiltrate data using common, unencrypted protocols such as HTTP (port 80), FTP (port 21), or SMTP (port 25). They leverage built-in command-line tools or scripting engines to transmit staged archives to rogue external servers. Since the protocol is unencrypted, network analysis can read payloads, but host-based logs are necessary to identify the initiating processes.
* Log Source Requirements: Sysmon network connection logs (Event ID 3) combined with initiating process metadata (Sysmon Event ID 1).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 3 logs outbound TCP/UDP connections along with the parent process, source/destination ports, and IP addresses. Wazuh aggregates these events.
    * NIDS (Suricata + Zeek): YES. Zeek `http.log`, `ftp.log`, or `smtp.log` records unencrypted protocol transactions and file uploads in transit.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 3 (Network Connection) to detect scripting engines or cmdline tools initiating connections over unencrypted protocols (80, 21, 25) to external networks.

```yaml
title: Exfiltration - Outbound Unencrypted Connection by Scripting Host (AN0423)
id: 27ba2a0d-92c4-4a3d-9436-55fc2e0aea6e
status: experimental
description: Detects command interpreters or scripting utilities (PowerShell, cscript, wscript) initiating network connections over unencrypted ports (80, 21, 25) to external IP addresses.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: network_connection
    product: windows
    # Relies on Sysmon Event ID 3
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\cmd.exe'
    selection_ports:
        DestinationPort:
            - 21 # FTP
            - 25 # SMTP
            - 80 # HTTP
    filter_internal:
        DestinationIp|startswith:
            - '10.'
            - '192.168.'
            - '172.16.'
            - '172.17.'
            - '172.18.'
            - '172.19.'
            - '172.2'
            - '172.3'
            - '127.'
            - '169.254.'
    condition: selection_process and selection_ports and not filter_internal
fields:
    - Image
    - CommandLine
    - User
    - LogonId
    - Initiated
    - SourceIp
    - DestinationIp
    - DestinationPort
falsepositives:
    - Administrative scripts executing HTTP queries to download public updates or syncing time via NTP.
    - Automated system backup tools transferring statistics to internal monitoring servers.
level: high
tags:
    - attack.exfiltration
    - attack.t1048.003
    - analytic.an0423
    - detection.det0149
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Dynamic Client IP Range
  * The Issue: Legitimate client processes communicating with external SaaS platforms can generate massive outbound log volumes.
  * The Fix: Baseline client egress destinations, restricting alerts to network connections initiated by execution shells or scripting hosts.

* Problem 2: Encrypted Payload Blind Spots
  * The Issue: Standard port monitoring cannot inspect encrypted TLS/HTTPS payload contents, leaving C2 beaconing undetected.
  * The Fix: Analyze TLS handshake metadata (specifically SNI domain names) and calculate connection frequency or beaconing heuristics.

* Problem 3: Proxy and Gateway Redirection
  * The Issue: Outbound connections routed through internal proxy servers will report the proxy IP as destination, masking the target C2 server.
  * The Fix: Correlate client endpoint process logs with proxy server access logs to resolve the true external destination IP.

### 4. Test Cases (Engine Pipeline Verification)

#### True Positives
* True Positive 1: Outbound Unencrypted Connection by Scripting Host (Rule 1)
  * The Log: Network Activity from PowerShell connecting to port 80 (HTTP) on a public IP.
  * Expected Outcome: Matches `selection_process` and `selection_ports` without hitting `filter_internal`. MUST trigger an alert.

* True Positive 2: Malformed JSON Robustness Test (Rule 1)
  * The Log: Network Activity simulating TP-01 but intentionally omitting the `actor` object entirely.
  * Expected Outcome: Engine parser should degrade gracefully and still trigger the alert. MUST trigger an alert.

* True Positive 3: Schema Type Validation Failure (Rule 1)
  * The Log: Exact match of TP-01, but `activity_id` is passed as a string `"1"` instead of an integer `1`.
  * Expected Outcome: Tests if the engine's JSON parser crashes on type mismatches or coerces the type gracefully. MUST trigger an alert.

* True Positive 4: Exact Duplicate Event (Rule 1)
  * The Log: Exact duplicate of TP-01 with the exact same timestamp.
  * Expected Outcome: Tests if the engine's deduplication window correctly suppresses identical events.

#### True Negatives
* True Negative 1: Internal Unencrypted Connection (Rule 1 Filter)
  * The Log: Network Activity from PowerShell connecting to port 80 on a 10.x.x.x IP.
  * Expected Outcome: Filtered by `filter_internal`. MUST NOT trigger an alert.
