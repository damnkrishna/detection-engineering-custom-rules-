### 1. Technique Breakdown: T1048.001

* What it is: Exfiltration Over Alternative Protocol: Exfiltration Over Symmetric Encrypted Non-C2 Protocol. Adversaries encrypt stolen files locally using symmetric cryptography (like AES-256) and upload the data via an alternative network protocol or a public file hosting API that is distinct from their primary C2 channel. Detections monitor scripting hosts loading cryptographic DLLs (bcryptprimitives.dll, cryptsp.dll) to prepare for secure transfers, or network connection events containing encryption-related commands.
* Log Source Requirements: Endpoint logs capturing image/library load events and network connection events.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 7 (Image Load) logs when cryptographic DLLs are loaded by scripting engines, and Event ID 3 (Network Connection) logs outbound uploads initiated by these scripting processes.
* NIDS (Suricata + Zeek): YES (Partial). Outbound uploads over alternative channels are logged, but host-level context confirms local encryption actions.
* Log Sources Covered:
  - Sysmon Event ID 3 (network_connection)
  - Sysmon Event ID 7 (image_load)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into monitoring scripting host processes loading Windows cryptographic libraries, and network connection events combined with command-line arguments specifying encryption/encoding options.

Rule 1 of 2: Cryptographic DLL Loaded by Scripting Host (Image Load)
```yaml
title: Cryptographic DLL Loaded by Scripting Host (AN1389)
id: 1a59e4fb-05c9-49c1-98ca-bae5c8832b27
status: experimental
description: Detects command-line interpreters or scripting hosts loading Windows cryptographic libraries (e.g., bcryptprimitives.dll, cryptsp.dll), which may indicate symmetric encryption of data prior to exfiltration.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: image_load
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\cmd.exe'
    selection_dll:
        ImageLoaded|endswith:
            - '\bcrypt.dll'
            - '\bcryptprimitives.dll'
            - '\cryptsp.dll'
            - '\ncrypt.dll'
    condition: selection_process and selection_dll
fields:
    - Image
    - ImageLoaded
    - Signed
    - SignatureStatus
falsepositives:
    - Administrative scripts executing complex hashing routines (e.g. comparing file hashes using Get-FileHash) or managing secure password fields.
level: medium
tags:
    - attack.exfiltration
    - attack.t1048.001
    - analytic.an1389
    - detection.det0503
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.

* True Positive 1: Cryptographic DLL Loaded by Scripting Host (Rule 1)
  * The Log: Library Activity where PowerShell loads bcrypt.dll.
  * Expected Outcome: Matches `selection_process` and `selection_dll`. MUST trigger an alert.

* True Positive 2: Outbound Encrypted File Upload (Rule 2)
  * The Log: Network Activity from PowerShell connecting to port 443 with '-enc' in args.
  * Expected Outcome: Matches `selection_process`, `selection_ports`, and `selection_obfuscation`. MUST trigger an alert.

* True Positive 3: Malformed JSON Robustness Test (Rule 1)
  * The Log: Library Activity simulating TP-01 but intentionally omitting the `actor` object entirely.
  * Expected Outcome: Engine parser should degrade gracefully and still trigger the alert. MUST trigger an alert.

* True Positive 4: Schema Type Validation Failure (Rule 1)
  * The Log: Exact match of TP-01, but `activity_id` is passed as a string `"1"` instead of an integer `1`.
  * Expected Outcome: Tests if the engine's JSON parser crashes on type mismatches or coerces the type gracefully. MUST trigger an alert.

* True Positive 5: Exact Duplicate Event (Rule 1)
  * The Log: Exact duplicate of TP-01 with the exact same timestamp.
  * Expected Outcome: Tests if the engine's deduplication window correctly suppresses identical events.

#### True Negatives
* True Negative 1: Valid Process Loading DLL (Rule 1 Filter)
  * The Log: Library Activity where explorer.exe loads bcrypt.dll.
  * Expected Outcome: Fails to match `selection_process`. MUST NOT trigger an alert.
