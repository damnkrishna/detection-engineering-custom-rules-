### 1. Technique Breakdown: T1078

* What it is: Valid Accounts. Adversaries hijack legitimate credentials of local, domain, or service accounts to gain initial access, establish persistence, or escalate privileges. Because they utilize valid credentials, their activities appear benign. Detection relies on monitoring anomalous authentication indicators, such as remote logons (Logon Type 3 or 10) by highly privileged accounts executing from unexpected source endpoints.
* Log Source Requirements: Windows Security Event Log capturing authentication events, and network connection logs tracking access to remote systems.
* Coverage Check:
  - HIDS (Sysmon + Wazuh): YES. Windows Security Event ID 4624 logs logon events. Sysmon Event ID 3 captures network connections.
  - NIDS (Suricata + Zeek): YES (Partial). Network security tools can log Kerberos or NTLM authentications over protocols like SMB/RDP.
* Log Sources Covered:
  - Security Event ID 4624 (security)
  - Sysmon Event ID 3 (network_connection)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into Security logons for Administrative accounts via remote logon, and network connection logs tracking admin tool outbound requests.

Rule 1 of 2: Anomalous Administrative Account Logon (Security Log)
```yaml
title: Anomalous Administrative Account Logon (AN1543)
id: f48bca72-d48e-4a6c-947b-a25da6213ac4
status: experimental
description: Detects successful remote network or RDP logons by highly privileged administrative accounts, which may indicate account hijacking or lateral movement.
author: Krishna Gupta
date: 2026-06-07
logsource:
    product: windows
    service: security
detection:
    selection_event:
        EventID: 4624
    selection_logon_type:
        LogonType:
            - 3 # Network
            - 10 # Remote Interactive
    selection_admin_accounts:
        TargetUserName|contains:
            - 'admin_'
            - 'administrator'
            - 'adm_'
            - 'root'
    condition: selection_event and selection_logon_type and selection_admin_accounts
fields:
    - EventID
    - LogonType
    - TargetDomainName
    - TargetUserName
    - IpAddress
falsepositives:
    - Legitimate remote administration by IT personnel using approved administrator accounts.
level: high
tags:
    - attack.initial-access
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1078
    - analytic.an1543
    - detection.det0380
```

Rule 2 of 2: Anomalous Administrative Account Network Connection (Network Connection)
```yaml
title: Anomalous Administrative Account Network Connection (AN1543-B)
id: 71f76707-d902-42a3-8cf3-97bf0015917b
status: experimental
description: Detects outbound network connections over remote admin ports (445, 3389, 5985) by shell processes, suggesting administrative account lateral movement activity.
author: Krishna Gupta
date: 2026-06-17
logsource:
    category: network_connection
    product: windows
detection:
    selection_ports:
        DestinationPort:
            - 445
            - 3389
            - 5985
            - 5986
    selection_process:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
    condition: selection_ports and selection_process
fields:
    - Image
    - SourceIp
    - DestinationIp
    - DestinationPort
    - User
falsepositives:
    - Standard admin scripts performing remote management.
level: medium
tags:
    - attack.initial-access
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1078
    - analytic.an1543
    - detection.det0380
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  - The Issue: IT personnel performing legitimate maintenance operations using local or administrative accounts.
  - The Fix: Restrict network alerts to interactive logins from unauthorized subnets.

* Problem 2: Command and Execution Obfuscation
  - The Issue: Attackers employ encoding to bypass filters.
  - The Fix: Enable PowerShell Script Block Logging.

* Problem 3: Log Deletion and Modification
  - The Issue: Adversaries can clear security logs to blind defenders.
  - The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM.
