### 1. Technique Breakdown: T1548

* What it is: Abuse Elevation Control Mechanism. User Account Control (UAC) is a key Windows security feature that limits application privileges to standard user levels until an administrator authorizes an elevation. Adversaries bypass UAC by hijacking auto-elevated system binaries or hijacking COM objects and Registry paths to execute command payloads at High Integrity without triggering consent dialogs.
* Log Source Requirements: Endpoint logs capturing process creation, parent-child relationships, and command-line execution parameters (Sysmon Event ID 1 / Windows Security Event ID 4688).
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures parent process paths, target process paths, and full command-line arguments. Wazuh aggregates these to detect UAC bypass signatures.
* NIDS (Suricata + Zeek): NO. Elevation of privileges is entirely a local operating system event. It does not generate network traffic.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect auto-elevated Windows binaries spawning shell processes, or registry modifications targeting common UAC bypass command keys via command line tools.

```yaml
title: Abuse of UAC Elevation Control Mechanisms (AN0975)
id: 6a088cec-84e0-4bfe-aedf-a07307bcccba
status: experimental
description: Detects bypass of User Account Control (UAC) by monitoring auto-elevating Windows binaries spawning shell utilities or command-line modifications of registry entries targeting UAC bypass paths.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_parent:
        ParentImage|endswith:
            - '\control.exe'
            - '\sdclt.exe'
            - '\fodhelper.exe'
            - '\eventvwr.exe'
            - '\computerdefaults.exe'
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
    selection_registry:
        CommandLine|contains:
            - '\Software\Classes\ms-settings\shell\open\command'
            - '\Software\Classes\mscfile\shell\open\command'
            - '\Software\Classes\exefile\shell\runas\command'
        CommandLine|contains:
            - 'reg'
            - 'add'
            - 'New-ItemProperty'
            - 'Set-ItemProperty'
    condition: selection_parent or selection_registry
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Administrative maintenance or backup tools using auto-elevating scripts.
level: high
tags:
    - attack.privilege-escalation
    - attack.defense-evasion
    - attack.t1548
    - analytic.an0975
    - detection.det0345
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  * The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes (^), or base64 encoding, evading simple string matching.
  * The Fix: Implement PowerShell Script Block Logging and utilize regex or script-decoding scripts in the SIEM to check arguments.

* Problem 2: Administrative Activity Noise
  * The Issue: IT administrators legitimately run command-line tools or installers that trigger these rules during system maintenance.
  * The Fix: Establish a baseline of legitimate admin tools, whitelisting specific administrative account names or management servers.

* Problem 3: Masquerading via Renamed Binaries
  * The Issue: Attackers rename native Windows utilities (such as net.exe or cmd.exe) to custom filenames to bypass path-based filters.
  * The Fix: Incorporate Masquerade-resistant criteria, matching on OriginalFileName rather than the static Image path in process creation logs.
