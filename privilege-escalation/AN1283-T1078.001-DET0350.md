### 1. Technique Breakdown: T1078.001

* What it is: Valid Accounts: Default Accounts. Operating systems and software packages are installed with default built-in accounts (e.g., `Administrator`, `Guest` in Windows). Adversaries scan for and exploit default accounts that have default passwords, weak passwords, or are left enabled. Operating systems with default accounts exposed to remote protocols like SMB or RDP represent primary targets.
* Log Source Requirements: Windows Security Event Log capturing authentication events (Event ID 4624 for successful logon) containing user names, logon types, and source IP addresses.
* Coverage Check:
* HIDS (Sysmon + Wazuh): YES. Windows Security Event ID 4624 logs all successful authentication sessions. Wazuh retrieves and alerts on specific usernames and logon types.
* NIDS (Suricata + Zeek): YES (Partial). Network security tools can identify authentication attempts over SMB (NTLM) or RDP (TLS) containing default usernames but cannot determine if authorization was successful.

### 2. Custom Sigma Rule

This rule utilizes Windows Security Event ID 4624 (Successful Logon) to detect network or remote interactive logons using built-in default accounts (`Administrator`, `Guest`).

```yaml
title: Default Account Remote Logon (AN1283)
id: e6ef5fe7-2752-476e-b1eb-9599b236fd22
status: experimental
description: Detects successful remote network or remote interactive logons using built-in default accounts (e.g., Administrator, Guest).
author: Krishna Gupta
date: 2026-06-07
logsource:
    product: windows
    service: security
    # Relies on Windows Security Event ID 4624
detection:
    selection_event:
        EventID: 4624
    selection_logon_type:
        LogonType:
            - 3 # Network
            - 10 # Remote Interactive
    selection_default_users:
        TargetUserName:
            - 'Administrator'
            - 'Guest'
    condition: selection_event and selection_logon_type and selection_default_users
fields:
    - EventID
    - LogonType
    - TargetUserName
falsepositives:
    - Initial operating system setup or legacy systems where local domain configurations are not yet deployed.
level: high
tags:
    - attack.defense-evasion
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1078.001
    - analytic.an1283
    - detection.det0350
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.
