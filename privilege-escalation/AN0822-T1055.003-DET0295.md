### 1. Technique Breakdown: T1055.003

* What it is: Process Injection: Thread Execution Hijacking. Instead of creating a new thread (like in PE injection), an adversary targets an existing, legitimate thread in a remote process. They suspend the thread (`SuspendThread`), allocate memory and write their payload (`VirtualAllocEx` / `WriteProcessMemory`), modify the thread's instruction pointer (EIP/RIP) using `SetThreadContext` to point to the payload, and finally resume the thread (`ResumeThread`). This evades defenses that trigger purely on `CreateRemoteThread`.
* Log Source Requirements: Advanced EDR telemetry (API hooking for `SetThreadContext`), Sysmon Event ID 10 (ProcessAccess).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES (Partial). Sysmon logs `ProcessAccess` (Event ID 10) when the handle is opened. However, Sysmon does NOT log `SetThreadContext`.
    * NIDS (Suricata + Zeek): NO. Local memory manipulation.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 10 (ProcessAccess) to detect suspicious access requests targeting critical processes, specifically looking for access masks that imply thread manipulation and context setting, which are prerequisites for Thread Execution Hijacking.

```yaml
title: Suspicious Process Access indicating Thread Hijacking (AN0822)
id: f48b1112-9844-4632-901b-c1284a14f4e8
status: experimental
description: Detects hijacking of an existing thread by monitoring suspicious ProcessAccess requests indicative of thread context manipulation.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_access
    product: windows
    # Relies on Sysmon Event ID 10
detection:
    selection_target:
        TargetImage|endswith:
            - '\explorer.exe'
            - '\svchost.exe'
            - '\winlogon.exe'
    selection_access:
 # Access rights needed to suspend threads and set context
 # THREAD_SUSPEND_RESUME (0x0002) + THREAD_SET_CONTEXT (0x0010)
        GrantedAccess|contains:
            - '0x1F0FFF' # All Access
            - '0x143A'
    filter_known:
        SourceImage|endswith:
            - '\taskmgr.exe'
            - '\MsMpEng.exe'
            - '\csrss.exe'
    condition: selection_target and selection_access and not filter_known
fields:
    - SourceImage
    - TargetImage
    - GrantedAccess
falsepositives:
    - Debugging tools like WinDbg or Process Hacker.
    - EDR agents aggressively scanning process memory.
level: high
tags:
    - attack.privilege-escalation
    - attack.defense-evasion
    - attack.t1055.003
    - analytic.an0822
    - detection.det0295
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.
