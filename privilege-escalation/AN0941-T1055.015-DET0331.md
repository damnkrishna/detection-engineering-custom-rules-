### 1. Technique Breakdown: T1055.015

* What it is: Process Injection: ListPlanting. Adversaries may inject malicious code by abusing list-view controls (e.g., `SysListView32`) in legitimate Windows applications. They allocate memory in the target process (`VirtualAllocEx`), write their shellcode (`WriteProcessMemory`), and then send specialized window messages (like `LVM_SETITEMPOSITION` or `LVM_SORTITEMS`) to the list-view control using `PostMessage` or `SendMessage`. This forces the application to execute the shellcode disguised as a callback function used for sorting or positioning items.
* Log Source Requirements: Advanced EDR telemetry (API hooking for `SendMessage`, `PostMessage`), Sysmon Event ID 10 (ProcessAccess).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES (Partial). Sysmon logs `ProcessAccess` (Event ID 10) to the target GUI application, but lacks visibility into the specific window messages being sent.
    * NIDS (Suricata + Zeek): NO. Local GUI message abuse.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 10 (ProcessAccess) to detect suspicious access requests targeting known GUI-heavy applications that frequently utilize list-view controls, which is a prerequisite for ListPlanting.

```yaml
title: Suspicious Process Access indicating ListPlanting (AN0941)
id: fbbcc3f9-676b-4e6c-a8eb-8b0ab3606f1d
status: experimental
description: Detects the potential use of message-based injection (ListPlanting) by monitoring for suspicious ProcessAccess requests to GUI applications.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_access
    product: windows
    # Relies on Sysmon Event ID 10
detection:
    selection_target:
        TargetImage|endswith:
            - '\explorer.exe'
            - '\taskmgr.exe'
    selection_access:
        GrantedAccess|contains:
            - '0x1F0FFF' # All Access
            - '0x143A'
    filter_known:
        SourceImage|endswith:
            - '\MsMpEng.exe'
            - '\dwm.exe'
    condition: selection_target and selection_access and not filter_known
fields:
    - SourceImage
    - TargetImage
    - GrantedAccess
falsepositives:
    - Accessibility tools and legitimate UI automation software interacting with list views.
level: high
tags:
    - attack.privilege-escalation
    - attack.defense-evasion
    - attack.t1055.015
    - analytic.an0941
    - detection.det0331
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.
