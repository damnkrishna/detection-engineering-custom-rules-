### 1. Technique Breakdown: T1078.003

* What it is: Valid Accounts: Local Accounts. Local accounts exist on individual systems and are managed locally (e.g., the built-in local Administrator account). Adversaries exploit local accounts to move laterally between endpoints (using Logon Type 3 network connections) by leveraging credential reuse (where multiple workstations share the same local administrator password). Monitoring successful network logons using local administrative accounts is a highly effective method to identify lateral movement.
* Log Source Requirements: Windows Security Event Log capturing authentication events, and network connection logs tracking access to remote systems.
* Coverage Check:
  - HIDS (Sysmon + Wazuh): YES. Windows Security Event ID 4624 logs network logon sessions. Sysmon Event ID 3 captures network connection details.
  - NIDS (Suricata + Zeek): YES (Partial). Network security tools can identify authentication attempts over SMB.
* Log Sources Covered:
  - Security Event ID 4624 (security)
  - Sysmon Event ID 3 (network_connection)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into Security logons for Local Administrator accounts via network logon, and network connection logs tracking admin tool outbound requests.

Rule 1 of 2: Local Administrator Network Logon (Security Log)
```yaml
title: Local Administrator Network Logon (AN1137)
id: cb73d328-98e4-4ab2-b258-aa84102cfda8
status: experimental
description: Detects successful network logons (Logon Type 3) using local administrator accounts, which may indicate lateral movement using compromised local credentials.
author: Krishna Gupta
date: 2026-06-07
logsource:
    product: windows
    service: security
detection:
    selection_event:
        EventID: 4624
    selection_logon_type:
        LogonType: 3 # Network
    selection_local_admin:
        TargetUserName:
            - 'Administrator'
            - 'admin'
    selection_domain:
  # Focus on local accounts or workgroups, not domain
        TargetDomainName:
            - 'WORKGROUP'
            - 'localhost'
    condition: selection_event and selection_logon_type and selection_local_admin and selection_domain
fields:
    - EventID
    - LogonType
    - TargetDomainName
    - TargetUserName
    - IpAddress
falsepositives:
    - Legitimate administrative actions by IT personnel performing system maintenance using local admin accounts.
level: high
tags:
    - attack.lateral-movement
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1078.003
    - analytic.an1137
    - detection.det0360
```

Rule 2 of 2: Local Administrator Network Connection (Network Connection)
```yaml
title: Local Administrator Network Connection (AN1137-B)
id: c4710ffb-52da-4c85-9a77-d00ac99bb360
status: experimental
description: Detects outbound network connections over remote management ports (SMB, RDP, WinRM) associated with local admin lateral movement.
author: Krishna Gupta
date: 2026-06-17
logsource:
    category: network_connection
    product: windows
detection:
    selection_ports:
        DestinationPort:
            - 445   # SMB
            - 3389  # RDP
            - 5985  # WinRM HTTP
            - 5986  # WinRM HTTPS
    selection_process:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
    condition: selection_ports and selection_process
fields:
    - Image
    - SourceIp
    - DestinationIp
    - DestinationPort
    - User
falsepositives:
    - Authorized remote administration by IT administrators using automation scripts.
level: medium
tags:
    - attack.lateral-movement
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1078.003
    - analytic.an1137
    - detection.det0360
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  - The Issue: IT personnel performing legitimate maintenance operations using local accounts.
  - The Fix: Restrict network alerts to interactive logins from unauthorized subnets.

* Problem 2: Command and Execution Obfuscation
  - The Issue: Attackers employ encoding to bypass filters.
  - The Fix: Enable PowerShell Script Block Logging.

* Problem 3: Log Deletion and Modification
  - The Issue: Adversaries can clear security logs to blind defenders.
  - The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM.
