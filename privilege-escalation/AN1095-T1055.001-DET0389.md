### 1. Technique Breakdown: T1055.001

* What it is: Process Injection: Dynamic-link Library Injection. Adversaries inject a path to a malicious DLL into the memory space of a remote process and force that process to load the DLL. This is commonly done by allocating memory (`VirtualAllocEx`), writing the DLL path string (`WriteProcessMemory`), and then calling `CreateRemoteThread` passing the address of `LoadLibraryA` (or `LoadLibraryW`) as the thread's start routine. This forces the target process to load and execute the attacker's DLL.
* Log Source Requirements: Sysmon Event ID 8 (CreateRemoteThread), Sysmon Event ID 7 (Image Loaded).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 8 captures the remote thread creation, and the `StartAddress` often points directly to `LoadLibrary`.
    * NIDS (Suricata + Zeek): NO. Local memory execution.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 8 (CreateRemoteThread) to detect cross-process thread creation where the thread's starting address points directly to the `LoadLibrary` function, a hallmark of classic DLL injection.

```yaml
title: Suspicious Remote Thread Creation (LoadLibrary Injection) (AN1095)
id: fbbcc3f9-676b-4e6c-a8eb-8b0ab3606f1d
status: experimental
description: Detects DLL injection by monitoring CreateRemoteThread events where the StartAddress points to LoadLibrary functions.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: create_remote_thread
    product: windows
    # Relies on Sysmon Event ID 8
detection:
    selection_target:
        TargetImage|endswith:
            - '\explorer.exe'
            - '\svchost.exe'
            - '\lsass.exe'
    selection_start_function:
        StartFunction:
            - 'LoadLibraryA'
            - 'LoadLibraryW'
            - 'LoadLibraryExA'
            - 'LoadLibraryExW'
            - 'LdrLoadDll'
    filter_known:
        SourceImage|endswith:
            - '\MsMpEng.exe'
    condition: selection_target and selection_start_function and not filter_known
fields:
    - SourceImage
    - TargetImage
    - StartFunction
falsepositives:
    - EDR agents injecting introspection DLLs into processes.
    - Some legacy video game anti-cheat engines.
level: critical
tags:
    - attack.privilege-escalation
    - attack.defense-evasion
    - attack.t1055.001
    - analytic.an1095
    - detection.det0389
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.
