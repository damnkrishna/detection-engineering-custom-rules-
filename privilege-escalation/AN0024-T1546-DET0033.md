### 1. Technique Breakdown: T1546

* What it is: Event Triggered Execution: WMI Event Subscription. Windows Management Instrumentation (WMI) can be used to register event filters, event consumers, and filter-to-consumer bindings. When a specific system event triggers the filter (e.g., system startup, time elapsed, or user logon), the WMI service executes the consumer (e.g., CommandLineEventConsumer or ActiveScriptEventConsumer) with local system (SYSTEM) privileges. Adversaries exploit WMI event subscriptions to establish persistent, elevated execution flows.
* Log Source Requirements: Endpoint logs capturing process creation and command line arguments, and WMI event subscription logs.
* Coverage Check:
  - HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 logs CLI invocations of wmic.exe or PowerShell cmdlets modifying WMI objects. Sysmon Event IDs 19, 20, and 21 log raw WMI consumer/filter additions.
  - NIDS (Suricata + Zeek): NO. WMI event subscription registration is a local OS management task.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event IDs 19/20/21 (wmi_event)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

The detection logic is split into process creation monitoring of CLI tools, and WMI event logs capturing consumers, filters, and bindings registration.

Rule 1 of 2: WMI Event Subscription Creation via CLI (Process Creation)
```yaml
title: WMI Event Subscription Creation via CLI (AN0024)
id: 71b5eb0d-5a08-48a4-b83c-8556c2b828a4
status: experimental
description: Detects command-line execution of wmic.exe or PowerShell cmdlets configuring WMI event consumers, filters, or bindings, which can be abused for privilege escalation and persistence.
author: Krishna Gupta
date: 2026-06-07
logsource:
    category: process_creation
    product: windows
detection:
    selection_wmic:
        - Image|endswith: '\wmic.exe'
        - OriginalFileName: 'wmic.exe'
    selection_wmic_args:
        CommandLine|contains:
            - 'ActiveScriptEventConsumer'
            - 'CommandLineEventConsumer'
            - 'EventConsumer'
            - 'EventFilter'
            - 'FilterToConsumerBinding'
    selection_powershell:
        - Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
        - OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.dll'
    selection_powershell_args:
        CommandLine|contains:
            - 'Wmi'
            - 'Cim'
        CommandLine|contains:
            - 'Consumer'
            - 'Filter'
            - 'Binding'
    condition: (selection_wmic and selection_wmic_args) or (selection_powershell and selection_powershell_args)
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate enterprise systems management software creating WMI event subscriptions during installation.
level: high
tags:
    - attack.persistence
    - attack.privilege-escalation
    - attack.t1546
    - analytic.an0024
    - detection.det0033
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Command Line Obfuscation
  - The Issue: Adversaries can obfuscate command-line arguments using environment variables, caret escapes, or base64 encoding.
  - The Fix: Implement PowerShell Script Block Logging.

* Problem 2: Administrative Activity Noise
  - The Issue: IT administrators legitimately run command-line tools that trigger WMI persistence rules during system maintenance.
  - The Fix: Establish a baseline of legitimate admin tools and whitelist specific accounts.

* Problem 3: Masquerading via Renamed Binaries
  - The Issue: Attackers rename native Windows utilities to bypass path-based filters.
  - The Fix: Match on OriginalFileName in process creation logs.
