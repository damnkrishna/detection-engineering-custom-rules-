### 1. Technique Breakdown: T1055.005

* What it is: Process Injection: Thread Local Storage. Adversaries may inject malicious code by manipulating the Thread Local Storage (TLS) callbacks of a Portable Executable (PE). Before the main entry point (`main()` or `DllMain()`) of a Windows executable is reached, the OS executes TLS callbacks to initialize thread-specific data. Attackers can hijack these callbacks in a suspended process (often combined with Process Hollowing) to execute their payload prior to the primary application logic, effectively evading security products that hook the main entry point.
* Log Source Requirements: Advanced EDR telemetry (API hooking, memory scanning), Sysmon Event ID 10 (ProcessAccess).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES (Partial). Sysmon logs `ProcessAccess` (Event ID 10) to the target process. It does not native log PE header modifications or TLS callback executions.
    * NIDS (Suricata + Zeek): NO. Local memory execution.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 10 (ProcessAccess) to detect suspicious access requests targeting common injection candidate processes, serving as an early indicator of memory manipulation required to rewrite TLS structures.

```yaml
title: Suspicious Process Access indicating TLS Callback Injection (AN1289)
id: fbbcc3f9-676b-4e6c-a8eb-8b0ab3606f1d
status: experimental
description: Detects process access indicative of memory modifications to PE headers and TLS directory structures for injection.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: process_access
    product: windows
    # Relies on Sysmon Event ID 10
detection:
    selection_target:
        TargetImage|endswith:
            - '\svchost.exe'
            - '\explorer.exe'
            - '\dllhost.exe'
            - '\notepad.exe'
    selection_access:
        GrantedAccess|contains:
            - '0x1F0FFF' # All Access
            - '0x143A'   # VM Write
    filter_known:
        SourceImage|endswith:
            - '\MsMpEng.exe'
            - '\csrss.exe'
            - '\services.exe'
    condition: selection_target and selection_access and not filter_known
fields:
    - SourceImage
    - TargetImage
    - GrantedAccess
falsepositives:
    - Debugging software attaching to processes to read/write memory.
    - Security products scanning memory.
level: high
tags:
    - attack.privilege-escalation
    - attack.defense-evasion
    - attack.t1055.005
    - analytic.an1289
    - detection.det0467
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.
