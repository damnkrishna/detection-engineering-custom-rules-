### 1. Technique Breakdown: T1055.002

* What it is: Process Injection: Portable Executable Injection. Adversaries allocate memory in a remote process (e.g., `VirtualAllocEx`), write a malicious PE file or shellcode into that space (`WriteProcessMemory`), and execute it by creating a new remote thread (`CreateRemoteThread`). This runs the malware in the context of the target process, evading defenses that monitor the original malware executable.
* Log Source Requirements: Sysmon Event ID 8 (CreateRemoteThread).
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 8 specifically records when a process creates a thread in another process.
    * NIDS (Suricata + Zeek): NO. This is entirely an in-memory local host execution technique.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 8 (CreateRemoteThread) to detect cross-process thread creation targeting critical system binaries.

```yaml
title: Suspicious Remote Thread Creation (PE Injection) (AN0297)
id: f43e2a1b-7890-4c12-b345-6d7e8f9a0b1c
status: experimental
description: Detects PE injection where a process initiates a new thread (CreateRemoteThread) in another live process, executing injected code.
author: Krishna Gupta
date: 2026-06-09
logsource:
    category: create_remote_thread
    product: windows
    # Relies on Sysmon Event ID 8
detection:
    selection_target:
        TargetImage|endswith:
            - '\explorer.exe'
            - '\svchost.exe'
            - '\lsass.exe'
            - '\winlogon.exe'
            - '\spoolsv.exe'
            - '\services.exe'
    filter_known_injectors:
        SourceImage|endswith:
            - '\MsMpEng.exe'
            - '\csrss.exe'
            - '\wbemprox.exe'
    condition: selection_target and not filter_known_injectors
fields:
    - SourceImage
    - TargetImage
    - StartAddress
falsepositives:
    - Antivirus solutions inspecting processes.
    - Legitimate Windows subsystems (csrss) creating threads.
level: high
tags:
    - attack.privilege-escalation
    - attack.defense-evasion
    - attack.t1055.002
    - analytic.an0297
    - detection.det0106
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Administrative Action False Positives
  * The Issue: IT personnel performing legitimate maintenance operations can invoke techniques that mirror adversarial persistence or evasion.
  * The Fix: Audit and baseline corporate administration accounts, whitelisting specific approved service accounts and administrative subnets.

* Problem 2: Command and Execution Obfuscation
  * The Issue: Attackers employ encoding, environment variables, or caret insertions to bypass keyword-based detection filters.
  * The Fix: Enable deep logging (such as Script Block Logging) and apply normalization or regex decoding inside the SIEM parsing pipeline.

* Problem 3: Log Deletion and Modification
  * The Issue: Adversaries can clear security logs or stop monitoring agents (like Wazuh or Sysmon) to blind defensive operations.
  * The Fix: Forward all endpoint logs immediately to a centralized write-once SIEM and alert on service stoppage or log clearing events.
