### 1. Technique Breakdown: T1568.002 & T1003.001

* **Description**: Detects a high volume of domain generation algorithm (DGA) DNS requests resulting in NXDOMAIN errors (Zeek), followed by a process handle request targeting the Local Security Authority Subsystem Service (Sysmon Event ID 10 to `lsass.exe` with `0x1010` permissions) on the host within 30 minutes, excluding standard AV/EDR calling processes.
* **Author**: Krishna Gupta
* **Log Source Requirements**:
  * Zeek connection/DNS logs tracking rapid bursts of NXDOMAIN responses with target direction anchoring.
  * Sysmon Process Access (Event ID 10) auditing target image `lsass.exe` with granted access `0x1010`, excluding known security agents.
* **Coverage Check**:
  * HIDS (Sysmon): YES. Sysmon accurately monitors process access requests to LSASS.
  * NIDS (Zeek): YES. Identifies anomalous DNS resolution fail sequences.

### 3. Blind Spots & Tuning (The "Problems")

* **Problem 1: Internal DNS Configuration Errors**
  * *Issue*: Misconfigured internal service agents trying to resolve decommissioned servers can trigger a continuous stream of NXDOMAIN errors.
  * *Fix*: Tune Stage 0 to require the DNS server address to be external (public resolvers) or target domain names matching entropy metrics of DGA algorithms.
* **Problem 2: Non-Malicious LSASS Handle Requests**
  * *Issue*: Local identity managers or password synchronization utilities regularly scan the LSASS process.
  * *Fix*: Ignore LSASS handle events coming from signed administrative processes or official security modules.
