### 1. Technique Breakdown: T1590
* What it is: Gather Victim Network Information. Adversaries gather details about the target organization's networks, such as IP ranges, subnets, routing paths, DNS servers, and external-facing systems. This information is collected from public registrars, WHOIS data, and search engines like Shodan or Censys.
* Log Source Requirements: Log sources capturing boundary connections or external DNS queries.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): NO. Pre-compromise external lookups leave no trace on endpoints.
  - NIDS (Suricata + Zeek): NO. Querying public search engines does not generate telemetry.
* Log Sources Covered:
  - None.
* Log Sources Missing / Unused:
  - None.
* Conclusion: This technique is not detectable from Sysmon, Windows Security, or Defender logs.

---

### 2. Custom Sigma Rule

This technique is passive OSINT. Attackers retrieve network ranges from third-party registrars, generating no corporate firewall or network logs. Detection is not possible via local logs.

---

### 3. Blind Spots & Tuning (The "Problems")
* Problem 1: Querying Public Search Engines
  * The Issue: Red Teams query Shodan/Censys to retrieve open ports instead of scanning the IP block directly.
  * The Fix: Subscribe to external scanner monitoring feeds and regularly check Shodan for company assets.
* Problem 2: Public DNS Querying
  * The Issue: Attackers resolve subdomains via public DNS resolvers.
  * The Fix: Implement passive DNS mapping tools to monitor lookups on your authoritative domains.
* Problem 3: WHOIS Registries Access
  * The Issue: WHOIS data is publicly available.
  * The Fix: Utilize WHOIS privacy options to hide administrative network details.
