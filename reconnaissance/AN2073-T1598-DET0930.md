### 1. Technique Breakdown: T1598
* What it is: Phishing for Information. Adversaries send phishing communications (typically emails) to target individuals to solicit sensitive organizational, credential, or system data. The email often links to a credential harvesting form or asks technical details from helpdesks.
* Log Source Requirements: Email server logs and gateway audits.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): NO. Handled by email server filters.
  - NIDS (Suricata + Zeek): NO. Focus is on email gateway and SMTP telemetry.
* Log Sources Covered:
  - Email Server Logs & SMTP Gateway Audits (product: msexchange, category: email)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

Detects inbound external emails asking for system configurations, org charts, or network infrastructure details.

```yaml
title: Phishing for Information (AN2073)
id: d1d2e3f4-f5a6-4b7d-9e9f-0a1b2c3d4e5f
status: experimental
description: Detects inbound phishing emails soliciting sensitive organizational information or credential verifications. Note - Subject-line obfuscation (zero-width spaces, homoglyphs, multi-lingual text) should be resolved by performing Unicode Normalization (NFKC) on incoming email subjects at the log ingestion pipeline level prior to parsing.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: email
    product: msexchange
detection:
    selection_phish:
        subject|contains:
            - 'vpn config'
            - 'antivirus config'
            - 'firewall rules'
            - 'employee directory'
            - 'org chart'
            - 'infrastructure details'
            - 'network topology'
            - 'it system query'
    selection_sender:
        sender_type: 'external'
    filter_legitimate:
        sender|endswith:
            - '@authorized-vendor.com'
            - '@internal-domain.com'
    condition: selection_phish and selection_sender and not filter_legitimate
fields:
    - sender
    - recipient
    - subject
    - mail_headers
falsepositives:
    - Legitimate IT notifications or surveys from authorized external vendors.
level: high
tags:
    - attack.reconnaissance
    - attack.t1598
    - analytic.an2073
    - detection.det0930
```

### 2.1 Companion Sigma Rule: Compromised Internal Sender Phishing (T1598)

This companion rule detects information-solicitation phishing emails originating from internal user accounts (indicating compromise) that target multiple internal recipients within a short timeframe.

```yaml
title: Phishing for Information from Compromised Internal Account (AN2073-Phishing-Internal)
id: d1d2e3f4-f5a6-4b7d-9e9f-0a1b2c3d4e6a
status: experimental
description: Detects internal emails querying for sensitive configurations or employee details, which may indicate a compromised mailbox. Note - Ingestion pipeline should normalize Unicode representations (NFKC) on incoming subjects to prevent evasion via multi-lingual or homoglyphic characters.
logsource:
    category: email
    product: msexchange
detection:
    selection_phish:
        subject|contains:
            - 'vpn config'
            - 'antivirus config'
            - 'firewall rules'
            - 'employee directory'
            - 'org chart'
            - 'infrastructure details'
            - 'network topology'
            - 'it system query'
    selection_internal:
        sender_type: 'internal'
    filter_training:
        subject|contains:
            - '[PHISHING TEST]'
            - 'Awareness Training'
        sender|endswith:
            - '@phishing-training-platform.com'
    condition: selection_phish and selection_internal and not filter_training
fields:
    - sender
    - recipient
    - subject
falsepositives:
    - Internal security awareness training tests.
level: high
tags:
    - attack.reconnaissance
    - attack.t1598
```

```yaml
correlation:
    type: value_count
    rules:
        - d1d2e3f4-f5a6-4b7d-9e9f-0a1b2c3d4e6a
    group-by: sender
    field: recipient
    timespan: 10m
    condition:
        gte: 4
```

### 2.2 Multi-Stage Correlation Rule: Phishing Attempt Followed by Host Compromise / Anomalous Outbound Connection

This correlation rule tracks when an employee receives an information-solicitation phishing email (AN2073) and subsequently establishes a suspicious outbound connection or executes WMI/system enumeration commands on their local endpoint within 2 hours. Note: The endpoint owner identity field in Rule AN2067 (5a8a1b24-9b2f-4c8d-8d4e-b5c6d7e8f9a0) has been verified to be 'User', which aligns with the recipient field in active directory scans.

```yaml
title: Phishing for Information Followed by Endpoint Enumeration (AN2073-Correlation)
id: d1d2e3f4-f5a6-4b7d-9e9f-0a1b2c3d4e7f
status: experimental
description: Correlates a T1598 phishing email target recipient with subsequent host configuration queries (AN2067) on the user's assigned system.
correlation:
    type: temporal
    rules:
        - rule_1: d1d2e3f4-f5a6-4b7d-9e9f-0a1b2c3d4e5f
        - rule_2: 5a8a1b24-9b2f-4c8d-8d4e-b5c6d7e8f9a0
    group-by:
        - user_alias
    aliases:
        user_alias:
            d1d2e3f4-f5a6-4b7d-9e9f-0a1b2c3d4e5f: recipient
            5a8a1b24-9b2f-4c8d-8d4e-b5c6d7e8f9a0: User
    timespan: 2h
    condition: rule_1 then rule_2
level: critical
tags:
    - attack.reconnaissance
    - attack.t1598
    - attack.t1592
```

### 3. Blind Spots & Tuning (The "Problems")
* Problem 1: Obfuscation of Subject Lines
  * The Issue: Attackers use homoglyphs or multi-lingual texts to bypass string checks.
  * The Fix: Deploy Natural Language Processing (NLP) classifiers on email gateways to detect urgency.
* Problem 2: Compromised Sender Accounts
  * The Issue: Phishing sent from compromised internal partners (sender_type is not external).
  * The Fix: Focus on anomalous subject lines and login profiles using behavior baselines.
* Problem 3: Spoofed Domains
  * The Issue: Attackers spoof company domains.
  * The Fix: Enforce DMARC, DKIM, and SPF validation policies at the gateway level.
