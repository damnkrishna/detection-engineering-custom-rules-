### 1. Technique Breakdown: T1597
* What it is: Search Closed Sources. Adversaries search closed or restricted sources (such as private code repositories, dark web forums, undergound markets, or commercial threat intelligence channels) to identify leaks, configurations, or credentials related to the target org.
* Log Source Requirements: External intelligence alerts.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): NO. Attacker searches external sources.
  - NIDS (Suricata + Zeek): NO. Off-network.
* Log Sources Covered:
  - None.
* Log Sources Missing / Unused:
  - None.
* Conclusion: This technique is not detectable from Sysmon, Windows Security, or Defender logs.

---

### 2. Custom Sigma Rule

This technique is passive OSINT. Attacker queries private leak databases. Detection is not possible via local logs.

---

### 3. Blind Spots & Tuning (The "Problems")
* Problem 1: Code Leakage on Public GitHub
  * The Issue: Developers mistakenly commit secrets to public repositories.
  * The Fix: Deploy secrets-scanning tools (GitGuardian, GitHub Advanced Security) to block leaks during commit.
* Problem 2: Leaked Credentials on Forums
  * The Issue: Employee credentials from personal leaks are traded on forums.
  * The Fix: Implement automated dark web intelligence alerts.
* Problem 3: Private Forum Anonymity
  * The Issue: Closed forums require hacker invites.
  * The Fix: Use external cyber threat intelligence (CTI) vendors who maintain persona access.
