### 1. Technique Breakdown: T1682
* What it is: Query Public AI Services. Adversaries or employees query public generative AI systems (like ChatGPT, Claude, Gemini) and input proprietary code, configurations, or credentials, leading to unintended information leakage.
* Log Source Requirements: Proxy logs tracking generative AI service endpoints.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): NO. Monitored at network level.
  - NIDS (Suricata + Zeek): YES. Network connections to GenAI domains.
* Log Sources Covered:
  - Web Proxy & Firewall logs (product: proxy, service: web_server)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

Detects outbound traffic to public generative AI endpoints indicating potential corporate data uploads.

```yaml
title: Outbound Data Upload to Public GenAI Services (AN2075)
id: a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d
status: experimental
description: Detects outbound POST requests with payloads exceeding 10KB to known public generative AI platforms indicating potential data uploads.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: web_proxy
    product: proxy
detection:
    selection_ai_domains:
        destination_domain|contains:
            - 'openai.com'
            - 'chatgpt.com'
            - 'claude.ai'
            - 'gemini.google.com'
            - 'cohere.com'
            - 'poe.com'
    selection_method:
        http_method: 'POST'
    selection_bytes:
        bytes_sent|gte: 10000  # Tuning candidate: adjust threshold pending real network traffic baseline (default 10KB)
    filter_legitimate:
        src_ip|cidr:
            - '10.100.200.0/24'  # Approved internal ML subnet
        user:
            - 'svc-internal-copilot'  # Approved automation accounts
    condition: selection_ai_domains and selection_method and selection_bytes and not filter_legitimate
fields:
    - src_ip
    - destination_domain
    - user
    - bytes_sent
    - http_method
falsepositives:
    - Legitimate large data uploads or queries from authorized internal developers.
level: medium
tags:
    - attack.reconnaissance
    - attack.t1682
    - analytic.an2075
    - detection.det0932
```

### 2.1 Companion Sigma Rules (For Blind Spots)

#### Companion Rule 1: Suspicious Connection to Unlisted/Generic GenAI Services
This rule detects connections to generic or unlisted AI endpoints matching keyword strings (such as `chat`, `ai-`, `-gpt`) using lower severity triggers, closing the gap for newly deployed AI tools.

```yaml
title: Connection to Unlisted Public GenAI Services (AN2075-Unlisted-GenAI)
id: a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c7d
status: experimental
description: Detects outbound POST requests to unlisted/generic domains containing AI-specific keyword strings.
logsource:
    category: web_proxy
    product: proxy
detection:
    selection_ai_keywords:
        destination_domain|contains:
            - 'chat'
            - 'ai-'
            - '-gpt'
    selection_method:
        http_method: 'POST'
    filter_known_ai:
        destination_domain|contains:
            - 'openai.com'
            - 'chatgpt.com'
            - 'claude.ai'
            - 'gemini.google.com'
            - 'cohere.com'
            - 'poe.com'
    condition: selection_ai_keywords and selection_method and not filter_known_ai
fields:
    - src_ip
    - destination_domain
    - user
    - http_method
falsepositives:
    - Legitimate internal portals or external vendors with "ai" or "chat" in their domain names.
level: low
tags:
    - attack.reconnaissance
    - attack.t1682
```

#### Companion Rule 2: Decrypted SSL Data Leakage Detection
This experimental companion rule scans decrypted SSL outbound proxy request payloads to detect active exfiltration of secret keys, database credentials, or passwords into public AI endpoints.

```yaml
title: Outbound Secret Leakage to GenAI Services via Decrypted SSL (AN2075-Decrypted-Leaking)
id: a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c7e
status: experimental
description: Scan decrypted outbound proxy payloads for sensitive credentials or keys being sent to public generative AI endpoints.
logsource:
    category: web_proxy
    product: proxy
detection:
    selection_ai_domains:
        destination_domain|contains:
            - 'openai.com'
            - 'chatgpt.com'
            - 'claude.ai'
            - 'gemini.google.com'
            - 'cohere.com'
            - 'poe.com'
    selection_decrypted_payload:
        request_body|re: # Tuning candidate: refine regular expressions to minimize false positives from source code libraries or system paths
            - '(?i)BEGIN (RSA|EC|PRIVATE) KEY'
            - '(?i)password\s*=\s*.*'
            - '(?i)api_key\s*=\s*.*'
            - '(?i)client_secret\s*=\s*.*'
    condition: selection_ai_domains and selection_decrypted_payload
fields:
    - src_ip
    - destination_domain
    - user
    - request_body
falsepositives:
    - Code debugging or development research by authorized engineering groups.
level: high
tags:
    - attack.reconnaissance
    - attack.t1682
```

### 2.2 Multi-Stage Correlation Rule: Sensitive File Read Followed by GenAI Upload (T1682-Correlation)

This correlation rule tracks when an endpoint reads sensitive proprietary file extensions (e.g. source code `.py`, `.java`, config `.env`, `.yml`, keys `.pem`) and subsequently executes an outbound GenAI data submission (`AN2075`) from the same source user/host within 1 hour.

```yaml
title: Sensitive File Staging Followed by GenAI Upload (AN2075-Correlation)
id: a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c7f
status: experimental
description: Correlates host file access monitoring for sensitive source files with outbound GenAI web traffic submissions.
correlation:
    type: temporal
    rules:
        - rule_1: 8f9b2d3c-4e5f-6a7b-8c9d-0e1f2a3b4c5d  # Host Sensitive File Access Event
        - rule_2: a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d  # Outbound GenAI POST data upload
    group-by:
        - user_alias
    aliases:
        user_alias:
            8f9b2d3c-4e5f-6a7b-8c9d-0e1f2a3b4c5d: User
            a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d: user
    timespan: 1h
    condition: rule_1 then rule_2
level: critical
tags:
    - attack.exfiltration
    - attack.t1682
```

### 3. Blind Spots & Tuning (The "Problems")
* Problem 1: Unlisted AI Services
  * The Issue: Users access new or proxy AI platforms.
  * The Fix: Categorize web proxy databases dynamically for AI/ML domains.
* Problem 2: Legitimate APIs
  * The Issue: Authorized corporate apps connect to OpenAI APIs.
  * The Fix: Allowlist approved application hostnames and developer accounts.
* Problem 3: Encrypted API Calls
  * The Issue: TLS encryption prevents inspection of the request content.
  * The Fix: Implement SSL decryption on outbound proxy devices to audit request payloads for sensitive keywords.
