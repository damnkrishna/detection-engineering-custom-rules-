### 2. Custom Sigma Rule

Detects basic connection sweeps and port scans against external assets originating from single or multiple IP sources, handling distributed and low-and-slow scanning profiles while whitelisting common public search engines. This base rule is meant to be used with SIEM-side correlation.

```yaml
title: External Port Scanning Detection (AN2070)
id: 3c6d7a5b-9f2e-4b1a-8c3d-0e1f2a3b4c5d
status: experimental
description: Detects connection sweeps and port scans against external assets originating from single or multiple IP sources, handling distributed and low-and-slow scanning profiles while whitelisting common public search engines.
author: Krishna Gupta
date: 2026-06-30
logsource:
    product: zeek
    service: conn
detection:
    selection:
        proto:
            - 'tcp'
            - 'udp'
    
    filter_legitimate_cidr:
        src_ip|cidr:
            - '1.2.3.0/24'      # Censys
            - '4.5.6.0/24'      # Shodan

    filter_internal:
        orig_h|cidr: '10.0.0.0/8'  # Internal scans OK
        
    condition: selection and not filter_legitimate_cidr and not filter_internal
fields:
    - orig_h
    - resp_h
    - resp_p
    - proto
falsepositives:
    - Authorized internal diagnostic vulnerability scanners.
level: low
tags:
    - attack.reconnaissance
    - attack.t1595
    - analytic.an2070
    - detection.det0927
```

### 2.2 Multi-Stage Correlation Rule: Port Scanning Followed by Connection Attempt / Exploitation

This correlation rule tracks when an external IP address performs port scanning (AN2070) and subsequently establishes a successful socket connection to one of the scanned ports, followed by command execution on the target host within 15 minutes.

```yaml
title: Port Scan Followed by Active Connection and Command Execution (AN2070-Correlation)
id: 5d4c3b2a-1f0e-4d9c-8b7a-6f5e4d3c2b1a
status: experimental
description: Correlates initial active scanning with a successful connection handshake and subsequent process execution anomalies on the same target host. Note: SIEM-side aggregation is required for this rule.
detection:
    selection_scan:
        proto: 'tcp'
    selection_shell:
        Image|endswith: '\cmd.exe'
    condition: selection_scan or selection_shell
level: critical
tags:
    - attack.reconnaissance
    - attack.t1595
    - attack.execution
```

### 3. Blind Spots & Tuning (The "Problems")
* Problem 1: Distributing Scanning
  * The Issue: Red Teams use proxy chains or botnets to scan using multiple IPs.
  * The Fix: Group alerts based on target subnets rather than only single source IPs.
* Problem 2: Slow Scanning
  * The Issue: Scanners check one port per hour (Low and Slow).
  * The Fix: Extend correlation windows to 24 hours.
* Problem 3: Common Cloud Probes
  * The Issue: Internet scanners continuously scan the IP ranges causing high alert volume.
  * The Fix: Ignore scanning from known threat feeds (e.g. Censys, Shodan, Shadowserver) if they are not targeting sensitive systems.
