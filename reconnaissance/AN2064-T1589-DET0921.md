### 1. Technique Breakdown: T1589
* What it is: Gather Victim Identity Information. Adversaries gather information about the identities of people within a target organization, including employee names, email addresses, usernames, and roles. This information is typically gathered via OSINT databases, social media platforms (like LinkedIn), or public email indexes to build target lists for phishing campaigns and credential stuffing attacks.
* Log Source Requirements: Log sources capturing outbound corporate connections or internal directory accesses.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): NO. This action is performed externally on third-party databases.
  - NIDS (Suricata + Zeek): NO. No network telemetry touches internal enterprise interfaces.
* Log Sources Covered:
  - None.
* Log Sources Missing / Unused:
  - None.
* Conclusion: This technique is not detectable from Sysmon, Windows Security, or Defender logs.

---

### 2. Custom Sigma Rule

This technique is passive OSINT. Telemetry querying corporate systems is absent because the attacker searches public platforms. Detection is not possible via local endpoint or network logs.

---

### 3. Blind Spots & Tuning (The "Problems")
* Problem 1: OSINT Footprint Absence
  * The Issue: Attackers query public social networks or data brokers without generating logs on corporate networks.
  * The Fix: Integrate external brand protection or threat intelligence platforms that monitor for company name queries or identity leaks.
* Problem 2: Darknet Credential Lists
  * The Issue: Leak databases are queried externally, exposing identity records.
  * The Fix: Use external credential intelligence feeds to proactively monitor and flag leaked employee accounts.
* Problem 3: Target Profile Building
  * The Issue: Attackers build detailed charts from public data.
  * The Fix: Minimize public directory listings of personnel and roles.
