### 1. Technique Breakdown: T1592
* What it is: Gather Victim Host Information. Adversaries query endpoints to discover host details, including operating system versions, patch levels, software versions, system configurations, and host names. Once a foothold is achieved, the Red Team executes system discovery commands to identify the host properties.
* Log Source Requirements: Endpoint process logs capturing command-line arguments.
* Coverage Check:
  - HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 logs process creation and CLI arguments.
  - NIDS (Suricata + Zeek): NO. Host-local commands.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.

### 2. Custom Sigma Rule

Detects the execution of host information gathering commands (like systeminfo, dxdiag, gpresult) within suspicious contexts.

```yaml
title: Suspicious System Information Gathering (AN2067)
id: 5a8a1b24-9b2f-4c8d-8d4e-b5c6d7e8f9a0
status: experimental
description: Detects the execution of utilities like systeminfo, dxdiag, and gpresult to discover system specifications, filtering out benign local interactive admin executions unless suspicious remote query parameters are used.
author: Krishna Gupta
date: 2026-06-30
logsource:
    category: process_creation
    product: windows
detection:
    selection_utilities:
        Image|endswith:
            - '\systeminfo.exe'
            - '\dxdiag.exe'
            - '\gpresult.exe'
        OriginalFileName:
            - 'systeminfo.exe'
            - 'dxdiag.exe'
            - 'gpres.exe'
    selection_suspicious_cli:
        CommandLine|contains:
            - '/S'  # Remote system query — suspicious
            - '/U'  # Remote credentials — suspicious
    filter_admin:
        ParentImage|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\explorer.exe'
            - '\mmc.exe'
    filter_approved_scripts:
        ParentCommandLine|contains:
            - 'C:\Program Files\Diagnostic Tools\'
            - 'C:\Windows\System32\drivers\etc\'
    condition: ((selection_utilities and selection_suspicious_cli) or (selection_utilities and not filter_admin)) and not filter_approved_scripts
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - User
falsepositives:
    - Administrative diagnostics or inventory software updates.
    - Approved diagnostic scripts running from whitelisted paths (e.g. C:\Program Files\Diagnostic Tools\).
level: medium
tags:
    - attack.reconnaissance
    - attack.t1592
    - analytic.an2067
    - detection.det0924
```

### 2.1 Companion Sigma Rules (For Blind Spots)

These companion rules address the blind spots where host information gathering is conducted via PowerShell, Registry command queries, or direct WMI commands.

#### Companion Rule 1: PowerShell WMI/CIM System Discovery (Event ID 4104)
```yaml
title: PowerShell System Information Gathering via WMI/CIM (AN2067-PowerShell)
id: dcb5c6d7-e8f9-4a0b-b1c2-d3e4f5a6b7c8
status: experimental
description: Detects PowerShell script block logs executing WMI or CIM queries targeting system specifications classes.
author: Krishna Gupta
date: 2026-06-30
logsource:
    product: windows
    service: powershell
detection:
    selection_cmdlet:
        ScriptBlockText|contains:
            - 'Get-WmiObject'
            - 'Get-CimInstance'
            - 'gwmi'
            - 'gcim'
    selection_classes:
        ScriptBlockText|contains:
            - 'Win32_OperatingSystem'
            - 'Win32_ComputerSystem'
            - 'Win32_BIOS'
            - 'Win32_Processor'
    condition: selection_cmdlet and selection_classes | count() by Computer > 3 in 5m
falsepositives:
    - Legitimate administrative system auditing or inventory scripts.
level: medium
tags:
    - attack.reconnaissance
    - attack.t1592
```

#### Companion Rule 2: Registry Query via Command Line (Sysmon ID 1)
```yaml

status: experimental
description: Detects command-line execution of reg.exe querying key system information registry paths.
author: Krishna Gupta

    product: windows

    selection_reg:
        Image|endswith: '\reg.exe'

falsepositives:
    - Legitimate diagnostic scripts.
level: low
tags:
    - attack.reconnaissance
    - attack.t1592
```

### 2.2 Multi-Stage Correlation Rule: Host Discovery Sequencing

This correlation rule addresses the sequence behavior where an adversary executes multiple distinct host information gathering tools in a short timeframe to build a complete profile of the target system.

```yaml
title: Sequential Host Discovery Utilities Execution (AN2067-Correlation)
id: c3d4e5f6-7a8b-9c0d-1e2f-3a4b5c6d7e8f
status: experimental
description: Detects when multiple distinct host discovery utilities (systeminfo, dxdiag, gpresult) are executed on the same host within a short window (5 minutes), indicating sequential post-compromise system profiling.
correlation:
    type: temporal
    rules:
        - rule_1: Suspicious System Information Gathering (AN2067)
    group-by:
        - Computer
        - User
    timespan: 5m
    condition: rule_1|count(Image) >= 2 and distinct(Image) >= 2
level: high
tags:
    - attack.reconnaissance
    - attack.t1592
```

### 2.3 Post-Discovery Execution Rule: Host Discovery Followed by Lateral Movement / Persistence Setup

This correlation rule detects the critical transition from reconnaissance to active threat actions. It triggers when a host discovery sequence (AN2067-Correlation) is followed by lateral movement (using tools like `net.exe` or `psexec.exe`) or persistence setup (account creation, Event ID 4720) on the same asset within 10 minutes.

```yaml
title: Host Discovery Followed by Lateral Movement Setup (AN2067-PostDiscovery)
id: e5f6a7b8-9c0d-1a2b-3c4d-5e6f7a8b9c0d
status: experimental
description: Detects when host discovery correlation is followed by lateral movement (psexec.exe, net.exe remote connections) or persistence (service account creation) within 10 minutes on the same system.
correlation:
    type: temporal
    rules:
        - rule_1: Sequential Host Discovery Utilities Execution (AN2067-Correlation)
        - rule_2: Windows Local/Service Account Creation (EventID 4720) or Suspicious Execution (net.exe, psexec.exe)
    group-by:
        - Computer
    timespan: 10m
    condition: rule_1 then rule_2
level: critical
tags:
    - attack.reconnaissance
    - attack.lateral_movement
    - attack.persistence
```

### 3. Blind Spots & Tuning (The "Problems")
* Problem 1: Obfuscation in PowerShell Script Blocks
  * The Issue: Attacker uses WMI queries inside PowerShell to gather host properties without spawning systeminfo.
  * The Fix: Implement PowerShell Script Block Logging (Event ID 4104) to audit Win32_OperatingSystem queries.
* Problem 2: Diagnostic Tool Noise
  * The Issue: IT support tools run gpresult or dxdiag for troubleshooting.
  * The Fix: Baseline authorized administrative tool paths or parent processes.
* Problem 3: Registry Queries
  * The Issue: Attacker queries Registry keys under CurrentVersion directly.
  * The Fix: Monitor access anomalies targeting the registry using Sysmon Event ID 13.
