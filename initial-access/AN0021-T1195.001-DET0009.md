### 1. Technique Breakdown: T1195.001

* What it is: Supply Chain Compromise: Compromise Software Dependencies and Development Tools. Adversaries target software dependencies or packages (e.g., npm, pip, PyPI, NuGet, Maven) to inject malicious payloads. During the installation phase (e.g., post-install scripts or initial package builds), these package managers execute local commands that spawn unexpected shell interpreters, scripting tools, or network utilities to download secondary implants or exfiltrate environment variables.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) capturing parent-child process relationships, and PowerShell script block logs (Sysmon Event ID 4104).
* Coverage Check:
  * HIDS (Sysmon + Windows Defender): YES. Sysmon Event ID 1 captures parent process command lines and paths (e.g., npm or pip executing under node/python) spawning shells or download utilities like curl.exe or certutil.exe. Sysmon Event ID 4104 (Script Block) is effective at catching PowerShell scripts initiating package build scripts.
  * Windows Security Logs: YES. Standard Security Logs track process execution (Event ID 4688) containing the command line arguments.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Supply chain tampering via development tools can be detected using process creation and PowerShell script block logs.

### 2. Custom Sigma Rule

The detection logic is split into command-line process relationship monitoring and script block content monitoring.

Rule 1 of 2: Supply Chain Tampering - Suspicious Process Spawned by Development Tool via CLI (Process Creation)
```yaml
title: Supply Chain Tampering - Suspicious Process Spawned by Development Tool via CLI (AN0021-A)
id: 50f3bf00-e552-4dab-a402-9b891308bc44
status: experimental
description: Detects package managers or development builds (like npm, pip, nuget, maven, gradle, python, node) spawning suspicious command interpreters, script engines, or network download utilities.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
detection:
    selection_parent:
        ParentImage|endswith:
            - '\node.exe'
            - '\npm.cmd'
            - '\pip.exe'
            - '\python.exe'
            - '\python3.exe'
            - '\nuget.exe'
            - '\mvn.cmd'
            - '\gradle.bat'
            - '\msbuild.exe'
    selection_child:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\curl.exe'
            - '\certutil.exe'
            - '\bitsadmin.exe'
        - OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'mshta.exe'
            - 'curl.exe'
            - 'certutil.exe'
            - 'bitsadmin.exe'
    condition: selection_parent and selection_child
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate post-install build scripts run by developers (e.g., compiling native C++ bindings for Node modules).
level: medium
tags:
    - attack.initial-access
    - attack.t1195.001
    - analytic.an0021
    - detection.det0009
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Developer Custom Scripts (Post-install Noise)
  * The Issue: Many NPM packages or Python packages legitimately use install hooks to run configure scripts or compile platform-dependent source code.
  * The Fix: Baseline the environment to whitelist known developer build servers or specific directories, or filter commands containing node-gyp.

* Problem 2: Execution in Hidden Python Venvs
  * The Issue: If python is running from a local virtual environment (venv\Scripts\python.exe), the parent image might not be standard system-installed python.exe, bypassing path checks.
  * The Fix: Match parent process images ending with \python.exe and \python3.exe using wildcard paths.

* Problem 3: Direct Download in Build Runner Memory
  * The Issue: If the tampered library downloads malicious modules directly in-memory using an HTTP request within the node/python runtime itself, no child process is created.
  * The Fix: Enable system network connection logging for developer tools and alert on connections to unknown domains.
