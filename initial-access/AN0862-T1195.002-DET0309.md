### 1. Technique Breakdown: T1195.002

* What it is: Supply Chain Compromise: Compromise Software Supply Chain. Adversaries compromise legitimate software installers or update mechanisms (e.g., utility software updates, driver installers) to deliver malware. When the compromised installer runs, it executes post-installation scripts or helper binaries that spawn command shells or scripting tools to download and install implants, often executing out of temporary directories.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) capturing installer executable activity spawning interpreter shells.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 tracks system installers (such as `msiexec.exe`) or update processes (e.g., `update.exe`, `setup.exe`) spawning child commands. Wazuh parses and forwards events.
    * NIDS (Suricata + Zeek): PARTIAL. Network tools can flag update downloads originating from compromised hosts or non-SSL HTTP channels, but cannot see what processes the updater launches on the system.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect software installation tools or updater binaries (e.g. `msiexec.exe`, `setup.exe`, `update.exe`) spawning command shell interpreters or network connection utilities.

```yaml
title: Software Supply Chain - Installer Spawning Suspicious Child Process (AN0862)
id: 7ec5a329-4f56-419b-9462-c473d17a812a
status: experimental
description: Detects software installer or updater processes (like msiexec, setup, install, update) spawning command-line interpreters or networking tools, which could indicate a compromised software supply chain.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_parent:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
            - '\install.exe'
            - '\update.exe'
            - '\updater.exe'
    selection_child:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\curl.exe'
            - '\certutil.exe'
            - '\bitsadmin.exe'
        - OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'mshta.exe'
            - 'curl.exe'
            - 'certutil.exe'
            - 'bitsadmin.exe'
    condition: selection_parent and selection_child
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate software installers running configuration shell commands, register DLL actions, or post-install cleanup batch files.
level: medium
tags:
    - attack.initial-access
    - attack.t1195.002
    - analytic.an0862
    - detection.det0309
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Complex Legitimate Application Installers (Noise)
  * The Issue: Large software suites (e.g. Adobe, Microsoft Office, SQL Server) run highly complex multi-stage install scripts that spawn cmd prompts to configure services, create directories, and add registry values.
  * The Fix: Implement specific exclusions for known, signed installer binaries of trusted enterprise packages, or build path exclusions for official installation directories.

* Problem 2: Execution in user Temp folder context
  * The Issue: Updaters often unpack themselves to `C:\Users\<user>\AppData\Local\Temp\` and run auxiliary setup files. If these sub-installers are unsigned or named randomly, simple binary name checks won't work.
  * The Fix: Add a core check that flags any unsigned process executing from Temp paths that attempts network connections or modifies boot settings.

* Problem 3: Direct API Execution without Shell Spawning
  * The Issue: If the compromised installer downloads malware using direct Winsock or WinINet APIs inside the installer process itself, no child process will be created, making parent-child rules ineffective.
  * The Fix: Correlate installer network activity (Sysmon Event ID 3) targeting non-vendor domains with driver configuration writes (Event ID 11).
