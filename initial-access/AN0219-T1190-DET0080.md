### 1. Technique Breakdown: T1190

* What it is: Exploit Public-Facing Application. Adversaries exploit vulnerabilities in internet-facing web servers (such as IIS, Apache Tomcat, Exchange, or Java-based web portals) to run arbitrary code on the host. This post-exploitation activity routinely starts with the web server process spawning shell environments (like cmd or PowerShell) or admin utilities (like `whoami.exe`, `ping.exe`, or `net.exe`) to perform initial reconnaissance or drop web shells.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) tracking parent-child process chains.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 records parent process paths (e.g., `w3wp.exe`, `tomcat.exe`, `java.exe`) spawning child processes. Wazuh parses and raises high-severity alerts.
    * NIDS (Suricata + Zeek): YES. Network monitoring can identify exploitation attempts (e.g. SQLi, directory traversal) in HTTP payloads, but host-based logs are critical to confirm post-exploit execution success.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect internet-facing application processes (e.g., IIS worker process `w3wp.exe`, Java, Tomcat, Apache) spawning command shells or system management tools.

```yaml
title: Exploit Public-Facing Application - Suspicious Child Process of Web Server (AN0219)
id: eec27a76-4b82-4220-bf16-e478d2f9ed36
status: experimental
description: Detects command-line interpreters or administrative utilities spawned by web server processes (e.g., IIS, Tomcat, Apache, Java web services), suggesting successful exploitation or web shell deployment.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_parent:
        ParentImage|endswith:
            - '\w3wp.exe'
            - '\httpd.exe'
            - '\nginx.exe'
            - '\tomcat.exe'
            - '\tomcat7.exe'
            - '\tomcat8.exe'
            - '\tomcat9.exe'
            - '\tomcat10.exe'
            - '\httpd.exe'
            - '\java.exe'
            - '\javaw.exe'
    selection_child:
        - Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\sh.exe'
            - '\bash.exe'
            - '\whoami.exe'
            - '\net.exe'
            - '\nltest.exe'
            - '\systeminfo.exe'
            - '\ipconfig.exe'
            - '\arp.exe'
            - '\curl.exe'
        - OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'whoami.exe'
            - 'net.exe'
            - 'nltest.exe'
            - 'systeminfo.exe'
            - 'ipconfig.exe'
            - 'arp.exe'
            - 'curl.exe'
    condition: selection_parent and selection_child
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate administrative scripts triggered by web application dashboards (e.g., automated server backup scripts triggered from an admin panel).
level: critical
tags:
    - attack.initial-access
    - attack.t1190
    - analytic.an0219
    - detection.det0080
```

        process.file.path|endswith:
            - '\cmd.exe'

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Legitimate PDF/Office Generation tools
  * The Issue: Web applications often generate reports by spawning helper processes (e.g. printing engines or converters) which can trigger general child-process alerts.
  * The Fix: Scope exclusions to allow only specific, fully-parameterized command lines from trusted bin directories (e.g., whitelisting specific report converter binary execution).

* Problem 2: Execution via Java wrapper shells (Double fork)
  * The Issue: If the Java process spawns an intermediate system wrapper service (such as `wrapper.exe`) which in turn launches the malicious commands, the parent process path is no longer `java.exe`.
  * The Fix: Implement multi-tiered parent-child correlation rules checking the grandparent process context, or scan for non-standard executables running under service accounts.

* Problem 3: In-Memory Web Shells (Filter/Listener Injection)
  * The Issue: Modern web shells can run completely in-memory by registering a Servlet Filter or Endpoint Listener inside the Tomcat/Java JVM. They handle incoming requests and run Java code without spawning external command shells.
  * The Fix: Monitor JVM class-loading behaviors for dynamically compiled classes, and alert on unexpected file creation events inside Java servlet directory structures.
