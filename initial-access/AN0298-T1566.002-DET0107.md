### 1. Technique Breakdown: T1566.002

* What it is: Phishing: Spearphishing Link. Adversaries deliver links in phishing emails or chat messages pointing to malicious resources (such as drive-by download sites, credential harvesting landing pages, or directly linking to malicious files hosted on cloud services). When a user clicks the link, the mail client or messaging app spawns the default system web browser with the URL in the command-line arguments.
* Log Source Requirements: Sysmon process creation logs (Event ID 1) capturing parent-child process chains and command-line execution parameters.
* Coverage Check:
    * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures parent process details (e.g., `outlook.exe`, `teams.exe`) spawning browser processes (`chrome.exe`, `msedge.exe`) along with the URL in the command line.
    * NIDS (Suricata + Zeek): YES. Network monitoring records HTTP GET requests to external hosts, but correlating the web traffic with the local application context requires host-based process data.

### 2. Custom Sigma Rule

This rule utilizes Sysmon Event ID 1 (Process Creation) to detect mail clients or collaboration chat applications spawning web browsers where the command-line parameters contain suspicious URL schemes or point to file downloads, IP addresses, or file shares.

```yaml
title: Spearphishing Link - Browser Spawned by Mail/Chat App with Suspicious URL (AN0298)
id: 43f1108d-b079-4a5d-b151-6e2f9c631d6a
status: experimental
description: Detects default web browsers spawned by email clients or collaboration apps (Outlook, Teams, Discord, Slack) containing command-line arguments that reference direct file shares (e.g., file://, UNC paths) or suspicious downloadable file extensions.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: process_creation
    product: windows
    # Relies on Sysmon Event ID 1
detection:
    selection_parent:
        ParentImage|endswith:
 # Mail Clients
            - '\outlook.exe'
            - '\thunderbird.exe'
 # Chat & Collaboration Clients
            - '\teams.exe'
            - '\slack.exe'
            - '\discord.exe'
            - '\Telegram.exe'
    selection_browser:
        Image|endswith:
            - '\chrome.exe'
            - '\msedge.exe'
            - '\firefox.exe'
            - '\brave.exe'
            - '\opera.exe'
    selection_args:
        CommandLine|contains:
            - 'file://'
            - '\\\\' # UNC path
            - '.zip'
            - '.iso'
            - '.img'
            - '.lnk'
            - '.bat'
            - '.cmd'
            - '.vbs'
            - '.exe'
            - '.scr'
    condition: selection_parent and selection_browser and selection_args
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Users clicking links in emails to download legitimate company files hosted on internal file servers or official repositories.
level: medium
tags:
    - attack.initial-access
    - attack.t1566.002
    - analytic.an0298
    - detection.det0107
```

            - 'file://'

    - attack.initial-access

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: HTTP Redirects and URL Shorteners
  * The Issue: Attackers hide the final payload URL behind url shorteners (e.g., bit.ly) or open redirects. The browser command-line will only show the shortened URL, bypassing any string checks for file extensions.
  * The Fix: Correlate process launching with web proxy logs that trace HTTP redirection paths, or inspect subsequent browser file writes to disk.

* Problem 2: Browser Web App SSO / Internal Links
  * The Issue: Office/Outlook routinely opens browser sessions for authentication (SSO) or Microsoft system pages, which can contain parameters that look complex or trigger generic string-matching filters.
  * The Fix: Specifically exclude trusted enterprise SSO domains (e.g., `*.microsoftonline.com`, `*.okta.com`) from the command-line query alerts.

* Problem 3: Standard Browser Session Reuse
  * The Issue: If Chrome is already running, clicking a link in Outlook might not spawn a new `chrome.exe` process. Instead, Outlook sends an IPC message to the existing Chrome instance, which opens a new tab. In this case, no process creation event is generated for the new URL.
  * The Fix: Deploy endpoint browser extension logging or query local browser history files and proxy logs to detect the URL visits, as host process auditing will not see the tab creation.
