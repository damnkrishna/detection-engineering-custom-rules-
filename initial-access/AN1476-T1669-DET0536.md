### 1. Technique Breakdown: T1669

* What it is: Wi-Fi Networks. Adversaries leverage rogue Wi-Fi access points (like Evil Twins) or connect corporate laptops to unauthorized, unencrypted public wireless networks to intercept traffic, perform man-in-the-middle (MitM) attacks, or bypass corporate egress filters. Detection involves monitoring processes executing wireless profile queries (e.g. netsh wlan show profiles).
* Log Source Requirements: Sysmon process creation logs (Event ID 1) and PowerShell script block logs (Event ID 4104).
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 1 captures network configuration queries (like netsh.exe wlan). Sysmon Event ID 4104 (Script Block) captures wireless profile queries executed via PowerShell commands.
  * Windows Security/Defender Logs: NO. These logs do not natively record Wi-Fi client association details unless specific verbose tracing is enabled in custom channels.
* Log Sources Covered:
  - Sysmon Event ID 1 (process_creation)
  - Sysmon Event ID 4104 (ps_script)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Querying of wireless network profiles can be detected using process creation and PowerShell script block logs.

### 2. Custom Sigma Rule

The detection logic is split into command-line process queries and PowerShell script block profile queries.

Rule 1 of 2: Wi-Fi Network Anomalies - Wireless Profile Query (Process Creation)
```yaml
title: Wi-Fi Network Anomalies - Wireless Profile Query (AN1476-A)
id: b9492d1a-e7b8-4529-a03d-0998833258c3
status: experimental
description: Detects processes executing wireless profile queries or WLAN auto-config events logging successful connection to unsecured (open) networks.
author: Antigravity
date: 2026-06-12
logsource:
    category: process_creation
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\netsh.exe'
        CommandLine|contains:
            - 'wlan'
            - 'show profiles'
            - 'show networks'
            - 'export profile'
    condition: selection_process
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - ParentCommandLine
    - CurrentDirectory
    - User
    - LogonId
falsepositives:
    - Legitimate administrator troubleshooting network connectivity.
level: medium
tags:
    - attack.initial-access
    - attack.t1669
    - analytic.an1476
    - detection.det0536
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: SSID Spoofing (Evil Twin with encryption)
  * The Issue: If an attacker sets up a rogue access point spoofing the corporate SSID and using WPA2-Enterprise with a rogue authentication server (Evil Twin), the connection will not be registered as an "Open" network, bypassing open-security checks.
  * The Fix: Monitor for changes in the BSSID MAC address (checking if the access point MAC belongs to the authorized corporate AP infrastructure baseline) and report on BSSID mismatches.

* Problem 2: netsh Command Obfuscation
  * The Issue: Attackers can retrieve wireless profiles by querying registry keys directly (HKLM\Software\Microsoft\WlanSvc\Interfaces\) rather than running netsh.exe wlan, rendering process command line filters blind.
  * The Fix: Add monitoring for registry reads or queries targeting the WLAN Interfaces registry paths by non-system processes.
