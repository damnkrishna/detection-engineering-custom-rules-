### 1. Technique Breakdown: T1659

* What it is: Content Injection. Adversaries insert malicious content (such as scripts, redirection links, or iframes) into web pages or web application code. On Windows systems hosting web applications (e.g., IIS, Apache, or Nginx), this often manifests as unauthorized processes (such as scripting hosts, shells, or downloaded utilities) modifying or writing to files within the web server root directories (e.g., `C:\inetpub\wwwroot\`, `C:\xampp\htdocs\`).
* Log Source Requirements: Sysmon File Creation logs (Event ID 11), and Sysmon process creation logs (Event ID 1).
* Coverage Check:
  * HIDS (Sysmon + Wazuh): YES. Sysmon Event ID 11 tracks web content file modifications by non-standard processes. Sysmon Event ID 1 tracks administrative web server configuration modification tools.
  * NIDS (Suricata + Zeek): PARTIAL. Network monitoring can detect anomalous web requests or malicious scripts in transit, but cannot easily detect file-level writes to local disk paths.
* Log Sources Covered:
  - Sysmon Event ID 11 (file_event)
  - Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  - None.
* Conclusion: Content injection and configuration modification can be detected using file creation and process creation logs.

### 2. Custom Sigma Rule

The detection logic is split into unauthorized processes modifying files in web roots and execution of administrative configuration tools targeting web server configurations.

Rule 1 of 2: Content Injection - Unauthorized Process Writing Web Content (File Event)
```yaml
title: Content Injection - Unauthorized Process Writing Web Content (AN0992-A)
id: 5213048d-466e-4f0d-a442-e0287b6d8324
status: experimental
description: Detects command-line interpreters or scripting hosts modifying or creating files within local web server roots (e.g., C:\inetpub\wwwroot, C:\xampp\htdocs), indicating potential content injection or defacement.
author: Krishna Gupta
date: 2026-06-08
logsource:
    category: file_event
    product: windows
detection:
    selection_path:
        TargetFilename|contains:
            - '\inetpub\wwwroot\'
            - '\xampp\htdocs\'
            - '\apache\htdocs\'
            - '\nginx\html\'
    selection_extension:
        TargetFilename|endswith:
            - '.html'
            - '.htm'
            - '.js'
            - '.aspx'
            - '.asp'
            - '.php'
            - '.jsp'
    selection_process:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\curl.exe'
    condition: selection_path and selection_extension and selection_process
fields:
    - Image
    - TargetFilename
    - User
    - LogonId
falsepositives:
    - Legitimate administrative deployments or manual updates of web assets by admins using command shell scripts.
level: high
tags:
    - attack.initial-access
    - attack.t1659
    - analytic.an0992
    - detection.det0349
```

Rule 2 of 2: Content Injection - Execution of Web Server Configuration Tool (Process Creation)
```yaml
title: Content Injection - Execution of Web Server Configuration Tool (AN0992-B)
id: fb332700-9bbf-42ae-a756-06878e3a9511
status: experimental
description: Detects command-line executions modifying web server configuration files (like web.config, httpd.conf, nginx.conf) or utilizing IIS configuration tools (appcmd.exe).
author: Krishna Gupta
date: 2026-06-16
logsource:
    category: process_creation
    product: windows
detection:
    selection_appcmd:
        - Image|endswith:
            - '\appcmd.exe'
        - OriginalFileName:
            - 'appcmd.exe'
    selection_config_files:
        CommandLine|contains:
            - 'web.config'
            - 'httpd.conf'
            - 'nginx.conf'
    selection_actions:
        CommandLine|contains:
            - 'set config'
            - 'add module'
            - 'unlock section'
    condition: selection_appcmd or (selection_config_files and selection_actions)
fields:
    - Image
    - CommandLine
    - User
falsepositives:
    - Authorized configuration updates by server administrators.
level: medium
tags:
    - attack.initial-access
    - attack.t1659
    - analytic.an0992
    - detection.det0349
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: CI/CD Automated Agent Noise
  * The Issue: Deployment tools or agents (like Jenkins, GitLab runner, or Azure DevOps agents) running local commands/scripts regularly update files in the web root directories, generating high numbers of false alerts.
  * The Fix: Scope the rule to ignore updates written by authorized CI/CD application paths or service accounts explicitly designated for deployment.
  * Alternative Tuning: Limit alerting to interactive shells only (checking for interactive logon session IDs associated with the process).

* Problem 2: Alternate Web Root Configurations
  * The Issue: The rule relies on standard directory paths. If the web server uses custom paths (e.g., `D:\WebSites\CustomRoot\`), this rule will not trigger.
  * The Fix: Customize the directory filter lists to reflect actual web server configurations in the environment, or monitor file writes to paths mapped in active IIS/Apache config configurations.

* Problem 3: Direct Web Server Exploit (In-Memory)
  * The Issue: If an attacker exploits a remote code execution vulnerability (e.g., Log4j or Apache Struts) and dynamically modifies in-memory responses rather than writing to files, this rule will not trigger.
  * The Fix: Deploy endpoint security monitoring for web server parent-child relationships and monitor outbound HTTP traffic originating from the web server application pool.
