### 1. Technique Breakdown: T1679

* What it is: Selective Exclusion. Adversaries may modify security tool configurations to exclude specific files, folders, or processes from scans. This prevents their malicious payloads or activities from triggering alerts or being quarantined. On Windows, this commonly involves running PowerShell commands like `Add-MpPreference` to configure Defender exclusions, or modifying registry exclusion paths.
* Log Source Requirements:
  * Sysmon Process Creation (Event ID 1) / Registry Value Set (Event ID 13) capturing the addition of Defender exclusion settings.
* Coverage Check:
  * HIDS (Sysmon): YES. Modifying exclusion keys via PowerShell commands or registry writes generates process and registry logs.
  * NIDS (Zeek/Suricata): NO. Security exclusions are entirely local host configuration tasks.
* Log Sources Covered:
  * Sysmon Event ID 1 (process_creation)
  * Sysmon Event ID 13 (registry_event)
* Log Sources Missing / Unused:
  * None.

### 2. Custom Sigma Rule

The following rule monitors both process creation and registry modifications for commands or writes configuring selective exclusions in Windows Defender or security products.

```yaml
title: Windows Defender Selective Exclusion Configuration (AN2127)
id: f1a2b3c4-e5f6-7a8b-9c0d-1e2f3a4b5c88
status: experimental
description: "Detects the modification of security tool exclusions (such as adding Windows Defender folder/process exclusions via Add-MpPreference or registry writes under the Windows Defender\\Exclusions key), which is commonly used to hide malicious files from AV scans."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_ps:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_ps_ofn:
        OriginalFileName:
            - 'PowerShell.EXE'
            - 'pwsh.exe'
    selection_cli_exclusions:
        CommandLine|contains:
            - 'Add-MpPreference'
            - 'Set-MpPreference'
    selection_cli_flags:
        CommandLine|contains:
            - ' -ExclusionPath'
            - ' -ExclusionProcess'
            - ' -ExclusionExtension'
    selection_reg_path:
        CommandLine|contains:
            - '\SOFTWARE\Microsoft\Windows Defender\Exclusions'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (((selection_ps or selection_ps_ofn) and selection_cli_exclusions and selection_cli_flags) or selection_reg_path) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - User
falsepositives:
    - IT administrators or deployment software configuring database folders or virtual machine storage directories to be excluded from real-time antivirus scans for performance tuning.
level: high
tags:
    - attack.defense_evasion
    - attack.t1679
    - analytic.an2127
    - detection.det0984
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Registry updates using SYSTEM account
  * The Issue: In our implementation, we do not restrict the user, which is correct; however, standard installers might use SYSTEM to write exclusions.
  * The Fix: Scrutinize exclusions added by SYSTEM using ParentImage checks to ensure they are verified software deployment systems (like SCCM).
* Problem 2: Obfuscated PowerShell parameters
  * The Issue: If `Add-MpPreference` is run via encoded Base64 command lines (`powershell -e ...`), this process CLI rule will fail to match the contains filter.
  * The Fix: Rely on a companion rule looking for PowerShell Encoded Commands (AN2106) or inspect script block logs (Event ID 4104).
* Problem 3: Exclusion of administrative folders
  * The Issue: legitimate administrative applications might legitimately add exclusions, creating alerts.
  * The Fix: Baseline standard folder paths (e.g. SQL directories or IIS folders) and whitelist them if they are configured by verified scripts.
```
