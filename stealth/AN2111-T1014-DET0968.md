### 1. Technique Breakdown: T1014

* What it is: Rootkit. Adversaries may install rootkits to hide files, processes, network connections, registry keys, or drivers from operating system APIs. On Windows systems, this is typically achieved by installing custom kernel-mode drivers (SYS files) or exploiting/loading vulnerable signed drivers (BYOVD) to disable Driver Signature Enforcement (DSE) and hook system routines.
* Log Source Requirements:
  * Sysmon Process Creation (Event ID 1) to detect rootkit inspection/installation tools or driver configuration parameters.
* Coverage Check:
  * HIDS (Sysmon): YES. Executing driver loading scripts or anti-rootkit tools generated telemetry.
  * NIDS (Zeek/Suricata): NO. Rootkit operations are completely local to the kernel.
* Log Sources Covered:
  * Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  * None.

### 2. Custom Sigma Rule

The following rule monitors the execution of driver signature enforcement bypass utilities, kernel mode helper tools, or anti-rootkit debuggers commonly abused to modify or hide kernel drivers.

```yaml
title: Rootkit Installation or Kernel Driver Bypass Tool Execution (AN2111)
id: e5f6a7b8-9c0d-1a2b-3c4d-5e6f7a8b9c90
status: experimental
description: "Detects the execution of known kernel driver loaders, driver signature enforcement bypass tools (e.g., dsefix, kdu, DSE-Bypass), or anti-rootkit forensic utilities (gmer, pchunter) commonly abused by attackers to inspect or disable kernel protection systems."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\dsefix.exe'
            - '\kdu.exe'
            - '\gmer.exe'
            - '\pchunter.exe'
            - '\pchunter64.exe'
            - '\hacker.exe'
    selection_ofn:
        OriginalFileName:
            - 'dsefix.exe'
            - 'kdu.exe'
            - 'gmer.exe'
            - 'PCHunter'
            - 'PCHunter64'
            - 'ProcessHacker.exe'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_images or selection_ofn) and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - User
falsepositives:
    - Incident response analysts or malware researchers running kernel inspection tools during forensic investigation.
level: critical
tags:
    - attack.defense_evasion
    - attack.t1014
    - analytic.an2111
    - detection.det0968
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Native service command loads (sc.exe)
  * The Issue: If the attacker loads a kernel driver using the native Windows command `sc.exe create [name] binPath= [path] type= kernel`, this rule will not trigger.
  * The Fix: Ensure you deploy a companion rule that explicitly flags `sc.exe` executions where `type= kernel` or `type= filesys` is present in the command line (e.g., AN0778 service creation rule).
* Problem 2: Custom compiled BYOVD tools
  * The Issue: Attackers using custom compiled utilities that interact directly with the LSA/Kernel via IOCTL calls to load drivers without DSEfix or KDU will bypass this signature.
  * The Fix: Monitor Sysmon Event ID 6 (Driver Load) and verify loaded drivers against a whitelist of known legitimate hashes.
* Problem 3: Process Hacker false positives
  * The Issue: Process Hacker is used legitimately by developers and administrators, leading to frequent medium/high alerts.
  * The Fix: Scope alerts for Process Hacker to non-admin directories or unexpected execution paths (e.g. C:\Users\Public\).
