### 1. Technique Breakdown: T1006

* What it is: Direct Volume Access. Adversaries may bypass host-based file access controls and auditing mechanisms by directly accessing and reading/writing to the raw logical or physical disk volume. This is typically done to extract protected system files (like the SAM registry hive or NTDS.dit database) or to overwrite disk sectors.
* Log Source Requirements:
  * Sysmon Process Creation (Event ID 1) capturing process command-lines attempting to read raw device paths.
* Coverage Check:
  * HIDS (Sysmon): YES. Processes attempting direct volume access via CLI parameters leave traces.
  * NIDS (Zeek/Suricata): NO. Host-level raw disk access is entirely local.
* Log Sources Covered:
  * Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  * Standard Windows file system audit logs (since direct volume access bypasses standard NTFS file access audits).

### 2. Custom Sigma Rule

The following rule monitors for command line operations that invoke utilities or scripts attempting direct volume access by querying physical drive paths (`\\.\PhysicalDrive`) or logical volume strings.

```yaml
title: Direct Volume Access Command Line Detection (AN2109)
id: c3d4e5f6-7a8b-9c0d-1e2f-3a4b5c6d7e80
status: experimental
description: "Detects process execution command-line parameters attempting direct access to raw physical drives, logical drives, or volume shadow copies (e.g., using physical drive paths like \\\\.\\PhysicalDrive or raw logical paths). This is commonly used to bypass OS file lock/permission security controls."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_images:
        Image|endswith:
            - '\dd.exe'
            - '\vshadow.exe'
            - '\rawcopy.exe'
            - '\ninja.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\cmd.exe'
    selection_ofn:
        OriginalFileName:
            - 'dd.exe'
            - 'vshadow.exe'
            - 'rawcopy.exe'
            - 'PowerShell.EXE'
            - 'pwsh.exe'
            - 'Cmd.Exe'
    selection_cli:
        CommandLine|contains:
            - '\\.\PhysicalDrive'
            - '\\.\Volume'
            - '\\.\c:'
            - '\\.\d:'
            - '\\.\e:'
            - '\\.\f:'
    filter_legitimate:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_images or selection_ofn) and selection_cli and not filter_legitimate
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - User
falsepositives:
    - Backup software or disk imaging utilities legitimately reading raw volumes to create system backups.
    - Disk checking tools (chkdsk) run by administrators.
level: high
tags:
    - attack.defense_evasion
    - attack.t1006
    - analytic.an2109
    - detection.det0966
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Custom C/C++ compiled binaries
  * The Issue: If the attacker runs a custom compiled utility that opens a handle to `CreateFileW` with the `\\.\PhysicalDrive0` path, the string will not appear in the process creation command line.
  * The Fix: Enable Sysmon Event ID 10 (Process Access) or Event ID 25 (Process Tampering) / Event ID 11 (File Event) monitoring for direct device object handle requests, or look for anomalous device driver openings.
* Problem 2: Disk volume drive letter variations
  * The Issue: Drive letters beyond A-F (e.g. `\\.\X:`) will not be matched by the specific drive lists in selection_cli.
  * The Fix: Replace containing strings with a generic regex check to match any single character drive letter path: `\\\\.\\\\[a-zA-Z]:`
* Problem 3: Volume Shadow Copy service noise
  * The Issue: Backup agents run `vshadow.exe` periodically, which triggers alerts.
  * The Fix: Whitelist known backup service account names or specific parent processes of enterprise backup agents.
