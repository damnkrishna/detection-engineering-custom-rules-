### 1. Technique Breakdown: T1001

* What it is: Data Obfuscation. Adversaries may obfuscate command and control traffic or payloads to bypass network security checks or file scanners. This includes using steganography to hide data inside media files (like images or audio) before transmission, or applying custom mathematical wrappers to payload streams.
* Log Source Requirements:
  * Sysmon Process Creation (Event ID 1) logging commands associated with known steganography tool usage or wrapping programs.
* Coverage Check:
  * HIDS (Sysmon): YES. Processes spawned to perform steg operations leave process telemetry.
  * NIDS (Zeek/Suricata): NO. Payloads inside network traffic are obfuscated and require inspection at the endpoint.
* Log Sources Covered:
  * Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  * Network flow logs (cannot decode the payload streams).

### 2. Custom Sigma Rule

The following rule monitors for the execution of common command-line steganography utilities used by adversaries to hide or extract embedded payloads in media files.

```yaml
title: Steganography or Data Obfuscation Utility Execution (AN2108)
id: f1c2d3e4-a5b6-4c7d-8e9f-0a1b2c3d4e65
status: experimental
description: "Detects the execution of known command-line steganography tools (e.g., steghide, openstego, outguess) commonly used by threat actors to embed or extract hidden payloads inside images or audio files to bypass network monitoring."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_steg_images:
        Image|endswith:
            - '\steghide.exe'
            - '\openstego.exe'
            - '\outguess.exe'
    selection_steg_ofn:
        OriginalFileName:
            - 'steghide.exe'
            - 'openstego.exe'
            - 'outguess.exe'
    selection_steg_cli:
        CommandLine|contains:
            - 'embed'
            - 'extract'
            - '-ef'
            - '-cf'
            - '-sf'
            - '-xf'
    filter_installer:
        ParentImage|endswith:
            - '\msiexec.exe'
            - '\setup.exe'
    condition: (selection_steg_images or selection_steg_ofn) and selection_steg_cli and not filter_installer
fields:
    - Image
    - OriginalFileName
    - CommandLine
    - ParentImage
    - User
falsepositives:
    - Developer or security audit environments where steganography tools are tested or used in training exercises.
level: medium
tags:
    - attack.defense_evasion
    - attack.t1001
    - analytic.an2108
    - detection.det0965
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: Custom Steganography scripts
  * The Issue: Python or PowerShell scripts that perform pixel manipulation or LSB encoding will not execute under these binary names and will bypass this rule.
  * The Fix: Implement script block logging filters to search for libraries like Python's `PIL` or `stegano` being imported by unknown scripts.
* Problem 2: Compiled custom wrappers
  * The Issue: If the attacker writes a custom compiled C/Go tool to perform XOR/AES wrapping, the tool will have a unique name and hash, bypassing known steg utility signatures.
  * The Fix: Rely on behavioural heuristics of the child processes or file writing anomaly detection (e.g., a non-standard process writing large volumes of encoded data).
* Problem 3: Multi-purpose archive tools
  * The Issue: Archivers like WinRAR or 7-Zip can embed data into self-extracting comments or append data to file ends, which is not flagged by these specific steg binaries.
  * The Fix: Monitor for execution of zip utilities with anomalous parameters or non-standard file appends.
