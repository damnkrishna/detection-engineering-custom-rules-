### 1. Technique Breakdown: T1221

* What it is: Template Injection. Adversaries may use template injection to execute malicious code via template relationships inside Microsoft Office documents. When a victim opens a document, the application fetches and loads a remote template containing malicious macros or exploit code, bypassing standard macro inspection.
* Log Source Requirements:
  * Sysmon Process Creation (Event ID 1) capturing Microsoft Office applications spawning child command shells or interpreters to execute injected code.
* Coverage Check:
  * HIDS (Sysmon): YES. Office processes launching interpreters generates telemetry.
  * NIDS (Zeek/Suricata): NO. Endpoint process telemetry is required to identify the parent-child relationships.
* Log Sources Covered:
  * Sysmon Event ID 1 (process_creation)
* Log Sources Missing / Unused:
  * Network flow logs (does not capture process relationship detail).

### 2. Custom Sigma Rule

The following rule monitors the process creation log for child command interpreters or script hosts spawned by Microsoft Office binaries (such as Word, Excel, PowerPoint), which is highly characteristic of template injection exploitation.

```yaml
title: Microsoft Office Application Spawning Script Interpreter (AN2119)
id: f1a2b3c4-e5f6-7a8b-9c0d-1e2f3a4b5c80
status: experimental
description: "Detects command-line script interpreters or shell utilities (cmd.exe, powershell.exe, mshta.exe, wscript.exe, cscript.exe) running as child processes of Microsoft Office applications (Word, Excel, PowerPoint), which is a common indicator of remote template injection or macro-based execution."
author: Krishna Gupta
date: 2026-07-01
logsource:
    category: process_creation
    product: windows
detection:
    selection_parent:
        ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\powerpnt.exe'
            - '\outlook.exe'
    selection_child_images:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\rundll32.exe'
            - '\regsvr32.exe'
    selection_child_ofn:
        OriginalFileName:
            - 'Cmd.Exe'
            - 'PowerShell.EXE'
            - 'pwsh.exe'
            - 'wscript.exe'
            - 'cscript.exe'
            - 'mshta.exe'
            - 'rundll32.exe'
            - 'regsvr32.exe'
    filter_legitimate_child:
        Image|endswith: '\rundll32.exe'
        CommandLine|contains: 'shell32.dll'
    condition: selection_parent and (selection_child_images or selection_child_ofn) and not filter_legitimate_child
fields:
    - ParentImage
    - Image
    - CommandLine
    - User
falsepositives:
    - Legitimate enterprise add-ins or custom office extensions that launch scripting interpreters to generate reports or integrate with database backends.
level: high
tags:
    - attack.defense_evasion
    - attack.t1221
    - analytic.an2119
    - detection.det0976
```

### 3. Blind Spots & Tuning (The "Problems")

* Problem 1: In-process exploitation (DDE/Exploits)
  * The Issue: If the attacker exploits a vulnerability in Word (like CVE-2017-11882 Equation Editor) to execute code directly inside the office process memory or via `eqnedt32.exe` without spawning standard command shells, this child process check will miss the behavior.
  * The Fix: Add `eqnedt32.exe` to the parent selection or monitor process access handle requests from office binaries to other processes.
* Problem 2: Legitimate VBA macro automation
  * The Issue: Some legacy corporate spreadsheets contain legitimate VBA macros that call shell commands to archive files or move data, generating frequent alerts.
  * The Fix: Baseline the specific scripts, limit exclusions to the exact hashes of the spreadsheets, or restrict execution to trusted service accounts.
* Problem 3: DLL loading via office folders
  * The Issue: The template can perform sideloading of an anomalous DLL into the Office application space directly, avoiding process creation altogether.
  * The Fix: Monitor Image Loads (Event ID 7) inside office processes for files loaded from Temp or non-standard paths.
